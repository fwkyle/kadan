# 발송 절차 — 사용자의 말을 판에 전하는 법

아래 표의 `kadan`은 PATH에 없으면 `node <저장소>/src/cli.mjs`로 치환한다.

## 전달 종류

새 실행만 중앙 카드로 등록해 --task로 발령한다. 기존 작업의 사용자 방향 정정·현황 질문은
슈퍼감독에게 일반 send로 전달하고 새 계획 카드를 만들지 않는다. 범위 정정은 수신 감독이
기존 카드의 판단/승인 이력에 반영한다. 보고/질문 전달이 새 실행 권한을 만들지는 않는다.

자동 첨부의 원본은 [공통](../../kadan-conductor/references/role-templates/common.md)과
[역할별 템플릿](../../../docs/role-instructions.md)이다. 역할 책임 안내가 카드의 수신자·승인값을 대신하지 않는다.
수신자는 받은 본문·최신 카드/결정을 읽고 이번 행동에 필요한 상세 절만 다시 읽는다.

## 순서

1. **사용자의 말을 카드로 정리한다.** Why 먼저, 실행형, 2시간 상한, 금지 목록,
   완료 기준. 작성 후 [중앙 카드 절차](../../kadan-conductor/references/central-cards.md)로 등록하고 그 원본 경로를 보낸다.
2. **받는 사람을 정한다.** 슈퍼감독이 살아 있으면 슈퍼감독에게, 없으면 해당 판
   감독에게만 보낸다. `kadan tree`·`kadan status`로 살아 있는 역할을 먼저
   확인한다.
3. **보낸다.**

```bash
KADAN_ROLE=비서 kadan send <역할> --task <카드id> "<카드 경로>를 읽고 수행. 완료 시 KADAN:DONE <카드id> <ok|failed> 형식으로 출력"
```

완성된 마커 문자열을 지문에 쓰지 않는다 — 형식과 카드 id만 주고 조립은 받는
에이전트가 한다(2026-08-30 실측, 입력 에코 오판 방지).

4. **CLI 전달 결과를 확인한다.** 정상 `send` 뒤 같은 목적의 `read`를 강제하지 않는다.
   전달 결과를 착수·완료로 확대하지 않는다(2026-08-07 흉터: 판정≠알림≠조치).
   새 역할 준비·전달 불명확·실제 오류·결과 불일치·사용자 확인 요청 때만 필요한 화면을 확인한다.
   상세는 [전달 후 확인 범위](../../kadan-conductor/references/dispatch-wait.md#전달-후-확인의-범위)를 따른다.

5. **사용자에게 보고한다.** 어디로(역할), 무엇을(카드 id), 어떤 전달 결과가 확인됐는지
   쉬운 말로 짧게 알린다. 착수·완료를 확인하지 않았으면 확인한 것처럼 말하지 않는다.

## 보내면 안 되는 경우

- 사용자가 시키지 않은 것 — 비서가 자기 판단으로 지시하는 순간 두 번째
  지휘자가 된다.
- 슈퍼감독도 판 감독도 없으면 보내지 않는다. 먼저 슈퍼감독을 세울지
  사용자에게 묻는다. 작업자에게 우회 발송하지 않는다(07-23).
- 작업자·검수자에게 직접 보내는 것 — 2026-07-23 이중 개입 흉터. 반드시
  슈퍼감독이나 판 감독을 거친다.
- 받는 세션이 죽었거나 PID가 다른 경우 — send가 실패 닫힘으로 거절한다.
  재시도하지 말고 사용자에게 보고한다.
- 내용이 모호한 경우 — 자동 재시도·재전송 없이 되묻는다.
- 이미 같은 이상을 받은 역할에게 같은 내용을 또 보내는 것.
- 비서가 직접 해결할 수 있는 것처럼 보여도 구현·수정 지문 — "제가 해둘까요?"는
  비서의 말이 아니다. 알아내서 말씀드리는 데까지가 비서다.

## 원장에 남는 것

발송·세우기에 `KADAN_ROLE=비서`를 붙이므로 원장에 `by:"비서"`로 남는다(card-28).
비서 세션은 사용자와 대화하는 창이라 카단 세션이 아니다 — 그래서 신분은 환경
변수로 명시한다. 나중에 "누가 시켰어?"에 한 줄로 답할 수 있는 근거다.
