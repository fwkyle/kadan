# watch 운영

## Why

감독이 감시 보고의 뜻과 실제 수신자를 확인하고 필요한 후속 조치만 하도록 한다.

## 생존과 재가동

```bash
pgrep -x kadan-watch
```

- PID 1개: 현재 watch를 유지한다.
- PID 0개: 감시 공백이다. 원인 조사 전에 현재 승인 명령으로 재가동한다.
- PID 2개 이상: RED 후보다. broad kill하지 말고 각 소유 터미널을 확인한다.

watch는 전용 터미널의 foreground에서 실행하고 Ctrl+C로 끝낸다.

```bash
kadan watch \
  --route <판>=<판-감독> \
  --super <슈퍼역할> \
  [--judge-cmd '<셸 명령>']
```

재가동 뒤 `pgrep -x kadan-watch`가 PID 하나인지 확인하고, 죽은 시각 전후의
터미널·자원·원장 사실을 읽는다. 자동 재시작 코드나 데몬을 추가하지 않는다.

## route 설계

- 역할 이름의 첫 `-` 앞이 판 이름이다.
- 특정 판의 이상을 지정 감독에게 보낼 때만 `--route <판>=<역할>`을 추가한다.
- `--hierarchy`가 있으면 실제 직속 상위 사슬이 우선이며, 상위가 없으면 같은 사슬을 따라 최종 `@user`로 간다.
- 명시 관계가 없고 명시 route도 없으면 살아 있는 `kadan-<판>-감독`, 그다음 `--super`, 마지막
  stdout 순서다.
- 자원 수치는 대시보드·CLI에서 감독이 확인하며 watch는 자원 경고·해제 우편으로 AI를 깨우지 않는다. 판 없는 실제 오류는 기존 경로를 따른다.
- 출력의 `→ <수신자>`가 이미 정한 한 명이다. 같은 이상을 다른 역할에 다시 보내지 않는다.

## 감시sh / 감시ai

감시sh는 현재 책임 대상과 시간 조건을 고른다. 실제 미완료 작업자는 화면 무변화 기본5분과 설정 횟수, 진행 조정30분 기준으로 감시한다. 완료·보류·취소·미발령·유효 입력 대기는 제외한다.

활성 실행 또는 발령 이력이 있는 열린 업무를 책임지는 일반감독은 별도로 1시간마다 응답 상태를 점검한다. 연결·SSE·문맥 압축 오류가 5분 지속되면 먼저 감시ai에 넘긴다. 감독의 정당한 결과 대기는 정상이다. 최상위 슈퍼감독·비활성 업무·관리 카드만 남은 판은 정기 점검에서 제외한다. 이전/현재 화면·맡은 실행·최근 우편을 함께 보고, 우편 저장·전송을 처리 완료로 추측하지 않는다.

감시ai는 관찰 자료를 판단한 뒤 `kadan watch-report <호출ID> --verdict <판정> --reason <이유>`를 실행한다. 이 명령이 기록·중복 방지·기존 상신 경로를 처리한다. stdout의 낱말·호칭을 감시sh가 다시 해석하는 방식은 폐기했다.

- 진행중/입력대기/실행완료: 기록만 남긴다. 감독을 깨우지 않는다. 기존 AI 경보도 조용히 닫는다.
- 응답장애/정체/조정/모름: 근거와 함께 기존 상위에게 보고한다. 모름은 AI의 근거 부족이며 호출 오류와 다르다.
- 새 감시ai는 정상 실행 완료를 죽음으로 보고하지 않는다. 실제 세션 부재는 감시sh가 알린다. 같은 실행의 동일 완료 화면은 AI를 다시 호출하지 않으며, 원장 done·업무 최종 완료는 감독이 확인한다.
- 같은 호출·같은 문제는 반복 발송하지 않는다. 정상 뒤 재발 또는 판정/등급 변화 때만 새 보고가 온다.
- 호출 실패·3분 시간 초과·보고 명령 미실행·전달 기록 미완료는 감시sh가 `감시AI 점검 필요`로 알린다. 이를 작업자 사망이나 완료로 해석하지 않는다.
- 감시ai는 동시에 하나만 실행하며 기다리는 동안에도 감시sh는 다른 대상을 계속 점검한다. 대기 후보는 역할별로 합쳐 순서대로 처리하고 시작할 때 현재 담당·화면을 다시 확인한다.
- 보고와 필요한 전달이 원장에 접수되면 해당 AI 호출만 종료한다. 마지막 대화 응답을 기다리지 않으며, 완료·보류·교대된 대상의 남은 호출도 그 호출만 취소한다.
- 확실한 세션/PID·접속 오류·시작 보고 누락은 감시sh의 기존 규칙 보고다. 자원 값은 감시ai 호출·상신 대상이 아니다.

## 알림 문구 읽기

| 알림 | 감독이 할 일 |
|---|---|
| `[감시AI] 작업 정체 확인 필요` | 이유와 현재 작업을 확인하고 다음 행동 연결 |
| `[감시AI] 응답 장애 의심` | 연결·압축 오류와 현재 처리 가능 여부 확인. 자동 재시작하지 않음 |
| `[감시AI] 진행 조정 필요` | 반복 실패/범위 확대의 근거를 확인하고 조정. 연속2회면 상위와 범위·담당 검토 |
| `[감시AI] 상태 판단 근거 부족` | 무엇이 부족한지 이유를 읽고 현재 상태 확인 |
| `감시AI 점검 필요` | AI 호출/보고 경로 확인. 작업자 상태 판정과 별개 |
| `끊김` | 식별된 접속 실패의 기존 재개 절차 |
| `한도` | [일시적 429 제한 재개](../../../docs/rate-limit-retry.md)의 대상·상한 확인. 그 밖의 새 근거 복구는 [일반감독 결정 범위](../../kadan-conductor/references/operating-contract.md#일반감독의-결정-범위) 적용 |
| `설정` | 설정 오류의 원인 확인 |

AI 보고의 실제 수신자는 `watch-ai-delivery`와 `send` 원장에 남는다. 감시sh 출력에는 `보고 전달 → 수신자`가 나온다. 같은 이상을 다른 감독이나 자신에게 재중계하지 않는다. 저장·전송 성공은 감독의 처리 완료가 아니다.

자원 경보·해제 우편은 보내지 않는다. 그 밖의 기계 경보 해제는 이전 이상을 받은 수신자에게 한 번 보낼 수 있다. AI 정상 판정·감시 제외·AI 호출 장애 해제는 기록만 남기고 해제 우편을 보내지 않는다. 어느 쪽도 작업 완료를 뜻하지 않는다.

구현·기록 원본: [감시 기준](../../../docs/watch-overview.md). 감시 기준을 다른 스킬에 복제하지 않는다.
