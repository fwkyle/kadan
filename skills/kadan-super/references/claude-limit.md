# Claude 한도에 멈춘 역할 이어가기

## Why

Claude 한도로 여러 역할이 멈췄을 때, 사용자가 계정·모델을 결정하고 어느 AI든 같은 명령으로
멈춘 세션을 확인하고 이어가게 한다. 계정 교체는 사용자가 직접 한다.

## 순서

1. `kadan claude refresh`로 멈춘 역할 수와 역할별 `초기화 줄`의 리셋 시각을 확인한다.
   `--json`에서는 `counts.target`과 `rows[].resetLine`이다. 시각이 없으면 미확인으로 남긴다.
2. 사용자에게 질문 하나: “계정 교체해 줄까요, 아니면 다른 모델(codex 등)로 돌릴까요?”
   계정 교체를 고르면 사용자가 직접 처리한다. AI가 로그인·키체인·자격 파일을 바꾸지 않는다.
3. 교체를 마쳤다는 안내 뒤 `kadan claude refresh --nudge`를 실행한다.
   한도로 보이는 역할만 대상이며 `--role <역할>[,…]`로 좁힐 수 있다.
   화면 끝의 확인된 한도 메뉴에는 Escape를 한 번 보내고, 닫힘과 빈 입력창을 확인한 뒤
   기존 우편 경로로 이어가기를 요청한다. 메뉴가 없으면 Escape를 누르지 않는다.
   역할 세션 안에서도 허용하며 재시작·계정 교체는 하지 않는다.
4. 기본 8초 뒤의 결과 표를 읽는다(`--interval <초>`, `--json` 지원).
   `깨움`은 화면 끝에서 한도 표시가 사라졌다는 뜻이며 계정 교체나 업무 완료의 증명이 아니다.
   `건너뜀`은 이유를 확인한다. `그대로 한도`인 역할만 사용자에게
   `kadan claude refresh --yes --role <역할>[,…]`를 안내한다. 이 재시작 명령은 사람만 직접 친다.
   한도 선택 메뉴가 남은 역할은 `--yes --role`도 건너뛴다 — 사람이 그 화면을 직접 보고 처리한다.

`--nudge`와 `--yes`·`--switch`·`--select`는 함께 쓰지 않는다.
응답 생성 중·입력 글·자기 자신·비서·기반 프로세스는 건드리지 않는다.
직전 화면 변경·PID 불일치·메뉴 닫힘 미확인은 건너뛰며 전달 불명확은 재시도하지 않는다.
지원하지 않는 메뉴 문구나 줄바꿈은 추정으로 Escape를 보내지 않는다.

카단의 [일시적 429 자동 재개](../../../docs/rate-limit-retry.md)는 명시 일일·주간 사용 한도를
해결하는 기능이 아니다. 이를 기다리는 것만으로 계정 한도가 풀리지는 않는다.
Claude 자체의 예약 재개와 카단의 429 재개는 별개다.

## 2026-10-27 관측과 미확인

- 관측: 주간 한도로 멈춘 Claude 역할 7개에 대해 사용자가 계정을 교체한 뒤,
  한도 메뉴 Escape → 이어가기 우편 → 약 1분 뒤 화면 확인으로 6개가 재시작 없이 다시 돌았다.
- 미확인: 다시 돈 세션이 실제로 어느 계정으로 요청했는지. “켜진 세션은 옛 로그인을 계속 쓴다”는
  10-23 관측과 결과가 달라졌지만, 계정이 바뀌었다고 단정하지 않는다.

## 판정 근거와 바닥

메뉴 문구는 설치된 Claude Code 2.1.311 실행 파일의 `rate-limit-options`에서 확인했다:
`What do you want to do?`, `Stop and wait for limit to reset`,
`Wait here, then continue automatically shortly` / `at …` / `when the limit resets`.
이 선택지와 취소 안내가 화면 끝에 있는 경우만 허용한다. 시험 화면 배치는 합성이며
이 명령을 실제 Claude 운영 세션에 실행한 검증은 아니다.

키 도우미는 tmux 구현에만 둔다. 공통 바닥의 7함수+선택1 계약은 늘리지 않으며 herdr에서는
이 명령 전체를 거절한다. 원장은 기존 `send`에 `nudge:true`, Escape를 보낸 경우
`escaped:true`만 더한다. `stop`·`start` 사건은 쓰지 않는다.
