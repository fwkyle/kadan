# 교대(handover) — 문맥 관리와 응답 장애 복구

## Why

정상적으로 처리하는 대화는 유지하고, 응답 장애가 확인된 대화는 저장 결과와 담당 관계를 보존하며 다음 담당이 이어받게 한다.

슈퍼감독·판 감독·검수자·비서 모두 이 절차 하나를 쓴다 (2026-09-02 card-42로 한곳에 모음).

## 언제

문맥이 많아도 정상적으로 처리하면 기존 압축을 사용한다. 판 경계·확인된 판단 품질 저하·
문맥 누적을 보고 교대가 필요한지 판단한다. 단순 사용률과 실제 응답 장애는 구분한다.

**기준은 실행기마다 다르다** (2026-10-19 [kyle] 결정: codex·claude code 모두 자동 압축이 잘 돈다. 2026-08-10 결정에서 claude를 "자동 압축을 기대하지 않는다 / 80%에서 교대"로 둔 것을 바꿨다):

| 계열 | 상주 역할에서 | 대화 용량이 많이 찼을 때 |
|---|---|---|
| gpt (codex: astra·sol·luna·terra), claude code (opus·fable 등) | 정상 압축 중에는 기존 대화 유지 | 비율만으로 교대하지 않는다. 실제 압축/응답 장애만 아래 기준 적용 |
| 그 외 (zai glm, kimi k3) | 자동 압축 실측 근거가 아직 없다 | 용량 %만으로 교대·보류하지 않는다. 실제 압축 실패가 화면·원장으로 확인되면 아래 기준으로 교대하고, 상주 편성 때 감안한다 |

- **%는 근거가 아니다.** 몇 번을 읽었는지, 오르는지와 상관없이 교대는 실제 압축·응답 장애로만
  판단한다 (사고 08-10 슈퍼감독, 09-01 비서 — 한 번 읽은 %로 교대를 올렸다가 취소, 같은 실수 두 번).
- 문맥 비율만으로 Codex·claude code 감독·검수자를 교대하지 않는다. 정상 입력 대기나 진전 있는 긴 작업도 교대 사유가 아니다.
- 자동 압축 근거가 없는 실행기(glm·kimi)를 상주 역할(감독·검수자)에 앉힐 때는 편성 단계에서
  압축 실패 가능성을 감안한다. 용량 %는 교대 근거가 아니며, 실제 장애가 보일 때만 교대한다.

## 응답 장애가 확인됐을 때

- 압축 오류가 반복되고 새 입력을 처리하지 못하는 등 실제 장애를 화면·원장으로 확인한다. 문맥 %만으로 원인을 단정하거나 실패한 compact/입력을 계속 밀어 넣지 않는다. 이 기준은 Codex·claude code에도 적용한다.
- 소유 작업자·검수자의 단일 교대는 일반감독이, 감독 자신의 교대는 직속 상위가 결정한다. 권한과 사용자 금지의 경계는 [일반감독의 결정 범위](../../kadan-conductor/references/operating-contract.md#일반감독의-결정-범위)를 따른다. 비서는 사용자 지시를 전달하고 감시체계는 알림만 맡는다.
- 같은 업무·실행·작업공간·승인 모델을 유지하고, 저장된 합격·실패·미확인·미처리 입력을 정확히 넘긴다. 새 카드/전체 재검증이나 병렬 인력 증원으로 바꾸지 않는다. 후임 준비 동안 선임을 보존하는 일시 공존은 단일 교대이며 선임의 새 실행을 겹치게 발령하지 않는다.
- 지원 `kadan handover` 절차를 사용한다. 후임 인수·담당/수신 관계 이전 확인 후 정확 선임만 종료한다. 인수 대기는 프로그램에 맡기고 완료/문제 통지를 받으며 AI 폴링으로 기다리지 않는다. 현재 명령은 [인계 안내](../../../docs/handover.md)에서 읽는다.

## 순서는 고정이다

`후임 생성 → 후임의 카드·원장 읽기와 인수 확인 → 담당·수신 관계 이전 확인 → 정확 선임 종료 → 후임 활성화`

- 화면에 CLI가 떴다는 것만으로 인수를 확정하지 않는다. 후임의 실제 자료 읽기·인수 근거와
  지원 CLI 전환 기록을 확인한다. 전환 전 새 구현을 시켜 첫 결과까지 기다리는 관문을 만들지 않는다.
- 후임 없이 선임을 종료하지 않는다. 한 단계라도 확인 안 되면 교대를 실패로 기록하고
  선임을 그대로 둔다 (사고 08-04: 후임 화면은 떴는데 등록이 안 된 채 교대 판정될 뻔).
  "일단 떴으니 됐다"로 반올림하지 않는다.

## 인계는 무상태다

넘기는 것은 **판 이름·역할 이름·원장 경로**뿐이다. 비서는 여기에 **사용자의 현재
지시**를 더한다. 선임의 대화 문맥·판단 이력·요약 브리핑을 넘기지 않는다. 후임은
`kadan tree`·`kadan log`·`kadan read`로 스스로 상태를 복원해야 한다. 그래야 선임의
오판이 상속되지 않는다.
