# 모델을 한꺼번에 바꾸기

## Why

사용자가 "모델을 일괄로 바꿔 달라"고 했을 때, 어느 슈퍼감독이든 같은 순서로 설정을 바꾸고
이미 떠 있는 역할까지 반영하게 한다. 설정만 바꾸면 떠 있는 역할은 옛 모델로 계속 돈다.

어떤 역할을 어떤 모델·강도로 바꿀지는 사용자의 지시를 따른다. 이 문서는 순서와 명령만 정한다.
`<…>`는 자리표시다. 옵션 전체는 [실행 모델 설정](../../../docs/runner-settings.md)과
[명령어 사전](../../../docs/commands.md)이 원본이다.

## 순서 한눈에

| 단계 | 하는 일 |
|---|---|
| 1 | 설정을 바꾼다(`kadan runners …`) |
| 2 | 새로 띄우는 역할은 그때부터 새 설정으로 뜬다. 떠 있는 역할은 그대로다 |
| 재시작 전 확인 | 여러 역할을 재시작하기 전에 각 역할 화면에서 도는 백그라운드 작업이 없는지 본다 |
| 3 | 떠 있는 역할은 재시작으로 바꾼다(기본) |
| 4 | 재시작할 수 없거나, 세션 안에서 도는 작업을 살려야 하면 그 창에서 바꾼다 |
| 5 | 한도에 걸려서 바꾸는 것이면 한도 문서를 먼저 본다 |
| 6 | 바뀌었는지 확인한다 |
| 7 | 되돌릴 때는 같은 순서를 원래 값으로 한다 |

## 1. 설정 바꾸기

```sh
kadan runners show                 # 지금 revision·활성 프리셋·역할별 값
kadan runners compare show         # 비교 모드가 켜져 있는지, 어느 프리셋을 비교 중인지
kadan runners model <실행기> <모델> --efforts <강도,…> --revision <N> --reason "<이유>"
kadan runners compare off --revision <N> --reason "<이유>"
kadan runners set <worker|reviewer|conductor|super> --runner <실행기> --model <모델> --effort <강도> --revision <N> --reason "<이유>"
```

- **바꾸기 전에 `kadan runners show` 출력을 적어 둔다.** 7번(되돌리기)에서 쓴다.
- **revision**: 저장할 때마다 1씩 오른다. 명령을 이어서 칠 때는 매번 1 큰 숫자를 넣는다.
  읽은 숫자와 다르면 현재 revision을 알려 주며 저장을 거절한다.
- **모델 등록(`runners model`)**: 바꿀 모델이 그 실행기 목록에 없을 때만 한다. 모델 목록 파일을 쓰는
  실행기(codex)는 이 명령을 거절한다. 그런 실행기는 목록 파일에 있는 모델만 고를 수 있다.
- **비교 모드**: 켜져 있으면 비교 목록에 든 프리셋은 고칠 수 없다(오류가 `kadan runners compare off`를
  안내한다). 또 켜져 있는 동안 새 작업자는 활성 프리셋이 아니라 비교 목록의 프리셋으로 뜬다.
  한꺼번에 바꾸려면 먼저 끈다. 목록 밖 프리셋은 켜진 채로도 고칠 수 있다.
- **`--preset`은 붙이지 않는다.** 붙이지 않으면 활성 프리셋을 고친다. 새로 띄우는 역할과 3번의 재시작은
  활성 프리셋만 읽는다. 없는 이름을 주면 그 이름의 프리셋이 새로 생기고 활성 프리셋은 그대로다.
- **`set`이 거절하는 값**: 목록에 없는 모델, 그 모델이 지원하지 않는 강도, 정책으로 막은 모델,
  작업자와 같은 계열이 되는 검수자. 작업자를 지금 검수자와 같은 계열로 옮기려면 검수자를 먼저 다른
  계열로 바꾼다.
- **Autopilot이 켜진 동안** 역할 세션에서는 `runners`의 쓰기 명령이 거절된다(`show`·`report`·
  `compare show` 같은 읽기 명령은 통과). 사용자가 직접 치거나 Autopilot을 끈 뒤 한다.

## 2. 새로 띄우는 역할

`kadan start <역할> --profile <프로필>`은 띄우는 순간의 설정으로 뜬다. 이미 떠 있는 역할은 바뀌지 않는다.

- **작업자·검수자**: 옛 실행기·모델로 떠 있는 세션에 카드를 발령하면 거절된다(`KADAN_STALE_RUNNER`,
  [옛 세션 발령 막기](../../../docs/runner-settings.md#옛-세션-발령-막기)). 강도만 다르면 경고 한 줄 뒤 통과한다.
  옛 모델이 그 프로필의 대체 후보(폴백) 목록에 있어도 거절하지 않고 경고만 한다. 옛 세션에 일부러
  보낼 때만 `kadan dispatch … --allow-old-runner "<이유>"`를 쓴다.
- **일반감독·슈퍼감독**: 이 검사의 대상이 아니다. 아무것도 하지 않으면 옛 모델로 계속 돈다.

## 재시작 전 확인

재시작은 끄기 직전에 안전 확인을 한다(`src/restart.mjs`의 `confirmBeforeStop` → `src/commands/restart.mjs`의
`confirmIdleBeforeStop`). 이 확인이 보는 것과 보지 않는 것은 다음과 같다.

- **보는 것**: 화면 아래 14줄(`src/watch-status-line.mjs`)에 응답을 만드는 중이라는 표시(회전 기호가 붙은
  `…(시계 · …)` 줄, codex의 `• Working (… esc to interrupt)` 줄, `⎿ Running… (…)` 도구 실행 줄)가 있는지,
  빈 입력창이 있는지, 그리고 사람이 그 창에서 최근 입력했는지(`src/floor-tmux.mjs`의 `checkHumanIdle`).
  하나라도 걸리거나 판정할 수 없으면 끄지 않고 거절한다.
- **보지 않는 것**: 그 세션 안에서 도는 백그라운드 명령·하위 에이전트. 이를 가리키는 화면 표시를 찾는 코드는
  없다(`rg` 0건). 응답이 끝나 빈 입력창만 보이면 백그라운드 작업이 돌고 있어도 안전 확인은 통과하고,
  재시작하면 그 작업은 프로세스와 함께 끊긴다(끊김 자체는 아래 관찰).

그래서 여러 역할을 한꺼번에 재시작하기 전에 역할마다 `kadan read <역할> --lines <N>`으로 화면을 보고
도는 백그라운드 작업이 있는지 확인한다. 있으면 그 역할은 건너뛰고 목록에 남겨 사용자에게 알린다(필요하면 4번).
자동으로 걸러 주는 명령은 없다. 화면에 어떤 표시가 뜨는지는 실행기마다 다르고 아래 "관찰"에만 있다.

## 3. 떠 있는 역할 바꾸기 — 재시작(기본)

```sh
kadan restart <역할> --model-from-settings --reason "<이유>"
```

같은 대화를 그대로 이어 열고 모델·강도만 활성 프리셋의 그 역할 프로필 값으로 바꾼다. 실행 파일과
다른 옵션은 옛 시작 명령 그대로다. 우편·맡은 카드·책임 관계가 끊기지 않고, 끝나지 않은 카드가 있어도
거절하지 않는다. 자세한 순서는 [`kadan restart` 자세히](../../../docs/commands.md#kadan-restart-자세히).

- **옵션 없이 `kadan restart <역할>`만 치면 마지막 시작 명령의 모델 그대로 다시 뜬다.** 4번으로 창에서만
  바꿔 둔 역할은 원래 모델로 돌아간다.
- 한 번에 한 역할이다. 여러 역할은 명령을 하나씩 친다. 끄고 켜는 몇 초 동안 감시기가 그 세션을 죽은
  것으로 볼 수 있다.
- 명령이 막는 호출자는 자기 자신뿐이다. 다른 슈퍼감독도 다시 띄울 수 있다. 막지 않는다는 뜻이지
  권한이 넓어진다는 뜻이 아니다. 사용자가 맡긴 범위의 역할만 바꾼다.
- Autopilot이 켜진 동안에도 이 명령은 통과한다. 거절되는 것은 `restart --force`다.
- 설정과 모델·강도가 이미 같으면 "설정과 같음: 바뀐 것 없음"을 알리고 평소처럼 다시 띄운다.

오류로 끝났다고 해서 그 역할이 늘 살아 있는 것은 아니다. 두 경우를 나눠 본다.

- **끄기 전의 거절(아래 표)**: 기존 세션을 끄기 전에 난다. 그 역할은 옛 모델로 그대로 살아 있다.
- **끈 뒤의 실패**: 사전 검사를 모두 통과하면 기존 세션을 끄고 새 세션을 만든다. 이 단계에서 실패하면
  기존 세션은 이미 종료돼 있다. 새 세션을 만들지 못한 오류는 `기존 <세션>은 종료됐고 새 세션을 만들지 못했다`로
  시작하고, 끝의 `직접 복구:` 뒤에 작업 폴더와 다시 만든 실행 명령을 보여 준다.
- **성공은 마지막 줄 `다시 띄움: <세션> (…)`으로만 센다.** 이 줄 없이 끝났고 아래 표의 사유도 아니면
  `kadan status`로 그 세션이 있는지부터 본다. 종료된 역할은 `kadan restart`를 다시 쳐도 되살아나지 않는다
  (살아 있는 역할만 다시 띄운다). 오류 원문과 세션 상태를 사용자에게 알린다.
- 여러 역할을 차례로 바꿀 때 오류가 난 역할을 "옛 모델로 살아 있음"으로 세지 않는다.

| 끄기 전에 거절되는 경우 | 할 일 |
|---|---|
| 응답을 만드는 중이거나 방금 사람이 입력했다 | 잠시 뒤 다시 한다. `--force`는 사람이 직접 확인했을 때만 쓰고 역할은 쓰지 않는다 |
| 자기 자신 | 다른 역할이나 사용자가 실행한다 |
| 비교 모드로 띄운 역할 | 아래 "새로 띄우기"로 바꾼다 |
| 설정의 실행기가 그 역할의 실행기와 다르다 | 아래 "새로 띄우기"로 바꾼다(대화를 이어 열 수 없다) |
| 시작 기록에 프로필이 없다(옛 역할) | 옵션 없이 다시 띄우거나 "새로 띄우기"로 바꾼다 |
| 활성 프리셋에 그 역할 값이 없다 | 1번으로 값을 채운 뒤 다시 한다 |
| 옛 시작 명령에 카단이 모르는 옵션이 있거나 모델 자리를 하나로 정할 수 없다 | "새로 띄우기" 또는 4번 |
| 비서 | 대상이 아니다 |

**새로 띄우기(대화가 이어지지 않는다)** — 작업자·검수자를 새로 띄울 때, 실행기까지 바뀔 때,
비교 모드로 띄운 역할일 때, 바꾼 모델의 성과가 `kadan runners report`에 집계돼야 할 때 쓴다.

```sh
kadan stop <역할>
kadan start <역할> --profile <프로필>   # 그 역할의 작업 폴더에서 친다
```

작업자·검수자를 끄고 새로 띄우는 일은 그 판의 감독이 한다([SKILL.md](../SKILL.md)의 "판 접기").
`kadan stop`은 확인하지 않은 완료 카드가 남아 있으면 세어 알린다.
같은 이름을 새 대화로 다시 띄우면 앞 세대의 미확인 우편과 업무·카드 책임을 넘겨받지 않는다. 열린 업무가
있는 감독을 이렇게 바꿀 때는 `kadan start`에 `--inherit-mail`을 붙여 바로 앞 세대 것을 이어받게 한다
([이름 규칙·세대](../../../docs/hierarchy.md#역할-이름-규칙과-같은-이름-재사용-2026-10-13)).

## 4. 재시작 없이 그 창에서 바꾸기

실행기 자체의 모델 전환 명령(Claude Code의 `/model <모델ID>` 등)을 그 창에 넣는 방법이다.
재시작이 거절되거나, 그 세션 안에서 도는 백그라운드 작업을 살려야 할 때 쓴다.
카단 명령이 아니라서 **카단은 이 변경을 모른다.** 그래서 카단 기록과 어긋난 채로 두는 임시 조치이고,
그 역할이 쉬는 틈에 3번으로 맞춘다.

넣는 길은 둘이다.

- 사용자가 그 창에서 직접 친다.
- 슈퍼감독이 원문 그대로 넣는다: `kadan mail <역할> --raw "/model <모델ID>"`. `--raw`는 머리말·역할 지침·
  읽음 안내를 붙이지 않고 본문만 붙여 넣은 뒤 Enter를 한 번 보낸다.
  - **슈퍼감독끼리는 `--raw`가 거절된다.** 다른 슈퍼감독은 사용자가 직접 치거나 3번을 쓴다.
  - 넣지 못한 `--raw` 우편(세션 없음, 사람이 방금 입력함 등)은 보관되지 않고 실패로 끝난다.
  - 비서·사람 우편함은 `--raw` 대상이 아니고, `--expect-reply`와 함께 쓸 수 없다.

### 관찰 (2026-11-10 슈퍼감독 설명·실측)

아래는 Claude Code 등 바깥 실행기에서 본 것이며 이 저장소 코드로 확인한 내용이 아니다. 실행기 버전이
바뀌면 달라질 수 있어 규칙이 아니라 참고로만 읽는다.

- `/model <모델ID>`를 넣은 뒤 확인 창이 떠서 Enter를 한 번 더 눌러야 했다. 카단에는 역할이 Enter 한 키만
  보내는 명령이 없으니, 확인 창이 남으면 사용자가 그 창에서 누른다.
- 오래 켜 둔 옛 버전 실행기는 새 모델을 모르는 모델로 보고 문맥 크기를 작게 잡았다. 실행기를 갱신한 뒤
  3번으로 다시 띄우면 프로그램이 새로 뜬다(새로 뜬다는 것까지가 코드로 확인되는 사실이다).
- `/model`은 실행할 때마다 새 세션의 기본 모델로 저장돼, 카단 밖에서 여는 실행기의 기본값까지 바뀐다고
  했다. 카단이 설정으로 역할을 띄울 때는 모델을 명령에 직접 넣으므로(실행기 명령 틀에 `{model}`이 있어야
  저장된다: `src/runner-settings.mjs`) 그 역할에는 이 기본값이 닿지 않는다고 읽을 수 있으나, 실행기가
  명령의 모델과 저장된 기본값 중 무엇을 따르는지는 확인하지 못했다.
- 두 방법 모두 바꾼 뒤 첫 응답에서 대화 전체를 다시 읽어 그만큼 비용이 든다고 했다.
- 재시작은 프로세스가 바뀌어 그 세션 안에서 돌던 백그라운드 작업·하위 에이전트가 끊긴다고 했다.
  `/model`은 프로세스가 그대로라 살아 있다.
- 실행기 화면 아래의 하위 에이전트 수 표시(`← 2 agents` 꼴)는 막 재시작한 쉬는 세션에도 똑같이 떠 있어
  "도는 작업"의 근거가 아니다(슈퍼감독이 9개 세션에서 확인했다고 했다).
- 감독 관찰 1건: 백그라운드 명령을 돌려 둔 채 빈 입력창으로 보이던 작업자 화면에는 `1 shell still running`
  줄과 표시줄의 `1 shell`이 있었다. 한 번 본 것이라 "이런 표시가 있었다"까지만 쓴다.

### 3번과 4번 고르기

| 견줄 점 | 3번 재시작(`--model-from-settings`) | 4번 그 창에서 바꾸기 |
|---|---|---|
| 쓰는 때 | 기본. 카단 기록과 맞고 되돌아가지 않는다 | 재시작이 거절될 때(비교 모드로 띄운 역할, 자기 자신, 위 거절 표), 세션 안에서 도는 작업을 살려야 할 때. 카단 기록과는 어긋난 채 임시 |
| 대화 | 같은 대화를 이어 연다 | 끊기지 않는다 |
| 실행기 프로그램 | 새로 뜬다 | 그대로다 |
| 강도 | 모델과 함께 설정값으로 바뀐다 | 모델 전환 명령이 정하는 대로(카단은 모른다) |
| 그 세션 안에서 도는 백그라운드 작업(관찰) | 끊긴다고 한다. 안전 확인은 이를 보지 않는다 | 살아 있다고 한다 |
| 바꾼 뒤 첫 응답의 비용(관찰) | 대화를 다시 읽는다고 한다 | 같다고 한다 |
| 슈퍼감독끼리 | 다른 슈퍼감독도 재시작할 수 있다 | `--raw`가 막힌다. 사용자가 직접 친다 |
| 카단 시작 기록 | 새 모델과 이전 모델이 남는다(`previousModel`, 바뀐 값만) | 남지 않는다 |
| `kadan status`의 모델 칸 | 새 모델 | 옛 모델 그대로 |
| 그 뒤 카드 발령 기록의 모델 | 새 모델이 남는다 | 옛 모델이 남는다 |
| 성과 보고서(`kadan runners report`) | **집계되지 않는다.** `kadan restart`가 남기는 시작 기록에는 띄운 방식이 없어, 그 뒤의 발령이 든 업무는 "귀속 불명"으로 빠진다. 집계되게 하려면 위 "새로 띄우기"로 바꾼다 | 시작 기록은 그대로라 카단은 바뀐 것을 모른다. 원래 집계되던 기록(`kadan start`로 띄운 역할)이면 옛 모델 쪽으로 세고, 이미 `kadan restart` 등으로 귀속 불명이던 역할은 `/model`로 바꿔도 계속 빠진다 |
| 작업자·검수자에게 카드 발령 | 통과한다(경고 한 줄이 붙을 수 있다) | 설정을 새 모델로 바꿨다면 옛 세션으로 보아 거절한다. 옛 모델이 대체 후보 목록에 있으면 경고만 하고 통과해 기록에는 옛 모델이 남는다 |
| 그 뒤 옵션 없는 `kadan restart` | 바꾼 모델을 유지한다 | 원래 모델로 돌아간다 |
| 누가 할 수 있나 | 다른 역할이나 사용자(자기 자신은 안 된다) | 그 창의 사용자, 또는 `--raw`(슈퍼감독끼리는 안 된다) |
| 확인하는 곳 | `kadan status` | 그 역할의 화면뿐이다 |

**재시작이 기본인 이유**: 카단 시작 기록과 `kadan status`가 새 모델로 맞고, 이후 옵션 없는 재시작에서도 바꾼
모델이 유지되며, 슈퍼감독끼리도 쓸 수 있다. 성과 보고서는 이 이유에 들지 않는다. 위 표대로 재시작한 역할의
발령이 든 업무는 보고서에서 빠진다.

**4번이 나은 경우**: 재시작이 거절될 때, 그리고 위 관찰대로 세션 안에서 도는 작업을 살려야 할 때. 쓴 뒤에는
카단 기록과 어긋나 있음을 사용자에게 알리고 쉬는 틈에 3번으로 맞춘다.

## 5. 한도에 걸려서 바꿀 때

[한도에 멈춘 역할 이어가기](claude-limit.md)를 먼저 따른다. 계정을 바꿀지 다른 모델로 돌릴지는 사용자가
정하고, 계정 교체와 `kadan claude refresh --yes --role <역할>`은 사용자만 한다(역할 세션에서는 거절된다).
사용자가 다른 모델을 고르면 이 문서의 1번으로 설정을 바꾸고 3번으로 떠 있는 역할을 바꾼다.

## 6. 확인

| 볼 것 | 명령 | 읽는 법 |
|---|---|---|
| 설정값 | `kadan runners show` | 역할별 값과 채워질 실행 명령 |
| 역할별 기록된 모델 | `kadan status` | 줄 끝의 `실행기 · 모델 · 계열`. 마지막 시작 기록의 값이다 |
| 실제 화면 | `kadan read <역할> --lines <N>` | 실행기가 화면에 보여 주는 모델. 4번은 여기서만 확인된다 |
| 조합별 성과 | `kadan runners report` | 발령 기록의 실행기·모델·강도와 띄운 방식으로 묶는다. 한 업무 도중에 조합이 바뀌면 그 업무는 "섞임"으로 지표에서 빠진다. `kadan restart`로 다시 띄운 역할(옵션이 있든 없든)에 간 발령이 든 업무는 출력 끝의 `귀속 불명` 줄에만 나오고 지표에서 빠진다 |

설정 변경은 원장에 `runner-settings` 사건으로, 재시작은 `stop`·`start` 사건에 이유와 함께 남는다.
사용자에게는 바꾼 역할, 거절되어 옛 모델로 남은 역할과 이유, 끈 뒤 실패해 종료된 역할, 4번으로 임시로 바꿔 둔 역할을 알린다.

## 7. 되돌리기

같은 순서를 원래 값으로 한다. 1번에서 적어 둔 값으로 `kadan runners set …`을 다시 하고, 3번으로 떠 있는
역할을 다시 띄운다. 비교 모드를 껐었다면 `kadan runners compare on --presets <프리셋,…> --revision <N>
--reason "<이유>"`로 다시 켠다(새 회차로 시작한다).

되돌릴 일이 잦으면 프리셋을 나눠 둔다. `kadan runners preset add <새이름> --revision <N> --reason "<이유>"`로
활성 프리셋을 복사하고, `kadan runners set … --preset <새이름>`으로 그 프리셋을 고친 뒤
`kadan runners preset <새이름> --revision <N> --reason "<이유>"`로 전환한다. 되돌릴 때는 옛 프리셋 이름으로
전환하고 3번을 한다.
