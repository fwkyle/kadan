# Kadan Go — 대화에서 카단으로 바로 넘기기

## Why

사용자는 평소처럼 이야기하다가 갑자기 "이건 카단으로 돌리자"가 된다. 그때마다 감독을 세우고
명령어를 치는 것은 무겁다. 이 스킬은 **사용자의 말 한마디를 카단 실행으로 바꾸는 입구**다.
사용자는 명령어를 몰라도 되고, 이 대화의 AI가 길을 골라 실행하고 결과를 쉬운 말로 보고한다.

## 길 고르기

먼저 아래 기준으로 감독을 권할 일인지 확인한다. 해당하면 감독으로 옮기는 방식을 권하고 사용자의 선택 뒤 시작한다.
그 밖에는 표에서 길을 고르고, 애매할 때만 한 번 묻는다("기다리실 건가요, 맡기고 가실 건가요?").
고른 뒤에는 한 줄로 알리고 바로 시작한다. 모델·이름·폴더는 아래 기본값으로 채우고 묻지 않는다.

### 먼저 볼 것: 감독을 세울 일인가

아래 넷 중 **하나라도** 맞으면 "카단으로 해 줘"처럼 말해도 1번 길로 바로 가지 않고, 먼저 [3. 감독으로 옮기기](#3-감독으로-옮기기-맡기고-가기)(adopt)를 권한다.
권하는 말에는 효과를 함께 적는다(내용은 [인수 절차](../../docs/adopt.md)를 따르고 문장은 옮겨 적지 않는다).
대화 복제, 권한 이어짐, 원래 탭이 닫힐 수 있음, 맡길 목표·범위 확인, 컴퓨터가 켜져 있어야 함.
사용자가 고르기 전에는 실행하지 않는다.

- 자리를 비운다(맡겨 놓고 간다)
- 구현과 검수를 오가는 여러 단계다
- 나중에 이어서 할 일이다
- 10분 이상 걸릴 일이다

**사용자가 같이 기다리는 짧은 단발 일**은 그대로 1·2번 길이다. adopt를 모든 일의 기본으로 강제하지 않는다.
사용자가 1번 길을 고르면 [1번](#1-이-대화가-조율-짧은-일)의 첫 안내(카드·감시가 없다는 차이)를 먼저 말한다.

| 사용자가 이렇게 말하면 | 길 |
|---|---|
| "카단으로 해 줘", "작업자한테 맡겨", "검수도 받고" | [1. 이 대화가 조율](#1-이-대화가-조율-짧은-일) |
| "검수만", "다른 AI한테 봐 달라고 해" | [2. 검수만](#2-검수만) |
| "오래 걸려", "맡겨 놓고 갈래", "밤새 돌려", "감독으로 올려" | [3. 감독으로 옮기기](#3-감독으로-옮기기-맡기고-가기) |
| "어떻게 됐어?", "지금 뭐 돌아가?" | [4. 현황](#4-현황) |
| "비서한테 전해 줘" | `kadan send 비서 "<전할 말>"` — 비서 우편함에 **저장**된다(비서 화면에 바로 붙지 않는다) |

## 공통 규칙

- **1·2번 길에서 이 대화는 조율만 한다.** 코드는 작업자 창이 고친다. 이 대화가 직접 고치면 감독이 구현하는 셈이 된다.
- 창은 카단 설정(`KADAN_WINDOW`, 비어 있으면 `kadan window show`로 보는 기계 설정)을 따른다. 사용자가 "조용히"라고 하면 `--hidden`. 단 로티 창 설정(`KADAN_WINDOW=rottie`)에서는 역할 세션의 숨김 시작을 카단이 막으므로(`KADAN_HIDDEN_FORBIDDEN`) 창 설정대로 띄운다.
- 이름은 공백 없이 `<레포>-빠른-작업-<주제>`, `<레포>-빠른-검수-<주제>`처럼 레포명으로 시작해 짓는다(규칙 위반은 경고만 난다). 이미 살아 있는 이름이면 뒤에 `-2`를 붙인다. 예전에 쓴 이름을 새 대화로 다시 쓰면 이전 세대 우편은 넘겨받지 않는다(같은 대화 resume은 이어받음).
- 모델은 실행 모델 설정(`kadan runners`)의 역할 기본값을 쓴다(`--profile worker|reviewer`면 자동).
- 작업 지시에 **완성된 완료 표시를 쓰지 않는다.** 형식(`KADAN:DONE <카드id> <ok|failed>`)과 쓸 id(`quick-<주제>-<시각>`)만 따로 주고 조립은 작업자가 한다. 완성된 표시가 지시에 있으면 화면에 그대로 찍혀 완료로 잘못 읽힌다.
- 빠른 일은 카드를 만들지 않는다. 감시기의 멈춤 경보 대상이 아니므로, 끝날 때까지 이 대화가 기다린다.
- 기다리기는 `kadan wait <이름> --timeout 3600 --quiet 600`를 **백그라운드로** 돌린다(Claude Code는 백그라운드 실행 후 완료 알림을 받는다). 기다리는 동안 사용자와 다른 이야기를 해도 된다.
- 결과는 `kadan read <이름> --lines 80`으로 읽고 쉬운 말로 보고한다. `완료 표시 없음 — 조용함`이면 판정하지 않고 화면을 읽어 상태를 그대로 전한다.
- 끝나면 이 대화가 띄운 창만 `kadan stop <이름>`으로 닫는다. 사용자가 더 보겠다고 하면 남긴다.

## 1. 이 대화가 조율 (짧은 일)

1. 안내 두 문장(차이를 먼저): "카드와 자동 감시 없이 이 대화가 끝까지 결과를 확인하므로, 대화를 닫으면 진행을 놓칠 수 있습니다. 작업자 창에서 수정하고 검수 창에서 확인하겠습니다."
2. `kadan start <레포>-빠른-작업-<주제> --profile worker`
3. `kadan send <레포>-빠른-작업-<주제> "<지시>"` — 지시에는 목표, 작업 폴더·브랜치(worktree 권장), 완료 조건, 커밋 여부, 완료 표시 형식과 id를 적는다.
4. 백그라운드 `kadan wait <레포>-빠른-작업-<주제> …` → 알림이 오면 `kadan read`로 결과(바뀐 파일·커밋·시험 결과)를 확인한다.
5. 작업이 `ok`면 [2. 검수만](#2-검수만)의 순서로 검수 창에 넘긴다. 지시에 작업자가 남긴 결과(브랜치·커밋)를 적는다.
6. 보고: "작업 완료, 검수 통과/지적 N건, 바뀐 곳은 …". 검수 실패면 "작업자에게 한 번 더 고치게 할까요?"라고 묻고, 답에 따라 같은 작업자 창에 수정 지시를 보낸다.

## 2. 검수만

1. `kadan start <레포>-빠른-검수-<주제> --profile reviewer`
2. `kadan send <레포>-빠른-검수-<주제> "<검수 요청>"` — 볼 대상(PR 번호·브랜치·커밋·파일), 특히 볼 곳, **고치지 말고 판정만** 할 것, 판정 형식(통과/실패 + 지적 목록: 파일·줄·이유), 완료 표시 형식과 id.
3. 백그라운드 `kadan wait` → `kadan read` → "통과" 또는 "지적 N건"을 보고하고 창을 닫는다.

## 3. 감독으로 옮기기 (맡기고 가기)

지금까지의 대화를 **복제해서** 카단의 감독 창으로 이어 연다. 그 뒤로는 감독이 우편을 받고, 이 앱을 꺼도 일이 이어진다.

1. 맡길 일이 대화에 분명히 있는지 확인한다. 복제본은 대화 전체를 이어받으므로, 마지막에 "무엇을 어디까지 맡기는지"가 한 문장으로 남아 있어야 한다. 없으면 사용자에게 한 문장으로 확인한다.
2. 대화를 시작한 폴더에서 실행한다(Claude Code는 대화 기록을 시작 폴더 기준으로 찾는다).
   - Claude Code: `kadan adopt <레포>-<감독이름> --model <지금 모델>` — 대화 ID와 생각 강도는 자동으로 읽는다. 긴 대화면 지금과 같은 큰 문맥 모델(예: `claude-opus-5-5[1m]`)을 그대로 적는다.
   - Codex: `kadan adopt <감독이름> --model <지금 모델> --resume <대화ID> --harness codex` — 대화 ID는 자동으로 못 읽는다. 사용자에게 받거나 Codex 화면에서 확인한다.
   - 상위는 기본이 사용자(`@user`)다. 슈퍼감독 아래에 두려면 `--parent <슈퍼감독>`, 슈퍼감독으로 세우려면 `--profile super`.
   - 다른 폴더에서 실행하면 `adopt`가 "이 폴더에서 시작한 대화가 아니다(기록 폴더 …)"로 거부한다. 그 폴더로 옮겨 다시 실행한다.
   - herdr 바닥: 사용자가 `KADAN_FLOOR=herdr KADAN_HOME=… KADAN_HERDR_SOCKET=…`를 명시한 셸에서만 같은 명령이 herdr 서버 안에 열린다. 환경 변수가 없으면 지금처럼 tmux이고, 서버를 자동으로 켜거나 다른 바닥으로 바꾸지 않는다. 새 폴더의 신뢰 확인 화면은 자동 수락하지 않으니 안내된 명령으로 사람이 넘긴다.
   - 원본 대화의 현재 권한을 이어받는다(Claude 권한 모드, Codex 승인·샌드박스). 바이패스였으면 그대로 유지하고 계획·제한 모드를 임의로 풀지 않는다. 별도 도구 권한 옵션을 확인할 수 없으면 비서가 확인할 동안 원본을 보존한다.
   - 새 감독은 대화의 목표·승인 범위·다음 행동을 읽고 첫 안내의 `adopt accept`를 한 번 실행한다. 원본 Rottie 탭은 이 확인이 끝난 뒤 닫힌다. 안내창·인수 지연·대상 불명확은 비서 우편함으로 넘어간다. 같은 감독을 다시 만들지 말고 비서가 기존 두 창을 확인하게 한다. → [인수 절차](../../docs/adopt.md)
3. 사용자에게 **복제 창 생성·인수 대기·인수 완료를 구분**해 알린다. 생성만 됐다면 "'<감독이름>'을 열었고 인수 확인 중입니다. 이 대화에서는 더 지시하지 않습니다. 진행은 대시보드나 '<감독이름> 어떻게 됐어?'로 물어보세요. 직접 말하려면 감독 창(`kadan attach <감독이름>`)에서 하세요."
4. **옮긴 뒤 이 대화는 더 발송하지 않는다.** 같은 두뇌가 둘이면 같은 일을 두 번 맡긴다. 이후 질문에는 4번 현황만 답한다.

## 4. 현황

- `kadan status`(살아 있는 역할·미완료 일), `kadan tree`(책임 관계), 필요하면 `kadan read <역할> --lines 40`.
- 대시보드(`http://127.0.0.1:8790`) 전략 맵·전체 현황과 같은 기준이다. 사용자에게는 "누가 무엇을 하는 중, 막힌 곳, 다음에 할 일"로 짧게 답한다.
- 비서가 꺼져 있으면(`kadan status`에 `kadan-비서` 없음) "비서가 꺼져 있습니다. `kadan up`으로 켤까요?"라고 묻는다.

## 하지 않는 것

- 1·2번 길에서 이 대화가 직접 코드를 고치거나 커밋하지 않는다.
- 사용자가 맡기지 않은 일을 발송하지 않는다. push·merge·배포는 평소 승인 규칙을 따른다.
- 남이 띄운 창을 `kadan stop`하지 않는다. 이 대화가 띄운 빠른 작업·검수 창만 닫는다.
- 옮긴(adopt) 뒤 원래 대화에서 감독 일을 계속하지 않는다.
