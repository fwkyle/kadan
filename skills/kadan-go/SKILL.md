# Kadan Go — 대화에서 카단으로 바로 넘기기

## Why

사용자는 평소처럼 이야기하다가 갑자기 "이건 카단으로 돌리자"가 된다. 그때마다 감독을 세우고
명령어를 치는 것은 무겁다. 이 스킬은 **사용자의 말 한마디를 카단 실행으로 바꾸는 입구**다.
사용자는 명령어를 몰라도 되고, 이 대화의 AI가 길을 골라 실행하고 결과를 쉬운 말로 보고한다.

## 길 고르기

사용자의 말에서 길을 고른다. 애매할 때만 한 번 묻는다("기다리실 건가요, 맡기고 가실 건가요?").
고른 뒤에는 한 줄로 알리고 바로 시작한다. 모델·이름·폴더는 아래 기본값으로 채우고 묻지 않는다.

| 사용자가 이렇게 말하면 | 길 |
|---|---|
| "카단으로 해 줘", "작업자한테 맡겨", "검수도 받고" | [1. 이 대화가 조율](#1-이-대화가-조율-짧은-일) |
| "검수만", "다른 AI한테 봐 달라고 해" | [2. 검수만](#2-검수만) |
| "오래 걸려", "맡겨 놓고 갈래", "밤새 돌려", "감독으로 올려" | [3. 감독으로 옮기기](#3-감독으로-옮기기-맡기고-가기) |
| "어떻게 됐어?", "지금 뭐 돌아가?" | [4. 현황](#4-현황) |
| "비서한테 전해 줘" | `kadan send 비서 "<전할 말>"` — 비서 우편함에 **저장**된다(비서 화면에 바로 붙지 않는다) |

## 공통 규칙

- **1·2번 길에서 이 대화는 조율만 한다.** 코드는 작업자 창이 고친다. 이 대화가 직접 고치면 감독이 구현하는 셈이 된다.
- 창은 카단 설정(`KADAN_WINDOW`)을 따른다. 사용자가 "조용히"라고 하면 `--hidden`.
- 이름은 공백 없이 `빠른-작업-<주제>`, `빠른-검수-<주제>`처럼 짓는다. 이미 살아 있는 이름이면 뒤에 `-2`를 붙인다.
- 모델은 실행 모델 설정(`kadan runners`)의 역할 기본값을 쓴다(`--profile worker|reviewer`면 자동).
- 작업 지시에 **완성된 완료 표시를 쓰지 않는다.** 형식(`KADAN:DONE <카드id> <ok|failed>`)과 쓸 id(`quick-<주제>-<시각>`)만 따로 주고 조립은 작업자가 한다. 완성된 표시가 지시에 있으면 화면에 그대로 찍혀 완료로 잘못 읽힌다.
- 빠른 일은 카드를 만들지 않는다. 감시기의 멈춤 경보 대상이 아니므로, 끝날 때까지 이 대화가 기다린다.
- 기다리기는 `kadan wait <이름> --timeout 3600 --quiet 600`를 **백그라운드로** 돌린다(Claude Code는 백그라운드 실행 후 완료 알림을 받는다). 기다리는 동안 사용자와 다른 이야기를 해도 된다.
- 결과는 `kadan read <이름> --lines 80`으로 읽고 쉬운 말로 보고한다. `완료 표시 없음 — 조용함`이면 판정하지 않고 화면을 읽어 상태를 그대로 전한다.
- 끝나면 이 대화가 띄운 창만 `kadan stop <이름>`으로 닫는다. 사용자가 더 보겠다고 하면 남긴다.

## 1. 이 대화가 조율 (짧은 일)

1. 한 줄 안내: "작업자 창에서 고치고 검수 창에서 보겠습니다. 시작합니다."
2. `kadan start 빠른-작업-<주제> --profile worker`
3. `kadan send 빠른-작업-<주제> "<지시>"` — 지시에는 목표, 작업 폴더·브랜치(worktree 권장), 완료 조건, 커밋 여부, 완료 표시 형식과 id를 적는다.
4. 백그라운드 `kadan wait 빠른-작업-<주제> …` → 알림이 오면 `kadan read`로 결과(바뀐 파일·커밋·시험 결과)를 확인한다.
5. 작업이 `ok`면 [2. 검수만](#2-검수만)의 순서로 검수 창에 넘긴다. 지시에 작업자가 남긴 결과(브랜치·커밋)를 적는다.
6. 보고: "작업 완료, 검수 통과/지적 N건, 바뀐 곳은 …". 검수 실패면 "작업자에게 한 번 더 고치게 할까요?"라고 묻고, 답에 따라 같은 작업자 창에 수정 지시를 보낸다.

## 2. 검수만

1. `kadan start 빠른-검수-<주제> --profile reviewer`
2. `kadan send 빠른-검수-<주제> "<검수 요청>"` — 볼 대상(PR 번호·브랜치·커밋·파일), 특히 볼 곳, **고치지 말고 판정만** 할 것, 판정 형식(통과/실패 + 지적 목록: 파일·줄·이유), 완료 표시 형식과 id.
3. 백그라운드 `kadan wait` → `kadan read` → "통과" 또는 "지적 N건"을 보고하고 창을 닫는다.

## 3. 감독으로 옮기기 (맡기고 가기)

지금까지의 대화를 **복제해서** 카단의 감독 창으로 이어 연다. 그 뒤로는 감독이 우편을 받고, 이 앱을 꺼도 일이 이어진다.

1. 맡길 일이 대화에 분명히 있는지 확인한다. 복제본은 대화 전체를 이어받으므로, 마지막에 "무엇을 어디까지 맡기는지"가 한 문장으로 남아 있어야 한다. 없으면 사용자에게 한 문장으로 확인한다.
2. 대화를 시작한 폴더에서 실행한다(Claude Code는 대화 기록을 시작 폴더 기준으로 찾는다).
   - Claude Code: `kadan adopt <감독이름> --model <지금 모델>` — 대화 ID와 생각 강도는 자동으로 읽는다. 긴 대화면 지금과 같은 큰 문맥 모델(예: `claude-opus-5-5[1m]`)을 그대로 적는다.
   - Codex: `kadan adopt <감독이름> --model <지금 모델> --resume <대화ID> --harness codex` — 대화 ID는 자동으로 못 읽는다. 사용자에게 받거나 Codex 화면에서 확인한다.
   - 상위는 기본이 사용자(`@user`)다. 슈퍼감독 아래에 두려면 `--parent <슈퍼감독>`, 슈퍼감독으로 세우려면 `--profile super`.
3. 사용자에게 알린다: "'<감독이름>'으로 옮겼습니다. 이 대화에서는 더 지시하지 않습니다. 진행은 대시보드나 '<감독이름> 어떻게 됐어?'로 물어보세요. 직접 말하려면 감독 창(`kadan attach <감독이름>`)에서 하세요."
4. **옮긴 뒤 이 대화는 더 발송하지 않는다.** 같은 두뇌가 둘이면 같은 일을 두 번 맡긴다. 이후 질문에는 4번 현황만 답한다.

## 4. 현황

- `kadan status`(살아 있는 역할·미완료 일), `kadan tree`(책임 관계), 필요하면 `kadan read <역할> --lines 40`.
- 대시보드(`http://127.0.0.1:8790`) 전략 맵·전체 현황과 같은 기준이다. 사용자에게는 "누가 무엇을 하는 중, 막힌 곳, 다음에 할 일"로 짧게 답한다.
- 비서가 꺼져 있으면(`kadan status`에 `kadan-비서` 없음) "비서가 꺼져 있습니다. `kadan up`으로 켤까요?"라고 묻는다.

## 하지 않는 것

- 1·2번 길에서 이 대화가 직접 코드를 고치거나 커밋하지 않는다.
- 사용자가 맡기지 않은 일을 발송하지 않는다. push·merge·배포는 평소 승인 규칙을 따른다.
- 남이 띄운 창을 `kadan stop`하지 않는다. 이 대화가 띄운 빠른 작업·검수 창만 닫는다.
- 옮긴(adopt) 뒤 원래 대화에서 감독 일을 계속하지 않는다.
