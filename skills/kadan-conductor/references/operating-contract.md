# 카단 진행·승인 공통 기준

## Why

사용자가 요청한 작은 결과가 에이전트가 덧붙인 조건·검증 절차·항목별 발령 때문에 커지고 느려지는 것을 막는다. 비서가 보고 있지 않아도 승인된 일을 이어가고, 일부 막힘이 전체 판의 대기 사유가 되지 않게 한다.

## 가벼운 실행이 기본 (2026-09-10 사용자 정정)

- **작은 일은 직접 끝낸다.** 담당 분리·병렬 처리·독립검수가 필요 없는 명확한 단일 수정은 현재 대화에서 수정 → 필요한 검증 → 결과 1회로 끝낸다. 카단을 설치했거나 언급했다는 이유로 업무·실행·역할을 새로 만들지 않는다. 이미 소유자가 있는 작업은 빼앗지 않고 그 담당의 기존 실행으로 잇는다. 감독 전용 역할의 구현 금지는 유지하며, 사용자 직접 구현 지시가 있으면 그 지시를 따른다.
- **큰 일만 업무 한 장으로 묶는다.** 독립 소유나 병렬 효과가 필요한 일은 기존 업무에 연결한다. 같은 범위의 수정·보완은 기존 입력으로 전달하고, 독립검수의 결과/수정 차수만 구분한다. 작은 코드 수정마다 업무·원본 카드를 다시 작성하지 않는다.
- **정상 왕복은 기존 프로그램에 맡긴다.** 반복 구현·독립검수는 승인된 담당과 검수 기준을 정한 뒤 기존 `work auto-configure`/`auto-run`을 한 번 설정하는 경로를 우선한다. 설정 전에는 자동이라고 보고하지 않는다. 지원되지 않는 바닥·계약 또는 기존 수동 실행에는 강제로 소급 적용하지 않는다. 감독은 최종 PASS·실제 예외·블록 교대 경계만 처리한다. 정상 중간 결과를 다시 요약·복사·재발령하지 않는다.
- **기계가 확인한 것을 AI가 되풀이하지 않는다.** CLI가 같은 실행의 생존·전달·기록 성공을 반환하면 그 사실 확인용 read/show/log를 연쇄 호출하지 않는다. 전달 성공을 실제 작업 착수·완료로 확대하지도 않는다. 새 역할 준비, 오류·전달 불명확, 결과 불일치, 사용자 요청 때만 필요한 추가 확인을 한다. 최신 revision 조회처럼 명령에 필요한 읽기는 유지한다.
- **기록은 재개와 최종 판단에 필요한 만큼만 남긴다.** 같은 결과 파일에 변경·검증(대상 지문/환경/명령/결과/이후 변경 여부)·미완료/재개 위치를 모은다. 저장된 경로와 지문을 인계에 재사용한다. 같은 값을 카드·편지·부모 결과·일지에 각각 다시 쓰거나 별도 Python 대조 파일을 관행적으로 만들지 않는다. 데이터 쓰기 영수증과 독립검수의 최초 확인은 생략하지 않는다.
- **도구 호출도 묶는다.** 독립적인 읽기·검색은 한 번에 처리하고, 실제 변경·승인·실패에 따라 달라지는 명령만 나눈다. 기다리는 동안 AI가 반복 조회하거나 정상 진행 보고를 만들지 않는다.

이 절은 아래 수동 카드 절차에 앞서는 경로 선택 기준이다. 기존 사용자 중지·권한·소유·독립검수·원장 보존은 그대로이며, 새 감시·보고 서비스나 자동 권한 확대를 뜻하지 않는다.

## 단순화 규칙

카단 라이트의 모든 향후 작업에 적용한다. 판단은 기존 카드에 짧게 남긴다. 이 규칙을 추가 점검 카드·새 승인 양식·CLI 자동 복잡도 차단 기능으로 만들지 않는다.

1. **요구 밖 조건을 만들지 않는다.** 사용자 요구 밖 선행조건·완료기준을 임의로 추가하지 않는다. 실제 참조·권한·데이터 무결성 조건은 보존한다. 편의상 만든 과거의 모든 필드 동일·별개 상품(SKU) 증명·전체 정밀분류를 서비스 필수조건으로 주장하지 않는다. 필수라고 판단한 조건은 사용자 지시 또는 실제 코드·오류·참조관계 근거로 기존 카드 판단에 짧게 설명하고, 확인되지 않은 우려만으로 확정하지 않는다.
2. **기존 기능을 가장 작게 재사용한다.** 기존 기능·코드로 해결하는 최소 변경부터 고른다. 요구·구현·절차가 복잡해지면 실제 오류·필수조건과 스스로 만든 확인 절차를 나누고, 후자를 줄일 수 있는지 먼저 판단한다. 편의나 미래 가능성만으로 새 추상화·설정·계층을 추가하지 않는다.
3. **실패한 항목만 분리한다.** 특정 실패·예외는 영향받는 항목만 보류하고 가능한 나머지 승인 작업을 이어간다. 정확한 실패와 미확인을 기록한다. 미확인 안전·조건을 정상으로 간주하거나 원인을 모르는 실패를 반복하지 않는다. 새 근거에 따른 제한된 복구 확인은 아래 일반감독의 결정 범위를 따른다.
4. **승인 안의 수정은 계속한다.** 기존 승인 밖 큰 구조변경이 꼭 필요할 때만 간단한 안이 안 되는 실제 근거·최소 변경·예상 시간/영향·답 없이 계속할 일을 기존 질문 경로로 제시하고, 승인 후 종속 작업을 진행한다. 승인 안의 작은 수정·절차 축소·필수조건 보존 수정에는 재승인 관문을 만들지 않는다. 구조변경이라는 이름만으로 이미 승인된 명시 범위를 되묻지 않는다.
5. **같은 반복은 한 카드에서 이어간다.** 동일 방식·승인·소유의 반복 작업은 한 작업자가 한 실행 카드에서 연속 처리하고, 항목별 성공/실패/미착수와 재개 위치를 즉시 기록한다. 항목이나 임의 개수마다 준비·발령·검수를 반복하지 않는다. 독립 소유·병렬 효과·실제 충돌/위험·명시 시간 상한 때문에 나눌 때만 이유를 남긴다. 같은 시험 재실행을 줄이되 필요한 최초·변경 검수는 보존하며, 명시 시간 상한은 자동 연장하지 않는다.

## 기록 원본과 일지

실제 카단 업무·실행 카드에 연결된 작업은 진행 기록의 원본과 중복 작성에 한해 이 기준을 저장소의 일반 일지 의무보다 우선한다. 카단을 언급하거나 스킬을 읽은 것만으로 적용하지 않는다.

| 상황 | 기록 위치와 분량 |
|---|---|
| 카단으로 일반 업무 진행 | 목표·판단·상태는 기존 카드, 발령·전달·완료 사건은 원장, 실행·검수 근거는 [중앙 카드의 결과 파일](../../../docs/card-center.md#카드-결과와-검증-자료)이 원본이다(기존 카드는 지정 경로 보존). 제품 코드·테스트·지속 사용할 제품 문서는 대상 저장소에 둔다. 데일리에 같은 내용을 다시 쓰지 않는다. |
| 카단 자체 개발·수리 | 해당 저장소 데일리에 실제 문제·수정·검증 결과를 작업 단위로 짧게 1회 남긴다. 자세한 근거는 원본 경로로 연결한다. |
| 카단 없이 작업 | 해당 저장소 데일리에 실제 작업 요약을 남긴다. |

- 단순 질문·답변, 우편 확인, 알림 수신, 정상 ACK만으로 일지를 쓰거나 커밋하지 않는다. 작업에 영향을 주는 결정·상태 변경은 위 원본에 남긴다.
- 같은 사실은 한 곳에 쓰고 다른 문서에는 필요한 링크만 둔다. `docs/daily/`에 있어도 카드·검수 결과·오류 근거는 원본 자료이며 일반 일지와 구분한다.
- 코드·설계·사용법의 필요한 문서 갱신, 검수 기준, 커밋 권한·시점, 배포·안전·보안·도메인 규칙은 해당 저장소와 승인 범위를 따른다. 완료 통지·DONE 마커를 생략하거나 기존 원장·검수 결과·과거 일지를 다시 쓰지 않는다.

## 진행 기록과 상위 통지

정상 진행마다 상위 AI를 깨워 조회·재보고하게 하지 않는다. 기록은 남기고, 다음 판단이나 작업에 필요한 편지만 보낸다.

1. **진행은 기록한다.** 시작·외부 결과 대기 등 상태 전이마다 `card progress`를 1회 남긴다. 이는 상태 기록이며 `send`가 아니다. 항목별 영수증·성공/실패·재개 위치는 결과 파일에 계속 남기되 추가 편지를 붙이지 않는다.
2. **정상 증거를 편지로 요구하지 않는다.** 첫 명령·첫 호출·첫 생성·개수 증가·도착/적용 확인(ACK)을 매번 상위에 `send`하도록 요구하거나 발송·재중계하지 않는다. 기존 발령 도착 확인은 유지하되, 독립적인 확인 의미가 없는 “받았음” 답장을 요구하지 않는다.
3. **상위 편지는 완료와 필요한 질문이 기본이다.** 실패·부분 종결을 포함한 완료는 기존 직속 수신자에게 1회, 권한·막힘·시간 상한·충돌로 판단이 필요하면 기존 질문 경로로 보낸다. 필요한 실패 조율을 숨기거나 완료 편지를 생략하지 않는다.
4. **실제 다음 작업 인계는 바로 연결한다.** 다음 담당이 실제로 쓸 자료 인계·독립검수 요청·정확한 외부 실행(run/attempt)의 완료 통지는 해당 직속 담당에게 필요한 1회 허용한다. 전체 카드 DONE을 기다리느라 준비된 사진의 제품 연결을 막지 않는다. 정상 인계를 슈퍼·비서·사용자에게 자동 복사하지 않는다.
5. **명시한 현황 확인은 그 범위만 답한다.** 사용자가 현황·실착수·모델 진단을 요청하면 지정한 1회 또는 기간만 확인·회신한다. 이후 재개 때마다 첫 명령 증거를 다시 보내는 상시 계약으로 넓히지 않는다.
6. **감시를 정상 보고로 보완하지 않는다.** 기존 이상 후보·완료 후보 감시와 수신자를 유지한다. AI 반복 조회·타이머·정상 보고 요구를 추가하지 않는다.
7. **기존 카드도 최신 판단으로 정정한다.** 불필요한 정상 보고 요구는 철회 판단을 추가하고 원이력을 보존한다. 이를 위해 기존 실행을 재발령·중단하지 않는다. 명시 중지·시간 상한·안전·소유 범위와 기존 수신자·완료 마커 계약은 그대로 지킨다.

이 기준은 역할의 판단 지침이다. 편지 여부를 판정하는 새 CLI 필터·우편 종류·스키마·자동 차단 기능으로 만들지 않는다.

## 자원 확인

일반감독은 작업자 추가나 무거운 빌드·검증 발령 전에 대시보드 또는 CLI의 현재 메모리·스왑·CPU 수치와 진행 중인 작업을 보고 규모를 정한다. 색상이나 수치 하나를 자동 중단·상신 조건으로 쓰지 않는다. 판 사이 자원 충돌을 조정해야 할 때만 슈퍼에게 올린다.

watch는 자원 경고·해제 우편이나 사용자 알림을 만들지 않으며 자원 값으로 AI를 깨우지 않는다. 확인을 위한 AI 반복 조회·타이머·정상 보고나 작은 작업마다 새 승인 절차를 추가하지 않는다. 실제 작업 오류·응답 장애, 사용자 명시 상한과 중지는 기존 기준을 따른다.

## 누가 결정하는가

| 역할 | 책임 |
|---|---|
| 일반감독 | 카드 구체화·발령·수정/검수 연결, 승인 범위 안의 방법 선택·진단·작업 분리·장애 복구·재개 |
| 슈퍼감독 | 일반감독이 근거를 대조해도 못 푸는 막힘·판 간 충돌·우선순위·승인 범위 조정 |
| 비서 | 사용자 의도·결정 전달, 공식 보고 확인·설명. 감독의 일상 재개 승인자가 아님 |
| 사용자 | 기존 권한 밖 행동, 목적·승인 범위 변경, 명시된 사용자 관문 |

## 일반감독의 결정 범위

- 일반감독은 이미 승인된 목표·대상·환경·변경 범위와 계정·모델·비용/시간 상한 안에서 구현·검수 방법, 읽기 진단, 준비된 결과의 다음 담당 연결을 직접 결정한다. 실행 방법을 고르는 질문을 슈퍼에게 넘기기 전에 자기 범위의 근거로 판단한다. 결정은 기존 카드에 짧게 남기고 필요한 담당에게 바로 전달한다. 별도 승인 카드·정상 ACK는 만들지 않는다.
- **같은 유형에는 공통 기준을 적용한다.** 승인된 기준과 사실관계가 같으면 다음 항목에도 적용한다. 항목별 데이터 무결성·의미·조건이 다른 경우만 분리해 판단한다. 슈퍼가 상담에 답할 때도 적용 기준과 실제 예외를 남기며, 실제 이유 없이 이번 ID 몇 개에만 허락을 한정해 같은 질문을 반복시키지 않는다.
- **복구 확인에는 새 근거가 필요하다.** 실패 원인이 확인됐거나 실패 조건과 관련된 변화가 확인·전달되면, 일반감독이 기존 오류 처리 계약 안에서 복구 방법을 정한다. 예를 들어 사용자가 한도 변경을 알려온 것은 새 판단 근거이며 실제 반영·회복의 증명은 아니다. 기존 상한이 없는 복구 확인은 같은 계정·모델·본작업 입력으로 1회만 하고, 같은 오류/원인 불명 실패면 해당 경로를 멈춘다. 같은 근거로 확인 횟수를 새로 세거나 새 ID를 돌며 반복하지 않는다. 오류 계약의 더 엄격한 제한·사용자 직접 중지는 그대로 따른다. 성공하면 확인한 범위만 기록하고 승인된 나머지를 이어간다.
- **소유 하위 역할의 확인된 장애는 일반감독이 복구한다.** 반복 압축 실패·미처리 입력 등 실제 응답 장애라면 같은 업무·실행·모델·작업공간과 저장 결과를 보존하는 단일 교대를 결정할 수 있다. 정당한 입력 대기·느린 진전·문맥 비율만으로 교대하지 않는다. 후임 인수 전 선임 보존, 담당 이전, 정확 선임 종료는 [교대 절차](../../kadan-super/references/handover.md)를 따른다. 감독 자신의 교대는 직속 상위가 맡고, 감시체계는 알림만 맡는다.
- **방법 제한과 사용자 금지를 구분한다.** 운영상 붙인 `기존 역할 유지`, `새 작업자 없음`, `이번 ID만`에는 적용 대상·이유·끝나는 조건을 적는다. 증원 금지나 특정 교대 중 다른 프로세스 보존을 이후 모든 장애 복구의 영구 금지로 확대하지 않는다. 일반감독은 이 위임 범위에서 기존 방법 제한을 바꿀 때 원이력을 보존하고 새 근거·적용 범위를 최신 판단으로 정정한다. 사용자 직접 중지·명시 상한·운영 금지·읽기 전용·원자료/소유 보호·계정/결제/권한 제한은 방법 제한으로 낮춰 해제하지 않는다.

상위 상담은 일반감독이 근거를 대조해도 결정하지 못한 문제, 판 사이 충돌, 위임 범위 밖 조치에 쓴다. 질문에는 이미 확인한 사실·자기 판단·남은 선택·답 없이 계속할 일을 적는다. 슈퍼는 해결 기준을 일반감독에게 맡기고 일상 실행의 승인자가 되지 않는다.

## 계속 / 일부 보류 / 결정 요청

- **계속:** 이미 승인된 목적·환경·대상·변경 범위 안이면 기존 승인 근거를 카드에 연결하고 진행한다. 새로운 수정/검수 카드라는 이유만으로 다시 승인받지 않는다. 상위 역할이라는 이유로 권한이 늘어나지는 않는다.
- **일부 보류:** 접속·자료·도구·외부 결과가 막힌 정확한 행동만 멈춘다. 영향 없는 구현·후보 준비·이미지·검수를 병렬로 이어간다. 영향 미확인을 정상으로 간주하거나 실패한 접속을 강행하지 않는다.
- **결정 요청:** 위 결정 범위로 해결하지 못한 문제만 일반감독이 슈퍼에게 상담한다. 슈퍼도 자기 권한 밖인 조치만 사용자 결정으로 올린다. 질문에는 막히는 행동·선택지·추천·답 없이 계속할 일을 적는다.
- 승인에는 환경·대상·행동 범위가 있다. push·병합·배포·DB 변경이라는 이름만으로 매번 재승인을 요구하지도, 승인된 한 건을 다른 환경 전체로 넓히지도 않는다. 운영 배포의 현재 시점 명시 승인 등 프로젝트 규칙은 그대로 적용한다.
- 사용자 명시 중지·카드 상한·필수 안전 조건은 지킨다. 일부 보류로 분리할 수 없으면 전체를 왜 멈춰야 하는지 근거를 남긴다.
- 최신 사용자 지시가 분명한 정정이면 기존 결정과의 차이를 기록하고 적용한다. 뜻이 실제로 갈리는 부분만 묻는다. 과거 금지 문구가 있다는 이유로 명확한 새 지시를 되묻지 않는다.

## 가장 작은 카드

카드를 더 잘게 쪼개는 것이 목적이 아니다. 한 카드에 아래를 짧게 고정한다.

1. 사람이 무엇을 어디서 확인하면 끝인가: 대상 환경·대표 사례·확인 흐름.
2. 기존에 무엇을 재사용하고 무엇만 바꾸는가.
3. 승인 근거·소유 파일/데이터·시간 상한과 하지 않을 일.
4. 합격을 보여줄 최소 검증과 결과/후속을 받을 직속 감독.

사용자가 지정한 대표 개수는 최초 확인 단위인지 전체 실행 상한인지 구분한다. 묶음·분리와 절차 선택은 위 단순화 규칙을 따른다.

## 한 사이클과 대기

- 구현 완료 → 필요한 독립검수 → 승인된 환경의 적용·실물 확인 → 결과 기록이 연결되어야 한다. 코드 카드 하나의 완료와 사용자가 요청한 전체 결과는 구분한다. 이미 합격한 동일 근거를 반복 검증하지 않는다.
- 완료/감시 편지를 받으면 결과·현재 세대·기존 후속 발령을 확인해 빠진 다음 행동을 수행한다. done이 있다는 이유로 검수/Preview 후속을 건너뛰지 않는다.
- 응답을 끝내는 것은 AI 폴링을 멈추는 것이다. 판 운영을 비서에게 넘기는 것이 아니다. 종료 전에 남은 일을 이어갈 담당·대기 대상·깨움 경로를 확정한다.
- 외부 실행은 정확 run/attempt에 연결된 일회성 결과 통지를 둔다. 없는 메시지를 기다리거나 완료된 실행을 다시 기다리지 않는다. 상세는 dispatch-wait.md.
- report/stored/ack는 보고·저장·확인이지 실행 승인이나 완료가 아니다. 비서 회신을 기다리며 전체 판을 멈추지 않는다. 사용자 결정은 중앙 decision 경로를 사용한다.
- 재개할 조건이 있으면 hold, 방향이 바뀌어 다시 하지 않을 카드는 superseded와 후속 카드 연결로 남긴다. 완료·과거 실패를 고쳐 쓰지 않는다. 원본은 중앙 카드/원장이고 화면은 조회 결과다.

## 판단 예시

- 과거 제품 메모와 현재 항목 값이 다름 → 실제 참조·권한·데이터 무결성에 문제가 없다면 그 차이만으로 중지하거나 별개 상품 증명을 요구하지 않는다.
- 이미 승인된 옵션 보존 작업 중 숨김 때문에 원래 조건이 사라짐 → 손실 부분만 최소 수정하고 영향 없는 승인 작업은 계속한다. 이 보존 수정에 재승인을 묻지 않는다.
- 같은 방식·승인·소유로 100개 처리 → 한 작업자가 한 카드에서 이어간다. 39번 실패 시 성공 1~38·실패 39·미착수 40~100·재개 위치 40을 즉시 기록하고, 영향 없는 40번부터 진행한다. 명시 시간 상한은 지킨다.
- 한 접속 자격의 영향이 불명확 → 그 접점만 보류하고 확인된 다른 경로·로컬 작업을 계속한다. 새 자격 교체 권한이 없으면 그 조치만 결정 요청한다.
- 사용자가 명시적으로 전체 중지 → 계속할 일을 추측해 실행하지 않는다.
- DB 검수가 길지만 진전이 있음 → 일반감독이 근거·다음 확인 조건을 남기고 카드 상한 안에서 유지한다. 시간과 라운드 기준은 tiki-taka.md.
- 등록명에 맞는 AI 예시 사진이 승인됨 → 명칭이 분명하면 일반감독이 그 이름의 예시 형태를 적용하고 원조건을 보존한다. 실제 모델·성능·인증 증명으로 쓰지 않는다. 뜻이 불분명한 이름은 그 항목만 분리하며 원데이터를 추정 수정하지 않는다.
- 429 뒤 원인·조건 변화가 없음 → 해당 호출만 보류한다. 사용자 한도 변경 전달 등 새 근거가 생김 → 일반감독이 위 복구 확인 범위에서 판단하며 슈퍼의 건별 허락을 새 관문으로 두지 않는다.
