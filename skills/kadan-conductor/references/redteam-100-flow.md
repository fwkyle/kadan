# 레드팀100 흐름 (redteam-100-flow)

## Why

만든 사람은 자기 서비스가 쉬워 보인다. 이 흐름은 서비스를 처음 보는 여러 수준의 사용자를 AI 페르소나 패널로 세우고, 실제 사용 관찰 증거를 함께 보게 한다. 그래서 출시 전에 "어디서 떠나고, 돈을 낼지"를 근거와 함께 빠르게 확인한다.

대상은 웹 서비스·데스크톱 앱·모바일 앱 모두다. 특정 제품 전용 절차가 아니다. 제품별 값은 업무 카드와 사례 기록에 둔다.

## 흐름 선택

- 사용자가 흐름을 지정하지 않으면 개발용 [표준 흐름](standard-flow.md)과 [티키타카](tiki-taka.md)를 쓴다.
- "레드팀100", "레드팀 패널", "시장성 레드팀", "FGI처럼"처럼 이 흐름을 지정했을 때만 이 문서를 따른다.
- 이름의 100은 기본 인원이다. 업무 카드에 실제 인원 N을 적는다. 시험 운영(파일럿)을 건너뛰고 N부터 돌리지 않는다.

## 결과물의 이름

최종 보고서에는 **"AI 페르소나 패널 N명 + 실제 사용 관찰 M회"**라고 적는다. "FGI 결과"나 "사용자 조사"라고 부르지 않는다. 이 흐름은 불편 지점과 가설을 찾는다. 시장 규모나 실제 전환율을 예측하지 않는다.

## 단계와 카단 연결

업무 카드 한 장(`kadan work create`)에 대상·판단 질문·대상 사용자 가정·N·완료 조건을 적는다. 아래 단계는 그 업무의 실행이다. 단계 값은 현재 저장 형식에 맞춘다(조사는 0라운드).

| 단계 | 하는 일 | 실행 단계 값 | 라운드 |
|---|---|---|---|
| 0. 준비 | 대상 브리프·페르소나 기준표·실행 도구 확인(probe) | `research` | 0 |
| 1. 직접 써 보기 | 대표 페르소나로 실제 사용 관찰 M회 → 증거 묶음 | `research` | 0 |
| 2. 시험 운영 | 페르소나 5명·실행 도구 2종으로 설계 점검 | `research` | 0 |
| 3. 패널 | 조별 진행자 실행 여러 개(병렬) | `research` | 0 |
| 4. 종합 | 조 결과를 묶어 최종 보고서 초안 | `implementation` | 1 |
| 5. 독립 검증 | 보고서 주장을 증거와 대조 | `review` | 1 |
| 6. 수정 | 검증 지적 반영 | `fix` | 2 |

4~6단계의 왕복과 상한은 [티키타카](tiki-taka.md)를 따른다. 종합 담당과 검증 담당은 다른 계열의 실행 도구를 쓴다.

## 0. 준비

**대상 브리프** (업무 카드에 적는다)
- 대상: URL, 설치 파일, 스토어 주소 중 무엇인지. 지원 OS와 요구 사양.
- 판단 질문: 예) "아무것도 모르는 일반인이 설치해서 첫 결과물을 얻고, 돈을 낼까?"
- 핵심 과업 1~3개: 예) "첫 방문 5초 안에 무엇인지 이해", "가입 또는 설치", "첫 핵심 결과 얻기", "결제 판단".
- 알려진 갈림길: 계정·API 키·모델 선택·권한 요청·경고 창처럼 초보자가 멈출 만한 지점.

**페르소나 기준표** (실제 조사 모집의 선별 기준표처럼)

디지털 숙련도(가장 중요한 축):

| 단계 | 모습 |
|---|---|
| 0 | 스마트폰 메신저·영상만 씀. PC를 거의 안 씀 |
| 1 | PC로 문서를 열어 보고 검색 정도 함 |
| 2 | 문서·표 프로그램으로 업무 문서를 만듦. 설치는 남에게 부탁함 |
| 3 | 프로그램을 혼자 설치하고 설정을 바꿈 |
| 4 | AI 서비스를 매일 쓰거나 유료로 씀 |
| 5 | API 키·로컬 모델·개발자 도구 개념을 앎 |

함께 섞는 축: 나이대, 주 사용 기기·OS, 주로 다루는 문서·업무, 현재 유료 AI 사용 여부, 개인정보 민감도, 월 지불 기준액. 대상 브리프에 따라 축을 더하거나 뺀다.

배분: 판단 질문의 대상 층에 60~70%를 두고 나머지는 비교용으로 둔다. 예) "일반인" 질문이면 숙련도 0~2에 60~70%. 배분표를 업무 카드에 남긴다.

**실행 도구 확인**: 패널에 쓸 실행 도구는 `$KADAN_HOME/agent-runners.json`에 등록된 것만 쓴다. 새 도구는 probe 1회로 모델 지정·종료 동작을 확인하고 실측 날짜와 근거를 적은 뒤 등록한다. 지정한 모델로 도는지는 발령 뒤 실제 명령줄로 확인한다.

## 1. 직접 써 보기

숙련도 대표 3명 정도(예: 0·2·4단계)를 한 명씩 연기하며 핵심 과업을 끝까지 해 본다. 생각을 소리 내어 적는다(think-aloud). 막힌 곳에서 그 사람이 실제로 할 행동(포기·검색·남에게 부탁)을 적는다.

| 대상 종류 | 방법 | 실행 위치 |
|---|---|---|
| 웹 서비스 | 브라우저 자동화. 가능하면 화면을 가져가지 않는 백그라운드 방식 | 작업 기기 가능. 페르소나마다 새 브라우저 문맥 |
| 데스크톱 앱 | 화면 캡처·클릭(컴퓨터 유즈) | 테스트 전용 기기나 가상 머신. 사용자 주 기기에 설치하지 않는다 |
| 모바일 앱 | 기기 자동화·화면 캡처 | 테스트 전용 기기. 연결 기기 안전 기준을 따른다 |

- 설치형 대상의 서명 없는 설치 파일, 계정 생성, 결제 단계는 업무 카드의 승인 범위 안에서만 진행한다. 실제 결제는 하지 않는다.
- 대상 사용자가 주로 쓰는 OS를 확인하지 못했으면 보고서에 "미확인 OS"로 남긴다. 다른 OS 결과로 대신하지 않는다.

**증거 묶음** (패널 전원이 같은 묶음을 받는다)
- 과업별 단계 수·걸린 시간·성공 여부
- 막힌 지점마다 스크린샷, 화면 문구 원문, 페르소나의 반응
- 공개 페이지(소개·가격·도움말) 원문 요약
- 확인하지 못한 것 목록

## 2. 시험 운영

페르소나 5명을 실행 도구 2종에 나눠 개인 답변만 받는다. 답이 서로 비슷하면(같은 막힘·같은 판정 문장) 기준표·질문·증거 묶음을 고친 뒤 다시 시험한다. 통과 기준과 고친 내용을 업무 카드에 남긴다.

## 3. 패널

실제 FGI처럼 **6~8명씩 한 조, 진행자 1명**으로 나눈다. 조 하나가 실행 카드 하나다. N=100이면 약 14개 조다.

- 같은 숙련도 단계끼리 한 조로 묶는다.
- 조마다 실행 도구·모델 계열을 번갈아 배정한다. 한 계열이 전체의 절반을 넘지 않게 한다.
- **개인 답변 먼저, 토론은 나중에.** 각 페르소나 답변을 먼저 파일로 고정한 뒤 조 토론을 한다. 가능하면 페르소나 답변은 새 문맥에서 따로 받는다. 한 문맥에서 모두 쓴 조는 결과에 그 사실을 표시한다.
- 조 토론에서는 진행자가 반대 의견을 일부러 끌어낸다. 예) "이걸 절대 안 쓸 이유", "경쟁 대안으로 가는 이유".

**개인 답변 양식**
```
페르소나: 숙련도 / 나이대 / 기기·OS / 업무 / 유료 AI 사용
처음 막힌 곳 3개: (증거 묶음 항목 번호)
그 자리에서 할 행동: 포기 / 검색 / 남에게 부탁 / 계속
돈을 낼까: 예 / 아니오 / 조건부 + 이유 + 비교 대상
치명적인 반대 1줄:
한 줄 판정:
```

**조 결과 양식**: 조 구성, 개인 답변 원문 경로, 토론에서 바뀐 의견과 이유, 조 합의·이견.

## 4~6. 종합과 독립 검증

종합 담당은 막힌 곳을 묶고, 몇 명이 어느 숙련도에서 말했는지 센다. 각 주장에 증거 묶음 항목을 붙인다.

독립 검증 담당은 아래를 확인한다.
- 증거 묶음 없이는 알 수 없는 주장(써 봐야 아는 내용)에 근거가 있는가
- "여러 조가 같은 말"이 같은 모델 계열이나 같은 문구에서만 나온 맞장구는 아닌가
- 비교용 층의 결과를 대상 층의 결과로 섞지 않았는가
- 결과물 이름과 방법 한계를 정직하게 적었는가

**최종 보고서 양식**
1. 한 줄 결론: 판단 질문에 대한 답
2. 치명적인 이탈 지점 순위: 지점 / 숙련도별 언급 수 / 증거
3. 지불 의향: 숙련도별 분포와 주된 이유·비교 대상
4. 숙련도별 판정 요약
5. 고치면 효과가 큰 순서의 제안
6. 확인하지 못한 것과 방법 한계(AI 페르소나, 관찰 M회, 미확인 OS 등)

## 하지 않는 것

- 증거 묶음 없이 소개 페이지만 읽고 "써 봤다"고 쓰지 않는다.
- 페르소나 수를 늘리는 것으로 다양성을 대신하지 않는다. 기준표·실행 도구·관점이 다양성을 만든다.
- 조마다 역할·카드를 따로 만들어 페르소나 한 명당 세션 하나를 띄우지 않는다.
- 사용자 주 기기에 설치형 대상을 설치하거나 화면 포커스를 가져가지 않는다. 사용자가 그 실행에 명시적으로 허락한 경우만 예외다.
