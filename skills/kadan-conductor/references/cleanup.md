# 종료·정리

## Why

할 일이 끝난 작업자·검수자 세션이 쌓이지 않게 정리하면서, 연속 작업에 필요한 맥락과 결과·원장 증거를 보존한다.

## 종료·정리

- **할 일이 끝난 작업자·검수자는 판 종료를 기다리지 않고 종료한다.** 결과·완료 기록과 그 역할의 남은 담당 일을 확인한 감독이 판단한다. 조용한 화면이나 유휴 시간만으로 종료하지 않는다.
- **유지는 구체적인 연속 작업이 있을 때만 한다.** 같은 대상의 수정·재검수, 진행 중인 검수 결과 대기처럼 직전 맥락이 필요한 경우다. 기존 카드의 다음 행동·대기 대상에 유지 이유와 종료 판단 시점을 남긴다. "나중에 쓸 수도 있음"은 유지 이유가 아니다. 새 작업에는 새 세션을 세운다.
- 명시된 자동 구현·검수 왕복은 같은 블록의 두 세션을 유지하는 연속 작업이다. 중간 실행 done마다 닫지 않고, PASS·예외·블록 경계에서 남은 일을 확인해 정리한다. 다른 미완료 실행·응답 책임·인계가 남은 역할은 먼저 이어갈 담당과 경로를 정한다.
- 작업자·검수자 결과 파일과 원장 `done`을 확인한 뒤 종료한다. **확정은 종료에 딸린 것이
  아니라 카드에 딸린 것**이라, 접지 않아도 카드가 끝나면 그 자리에서 확정한다.
- **이번 판에서 만든 정확한 역할만** 하나씩 종료한다.

  ```bash
  kadan stop <판>-작업자
  kadan stop <판>-검수자
  ```

- **판 종료 때는 남은 소유 세션을 정리한다.** 판 감독이 자기 작업자·검수자를 정리하고, 직속 상위가 보고와 남은 책임을 확인한 뒤 자신이 세운 판 감독을 종료한다. 진행 중인 판 감독이나 다른 업무를 맡은 역할은 일괄 종료하지 않는다. 사용자 보존 지시는 우선한다.
- `kadan stop`은 카단 구획의 카단이 만든 역할만 닫는다. 넓은 process-name kill,
  tmux 서버 전체 종료, 다른 판 역할 종료는 금지한다.
- 역할 이름을 원장에서 지우지 않는다. 원장은 append-only이고 `stop` 줄을 뒤에 붙인다.
- 산출물이 필요한 worktree는 정리 전에 백업 경로와 커밋 SHA를 보고한다.
- worktree **병합**은 사용자 승인 범위를 따른다. 병합이 확인된 worktree의 **정리**는 아래 [worktree 정리](#worktree-정리) 규칙대로 추가 승인 없이 한다.
- 강제 종료 뒤 실행기 자식 프로세스가 남았는지는 자기 판 PID 범위만 읽기 전용으로
  확인한다. 남아도 다른 판과 구분 없이 죽이지 말고 목록을 보고한다.
- companion·relay·kicker·watch 스크립트는 라이트에 없다. 정리 대상으로 만들지 않는다.

## worktree 정리

**Why**: 예전 규칙("worktree 삭제는 사용자 승인 뒤에만")에서는 아무도 승인을 묻지 않아 정리가 일어나지 않았다. 병합은 작업자 세션이 끝난 뒤 사용자 승인으로 묶어 하므로 "병합 뒤 정리" 담당도 비어 있었다. 2026-09-30 한 제품 저장소 3곳에 worktree 221개가 쌓였고 디스크 여유가 19GB까지 줄었다(사용자 결정: 병합한 쪽이 바로 정리).

- **책임자**: 기능 브랜치를 기준 브랜치에 합류시킨 감독이 합류 확인 직후 같은 작업 안에서 정리한다. 작업자·검수자 세션이 이미 끝났어도 감독이 한다. 정리하지 않고 끝내면 합류 완료가 아니다.
- **검수 자리**(`kadan slot`): 검수자가 결과 등록 직후 `kadan slot release <자리경로>`로 돌려준다. 자리 worktree와 `node_modules`는 지우지 않는다(다시 쓰는 것이 목적). 검수자가 못 했으면 결과를 받은 감독이 `kadan slot release --for <카드id>`로 돌려준다. 임시 자리(`--temporary`)는 release가 worktree까지 지운다. 예전 방식으로 만든 **검수 전용 worktree**는 검수자가 결과 등록 직후 정리한다.
- **병합 판정**: `git merge-base --is-ancestor <worktree HEAD> origin/<기준 브랜치>`가 참이거나, 스쿼시 병합이면 PR 상태가 `MERGED`이고 PR head가 worktree HEAD와 같다. 로컬 기준 브랜치가 뒤처질 수 있으니 판정 전에 `git fetch`한다.
- **지우기 전 확인**(하나라도 걸리면 남기고 이유를 보고): 추적 파일 변경·새 소스 파일이 있음 / upstream에 없는 커밋이 있음 / 그 폴더를 현재 폴더로 쓰는 프로세스가 있음(`lsof -a -d cwd`) / 남의 브랜치.
- **도구 흔적**(`.rottie/`, `.trash/`, 증거 폴더처럼 추적되지 않는 도구 산출물)만 남아 정리가 거부되면, 지우지 말고 해당 허브의 `.trash/` 아래로 옮긴 뒤 정리한다. `--force`로 넘기지 않는다.
- **순서**: `git worktree remove <절대경로>` → `git branch -d <브랜치>`(로컬 기준 브랜치가 뒤처져 거부되면 origin 기준 병합을 다시 확인한 뒤에만 `-D`) → `git push origin --delete <브랜치>`. 열린 PR이 base로 쓰는 브랜치는 원격에서 지우지 않는다.
- **병합 안 된 worktree**: 소스·브랜치는 보존한다. 3일 넘게 수정이 없고 쓰는 프로세스도 없으면 캐시(`node_modules`, `target`, `.next`, `dist`)만 지운다. 닫힌(병합 안 된) PR의 worktree는 목록을 사용자에게 보고하고 결정을 받는다.
- **점검**: 감독은 하루 합류를 마칠 때 대상 저장소마다 `git worktree list`로 병합된 worktree가 남았는지 한 번 확인한다.
- **보고**: 정리한 worktree·브랜치 수, 남긴 것과 이유, 회수 용량.
