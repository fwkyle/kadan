# 종료·정리

## Why

할 일이 끝난 작업자·검수자 세션이 쌓이지 않게 정리하면서, 연속 작업에 필요한 맥락과 결과·원장 증거를 보존한다.

## 종료·정리

- **할 일이 끝난 작업자·검수자는 판 종료를 기다리지 않고 종료한다.** 결과·완료 기록과 그 역할의 남은 담당 일을 확인한 감독이 판단한다. 조용한 화면이나 유휴 시간만으로 종료하지 않는다.
- **유지는 구체적인 연속 작업이 있을 때만 한다.** 같은 대상의 수정·재검수, 진행 중인 검수 결과 대기처럼 직전 맥락이 필요한 경우다. 기존 카드의 다음 행동·대기 대상에 유지 이유와 종료 판단 시점을 남긴다. "나중에 쓸 수도 있음"은 유지 이유가 아니다. 새 작업에는 새 세션을 세운다.
- 명시된 자동 구현·검수 왕복은 같은 블록의 두 세션을 유지하는 연속 작업이다. 중간 실행 done마다 닫지 않고, PASS·예외·블록 경계에서 남은 일을 확인해 정리한다. 다른 미완료 실행·응답 책임·인계가 남은 역할은 먼저 이어갈 담당과 경로를 정한다.
- 작업자·검수자 결과 파일과 원장 `done`을 확인한 뒤 종료한다. **확정은 종료에 딸린 것이
  아니라 카드에 딸린 것**이라, 접지 않아도 카드가 끝나면 그 자리에서 확정한다.
- **이번 판에서 만든 정확한 역할만** 하나씩 종료한다.

  ```bash
  kadan stop <판>-작업자
  kadan stop <판>-검수자
  ```

- **판 종료 때는 남은 소유 세션을 정리한다.** 판 감독이 자기 작업자·검수자를 정리하고, 직속 상위가 보고와 남은 책임을 확인한 뒤 자신이 세운 판 감독을 종료한다. 진행 중인 판 감독이나 다른 업무를 맡은 역할은 일괄 종료하지 않는다. 사용자 보존 지시는 우선한다.
- `kadan stop`은 카단 구획의 카단이 만든 역할만 닫는다. 넓은 process-name kill,
  tmux 서버 전체 종료, 다른 판 역할 종료는 금지한다.
- 역할 이름을 원장에서 지우지 않는다. 원장은 append-only이고 `stop` 줄을 뒤에 붙인다.
- 산출물이 필요한 worktree는 정리 전에 백업 경로와 커밋 SHA를 보고한다.
- worktree 삭제·병합은 사용자 승인 뒤에만 한다. 승인 전에는 보존한다.
- 강제 종료 뒤 실행기 자식 프로세스가 남았는지는 자기 판 PID 범위만 읽기 전용으로
  확인한다. 남아도 다른 판과 구분 없이 죽이지 말고 목록을 보고한다.
- companion·relay·kicker·watch 스크립트는 라이트에 없다. 정리 대상으로 만들지 않는다.
