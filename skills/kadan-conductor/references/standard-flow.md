# 표준 흐름 패턴 (반복/독립 구분 → 처리 → 검수 → 보고)

## Why

대량 작업을 실제 소유·검수 단위로 묶어 항목별 준비와 중계를 반복하지 않는다.

대량 작업의 묶음·분리는 [단순화 규칙](operating-contract.md#단순화-규칙)을 따른다.
실행 절차는 `dispatch-wait.md`, 왕복·검수 규칙은
`tiki-taka.md`, 실행기 선택은 `$KADAN_HOME/agent-runners.json`(예시: `skills/kadan-conductor/references/agent-runners.example.json`)을 따른다.

`work auto-configure`로 명시 설정한 업무의 구현·검수·수정 전달과 블록 내 세션 유지는
[자동 전달 계약](dispatch-wait.md#구현검수-자동-전달--명시-설정한-업무만)을 적용한다.
아래 수동 새 검수 역할·감독 재발령 절차는 미설정 업무의 기본값이다.

## 1) 묶음·분리 — 작업 단위와 등급

- 동일 방식·승인·소유의 반복은 한 작업자가 한 실행 카드에서 연속 처리한다. 항목 상태와 재개 위치는 즉시 기록한다.
- 독립 소유·병렬 효과·실제 충돌/위험·명시 시간 상한 때문에 나눌 때만 이유를 카드에 남긴다. 나눈 단위를 섹션이라 한다.
- 각 카드에 난이도(low/medium/high)와 절차 무게(LIGHT/HEAVY)를 붙인다.
  판정 기준·래칫은 `tiki-taka.md`를 따른다. 무검수 단독 편성은 없다.
- 방향이 갈리는 카드는 `tiki-taka.md`의 배틀 오프닝으로 시작한다.
- 반복 카드 전체 또는 독립 섹션을 검수 단위로 삼는다. 항목이나 임의 개수마다 준비·발령·검수를 반복하지 않는다.

## 2) 작업 단위 검수 — gajae

- 반복 카드 전체 또는 독립 섹션의 작업 카드가 모두 DONE이면 필요한 검수를 새 검수 역할에 한 번 발령한다.
- 검수 카드에는 [검수 공통 계약](card-template.md#검수-공통-계약)의 확인한 절대경로와 검수 대상·기준을 적는다. 공통 전문을 다시 복사하지 않는다.
- 검수 발견은 같은 업무의 작업자에게 원문으로 잇는다. 진행 중 실행에는 추가 입력, 종료 뒤에는 기존 기준을 참조하는 새 실행 ID를 쓴다. 검수자가 직접 고치지 않는다.

## 3) 보고

각 작업 단위 종료 시 사용자에게 완료 카드 수, 배틀 결과, 검수 발견(심각도별), 남은 작업,
사용량 상태를 쉬운 말로 보고한다. 승인된 환경 적용·실물 확인이 남으면 이어간다.
push·병합·배포·삭제·worktree 정리는 해당 승인 범위를 확인하고 권한 밖인 것만 결정 요청한다.
