## Why

사용자의 최신 뜻과 승인 범위를 지키며 필요한 일을 이어간다.

- 최신 사용자 지시·승인과 카드의 범위·보류·교대 조건을 우선한다.
- 이 기본 지침은 새 발령이나 권한이 아니다. 역할이 높아도 승인 범위는 늘지 않는다.
- 받은 본문과 안내된 최신 카드·판단을 읽고, 스킬·운영기준의 이번 행동에 필요한 절을 다시 읽는다.
- 정상 ACK 편지나 AI 반복 조회·대기 보고를 만들지 않는다. 명령에 필요한 최신 정보는 확인한다.
- 우편 ID와 읽음 확인 명령이 안내된 편지는 내용을 확인한 수신자가 직접 확인을 기록한다. 이는 로컬 읽음 사건이며 ACK 회신을 보내는 일이 아니다. 조회·답장·DONE으로 읽음을 대신하지 않는다.
- 완료 통지 편지의 발송 실패(입력 거절·세션 없음 등)는 작업 실패가 아니다. 명령이 보내기 전에 원인을 적어 거절했고(본문 중복·사용법 오류 등) 그 원인을 스스로 고칠 수 있으면 고쳐서 1회 다시 보낸다. 그래도 실패하거나, 받는 쪽 사정(세션 없음·입력 거절)이거나 전달 여부가 불명확하면 카드 메모에 남기고 다시 보내지 않는다. 실행 `ok|failed`는 결과 파일·`card report`의 실제 내용으로만 정하며, 통지가 안 갔다는 이유로 `failed`를 찍지 않는다.
- herdr 화면 확인은 바로 끝나는 `terminal session observe`·`pane read`만 쓴다. `terminal session control`·`terminal attach`를 백그라운드나 사람 없는 셸에서 띄우지 않는다. 다른 이유로 띄웠다면 그 셸이 끝나기 전에 직접 종료하고 남은 프로세스가 없는지 확인한다.
- 전달·저장·확인을 착수·성공·완료로 확대하지 않는다. 미확인 근거로 성공이나 완료를 꾸미지 않고 모르는 것은 그대로 남긴다.

- 기기 전체에 부하를 거는 시험(CPU를 계속 쓰는 무한 반복, 대량 병렬 프로세스, 메모리 채우기, `stress`·`yes` 같은 부하 도구)을 돌리지 않는다. 부하·지연·시간 초과 재현은 시험 안의 가짜 시계·지연 주입·작은 고정 입력으로 한다. 실제 부하가 꼭 필요하면 멈추고 직속 감독에게 묻는다. 2026-10-21 작업자가 node 무한 반복 31개를 돌려 맥 부하 평균이 약 300까지 올랐다.

- 결과 확인용 서버(개발 서버·Studio·미리보기)는 `127.0.0.1`에만 열고 `0.0.0.0`·외부 주소는 쓰지 않는다. 띄운 쪽이 DONE·완료 통지 전에 끄고 `lsof -nP -iTCP:<포트> -sTCP:LISTEN`이 빈 것을 확인한 뒤, 띄운 PID·포트와 끈 확인을 결과 파일에 적는다. pid 파일은 실제 포트를 잡은 프로세스 번호와 맞는지 본다. 남겨야 하면 이유·PID·포트를 적고 말없이 끝내지 않는다. Docker 검증 컨테이너 정리 규칙과 같은 원칙이다(2026-10-22 작업자가 확인용 서버를 `0.0.0.0:59783`로 띄운 채 DONE, 약 3시간 켜져 있었다).

- 역할은 `kadan restart --force`를 쓰지 않는다. 끝나지 않은 카드가 있는 역할을 다시 띄우는 판단은 사람의 몫이다.

- 남은 사용 한도(주간·5시간 남은 양, 크레딧)를 이유로 일을 미루거나 실행기·모델을 미리 바꾸지 않는다. 호출이 실제로 실패하기 전에는 피하지 않는다. 사용자가 명시로 요청한 때만 그 요청 범위에서 한도에 맞춰 조정한다. 이유: 2026-11-13·11-17 남은 한도 숫자만 보고 실행기를 바꾸거나 발령을 미룬 일이 있었다.

- 호출이 실제로 한도로 멈췄고(일일·주간 한도 화면, 최종 429) 그 역할의 자리(실행 모델 설정의 worker·worker-hard·reviewer)에 대체 후보가 있으면, 그 역할을 맡긴 감독이 기다리지 않고 바로 교대한다. 작업자·검수자는 자기를 스스로 바꾸지 않고 감독에게 알린다. 한도에 걸린 쪽이 감독이면 직속 상위가 맡는다.
  - 순서: 옛 세션의 끝나지 않은 카드 정리([소유 하위 역할 교대](../operating-contract.md#일반감독의-결정-범위)) → 옛 세션 `kadan stop`(한도가 풀려 깨어난 옛 세션과 새 세션이 같은 작업 폴더에 함께 쓰지 않게) → `kadan start <새 이름> --profile <프로필> [--difficulty hard] --fallback N --reason "<한도 화면 한 줄>"`([폴백으로 띄우기](../../../../docs/runner-settings.md#폴백으로-띄우기)) → 같은 카드를 새 역할에 발령. 어려운 일 작업자는 `--difficulty hard`로 그 자리의 후보를 쓴다.
  - 검수자는 작업자와 같은 계열(실행 모델 설정의 계열 표 `families`)을 쓰지 않는다. 특정 모델 짝을 정하지 않는다. 검수자는 늘 `kadan start <검수자> --profile reviewer --for <작업자>`로 띄운다([작업자에 맞춰 검수자 시작하기](../../../../docs/runner-settings.md#작업자에-맞춰-검수자-시작하기) — 코드가 1순위부터 다른 계열 첫 후보를 고른다). 작업자를 교대했다면 새 작업자 기준으로 검수자도 `--for`로 다시 띄운다.
  - 검수자가 실제로 한도로 멈췄을 때는 `--for`가 멈춘 후보를 건너뛰지 못하고(`--for`는 `--fallback`과 함께 쓸 수 없다) 1순위부터 다시 고르므로, 맡긴 감독이 `kadan runners show`의 검수자 대체 후보 중 멈춘 후보 다음부터 작업자와 **다른 계열인** 첫 후보 번호 N을 직접 골라 `kadan start <새 검수자> --profile reviewer --fallback N --reason "<한도 화면 한 줄>"`로 교대한다. 같은 계열이거나 계열을 모르는 후보는 건너뛴다.
  - codex(ocx 경유)는 먼저 기존 사용량 새로고침 결과를 본다. 새로고침 뒤 사용량이 낮으면 가짜 한도일 수 있어 교대하지 않는다([ocx 사용량 새로고침 절](../../../../docs/rate-limit-retry.md)). 최종 429 자동 재개가 예약됐거나 입력창이 비어 있으면 그 처리가 먼저다.

- 그 자리에 대체 후보가 없을 때만 보고하고 기다린다.

- 계정 전환·사용량 증액·대체 후보 목록 바꾸기는 사용자가 정한다. 교대는 설정에 이미 있는 후보만 쓰며 목록을 바꾸지 않는다.

- **tmux 격리 (2026-11-04 사고).** tmux는 늘 `-L <격리 이름>` 또는 `-S <절대경로>`로 부른다. 시험·QA 스크립트 첫 줄에서 `unset TMUX TMUX_PANE`을 한다. `kill-server`는 직접 만든 격리 소켓에만 쓰고, 실행 전에 소켓 이름을 출력한다. 운영 이름 `-L kadan`은 쓰지 않는다. 소켓 없는 날것의 `tmux kill-server`도 치지 않는다(`TMUX`를 지우면 개인 기본 서버를 죽인다). 기본 서버를 다루는 재현은 실행별 `TMUX_TMPDIR`(tests/run.mjs가 깐 것) 안에서만 한다. 이유: 2026-11-04 카단 pane 안에서 돈 QA 스크립트가 `-L` 없이 `kill-server`를 쳐서 운영 tmux 서버가 통째로 내려갔다.
