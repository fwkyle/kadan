## Why

사용자의 최신 뜻과 승인 범위를 지키며 필요한 일을 이어간다.

- 최신 사용자 지시·승인과 카드의 범위·보류·교대 조건을 우선한다.
- 이 기본 지침은 새 발령이나 권한이 아니다. 역할이 높아도 승인 범위는 늘지 않는다.
- 받은 본문과 안내된 최신 카드·판단을 읽고, 스킬·운영기준의 이번 행동에 필요한 절을 다시 읽는다.
- 정상 ACK 편지나 AI 반복 조회·대기 보고를 만들지 않는다. 명령에 필요한 최신 정보는 확인한다.
- 우편 ID와 읽음 확인 명령이 안내된 편지는 내용을 확인한 수신자가 직접 확인을 기록한다. 이는 로컬 읽음 사건이며 ACK 회신을 보내는 일이 아니다. 조회·답장·DONE으로 읽음을 대신하지 않는다.
- 완료 통지 편지의 발송 실패(입력 거절·세션 없음 등)는 작업 실패가 아니다. 카드 메모에 남기고 반복 재전송하지 않는다. 실행 `ok|failed`는 결과 파일·`card report`의 실제 내용으로만 정하며, 통지가 안 갔다는 이유로 `failed`를 찍지 않는다.
- herdr 화면 확인은 바로 끝나는 `terminal session observe`·`pane read`만 쓴다. `terminal session control`·`terminal attach`를 백그라운드나 사람 없는 셸에서 띄우지 않는다. 다른 이유로 띄웠다면 그 셸이 끝나기 전에 직접 종료하고 남은 프로세스가 없는지 확인한다.
- 전달·저장·확인을 착수·성공·완료로 확대하지 않는다. 미확인 근거로 성공이나 완료를 꾸미지 않고 모르는 것은 그대로 남긴다.

- 기기 전체에 부하를 거는 시험(CPU를 계속 쓰는 무한 반복, 대량 병렬 프로세스, 메모리 채우기, `stress`·`yes` 같은 부하 도구)을 돌리지 않는다. 부하·지연·시간 초과 재현은 시험 안의 가짜 시계·지연 주입·작은 고정 입력으로 한다. 실제 부하가 꼭 필요하면 멈추고 직속 감독에게 묻는다. 2026-10-21 작업자가 node 무한 반복 31개를 돌려 맥 부하 평균이 약 300까지 올랐다.

- 결과 확인용 서버(개발 서버·Studio·미리보기)는 `127.0.0.1`에만 열고 `0.0.0.0`·외부 주소는 쓰지 않는다. 띄운 쪽이 DONE·완료 통지 전에 끄고 `lsof -nP -iTCP:<포트> -sTCP:LISTEN`이 빈 것을 확인한 뒤, 띄운 PID·포트와 끈 확인을 결과 파일에 적는다. pid 파일은 실제 포트를 잡은 프로세스 번호와 맞는지 본다. 남겨야 하면 이유·PID·포트를 적고 말없이 끝내지 않는다. Docker 검증 컨테이너 정리 규칙과 같은 원칙이다(2026-10-22 작업자가 확인용 서버를 `0.0.0.0:59783`로 띄운 채 DONE, 약 3시간 켜져 있었다).

- 역할은 `kadan restart --force`를 쓰지 않는다. 끝나지 않은 카드가 있는 역할을 다시 띄우는 판단은 사람의 몫이다.
