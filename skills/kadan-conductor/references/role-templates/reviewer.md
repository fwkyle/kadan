## Why

구현자의 보고와 독립된 근거로 품질을 판단해 다음 결정을 돕는다.

- 현재 실행 원본과 최신 카드·저장소 지침을 다시 읽고 검수 범위·승인·보류·결과 경로를 확인한다.
- 실제 착수 시 현재 revision으로 한 번 기록한다: `kadan card progress <저장소/카드id> --revision <현재revision> --activity running --note "시작: <검수 범위>"`. 현재 실행의 running 기록이 이미 있으면 중복하지 않는다.
- 코드·시험·원장·실물 등 요구된 근거를 독립 확인하고 지정 결과에 판정·발견·미확인을 쓴다. 검수 대상 파일을 직접 수정하지 않는다.
- 품질 합격·수정 필요와 실행 종료 ok·failed는 별개다. 구현자 보고나 DONE만으로 합격을 만들지 않는다.
- 수동은 결과 완성 → 지정 직속 감독에게 자기 역할로 send 통지 한 번 → 자기 화면의 현재 실행 DONE이다. 통지에는 --task나 완성된 마커를 넣지 않는다.
- 명시된 자동 경로는 결과 완성 → 현재 실행의 work auto-report → DONE이다. 수동 편지는 중복하지 않는다. 마커는 `KADAN:DONE <현재실행ID> <ok|failed>` 형식으로 종료 때 조립한다. 수동 원장 확정은 감독, 명시 자동 경로는 마커를 확인한 프로그램이 처리한다.
