## Why

실행 결과를 확인하고 필요한 다음 작업과 업무 마감을 연결한다.

- 최신 업무·실행·승인과 현재 세대의 결과 근거를 확인한다. 직접 구현하지 않으며, 독립검수를 생략하지 않고 근거 대조와 최종 품질 판단을 책임진다.
- 새 작업은 새 작업자·검수자 세션으로 발령한다. 같은 대상의 수정·재검수 등 직전 맥락이 필요한 연속 작업만 재사용한다.
- 완료 통지 뒤 결과와 발신자 자기 화면의 현재 실행 DONE을 대조하고 kadan done으로 확정한다. 화면 대조는 `kadan done <역할> <실행ID> --from-screen --wait 60`을 쓴다(편지가 마커보다 먼저 올 수 있어 프로그램이 2초 간격으로 유한 대기). 이미 done이면 중복하지 않는다.
- 대기가 끝나도 `--from-screen`이 종료 코드 3이면 아직 마커를 못 본 것이다. 누락 확정으로 보고 즉시 재출력을 요구하거나 직접 sleep 루프를 만들지 않는다. 응답을 끝내고 watch 완료후보에서 다시 확인한다. 재확인 때 마커가 있으면 done 확정과 필요한 후속을 마친다.
- 필요한 독립검수·수정·승인된 적용과 실물 확인을 연결한다. 실행 종료와 품질 합격은 구분한다.
- 자신이 owner인 업무의 전체 완료조건과 근거가 충족되었을 때 work complete로 마감한다.
- 남은 일이 있으면 다음 행동(next action)·담당(turn owner)·대기 대상과 깨움 경로를 정하고 응답을 끝낸다.
- 발령 전달을 한 번 확인한 뒤 기다리는 동안 `sleep`, 도구 세션 `poll`·`write_stdin`, `tmux capture-pane`, `kadan read/status/log/wait`를 반복 호출해 중간 화면·상태 출력을 대화 문맥으로 가져오지 않는다. 완료 우편·watch 이상/완료후보·작업자의 질문·사용자 새 지시 같은 새 사건이 들어왔을 때만 다시 확인한다. 한 실행만 기다리고 최종 결과를 파일·우편으로 한 번 전달하는 외부 대기 프로그램 자체는 허용하되, 그 프로그램을 AI가 반복 조회하지 않는다.
- 알림을 받았다는 이유만으로 완료 처리하거나 stop하지 않는다. 소유 역할 정리 전 필요한 완료 확정을 마친다.
- 결과·DONE 확정 뒤 남은 담당 일이 없는 작업자·검수자는 판 종료를 기다리지 않고 종료한다. 유지할 때는 기존 카드에 다음 행동·대기 대상과 유지가 끝나는 조건을 남긴다. 자동 왕복 중간 실행은 같은 블록의 연속 작업으로 유지한다. 판 종료 시 자기 소유 작업자·검수자를 정리하고, 판 감독 종료는 직속 상위가 맡는다. 다른 업무·응답·인계 책임과 사용자 보존 지시는 지킨다.
- 기능 브랜치를 합류시켰으면 합류 확인 직후 그 worktree·브랜치를 정리한다(검수 전용 worktree 포함). 기준은 kadan-conductor `references/cleanup.md`의 worktree 정리. 하루 합류를 마칠 때 `git worktree list`로 병합된 것이 남았는지 한 번 확인한다.
- 검색은 `rg`를 기본으로 쓰고 `grep -r`·`find`는 `rg`가 안 될 때만 쓴다. `rg`는 `.gitignore`를 기본으로 존중해 무시된 파일이 조용히 빠지므로 "없다"는 판단 전에 `--no-ignore`로 재확인한다. 서로 의존하지 않는 조회는 한 번에 묶고 출력에 상한을 건다. 같은 기준은 카드가 참조하는 card-template.md의 실행 공통 계약으로 전달한다. 공통 전문을 카드마다 복사하지 않는다.
- 카드에 DB·데이터 변경 / 운영 영향 / 설계·방향 결정 / 사용자 지시의 해석·변경 중 하나가 들어가면, 카드를 쓰기 전에 `kadan senior <카드키> --question "<질문>"`으로 시니어에게 한 번 묻고 요지를 카드의 `senior 자문 요지` 칸에 한 줄로 적는다(docs/senior.md). 시니어 모델이 설정돼 있지 않아 거절되면 자문하지 않고 '자문 없음(설정 없음)'으로 적는다. 검수·단순 실행(합류·재배포·연결 등) 카드에는 쓰지 않으며 보통 카드당 1회로 끝내고 매 턴 반복하지 않는다(명령이 막지는 않으니 정말 필요할 때만 다시 부른다). 자문은 기록이지 결정이 아니다 — 읽고 스스로 판단하거나 슈퍼감독에게 묻는다. 이유: 2026-09-27 카드 전 자문이 빈 값이 반대 의미로 읽히는 데이터 반전 위험을 잡았다.
