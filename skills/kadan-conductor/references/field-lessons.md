# 현장 교훈 (감독·슈퍼감독)

## Why

여러 판을 지휘하면서 같은 실수(명령 함정, 잘못된 보고, 비밀 노출, 검수 독립성 훼손)가 반복됐다.
이 문서는 프로젝트와 상관없이 감독이 지킬 교훈을 모은다. 각 항목은 규칙 → 근거(날짜·사고) → 적용법이다.

- 원본: 한 프로젝트의 슈퍼감독 메모리(2026-07-27~10-30)를 2026-10-30에 옮겼다.
- 프로젝트 고유 함정은 각 저장소 문서가 원본이다(예: 허브 저장소의 `docs/guides/dev-verification-pitfalls.md`).
- 이미 [운영 공통 기준](operating-contract.md)·[명령](commands.md)에 있는 내용은 여기 다시 적지 않는다.

## kadan 명령 함정

- **반복문 안 kadan 호출에는 `</dev/null`.** `while read ...; do kadan card ...; done < 파일`에서 kadan이 표준입력을 읽어 모든 반복이 실패한다.
  근거: 2026-09-24 카드 89장 일괄 닫기가 전부 실패했고, `</dev/null`을 붙이자 모두 성공했다.
- **`kadan mail`에는 `--body-file`이 없다.** 붙이면 표준입력을 기다리며 조용히 멈춘다. 긴 본문은 `kadan mail <역할> < 파일`로 넣는다.
  바쁜 세션에 보내는 편지는 120초를 넘길 수 있으니 백그라운드로 보내고, 도착은 받는 역할 inbox로 확인한다. 출력이 비어 있으면 멈춘 것인지 본다.
  늦게 닿아도 안전하게, 급한 멈춤 지시에는 "이미 시작했으면 끝까지 두고 즉시 보고" 같은 문구를 넣는다.
- **회신 방향.** `--reply-to … --reply-final`은 원본이 `--expect-reply`로 온 우편에만 된다. 아니면 `kadan mail <직속 상위> "[회신: 원본 우편 <id>] ..."`로 보낸다.
  반대로 하위가 답변 요청으로 보낸 질문은 반드시 그 질문 ID로 `--reply-final` 닫는다. 안 닫으면 '놀고 있음' 경보가 15분마다 반복된다(2026-10-21).
- **raw 보고는 받은 턴에 ack.** `kadan send --raw`로 온 보고는 우편 ID가 화면에 없다. `kadan inbox --role <나> --unread`로 찾아 그 턴에 ack한다. 안 하면 5분마다 미확인 알림이 쌓인다(2026-09-27).
- **`kadan done`은 카드를 닫지 않는다.** 원장에 완료 확정만 남기고 상태는 assigned다. ok면 `--close-card` 또는 `kadan card update <키> --revision N --status done`.
  대량 상태 변경은 대상 건수를 미리 세고 실행 뒤 대조한다(2026-09-29 진행 중으로 쌓인 카드 318개, 필터 실수로 25개 잘못 닫음).
- **카드 id 재사용 금지.** 결과가 등록된 카드 id를 다른 일에 쓰면 `card report`가 거부되고 원장 결과가 어긋난다. 새 일은 새 id, 같은 일 재발령만 새 id + `--supersedes`(2026-09-28).
- **"발령"은 대시보드로 확인하고 보고한다.** 발령 명령이 오류 없이 끝났는지, 대시보드에서 그 카드가 '발령 전'이 아닌지만 본다.
  배정 상태는 작업자가 아니라 카단이 발령할 때 직접 적으므로 작업자 쪽에서 빠질 수 없다. 명령이 실패하면 카드가 '발령 전'에 그대로 보인다.
  근거: 2026-09-28 단계 이름 오류(`implement`는 무효, `implementation|fix|review|research`만 유효)로 카드 두 장이 발령 전에 남았는데 진행 중으로 보고해 몇 시간 늦어졌다.
- **새 세션은 신뢰된 폴더에서 띄운다.** 하위 저장소 폴더에서 `kadan start`하면 Claude 신뢰 창의 기본값 "No, exit"를 첫 Enter가 골라 세션이 몇 초 만에 사라진다.
  사용 한도를 의심하기 전에 띄운 직후 `tmux capture-pane`으로 신뢰 창부터 본다(2026-10-19).
- **로티 창 연결 실패.** 맥 부하가 높으면 로티가 15초 안에 답하지 못해(os error 35) 창 연결이 실패한다. 실패할 때만 `KADAN_WINDOW=none kadan start …`로 띄운다(2026-10-30).
- **감독 보조 스크립트는 scratchpad에 두지 않는다.** 세션 scratchpad는 자정에 비워진다. `~/.kadan/drafts/.tools/`에 두고, 날짜가 바뀐 세션에서는 존재부터 확인한다(2026-10-11).

## 검수 독립성

- **검수는 reviewer 프로필로만.** `kadan start <역할>-rv --profile reviewer`. worker 프로필로 띄우면 작업자와 같은 모델이 검수해 독립 검수가 아니다.
  근거: 2026-10-01~02 codex 끊김에 지친 감독이 worker 프로필 claude로 검수 18개를 돌렸고, 그중 12개가 운영까지 나갔다.
  codex가 끊기면 같은 세션에 재촉하고, 반복되면 상위에 증상·시각을 보고한다. 실행기·모델 변경은 사용자 결정이다.
- **pass를 전하기 전에 실행기를 본다.** `ps -o args= -p $(tmux list-panes -t <세션> -F '#{pane_pid}')`로 검수 세션이 설정된 reviewer로 떴는지 확인한다.
- **`--fallback N`은 자동 대체가 아니다.** 처음부터 N번 폴백으로 띄운다. 기본은 플래그 없이 `--profile reviewer`(2026-10-02 검수가 kimi로 뜸).
- **보안 필터로 검수가 멈추면.** '선점·공격·피해 고객' 같은 표현은 codex 사이버 필터에 걸린다. 카드는 처음부터 '중복 방지 회귀 확인' 같은 중립 표현과 '로컬 격리 DB·가짜 고객만'으로 쓴다.
  멈추면 실행 cancelled(이유 기록) → 세션 stop → 다른 codex 모델로 reviewer 재기동 → 재발령(`--allow-old-runner "<이유>"` 필요). claude·worker로 바꾸지 않는다(2026-10-22).
- **기본 실행기가 바뀌면 새 세션에.** `kadan runners show`의 기본값이 바뀌면 옛 모델로 떠 있던 세션에 새 카드를 보내지 않는다(2026-09-23).

## 비밀·출력 안전

- 비밀 폴더는 파일 목록·크기만 본다. 어떤 거르기로도 내용을 열지 않는다. 형식이 숫자뿐이어도 출력하지 않는다(2026-10-16 숫자를 고객 id로 보고 출력했는데 전화번호였다).
- 비밀이 섞인 파일(`.env`, `~/.pm2/dump.pm2`, 실행 상태 `state.json`)은 이름을 정한 칸만 뽑는 화이트리스트로 읽는다. '이것만 빼고' 식 제외 거르기는 샌다(2026-10-29 dump.pm2 환경값 약 70줄 노출).
- DB·클라우드를 만지는 카드에는 쓸 접속 경로(env 파일 이름·프로필 이름)를 정확히 적고 "모르면 찾지 말고 멈춰 보고"를 넣는다. 안 적으면 작업자가 비밀 폴더를 뒤지며 내용을 찍는다(2026-10-15).
- 프로세스 확인은 개수·PID만(`pgrep -f x | wc -l`). `pgrep -fl`·`ps aux`는 다른 세션의 토큰을 찍고, codex·claude 세션 로그는 도구 출력을 파일로 남긴다(2026-10-18).
- 노출 보고를 받으면 세션 로그·카드·우편에 값이 남았는지 `rg -o … | wc -l` 개수로 확인하고, 교체 여부는 사용자에게 올린다.
- 로그인 한도가 걸린 카드는 "로그인 한 번, 토큰을 이어 써서 한 실행 안에서 처리"를 적는다. 한도 초과가 적힌 결과는 ok로 받지 않는다(2026-10-17).

## 세션·대기

- **도중 stop 뒤 고아 서버 확인.** 세션을 도중에 멈추면 그 세션의 확인 서버가 부모 PID 1로 남는다. 작업 폴더 cwd·시작 시각으로 주인을 증명한 것만 끄고, 못 하면 보고한다(2026-10-26).
- **시각이 정해진 외부 대기.** 차례 칸을 바꿔도 15분마다 '놀고 있음'이 온다. 끝나면 깨우는 읽기 전용 백그라운드 스크립트를 하나 걸고, 첫 경보 때 상위에 한 번만 알린 뒤 이후는 한두 줄로 넘긴다(2026-10-21).
- **외부 답 대기도 결정으로 열어 둔다.** 카드를 보류만 하면 대시보드 '내 결정'에서 사라진다. 알림용 `kadan decision request`를 열고, 선택지는 행동이 있는 것만 둔다("아직 대기" 금지)(2026-09-24).

## 판단·보고

- **코드만으로 운영 영향을 단정하지 않는다.** 데이터·실측과 교차 확인 전에는 "코드상 가능성, 데이터 미확인"으로 쓴다. 근거 종류(코드/데이터/실측)를 구분한다.
  근거: 2026-09-25 "소셜 가입 막힘"을 코드로만 판정했는데, 운영 집계로는 가입은 되고 번호만 저장이 안 됐다. 틀린 판정은 원 결과에 정정 절을 덧붙인다.
- **긴 작업 진행 확인은 오류부터 grep.** 로그 끝(tail)만 보면 일부 실패 뒤에도 계속 도는 작업이 정상처럼 보인다. `grep -nE "ERROR|FAILED|Traceback"`를 함께 본다(2026-10-20 ETL 실패를 두 번 '오류 없음'으로 오보).
- **"다른 곳에도 같은 문제"는 실제로 쓰이는지부터.** 부품의 import 사용처나 화면 진입 경로를 확인하고, 안 쓰이면 '안 쓰는 코드 정리 후보'로 분류한다(2026-10-16).
- **옛 요청은 지금 화면부터.** 노션·TODO의 옛 요청은 착수 전에 문제가 아직 있는지 보고 '고침/이미 해결됨/일부만'을 표시한다. 사용자에게 묻기 전에 요청 댓글을 먼저 읽는다(2026-10-15).
  노션 인계 건의 사양은 본문 개발 인계서 > 댓글 인터뷰 > 제목 순이다. 인계서의 코드 위치는 옛 기준일 수 있으니 현재 기준 브랜치에서 다시 찾는다.
- **위임 승인 전 확인.** "위험하지 않은 것 승인해줘"로 위임받아도 (1) 사용자가 그 건을 직접 미뤘는지, (2) 확인 기록이 실제 화면·API 확인인지(SHA 일치만으론 아님)를 본 뒤에만 승인한다(2026-09-23).
- **드문 운영 작업에 과잉 안전 금지.** 사용자가 직접 승인하고 다른 작업이 없을 때만 돌리는 작업의 동시성 경계는 "받아들인 위험"으로 기록하고 진행한다. 실제로 막히는 결함만 고친다(2026-09-23).
- **설계는 단순하게.** 결정 항목·승인자 칸·점검 절차·새 표·전용 연결을 늘리지 않는다. 기존 것을 재사용하고, 검수 지적은 가장 작은 수정으로 닫는다(2026-09-30 "심플하게, 너무 복잡하게 하지 마").
- **사용자에게 쓰는 말.**
  - 바뀌는 동작은 As-is(지금) / To-be(바뀐 뒤)를 나란히 쓴다. 기존 동작을 좁히는 변경은 특히 분명히 한다(2026-09-27).
  - 결정 ID·SHA·PR 번호만 단독으로 쓰지 않는다. 기능 이름을 먼저, 번호는 괄호 보조로(2026-09-27 "커밋 넘버만 쓰면 내가 어케 알어").
  - 자동화 구조를 설명할 때는 층마다 `(스크립트, 토큰 0)` / `(AI, 모델명)`을 붙인다(2026-07-27).
  - 결정 문안의 요청 제목과 실제 범위가 다르면 "이 PR이 맡은 부분 / 남은 부분"을 한 줄 넣는다.
- **정확도 측정의 독립성.** 규칙 커밋 → 라벨 커밋 → 측정 순서로 하고, 규칙 입력은 원문 그대로, 라벨 작업자는 규칙·이전 결과를 보지 않으며, 측정 뒤에는 둘 다 고치지 않는다(2026-10-30 사람이 손본 입력으로 놓침 0/50이 나왔지만 원문으로는 2/54).
