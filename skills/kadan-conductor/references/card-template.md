# 카드 템플릿 — 작업 카드와 검수 카드

## Why

감독이 작업마다 목표·범위·완료 조건만 구체화하고, 작업자와 검수자는 같은 공통 계약으로 실행하게 한다.

## 작성 방법

아래 해당 양식만 복사해 실제 값을 채운다. 공통 계약 전문은 복사하지 않고 **이 파일의 확인한 절대경로와 적용 절**을 카드에 적는다. 참조한 계약은 필수이며 자동 역할 지침의 첨부 여부와 무관하게 직접 읽고 적용한다. 참조를 열 수 없으면 누락한 계약을 추측해 시작하지 않는다.

- 신규 실행은 [중앙 카드 절차](central-cards.md)로 등록한다. 등록 후 원본은 `KADAN_HOME/cards/<저장소>/<실행ID>/card.md`, ID·revision·결과 경로는 현재 `card show`가 기준이다.
- 저장소 지침은 실제 존재하는 `AGENTS.md` 또는 `CLAUDE.md` 하나를 확인해 절대경로로 적는다. worktree에 자동 적용될 것으로 가정하지 않는다.
- 카드에는 범위·승인 근거·시한·합격 기준·직속 감독·전달 방식을 실제 값으로 적는다. 공통 계약에 없는 작업 고유의 금지·필수 순서·검증도 적는다. 기존 카드의 별도 계약과 결과 경로는 보존한다.
- 같은 업무의 후속은 원본 기준과 직전 발견을 참조한다. 진행 중 실행에는 추가 입력, 이미 끝난 실행 뒤에는 새 실행 ID를 사용한다. 기존 DONE·등록 결과를 덮어쓰지 않고 긴 원본 주문서를 다시 만들지 않는다.
- 자동 전달의 원본 두 카드는 한 번 작성한다. 프로그램이 만드는 실행 카드의 현재 ID·결과 경로·통지 방식이 원본의 옛 실행값을 대신한다. 범위·합격 기준은 그대로다. [자동 전달 안내](../../../docs/automatic-review.md)를 따른다.

## 작업 카드

```markdown
# card-<id> — <제목>

## Why
<누가 무엇이 불편하고, 어떤 결과로 해결하는가>

## 읽고 시작할 것
- <확인한 저장소 지침 절대경로>
- <이 card-template.md의 절대경로> — 실행 공통 계약·작업자 계약
- <이번 일에 필요한 원본 기준·직전 결과·스킬 경로만>

## 범위
- 작업공간·브랜치·소유 파일 또는 데이터: <값>
- 승인 근거·대상 환경·허용 행동: <값>
- 재사용할 것·하지 않을 일·고유 금지/필수 순서: <값>
- 무게: <LIGHT | HEAVY와 이유>; 시간 상한: <승인된 값>

## 합격 기준
- <정상 경로와 가장 위험한 엣지; HEAVY면 회귀 추가>
- <사용자가 보는 결과의 실제 확인 방법·대표 사례>

## 결과와 완료 통지 수신자
- 결과·근거: 현재 실행 card show의 resultPath·evidenceDir. <기존 지정 경로면 그 값>
- 직속 감독: <역할>; 전달 방식: <수동 | 자동, 자동이면 업무키>
- 현재 실행 ID로 공통 계약의 결과 등록·통지·DONE을 수행한다.
```

## 검수 카드

```markdown
# card-<id>-review — <대상> 검수

## Why
<어떤 결과가 합격 기준을 충족했는지 독립 확인한다>

## 읽고 시작할 것
- <확인한 저장소 지침 절대경로>
- <이 card-template.md의 절대경로> — 실행 공통 계약·검수 공통 계약

## 대상과 범위
- 원본 작업 카드·최신 판단·결과 경로: <값>
- 고정할 commit SHA 또는 변경 지문·작업공간·대상 파일: <값>
- 검수 범위: <첫 검수 전체 | 수정 지점·인접 회귀·발견 재현>
- 승인된 검증 환경·허용 행동·고유 금지/필수 순서: <값>
- 시간 상한: <승인된 값>

## 합격 기준
- 치명·중요 0건과 원본 작업 카드의 명시 합격 기준. <추가 기준·실물 재현 방법이 있으면 값>

## 결과와 완료 통지 수신자
- 결과·근거: 현재 검수 실행 card show의 resultPath·evidenceDir. <기존 지정 경로면 그 값>
- 직속 감독: <역할>; 전달 방식: <수동 | 자동, 자동이면 업무키>
- 검수 대상은 수정하지 않는다. 현재 실행 ID로 공통 계약의 결과 등록·통지·DONE을 수행한다.
```

## 실행 공통 계약

이 절과 자기 역할의 계약을 읽고, 현재 실행의 최신 카드·승인·저장소 지침을 확인한 뒤 시작한다. 감독용 SKILL 전체를 읽지 않는다. 승인·부분 보류·복구·기록은 [운영 공통 기준](operating-contract.md)의 해당 절을 따른다.

- 실제 착수 시 최신 revision으로 한 번 기록한다: `kadan card progress <현재실행키> --revision <최신값> --activity running --note "시작: <현재 작업>"`. 이미 현재 실행의 running 기록이 있으면 중복하지 않는다. 외부 결과 대기 등 상태 전환도 1회 기록하며 정상 ACK 편지는 보내지 않는다.
- 검색은 `rg`가 기본이다. `grep -r`·`find`는 `rg`가 안 될 때만 쓴다. 무시·숨김 경로가 관련된 "없다" 판정은 `--no-ignore`·`--hidden`으로 재확인한다. 독립 조회를 묶고 출력은 필요한 줄로 제한한다.
- 사용자 요구 밖 조건을 붙이지 않고 기존 기능을 최소로 재사용한다. 동일 방식·승인·소유의 반복은 같은 실행에서 이어가며 결과에 항목별 성공·실패·미착수·재개 위치를 남긴다.
- 승인 안의 수정은 이어간다. 범위 밖 행동·명시 시간 상한 연장은 직속 감독에게 판단을 요청한다. 질문에 종속된 부분만 멈추고 영향 없는 승인 작업은 계속한다.
- 원인 불명의 실패를 재시도하지 않는다. 실패·미확인·영향을 결과에 남기고 해당 항목만 보류한다. 새 근거에 따른 복구 확인은 직속 감독이 정한 범위·횟수·중단 조건을 따른다. 분리 불가면 전체 중지 근거를 남긴다.
- 운영 영향(운영 기능 차단·데이터 손상 등)은 코드 판단만으로 확정하지 않는다. 카드에 허용된 읽기 전용 운영 데이터(집계 등)로 교차 확인하고, 확인하지 못하면 "코드상 가능성·운영 미확인"으로 보고한다. 이유: 2026-09-24 코드만 보고 "운영 가입 막힘(확신도 높음)"이라 보고했다가 운영 집계와 어긋났다.
- 비밀값은 화면·로그에 출력하지 않고 승인된 파일에서 변수로 읽는다. 비밀 파일에 cat/echo/head/grep 또는 set -x를 사용하지 않는다. 노출되면 사실만 보고하며 삭제·변경은 사용자 결정이다. 사용자가 수용한 동일 노출은 카드의 수용 근거를 확인하고 매 검수에서 다시 중요 결함으로 올리지 않는다.
- 범위 밖 파일·다른 역할 변경을 건드리지 않는다. 삭제는 `.trash/` 이동이며 실제 삭제는 하지 않는다. main 합류·운영 배포는 사용자 승인, 그 외 push·프리뷰·DB 쓰기도 카드에 명시된 허용 범위에서만 한다.
- `git stash`를 쓰지 않는다. 변경을 잠시 치워야 하면 자기 브랜치에 작업 중 커밋을 만든다. 이유: stash 목록은 같은 저장소의 모든 worktree가 함께 써서, 2026-09-24 병렬 작업 중 두 작업자의 변경이 뒤바뀌었다.
- 결과·검증 자료는 현재 실행의 `resultPath`·`evidenceDir`에 쓰고 기존 지정 경로는 유지한다. 등록한 결과와 이전 실행 결과를 덮어쓰지 않는다. 같은 진행을 데일리·편지에 복제하지 않는다.

### 결과 등록과 완료

| 방식 | 순서 |
|---|---|
| 수동 | 결과 파일 완성 → 새 실행은 `kadan card report <현재실행키> --revision <최신값> --outcome <판정>` → 직속 감독에게 완료 통지 1회 → 자기 화면 DONE |
| 자동 | 결과 파일 완성 → `kadan work auto-report <업무키> --execution <현재실행키> --outcome <판정>` → 자기 화면 DONE. 별도 card report·수동 완료 편지는 보내지 않는다. |

구현 판정은 `implemented`, 검수는 `pass|changes`, 실행 장애·판정 불명확·범위 밖 수정 요구는 `exception`이다. 실행 종료 `ok|failed`와 품질 판정은 별개다. 절차를 어겼으면 기능이 동작해도 실행은 failed이며, 검수를 정상 수행한 불합격은 실행 ok와 품질 changes로 구분한다.

수동 완료 편지는 자기 역할 명의로 `KADAN_ROLE=<자기역할> kadan send <직속감독> --execution <현재실행키> "완료 통지: <자기역할> / <현재실행ID> / <ok 또는 failed> / 결과: <절대경로>"`를 한 번 보낸다. `--task`와 완성된 DONE 마커는 넣지 않는다. 발송 실패는 카드 메모에 남기고 반복 재전송하지 않는다.

마지막에 결과 경로 한 줄과 `KADAN:DONE <현재실행ID> <ok 또는 failed>` 형식을 조립해 자기 화면에 출력하고 응답을 끝낸다. 발령 지문에 완성된 마커를 적지 않는다. 필수 판정·근거를 갖춘 뒤 사소한 문장 다듬기로 완료를 늦추지 않는다. 작업자·검수자는 `kadan done`을 실행하지 않는다. 수동 원장 확정은 감독, 자동 경로는 프로그램이 맡는다. 경합·통지 실패는 [발령과 대기](dispatch-wait.md#완료-편지와-입력-대기--기본-경로)를 따른다.

## 작업자 계약

- 카드의 소유 범위만 수정한다. 완료 시 자기 브랜치에 카드 단위로 커밋하고 메시지에 카드 ID를 적는다. 자기 변경 파일만 담는다.
- 작업 중에는 관련 focused 테스트, 종료 시 필요한 전체 테스트·타입 검사·빌드를 각 1회 수행한다. 새 변경·실패·미해결 의문 없이 반복하지 않는다.
- 사용자 눈에 보이는 작업은 실제 API/CLI 응답·브라우저·GUI 조작 등 카드에 정한 실물 증거를 남긴다. 코드 추적·단위 테스트만으로 이를 대체하지 않는다.
- 결과에는 변경 파일:줄, 검증 결과 원문, 막힌 것·미완료·범위 밖 발견을 적는다. 검증 근거는 다음 5항목을 보존한다: **SHA 또는 변경 지문 / 환경·설정 / 명령·선택 범위 / 성공·실패 수와 종료 코드 / 검증 후 관련 파일 불변 여부**.
- 허용 범위·시간 안의 가능한 작업을 마친 뒤 카드 기준을 충족하지 못하면 실행 failed로 마친다. 보고·통지·마커는 생략하지 않는다.

## 검수 공통 계약

- 검수 대상 파일은 수정하지 않는다. 작업자 보고만 믿지 않고 코드·시험·실물로 독립 확인한다. 서브에이전트를 쓰면 이 읽기 전용·수정 금지 계약을 그 프롬프트에도 직접 전달한다.
- 첫 검수는 전체 범위, 재검수는 수정 지점·인접 회귀·발견 재현을 본다. 재설계급 수정이나 치명 발견 뒤에는 전체 범위를 다시 본다. 요구된 실물 증거는 직접 재현한다.
- 작업자 결과의 검증 근거 5항목이 현재와 모두 같으면 전체 테스트를 반복하지 않고 위험 구간의 focused 검증·원문 대조를 한다. 하나라도 다르거나 기존 실행이 0개 선택·timeout·부분 실행·환경 오류였거나 focused 결과가 충돌하면 전체를 다시 돌리고 이유를 남긴다.
- 결과는 판정(합격/불합격), 심각도별 발견(치명/중요/사소·파일:줄·재현 방법), 실행과 결과 원문, 재사용 판정과 이유, 걸린 시간을 적는다. 검수 대상 작업공간에는 근거 파일도 만들지 않는다. 현재 검수의 결과·근거 경로에만 쓰고 낯선 기존 파일은 지우지 않고 범위 밖 산출물로 보고한다.

## 감독이 카드를 받은 뒤

결과의 실제 검증 범위와 재사용 근거를 확인한다. 빠르게 끝났다는 이유로 재검수를 추가하지 않고 누락만 보완한다. 수정은 검수자에게 시키지 않고 같은 업무의 작업자에게 발견 원문과 기준 참조를 전달한다.

수동 경로는 현재 세대의 결과·발신자 자기 화면 DONE을 대조해 그 자리에서 `kadan done`으로 확정한다. 자동 경로는 프로그램의 확정을 중복하지 않는다. 종료하려고 근거 없는 done을 만들지 않는다. 남은 담당 일과 [종료·정리](cleanup.md)를 확인한 뒤 정확한 소유 역할만 stop한다.

## 근거 폴더와 작업 공간

`evidenceDir`에는 결과를 재확인할 명령·작은 로그·스크린샷 등 검증 자료만 둔다. Git 체크아웃·worktree·`node_modules`·빌드 캐시는 대상 저장소의 작업 공간에 두고, 근거에는 경로·커밋·검증 명령을 적는다. 기존 카드의 자료는 자동으로 이동·삭제하지 않는다.
