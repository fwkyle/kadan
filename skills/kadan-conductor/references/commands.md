# 사용자의 말 → kadan 명령

## Why

필요한 명령과 기준 원본을 바로 찾고 카드·완료 규칙을 이 표에서 다시 정의하지 않는다.

`kadan`은 설치된 명령이다. PATH에 없으면 설치로 환경을 바꾸지 않고 `node <저장소>/src/cli.mjs`로 치환한다.

| 요청 | 실행 경로 |
|---|---|
| 작은 수정해 줘 | 직접 수정·필요 검증·결과 보고. 카드·역할 없음 |
| 카드 만들어 | [카드 양식](card-template.md)에 작업 고유 값 작성 → [중앙 등록](central-cards.md) |
| 역할 / 판 / 업무 보여줘 | `kadan status` / `kadan tree` / `kadan work show <업무키>` |
| 관제 화면 열어줘 | `kadan wall` |
| 작업 내용 봐줘 | `kadan read <역할> --lines 30` 이상. 상태 판정은 원장 사용 |
| 원장 보여줘 | `kadan log` |
| 새 작업자 띄워 | `kadan start <판>-작업자 --profile worker` (설정과 다른 명령은 `--cmd … --reason …`) |
| 카드 보내 | 중앙 배정·plan 후 `kadan send <역할> --task <현재실행키> "<카드 경로와 지시>"` |
| 반복 구현·검수 이어줘 | [자동 전달 설정](../../../docs/automatic-review.md). 명시 설정한 업무만 auto-run |
| 수동 검수 붙여 | 원본 기준을 참조하는 검수 실행·독립 reviewer 역할 → send → 응답 종료 |
| 수정 다시 시켜 | 같은 업무의 기준과 발견 원문 참조. 진행 중 실행은 추가 입력, 완료 뒤는 새 실행 ID |
| 끝날 때까지 봐 | 완료 통지 경로 확보 후 응답 종료. `kadan wait`는 한정 진단·복구용 |
| 창에서 직접 볼게 | `kadan attach <역할>` |
| 로티 재시작 뒤 탭 되살려 | `kadan restore --dry-run`으로 대상 확인 → `kadan restore [역할...]`. 기록된 로티 탭이 죽은 살아 있는 세션에만 새 탭을 붙인다 |
| 역할 멈춰 | 완료 근거·남은 책임 확인 후 `kadan stop <정확한 소유 역할>` |
| 죽은 역할 다시 세워 | [복구 절차](worker-creation.md). 기존 역할 확인·정리 후 새 이름으로 시작 |
| 결정이 필요해 | 직속 감독이 승인 안 판단. 사용자 판단은 [중앙 결정 경로](central-cards.md#사용자-결정-요청-전용-경로) |
| 병렬 충돌을 막아 | 구체적 충돌 사유와 승인 범위 확인 후 필요한 worktree만 생성 |

## 카드와 마커

카드·결과 위치와 채울 항목은 [카드 템플릿](card-template.md) 한 곳을 따른다. ID·revision·결과 경로는 현재 `card show`로 확인한다. 옛 파일명·`.staging` 경로를 새 카드의 기본값으로 추측하지 않는다. 기존 카드가 지정한 경로는 유지한다.

발령에는 카드 절대경로, 읽고 시작할 것, 마커 형식 `KADAN:DONE <현재실행ID> <ok 또는 failed>`만 안내한다. 실제 값으로 조립한 완성 마커는 보내지 않는다. 종료 때 필수 판정·근거를 갖춘 역할이 자기 화면에 출력한다.

새 역할은 [프로필 명령](worker-creation.md#새-역할의-프로필), 주소와 DONE 연결은 [카드 주소 규칙](../../../docs/task-identity.md), 통지·대기·실패는 [발령과 대기](dispatch-wait.md)를 따른다. 기존 세션을 새 프로필 때문에 재시작하지 않는다.
