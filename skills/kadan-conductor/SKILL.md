# Kadan Conductor — 지휘 하네스

## Why

여러 AI 코딩 도구를 병렬로 돌리되, 사용자의 안전 원칙(main 보호, 승인 없는 삭제 금지,
검수 뒤 합류)을 지키는 옛 Orca 지휘 절차를 카단 위에서
그대로 쓴다. 카단 라이트는 엔진이 아니다. 카드 상태는 카드 파일과 결과 파일로,
전달·완료 증거는 append-only 원장과 DONE 마커로 확인한다.

먼저 [가벼운 실행이 기본](references/operating-contract.md#가벼운-실행이-기본-2026-09-10-사용자-정정)으로 직접 처리와 위임을 고른다. 아래 카드·발령 절차는 실제로 위임할 때만 적용한다.

카드 작성·발령·현황 확인 전에는 [중앙 카드 절차](references/central-cards.md)를 읽는다. 카드 본문과 최신 승인/판단 기록을 함께 사용한다.

작업자·검수자는 새 작업마다 새 세션을 세우고, 같은 대상의 연속 작업에만 재사용한다. 결과·DONE을 확정한 뒤 남은 담당 일이 없으면 판 종료를 기다리지 않고 종료한다. 유지 예외와 판 종료 순서는 [종료·정리 기준](references/cleanup.md)을 따른다.

자동 리마인더 원본은 [공통](references/role-templates/common.md)과 [일반감독](references/role-templates/conductor.md) 템플릿이다.
역할 지침은 책임을 상기시키며 새 발령·승인이나 카드의 범위·시작·검증·완료 계약을 대신하지 않는다.
메시지 본문과 안내된 최신 카드·판단을 읽고, 스킬은 이번 행동에 필요한 상세 절만 다시 읽는다.
설정과 첨부 방식은 [역할별 지침](../../docs/role-instructions.md)을 따른다.

일반감독은 승인 범위 안의 방법 선택·읽기 진단·장애 복구를 직접 결정한다. 같은 유형은
공통 기준으로 이어가고, 근거를 대조해도 못 푸는 문제나 범위 밖 조치만 슈퍼에게 묻는다.
구체적인 위임과 기존 방법 제한의 정정은 [일반감독의 결정 범위](references/operating-contract.md#일반감독의-결정-범위)를 따른다.

## 진행·승인 기준

[진행·승인 공통 기준](references/operating-contract.md)의 단순화 규칙을 카드 구체화·발령·분리·막힘 판단 전에 적용한다.
승인된 일은 끝까지 연결하고, 정확히 막힌 부분만 보류하며 권한 밖 조치만 사용자에게 묻는다.
기록 위치·일지 중복은 [기록 원본과 일지](references/operating-contract.md#기록-원본과-일지), 편지 발송은 [진행 기록과 상위 통지](references/operating-contract.md#진행-기록과-상위-통지)를 따른다.
카드에 정상 진행의 추가 편지를 요구하지 않고, 완료·필수 질문·실제 다음 작업 인계를 연결한다.

## 판 상태는 원장으로 판단한다 — 화면을 긁지 마라 (2026-09-12 사용자 지시)

원장(대시보드)이 사람과 에이전트의 **공통 장부**다. 역할이 일하는 중인지, 끝났는지, 확정됐는지는
`kadan tree` **한 번**으로 다 나온다. 다른 방법으로 추측하지 마라.

- `liveRoles` — 역할별 생존과 PID 일치.
- `pendingCards[].state` — `unconfirmed` 는 발령됐고 아직 확정되지 않은 것, `waiting` 은 대기.

**`kadan read` 로 상태를 판정하지 마라.** 화면 하단은 일하는 중이든 끝났든 똑같이 프롬프트만 보인다.
실제로 6줄만 읽고 "셋 다 놀고 있다"고 잘못 보고한 사고가 있었다(2026-09-12). `read` 는 *무엇을* 하고
있는지 눈으로 볼 때만 쓰고, 쓸 때는 30줄 이상 읽는다. 정상 대기 중에 반복 호출하지 않는다.

**완료 통지를 받으면 최신 실행·현재 세대의 결과와 발신자 자기 화면 DONE을 대조하고,
`stop`보다 먼저 `kadan done <역할> <카드id> <ok|failed>`로 확정한다. 이미 done이면 중복하지 않는다.**
확정하지 않고 세션을 닫으면 원장에 끝난 기록이 남지 않아 사람도 에이전트도 상태를 잃는다.
실제로 확정 없이 두 역할을 닫아 나중에 소급 기록한 사고가 있었다(2026-09-12). `stop` 이 경고를 띄우니
그 경고를 넘기지 마라. done 의 ok 는 "끝났다"는 뜻이고 품질 합격은 검수 결과로 따로 판단한다.

**카드에는 반드시 `완료 통지 수신자` 절이 있어야 하고, 작업자에게 `kadan done` 을 시키지 마라.**
`kadan done` 은 원장에만 적히고 감독 화면에는 아무것도 오지 않는다. 수동 경로의 완료 통지는 작업자가
`kadan send <감독> "완료 통지: <역할> / <카드id> / <ok|failed> / 결과: <경로>"`로 한 번 보낸다.
명시된 자동 경로는 아래 자동 전달 계약을 따르며 수동 편지를 중복하지 않는다.
실제로 감독이 카드 넷에서 이 절을 빼고 "끝나면 kadan done 을 실행하라"고 적어, 세 역할이 끝났는데
감독이 40분 동안 모르고 검수도 안 붙은 사고가 있었다(2026-09-12). 완료 통지는 작업자가 보내고 확정(`done`)은 감독이 한다.

## 안전 규칙 — 항상 적용

1. **보호 대상은 main뿐이다 (2026-09-12 사용자 결정 — 07-24의 "작업자 커밋 금지·지휘자 체크포인트 커밋"을 대체).**
   작업자는 자기 워크트리·자기 브랜치에 카드 단위로 커밋한다(메시지에 카드 id, 자기 소유 파일만 담는다).
   기능 브랜치 push와 draft PR 생성도 카드가 허용한 범위 안에서 한다. 감독은 검수 합격 뒤 통합 브랜치 합류와
   프리뷰 배포를 맡는다. **main 합류(머지)와 운영 배포만 사용자의 현재 시점 승인이 필요하다.**
2. worktree 삭제·병합은 해당 대상·행동에 대한 사용자 승인 범위 안에서만 한다. 기존 승인을 확인하며 범위 밖이면 묻는다.
3. 작업 카드·검수 카드는 `references/card-template.md`를 복사해 `<…>` 칸만 채운다.
   계약 문장(단순화·금지·실물 증거·검증 증거 5항목·재사용 판정·근거 파일 장소·서브에이전트
   전파)은 템플릿에 있으니 지우지 않는다. 작업자는 현재 실행·최신 카드를 읽고 안내된 카드·운영계약·발령 참조의 필요한 절을 확인한다.
   작업자·검수자에게 감독 전용 SKILL 전체를 적용하지 않는다.
4. 실행기는 `$KADAN_HOME/agent-runners.json`(예시: `skills/kadan-conductor/references/agent-runners.example.json`)에서 사람이 고른다. 기본은
   codex이고, **어떤 모델·강도로 띄울지는 그 파일의 `_기본모델` 블록**이다 (사용자가 적어 둔 값).
   쿼터·429처럼 **원인이 확인된 막힘**이면 같은 파일의 `_폴백순서`를 한 칸만 내려간다
   (2026-09-06). 자동 전환 코드는 없다 — 사람이 고르고 이유를 카드에 적는다.
   거기 없으면 짧게 묻는다. CLI별 어댑터는 만들지 않는다(`docs/design.md` 정체성·다시 만들지 않기). 라우터·실행기 자동 교체는
   금지가 아니라 **아직 없는 것**이다. 429 같은 사고가 반복되면 그때 사용자와 가장 작은
   형태를 정한다 (2026-09-02 사용자 정정: 08-30 초판이 어댑터 금지를 라우터 금지로 넓혀 적었다).
   역할별 모델·강도는 같은 파일의 `_역할별기본`(기본 프리셋 B)을 읽고, 작업자≠검수자 계열은 `_계열`의 고정 제약이다.
5. 검수자는 결과만 보고한다. 수정은 같은 업무의 기존 작업자에게 잇는다. 자동 설정 업무는 프로그램이 다음 실행을 연결하고, 수동 경로도 범위가 같은 원본 주문서를 다시 만들지 않는다.
6. 감독은 직접 구현·원인 탐색을 하지 않는다. 대상 파일 몇 개를 읽는 단순 대조만
   직접 하고, 원인을 모르는 탐색·실측·코드 변경은 카드로 작업자에게 보낸다.
7. 다른 판과 역할을 건드리지 않는다. 역할 이름에 판 접두사를 붙이고, 이번 판에서
   만든 정확한 역할만 `kadan stop`으로 종료한다.

## 진행 조정

감시의 진행 조정/판단 불가 알림 또는 장시간 작업 보고를 받으면
[한 라운드 안의 진행 조정](references/tiki-taka.md#한-라운드-안의-진행-조정-2026-09-07-사용자-결정)을 따른다.
일반감독이 진전·병목·조치·다음 확인 조건을 카드에 남기고, 권한 안에서는 조정한다.
DB·복잡한 검수도 진전이 있으면 유지한다. 결정 불가·판 간 충돌·승인 범위 문제는 슈퍼에게 묻는다.

## 명시 설정한 업무의 자동 전달

감독이 `work auto-configure`로 설정한 업무에서는 [자동 전달 계약](references/dispatch-wait.md#구현검수-자동-전달--명시-설정한-업무만)을 적용한다.
정상 중간 완료는 결과 파일 + `work auto-report` + 현재 실행 DONE으로 전달하고,
프로그램이 검수·수정을 잇는다. 같은 블록의 두 세션을 유지하며 다음 블록은 둘 다 교대한다.
PASS·예외·3라운드 경계만 감독에게 1회 통지한다. 최종 업무 완료·커밋·배포는 감독 판단이다.
아래 수동 완료 편지는 미설정 업무에만 적용한다. 자동 경로에 추가하지 않는다.
자동 경로도 원본 카드의 필수 검증·근거·범위를 그대로 따른다.

자신이 owner인 업무는 전체 완료조건과 근거가 충족되면 `work complete`로 마감한다.
남은 일이 있으면 다음 행동·담당(turn owner)·대기 대상과 깨움 경로를 연결한다.
완료후보·보고 수신이나 실행 done만으로 업무 전체를 완료하거나 역할을 stop하지 않는다.

## 완료 보고 3종 — 터미널은 보고가 아니다 (2026-08-10 실사고)

수동 전달 작업·검수 카드는 결과 파일을 완성한 뒤 직속 감독에게 완료 편지를 한 번 보내고 다음 셋을 남긴다.

```text
1. 결과 전문을 카드가 지정한 결과 파일에 쓴다.
2. 마지막 줄에 형식 KADAN:DONE <카드id> <ok 또는 failed>를 출력한다.
3. 터미널에는 결과 파일 경로를 포함한 한 줄 요약만 남긴다.
```

완성된 마커 문자열을 지문에 쓰지 않는다. 형식과 카드 id만 주고 에이전트가 조립하게
한다. 터미널 스피너나 조용한 화면은 완료 증거가 아니다.

**기본 대기는 응답 종료 후 CLI 편지 수신이다.** 발령의 CLI 전달 결과를 확인한 뒤 AI 대기 루프를 만들지 않는다.
GitHub 배포 등 완료 편지가 없는 외부 실행에는 `references/dispatch-wait.md`의 일회성
대기·통지 프로그램을 먼저 붙인다. 프로그램의 wait는 허용하며 AI의 반복 대기와 구분한다.
완료 편지 또는 watch 완료후보를 받은 감독이 결과·마커·기존 완료/후속 발령을 확인한 뒤
`kadan done`으로 기록한다. 중복 처리와 마커 도착 경합은 `references/dispatch-wait.md`를 따른다.

## 에이전트 실행기는 conductor 스킬을 참조한다

실행법·필수 플래그·검증법은 `$KADAN_HOME/agent-runners.json`(예시: `skills/kadan-conductor/references/agent-runners.example.json`)이 원본이다.
여기에 복제하지 않는다. 긴 지시는 파일에 쓰고 `kadan send`에는 경로 한 줄만 보낸다.

## 진입 판단 루프

0. `git worktree list --porcelain`, 저장소 루트, 현재 브랜치를 확인한다.
1. `kadan status`, `kadan log`, 오늘의 카드 파일 목록을 확인한다. 다른 판의 역할과
   카드는 읽기만 하고 건드리지 않는다.
2. 위임이 필요한 요청만 기존 업무의 실행으로 구체화하고, 묶음·분리는 공통 기준으로 판단한다. 각 파일명은
   `docs/daily/<날짜>/card-<id>.md`이고 파일명이 카드 id다. 해석이 실제로 갈리면 기존 질문 경로를 따른다.
3. 방향이 갈리면 `references/tiki-taka.md`의 배틀 오프닝, 대량 작업이면
   `references/standard-flow.md`로 반복 연속 처리와 독립 병렬을 구분한다.
4. 카드가 생긴 뒤에만 `references/worker-creation.md`와
   `references/dispatch-wait.md` 순서로 발령한다. 카드 0장 상태의 발령은 없다.

## 컨텍스트 절약 3칙

1. 스킬 전체는 첫 정독 1회, 이후에는 필요한 절만 다시 읽는다.
2. 감독이 화면을 보는 경우는 (a) 발령 전 `kadan read` 하단 30줄로 TUI·훅·신뢰 창
   확인, (b) 완료 편지·watch 이상에 필요한 확인, (c) 보고 유실 복구뿐이다.
   사람이 직접 볼 때는 `kadan attach`를 쓴다.
3. 입력 대기 중에는 조회하지 않는다. 메시지가 오면 필요한 원장·카드·결과만 읽는다.

## 흐름 지도

```text
사용자 요청
  → 작은 직접 작업: 수정 → 필요한 검증 → 결과 1회 (아래 발령 절차 없음)
  → 위임할 작업: 진입 판단
  → 카드 파일 구체화 (반복은 한 카드, 이유가 있을 때만 분리)
  → start
  → 창 또는 `kadan read`로 TUI·훅·신뢰 확인
  → send
  → 응답 종료·완료 편지 수신
  → 결과 파일 확인
  → 새 검수 역할에 가재 계약 send
  → 응답 종료·완료 편지 수신
  → 치명·중요 0 + 실물 검증
  → 감독이 통합 브랜치에 합류 (작업자 커밋은 이미 브랜치에 있다)
  → 승인된 환경 적용·실물 확인 (새 권한이 필요하면 사용자 결정 관문)
  → kadan done으로 원장 확정
  → 보고와 정확한 역할 stop
```

핵심 원칙 세 줄:

- 카드 설계가 품질 상한선이다.
- 확인한 결과 파일·DONE·원장이 증거다. 스피너는 증거가 아니다.
- 파일 충돌은 부탁이 아니라 필요한 경우의 worktree 격리로 막는다.
