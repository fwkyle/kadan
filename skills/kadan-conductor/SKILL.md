# Kadan Conductor — 지휘 하네스

## Why

여러 AI CLI의 구현·독립검수를 연결하고, 사용자가 다음 담당과 완료 근거를 확인할 수 있게 한다. 정상 왕복의 카드 작성·중계는 최소화한다.

## 먼저 경로를 고른다

| 작업 | 경로 | 감독이 할 일 |
|---|---|---|
| 작고 명확한 직접 수정 | 현재 대화에서 수정 → 필요한 검증 → 결과 1회 | 카드·역할을 만들지 않는다. |
| 반복 구현·독립검수가 필요한 신규 업무 | 기존 `work auto-configure` / `auto-run`을 우선 검토 | 목표·기준·담당·시한을 한 번 정하고 PASS·예외·블록 경계에서 판단한다. |
| 기존 수동 업무, 자동 전달이 지원하지 않는 환경·계약 | 수동 전달 | 완료 근거를 확인하고 같은 업무 안에서 검수·수정을 연결한다. |

자동 전달은 명시 설정한 업무에만 작동한다. 설정하지 않은 일을 자동이라고 보고하거나 진행 중 업무를 임의 전환하지 않는다. 구체적인 선택 기준은 [가벼운 실행이 기본](references/operating-contract.md#가벼운-실행이-기본-2026-09-10-사용자-정정), 자동 설정은 [자동 전달 안내](../../docs/automatic-review.md)를 따른다.

## 업무와 카드는 한 번 구체화한다

- 위임할 결과 중심 작업은 업무 한 장에 목표·전체 대상·완료 조건·책임 감독을 둔다. 구현·검수·수정은 그 업무의 실행으로 연결한다.
- [카드 템플릿](references/card-template.md)의 해당 양식에 이번 작업의 값만 채운다. 공통 계약은 그 파일을 절대경로로 참조하고, 카드마다 전문을 복사하지 않는다. 범위·승인·시한·합격 기준·완료 수신자와 전달 방식은 실제 값으로 적는다.
- 중앙 등록·배정과 최신 판단은 [중앙 카드 절차](references/central-cards.md)를 따른다. 등록 뒤 원본은 중앙 카드이며 새 결과·근거도 `card show`가 안내한 위치에 둔다. 기존 지정 경로와 과거 기록은 보존한다.
- 같은 범위의 수정은 기존 업무·원본 기준에 발견 원문과 후속 판단을 연결한다. 아직 진행 중인 실행에는 추가 입력으로 잇는다. 끝난 실행 뒤 수정·재검수는 새 실행 ID를 쓰되 목표·공통 계약을 다시 작성하지 않는다. 이전 DONE·등록 결과를 덮어쓰지 않는다.
- 미래 아이디어를 미리 실행 카드로 만들지 않는다. 묶음·분리는 [단순화 규칙](references/operating-contract.md#단순화-규칙)을 따른다.

## 역할과 발령

1. 작업공간·브랜치·기존 업무와 담당을 확인한다. 상태는 `kadan tree` 등 필요한 원장 조회로 한 번 확인하고 다른 판은 건드리지 않는다.
2. 실행기는 `$KADAN_HOME/agent-runners.json`에서 고른다. 기본 모델·강도는 `_기본모델`, 역할별 값은 `_역할별기본`, 작업자≠검수자 계열은 `_계열`을 따른다. 실행 명령을 스킬에 복제하지 않는다. 값이 없으면 묻는다.
3. 새 작업은 새 세션으로 시작한다. 같은 대상의 수정·재검수처럼 직전 맥락이 필요한 연속 작업만 재사용한다. 자동 전달은 같은 3라운드 블록의 두 세션을 유지하고 다음 블록에는 둘 다 교대한다.
4. [역할 생성](references/worker-creation.md) → [발령과 대기](references/dispatch-wait.md) 순으로 진행한다. 새 세션의 TUI·훅·신뢰 창을 확인하고, 중앙 배정과 plan을 기록한 뒤 발령한다. 카드 없는 위임은 하지 않는다.
5. 전달 성공을 같은 목적의 read/status/log로 재확인하지 않는다. 독립적인 승인 작업을 이어가고 완료·질문 통지를 기다릴 때는 응답을 끝낸다. AI 폴링을 만들지 않는다.

쿼터·429처럼 원인이 확인된 실행기 막힘은 같은 설정의 `_폴백순서`에서 한 칸만 내려가고 이유를 카드에 남긴다. 이는 감독의 선택이며 실행기 자동 교체 기능이 아니다.

## 구현·검수와 종료

왕복 단위·LIGHT/HEAVY·상한은 [티키타카](references/tiki-taka.md)가 원본이다. 1라운드는 구현 또는 수정 + 독립검수이며, 품질 `pass|changes`와 실행 종료 `ok|failed`를 구분한다.

| 전달 방식 | 중간 실행 종료 | 다음 실행 연결 |
|---|---|---|
| 자동 | 결과 파일 → `work auto-report` → 현재 실행 DONE | 프로그램이 마커·결과를 확인해 done을 기록하고 검수·수정을 연결한다. 수동 편지를 중복하지 않는다. |
| 수동 | 결과 파일 → 새 카드는 `card report` → 직속 감독에게 완료 편지 1회 → 현재 실행 DONE | 감독이 결과·현재 세대·발신자 자기 화면 DONE을 확인해 `kadan done`으로 확정하고 다음 실행을 연결한다. |

완료 명령과 마커 경합·통지 실패 처리는 [완료 편지와 입력 대기](references/dispatch-wait.md#완료-편지와-입력-대기--기본-경로)를 따른다. 이미 done이면 중복하지 않으며, done이 있다는 이유로 빠진 검수를 건너뛰지 않는다.

- 합격 뒤에는 필요한 통합·승인된 환경 적용·실물 확인을 이어간다. 같은 근거의 추가 검수를 만들지 않는다.
- 책임 owner는 전체 완료조건과 근거가 충족되면 `work complete`한다. 남은 일이 있으면 다음 행동·담당·대기 대상과 깨움 경로를 연결한다. 보고 수신이나 실행 DONE은 업무 최종 완료가 아니다.
- 결과·done 확정 뒤 남은 담당 일이 없는 소유 역할은 [종료·정리](references/cleanup.md)에 따라 종료한다. 확정은 역할 종료 때까지 미루지 않는다.

## 판단과 안전 경계

- 감독은 승인 안의 방법 선택·읽기 진단·제한된 복구·소유 역할 교대를 결정한다. 직접 하는 일은 단순 근거 대조이며 원인 탐색·구현은 작업자에게 맡긴다. 같은 유형은 공통 기준으로 이어가고 범위 밖 판단만 상위에 묻는다. [일반감독의 결정 범위](references/operating-contract.md#일반감독의-결정-범위)를 따른다.
- 작업자는 자기 브랜치의 소유 변경을 카드 단위로 커밋한다. 기능 브랜치 push·draft PR은 카드의 허용 범위 안에서 한다. 감독은 검수 합격 뒤 통합 브랜치 합류·허용된 프리뷰 배포를 맡는다. **main 합류와 운영 배포는 사용자의 현재 시점 승인이 필요하다.** worktree 병합·정리도 대상·행동의 승인 범위를 지킨다.
- 검수자는 소스를 고치지 않고 독립된 근거로 판단한다. 구현 문맥을 넘겨받지 않으며 증거 재사용 조건과 직접 확인 범위는 [검수 공통 계약](references/card-template.md#검수-공통-계약)을 따른다.
- 카드·원장·과거 결과와 다른 판의 역할을 보존한다. 이번 판에서 만든 정확한 역할만 종료한다. 원인 불명의 실패를 반복하지 않는다.
- 작업 상태는 원장으로 판단한다. `kadan read`는 실제 작업 내용·새 세션 준비·오류·보고 유실 확인에만 쓰고 30줄 이상 읽는다. 조용한 화면은 완료나 장애의 증거가 아니다.

스킬 전체는 첫 정독 1회, 이후에는 이번 행동의 필요한 절만 읽는다. 작업자·검수자에게 감독용 SKILL 전체를 읽히지 않는다. 자동 역할 지침은 [공통](references/role-templates/common.md)과 [역할별 템플릿](../../docs/role-instructions.md)을 사용하며, 새 발령·승인이나 카드의 실제 값을 대신하지 않는다.

진행·기록·상위 통지의 원본은 [운영 공통 기준](references/operating-contract.md)이다. 정상 ACK 편지·중계 요약·중복 일지를 만들지 않는다. 옛 사고는 [흉터 요약](../kadan-super/references/scars.md)을 필요할 때만 읽는다.
