# 카드 주소와 실행 기록 연결

## Why

사용자가 화면과 감시에서 같은 실행 상태를 확인하도록, 카드 주소를 읽고 기록하는 기준을 한곳에 둔다.

## 최소 규칙

- 정식 카드 주소는 `저장소/카드ID`다. `send --task`, `plan`, 수동 `done`, 화면의 DONE 수집에 같은 기준을 쓴다. 업무 주소는 실행 발령에 쓰지 않는다.
- 짧은 카드 ID는 중앙 카드 목록에서 하나로 정해질 때만 별칭이다. 서로 다른 저장소에 같은 ID가 있으면 정식 주소를 사용한다. 명시한 저장소가 틀렸거나 없으면 저장소를 떼어 다른 카드에 연결하지 않는다.
- 발령은 주소 해석 뒤 기존 중앙 카드의 상태·담당·허용 범위를 검사한다. 전체 주소나 `--raw`로 이 검사를 생략하지 않는다. 세션 생존·PID 검사도 그대로 적용한다.
- 유일한 카드의 새 원장 `taskId`와 DONE ID는 기존 짧은 ID를 유지하고, `executionKey`에 정식 주소를 함께 남긴다. 동명 카드는 `taskId`도 전체 주소로 구분한다. 입력을 줄인 경우 `rawTaskId`로 원래 주소를 남긴다. 발령에 첨부되는 현재 ID를 DONE에 사용하면 된다.
- 중앙 카드 없이 쓰던 짧은 ID 실행은 계속 허용하고 `중앙 카드 미등록`으로 표시한다. 모호한 ID·없는 전체 주소·서로 충돌하는 연결 필드는 `기록 연결 실패`다. 연결 실패 사건은 정상 카드의 시작·완료·담당 이전 근거로 쓰지 않는다.

## 과거 기록과 상태 계산

원장은 append-only다. 기존 사건을 변경·삭제·재정렬하거나 별칭 복구를 위해 새 send/done을 만들지 않는다. 원문 조회는 저장된 주소를 반환한다. 원문 조회의 done 중복은 같은 역할·입력 taskId·executionKey 조합만 제거하고, 카드 상태를 계산할 때는 주소를 해석한 뒤 역할별 최초 done을 선택한다. 연결 실패 done은 정상 done을 소모하지 않는다.

화면·tree·감시·업무 우편·인계·완료 계산은 같은 주소 해석을 사용한다. 서로 다른 역할의 실행은 합치지 않는다. 인계는 확정된 담당 이전 사건에 한해 반영하며, 전체 카드 목록 없이 짧은 ID의 유일성을 추측하지 않는다.

지시 전달은 착수 증거가 아니다. 작업 중·결과 대기는 기존 담당자의 진행 보고와 전달 시각으로 판단한다. 실패 완료, 세션 부재, 기록 연결 실패도 구별한다. 최초 완료 뒤 같은 ID에 다시 send하면 기존 재발령 규칙을 따르며, 중복 done을 새 완료로 간주하지 않는다. 새로 끝낼 실행은 새 ID를 쓴다. 유일한 카드의 계산용 짧은 ID는 유지하므로 기존 경보 ID·감시 책임 지문·쿨다운은 주소 표기만으로 변경하지 않는다.

## 명령 예

```sh
kadan plan demo demo/card-a
kadan send demo-worker --task demo/card-a "카드 지시를 확인하고 수행"
kadan done demo-worker demo/card-a ok
```

미등록 실행을 계획하려면 기존 짧은 ID를 쓴다. 전체 주소를 쓸 때는 중앙 카드가 먼저 등록돼 있어야 한다. 작업 지문에는 완성된 DONE 마커 대신 형식 `KADAN:DONE <현재카드id> <ok|failed>`과 현재 ID만 적고, 완료 시 담당자가 조립한다.

코드 적용 후에는 해당 모듈을 이미 읽은 대시보드와 감시 프로세스에 별도 반영이 필요하다. 코드·격리 시험의 통과는 운영 화면·감시가 반영됐다는 증명이 아니다.
