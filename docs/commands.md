# 명령어 사전

## Why

[kyle]과 에이전트가 카단 명령을 쓸 때, 어떤 명령이 있고 무엇을 하는지 한곳에서 찾게 한다.
명령마다 한 줄 설명과 자주 쓰는 옵션만 적고, 규칙·판단 기준은 링크한 상세 문서가 원본이다.

## 읽는 법

- 모든 옵션은 명령이 직접 알려 준다. 묶음 명령(`work`, `card`, `decision`, `inbox`, `runners`, `storage`, `hierarchy`, `watch-report`, `slot`, `limit`)은 `kadan <명령> --help`, 나머지는 대상 없이 실행하면 사용법이 나온다.
- `<역할>`은 세션 이름에서 `kadan-`을 뺀 부분이다(`kadan-비서` → `비서`).
- 명령이 PATH에 없으면 `node <저장소>/src/cli.mjs <명령>`으로 같은 일을 한다.
- 새 명령을 추가하면 이 표와 `src/command-help.mjs`의 묶음 목록(`kadan help --all`)을 같은 커밋에서 고친다. 시험이 빠진 명령을 잡는다.

## 환경 설정

| 변수 | 뜻 |
|---|---|
| `KADAN_HOME` | 원장·카드·설정이 사는 폴더. 기본 `~/.kadan` (옛 이름 `KADAN_LITE_HOME`도 읽음) |
| `KADAN_FLOOR` | 에이전트가 사는 바닥. `tmux`(기본). 로티는 바닥이 아니라 창(`KADAN_WINDOW=rottie`)이라 `rottie`를 주면 `KADAN_FLOOR_INVALID`다. 시험 기능 `herdr`는 별도 `KADAN_HOME`으로 명시 선택하며, 실행 중 전환·자동 폴백 없음 |
| `KADAN_HERDR_SOCKET` | herdr 시험 기능의 named server 절대 소켓 경로. `KADAN_HOME`과 함께 필수. 서버 자동 기동·훅 설치 없음. [실행 방법](experiments/herdr-roundtrip.md) |
| `KADAN_WINDOW` | tmux 바닥에서 시작할 때 여는 창. `none`(기본) · `rottie` · `orca`. 있으면 기계 설정(`kadan window`)보다 먼저다 |
| `KADAN_ROTTIE_BIN` | `KADAN_WINDOW=rottie`일 때 말 걸 로티 CLI의 절대경로. 있으면 기계 설정의 경로보다 먼저다 |

| `KADAN_SECRET_<이름>_FILE` | 이름별 비밀 파일의 절대경로(`KADAN_SECRET_DISCORD_FILE`·`_DISCORD_BOT_FILE`·`_EXPLAIN_AI_FILE`). 있으면 기계 설정(`kadan secrets`)보다 먼저다 → [비밀값 위치 규칙](secrets.md) |
| `KADAN_NOTIFY_ENV_FILE` | `KADAN_SECRET_DISCORD_FILE`의 옛 이름(별칭). 둘 다 있으면 `KADAN_SECRET_DISCORD_FILE`이 이긴다. 없으면 설정, 그다음 기본 위치(`$KADAN_HOME/secrets/discord.env`), 모두 없으면 시스템 알림만 쓴다 → [사용자 알림](user-notify.md) |
| `KADAN_NOTIFY` | `off`면 디스코드·결정 알림·사용자 우편함 알림·맥 시스템 알림을 모두 보내지 않는다(시험용). 시험 러너는 가짜 osascript로 시도를 잡아 실패시킨다 |
| `KADAN_TEST_NOTIFY_SINK` | **시험 전용, 운영에서 설정하지 않는다.** `KADAN_NOTIFY=off`이고 절대경로가 있으면 맥 시스템 알림을 실행하지 않고 그 파일에 `{at,title,message}` 한 줄을 덧붙인다. 실제 알림을 켜지 않는다 |
| `KADAN_TEST_SYSTEM_NOTIFY_TIMEOUT_MS` | **시험 전용, 운영에서 설정하지 않는다.** 맥 시스템 알림(osascript) 한 건을 기다리는 상한(밀리초)을 늘린다. 1000~120000 정수만 받고 그 밖의 값은 기본 3000 |
| `KADAN_SOCKET` | tmux 구획 이름. 기본 `kadan` (`tmux -L kadan`). `KADAN_HOME`이 기본 홈(`~/.kadan`, 링크면 실제 경로)이 아닌데 이 값이 없거나 `kadan`이면 tmux 호출을 `KADAN_LIVE_FLOOR_DENIED`로 거절한다(시험이 운영 창으로 새는 것을 막는 장치). 기본이 아닌 홈에서는 격리 이름을 주고, `KADAN_WINDOW=rottie`·`orca`도 기본이 아닌 홈에서는 같은 이유로 거절한다 |
| `KADAN_ALLOW_LIVE_FLOOR` | `1`이면 위 거절을 끈다. 기본이 아닌 홈으로 운영 구획·창을 일부러 다룰 때만 쓴다 |
| `KADAN_ROLE` | 카단 세션 안에서 자동으로 붙는 자기 역할. 원장의 `by`가 된다 |

창 선택의 읽는 순서는 **환경변수 > 기계 설정(`$KADAN_HOME/window-setting.json`) > 기본 `none`** 이다. 값이 하나로 정해지는 우선순위이며 실패하면 다른 창으로 넘어가는 폴백이 아니다. 로그인 자동 시작과 대시보드의 '비서 켜기'는 `KADAN_WINDOW=none`을 명시하므로 설정이 `rottie`여도 창 없이 뜬다. 이 `none`은 그 실행에만 적용된다 — 카단이 tmux를 부를 때 `KADAN_WINDOW`·`KADAN_ROTTIE_BIN`을 클라이언트 환경에서 빼므로, 그 호출이 처음 만든 tmux 서버의 전역 환경과 이후 세션에 남지 않는다(2026-11-02, 재부팅 뒤 감독이 모두 '창: manual'로 뜨던 문제). 이미 값을 물려받은 카단 tmux pane 안에서 `kadan start`가 환경변수 창 값이 기계 설정과 다르면 경고 한 줄만 낸다(동작은 그대로). **단 하나의 결정적 예외**: 카단 tmux pane 안(`KADAN_PANE_SOCKET` 또는 옛 `TMUX`의 소켓 이름이 현재 카단 소켓)에서 `KADAN_WINDOW=none`이고 기계 설정이 `rottie`이며 `KADAN_WINDOW_FORCE`가 없으면, 창 값과 로티 경로를 둘 다 기계 설정에서 가져오고 stderr에 한 줄을 낸다(#321 이전에 뜬 역할이 물려받은 none 때문에 작업자가 창 없이 뜨던 문제). 폴백 체인이 아니라 입력이 같으면 결과가 같은 규칙이다. 일부러 none이면 `KADAN_WINDOW_FORCE=1`(로그인 자동 시작·대시보드 '비서 켜기'가 이미 붙인다. 이 표시도 tmux 클라이언트 환경에서 빠진다). 반대 방향(env rottie·설정 none)·pane 밖·설정 없음은 그대로다. `KADAN_WINDOW=""`처럼 빈 문자열은 미지정으로 보고 설정이 채워진다. **설정 파일이 손상**(깨진 JSON·잘못된 창 값·상대 로티 경로)이면 창을 여는 명령(`start`·`attach`·`handover`·`adopt`·`up`·`restore`)은 역할·창을 만들기 전에 `WINDOW_SETTING_CORRUPT`와 복구 명령을 알리고 종료 코드 2로 멈춘다. 다른 창으로 넘어가지 않는다. 단 `KADAN_WINDOW`가 비어 있지 않게 주어지면 그 값이 창을 정하므로 막지 않는다(`KADAN_WINDOW=rottie`인데 `KADAN_ROTTIE_BIN` 환경변수가 없어 설정의 경로가 필요할 때는 멈춘다). `send`·`status`·`read`·`watch`·대시보드처럼 창과 무관한 명령은 경고만 하고 진행한다. 복구는 `kadan window unset`(손상 파일도 지운다) 또는 `kadan window set ...`.

## 처음 준비

| 명령 | 하는 일 | 자주 쓰는 옵션 |
|---|---|---|
| `kadan init` | 환경 확인, 스킬 링크, 실행기 선택. 처음 한 번 | `--runner codex\|claude`, `--no-skills` |
| `kadan up` | 비서 세션과 대시보드 세션을 띄운다. 살아 있으면 그대로 쓰며, 이전 Codex 비서는 저장된 대화로 복원한다. tmux에서는 데이터 폴더에 기본 감시 프로필(`watch-profile.json`)이 있고 감시 프로세스가 없을 때 감시기도 세션 `kadan-watch`에 띄운다(재부팅 뒤 자동 시작에서 감시기가 빠지지 않게, 2026-10-13) | `--cmd <실행기 명령>`, `--port 8790`, `--hidden`, `--no-prompt` `--auto`는 launchd가 1분마다 부르는 자동 실행이다: 살아 있는 것은 그대로 두고 꺼진 기반 프로세스 4개(비서·대시보드·디코 다리·감시기)를 다시 띄운다. **실행 시작 때 tmux 서버가 통째로 없으면 `server-sessions.json`의 10분 이내 생존 감독만 같은 대화로 복원한다.** 서버가 있는 매 주기에 관찰 시각·세션 목록을 0600으로 교체 저장한다. 부팅 시각이 마지막 관찰보다 늦으면 재부팅으로 보고 건너뛴다. 스냅숏 없음/10분 초과·부팅 시각 불명·60분 복원 상한·대화 불명도 건너뛴다. 머지 직후 첫 주기에 서버와 스냅숏이 모두 없으면 수동 확인 알림만 한다. 조회 결과와 무관하게 기반 4개를 먼저 실행하며, 복원 오류가 기반 결과를 바꾸지 않는다. 서버 조회 오류면 스냅숏을 쓰지 않고 stderr 한 줄만 남긴다. `$KADAN_HOME/server-restore.off`가 있으면 감독 복원을 끈다(기반 프로세스는 기존대로). [상세 조건과 기록](decisions.md#서버-전체-손실의-감독-복원-2026-11-09). 사람이 `kadan stop`으로 끈 대상과 1시간에 3번 넘게 꺼진 대상(상한)은 건너뛰고, 바뀐 것이 있을 때만 출력한다. `--auto` 없이 친 `kadan up`은 그 멈춤을 모두 풀고 상한 집계를 새로 센다. 프로세스가 죽어 창만 남은 감시기·다리 세션은 마지막 화면을 `<데이터 폴더>/revive/`에 저장하고 치운 뒤 다시 만든다(감시기·다리 세션은 `remain-on-exit`를 켠다). 세션의 모든 창이 죽었을 때만 세션을 치운다(살아 있는 창이 하나라도 있거나 조회에 실패하면 지우지 않고 막힘으로 한 번 울린다). 기반 되살리기는 원장 `revive` 사건(`by autostart`)으로 남긴다. 서버 손실의 감독 복원은 요약 `revive(reason=server-loss)`와 각 역할의 `start(reason=server-restore, by=autostart)`를 함께 남긴다. 조용한 되살림 알림은 디코로만 보내고 맥 알림으로 대신하지 않는다(못 보냈으면 사건의 `notice`와 로그에 남긴다). 상한·막힘·손상 경보는 울림이며 맥 알림으로 대신한다. 기반 4개의 `kadan stop`도 같은 `revive.lock` 아래에서 멈춤 표시를 먼저 저장한 뒤 끈다(잠금을 못 잡으면 끄지 않고 안내하며, 끄기가 실패하면 표시를 되돌린다). 주인이 죽었거나(좀비 포함) pid 없이 2분 넘은 잠금은 되찾고 `autostart.log`에 한 줄 남긴다. `revive-state.json`이 깨지면 `--auto`는 모든 대상을 건너뛰고 한 번 울리며, 사람이 친 `up`·`stop`이 깨진 파일을 `<데이터 폴더>/.trash/`로 옮기고 새로 시작한다. 같은 때 자동 실행과 손으로 친 `up`이 겹치지 않게 `<데이터 폴더>/revive.lock`을 쓴다. 재부팅 뒤 기반 4개는 기존 상한대로 다시 띄운다. 서버 손실의 조용한 기반 알림은 실제 복원 결과 요약에만 모으며, 후보 없음·복원 끄기·같은 스냅숏 등으로 요약이 없으면 그대로 보낸다. 기반 울림 알림은 항상 따로 유지한다. 시작할 감독이 있으면 시작 전 한 통과 기반 결과를 포함한 복원·건너뜀·실패 결과 한 통을 보낸다. 기반 사건의 notice는 실제 요약 전달 결과, noticeSummary는 요약 restoreId와 연결된다. 실패해도 직전 관찰 세션 이름을 보존한다. 복원 예외와 스냅숏 쓰기 실패는 같은 사유로 한 시간에 한 번만 알린다. 사람이 친 `up`은 `gui/dist/index.html`을 읽을 수 없으면(대시보드 주소가 503이 되는 원인) 주소 다음 줄에 `경고: 대시보드 화면 빌드가 없다 — npm --prefix gui ci && npm run build:gui` 한 줄만 낸다. 빌드를 대신 돌리지 않고 종료 코드도 바꾸지 않으며, `--auto`는 내지 않는다 |
| `kadan help [--all]` | 처음 쓰는 사람용 짧은 목록 9개를 보인다. `--all`은 모든 명령을 묶음별 한 줄로 보인다. 모르는 명령은 "모르는 명령"과 짧은 목록을 stderr에 내고 종료 코드 1이다. 설명 원본은 `src/command-help.mjs` | `--all` |
| `kadan doctor [--json]` | **읽기 전용 한 방 점검.** 막힌 곳과 풀려면 칠 명령을 한 줄씩 보인다. 카단의 데이터와 상태(원장·설정·체크포인트·잠금)를 바꾸지 않고 tmux 세션도 만들지 않는다(`--fix` 없음). 원장 SQLite의 `-wal`·`-shm`과 tmux 런타임 폴더는 `kadan status` 같은 다른 읽기 명령처럼 생길 수 있다. 한 줄 꼴은 `항목 \| 상태 \| 이유 \| 풀려면: 명령`, 상태는 정상·해당 없음(선택 기능을 안 깐 정상)·주의·막힘·확인 불가(조회 자체 실패). 점검 11개: node·tmux, 대시보드 화면(`gui/dist/index.html`을 읽을 수 있는지), 데이터 폴더·원장, 기반 프로세스 4개와 되살리기 멈춤 표시, 비서 복원 체크포인트(codex 비서만 대상, claude 비서는 해당 없음), 로그인 자동 시작(설치 여부, 지금 환경과 다른 plist, plist가 가리키는 사라진 경로), 창·모델 설정 손상, 비밀 폴더 권한(값은 읽지 않음), 운영 바닥 거절 장치(기본이 아닌 `KADAN_HOME`일 때만), 스킬 링크, 복원 잠금 잔류(경로만 보이고 지우지 않음). 막힘이 하나라도 있으면 종료 코드 1, `--json`은 같은 내용을 JSON으로 낸다. 막히면 먼저 이것부터 → [복구](recovery.md) | `--json` |

### 우편과 발령 선택

- 맥락·질문·답장·보고는 `mail`, 실행 카드 발령은 `dispatch --task`를 쓴다.
- 두 명령은 인자에 본문이 없으면 표준 입력을 읽고, `--help`로 사용법을 보여 준다.
- `mail --execution`은 우편에 실행 주소만 연결한다. `--task`는 빈 값이나 값 없는 옵션도 거절한다.
- `dispatch`는 카드 ID 한 개를 요구하며 `--execution`만으로 추론하지 않는다.
  비서·사람 우편함 대상, `--expect-reply`, `--reply-to`, `--reply-final`은 거절한다. 옛 `--mailbox`는 받되 무시하고 알린다.
- 기존 `send`는 동작을 바꾸지 않는다. 터미널로 보내는 `send --execution`은 연결 카드가 수신자에게
  배정되어 있고 `--reply-to`·`--expect-reply`가 없으면 발령으로 추론한다. 새 우편에 이 명령을 쓰지 않는다.
- 전송·원장·읽음 확인·발령 감시는 기존 경로를 재사용한다. 원장의 `send` 사건 이름은 바뀌지 않는다.

### `kadan stop`의 로티 탭 정리

tmux 세션을 종료한 뒤 원장의 최신 탭 ID를 조회하고, `terminal close` → `terminal remove` 순서로 닫고 목록에서 지운다. `restore`로 새 탭을 붙였다면 그 탭을 쓴다.

- 로티 실행 파일이 없어졌거나 연결되지 않으면 `start`와 같은 규칙으로 경로를 교정한다. 실행 중인 후보가 정확히 하나이고 연결될 때만 바꾸며, `KADAN_ROTTIE_AUTO_ATTACH=off`이면 바꾸지 않는다. 앱을 새로 켜지는 않는다.
- 원장에 기록된 탭을 조회하지 못하면 닫기·제거를 보내지 않는다. 로티 탭 기록이 없으면 로티를 조회하지 않는다.
- 탭 정리에 실패하면 세션 종료 사실과 실패 이유를 표준 오류에 알리고 종료 코드 `1`을 반환한다. `stop` 원장에는 닫기·제거 결과와 경로 교정 내역을 남긴다. 준비·조회·닫기 중 실패하면 `rottieWindowError`(코드)와 함께 로티가 준 원인 문구를 `rottieWindowMessage`에, 제거 실패면 `rottieRemoveMessage`에 남긴다(줄바꿈·제어 문자는 공백 하나로 줄이고 글자 200개(넘으면 앞 200개 + `…`)로 자른다). 성공하거나 문구가 비면 이 칸은 없다.
- 이때 tmux 세션은 이미 종료됐으므로 같은 `stop`을 다시 실행해도 탭 정리가 재시도되지는 않는다. 원장에 남은 탭 ID와 실패 원인을 확인해야 한다.

### `kadan restore` 자세히

로티 데몬을 다시 켜면 tmux 세션(에이전트)은 살고, 그 세션을 보여 주던 로티 탭만 끊긴다. `restore`는 탭만 다시 붙인다.

- 바닥이 tmux이고 `KADAN_WINDOW=rottie`일 때만 쓴다.
- 세션마다 원장에 적힌 로티 탭 상태를 로티에 묻는다. `running`·`created`면 건너뛰고, `unknown`·`closed`·`exited`이거나 탭이 없으면 새 탭을 붙인다.
- 마지막 `start`에 로티 탭이 없는 세션(숨김으로 띄운 watch·대시보드)은 건너뛴다.
- 탭 조회가 하나라도 실패하면 아무것도 하지 않고 이유를 보고한다.
- 새 탭 번호는 원장에 `window` 기록으로 남는다. 이후 `stop`은 새 탭을 닫는다. 죽은 옛 탭은 한 번 지워 보고, 실패하면 알리기만 한다.
- 실측: 2026-09-24 데몬 실제 재시작에서 세션 5개를 되살렸고 에이전트 PID는 그대로였다.

### `kadan restart` 자세히

실행기를 업데이트하거나 설정을 바꾼 뒤 역할의 **대화는 그대로 두고 프로그램만** 다시 띄운다(2026-10-14 [kyle]). 실행기마다 다른 "같은 대화 다시 열기·대화 ID 찾기" 지식은 코드가 아니라 실행 모델 설정의 [실행기 명령 표](runner-settings.md#실행기-명령-표)에 있다.

순서(거절할 수 있는 확인은 모두 기존 세션을 끄기 **전에** 끝낸다):

1. 역할 잠금 → 마지막 `start` 기록 확인(이미 `stop`된 역할·죽은 pane·기록과 다른 PID·자기 자신은 거절).
2. 끝나지 않은 카드(`stop`이 알리는 것과 같은 판정)가 있어도 거절하지 않는다(2026-11-10 [kyle] "카드있을때 리스타트할수도있자나" — restart는 대화·우편 세대·카드 책임·감시 발령을 이어받아 카드가 끊기지 않는다). 목록은 stop·start 기록의 `pendingTasks`로 남긴다(카드가 없으면 칸 자체가 없다). 대신 대화 확인(3~4)과 마지막 원장 다시 읽기·세대 검사가 모두 끝난 뒤 **끄기 바로 앞에서**(확인 다음 단계가 곧 세션 종료다) 화면이 쉬는 중이고 최근 사람 입력이 없는지 확인한다(비서·계정 전환 재시작도 같은 자리). 응답 생성 중이거나 판정할 수 없으면 끄지 않고 거절한다("응답 생성 중(또는 최근 사람 입력)이라 끄지 않았다 — 잠시 뒤 다시 하거나, 사람이 확인했으면 --force"). `--force`는 이 확인만 건너뛰고 stop·start 기록에 `forced`·`forcedTasks`를 더 남긴다. 역할은 `--force`를 쓰지 않는다(스스로 밝힌 신분이라 사람인지 검증할 수 없다 — 역할 지침에 한 줄).
3. 이 pane의 **실행기 본체 사슬**이 **지금 실제로** 연 대화를 표의 `conversation`으로 확정한다. 본체 사슬 = 트리에서 마지막 `start` 명령의 실행기·모델과 `ps` 인자가 맞는 프로세스 중 조상에 맞는 것이 없는 **뿌리 1개**와, 그 아래로 맞는 프로세스가 하나씩 이어진 것(codex의 node 래퍼→네이티브 바이너리). 뿌리가 0·2개 이상이거나 사슬이 갈리면 거절한다(같은 실행기의 하위 에이전트와 구분할 수 없다). `open-file`은 사슬이 연 파일에서, `pid-json`은 **뿌리 PID의 파일만** 읽는다. 표의 `conversation.evidence`(lock 등 저장 여부와 무관하게 ID를 드러내는 파일의 정규식)까지 합쳐 서로 다른 대화 ID가 둘 이상 보이면 거절한다. 자식 도구가 연 파일은 후보가 아니다(2026-10-14 실측: 열린 rollout·lock은 네이티브 codex가 가진다).
   `pid-json`의 `match`는 없는 키는 건너뛰고 있는 키는 틀 값과 같아야 한다. 키 유무와 관계없이
   파일 수정 시각이 살아 있는 뿌리 프로세스 시작 시각 이상이어야 한다(`ps lstart`가 초 단위라 같은 초는 허용).
   낡은 파일이나 시작 시각 조회 실패는 끄기 전에 거절한다. 기존 운영 `runner-settings.json` 수정은 필요 없다.
4. 마지막 `start`의 명령에서 대화 인자만 바꾼다(`resume` 틀의 꼬리). 실행기·모델이 같고 같은 대화(resume)로 읽혀야 한다. 갈라 연 명령(`adopt`의 `--resume <ID> --fork-session`·`codex fork <ID>`)은 표에 `fork` 틀이 있으면 그 꼬리를 떼고 살아 있는 대화(갈라 연 뒤의 지금 대화, 원본 아님)로 resume한다. 꼬리는 명령 끝이 아니어도 된다 — `adopt`는 그 뒤에 모델·강도·권한 옵션을 붙이며, 그 옵션들은 그대로 남는다. 떼는 조건은 표의 `fork` 꼬리와 같은 모양이 한 벌이고 명령의 대화 지정이 모두 그 한 벌 안에 있는 것이다. 쌍과 떨어진 `--fork-session`, 한 벌 말고 더 있는 대화 지정(`--resume` 하나 더·`--continue`·값 없는 `--resume`), 표와 다른 꼴(`--resume=<ID>`·`-r <ID>`), `--` 뒤 입력이 있으면 끄기 전에 "대화 지정" 문구로 거절한다.
5. `stop`(`restart: true` 표시) → 같은 작업 폴더에서 새 명령으로 시작 → 기계 창 설정(`KADAN_WINDOW`)대로 창을 연다 → `start`에 `restartOf`(옛 start의 지문)·`restartConversation`을 적는다. `restartOf`는 `restoredFrom`처럼 새 세대가 아니다(우편·책임·감시 발령을 이어받음).

- 비서 복원 명령의 `--model`·`-c`는 키마다 시작 명령의 것이 이기고 대화의 옵션은 빈 키만 채운다([복원 규칙](recovery.md#로그인-때-비서-대화-복원)).
- `비서`는 일반 찾기 대신 `kadan up`과 같은 체크포인트(`secretary-resume.json`) 경로로 같은 `start` 사건을 만든다. 체크포인트를 못 만들면(codex가 아닌 비서·래퍼 명령) 끄지 않고 거절하며, 새 `start`에도 `restartOf`(`--force`면 `forced`·`forcedTasks`)를 남겨 감시 발령이 이어진다. `restart: true`인 `stop`은 사용자가 직접 끈 것으로 읽히지 않는다.
- 감시: `stop`과 `start` 사이 몇 초 동안 감시가 그 세션을 죽은 것으로 볼 수 있다. 감시 한 주기보다 훨씬 짧아 보통 경보가 나기 전에 끝나지만, 따로 감시를 멈추는 표시는 없다(한계).
- 운영 소켓의 역할에 쓰려면 먼저 해당 `runner-settings.json`에 표를 채워야 한다(없으면 "미지원"으로 거절).
- `--reason <이유>`(선택): restart가 남기는 `stop`(`restart: true`)·`start`(`restartOf`) 두 사건에 `reason` 칸으로 적는다. 옛 기록은 고치지 않는다.
- 계정 전환 재시작(`accountRefresh`, 2026-10-23 [kyle]): `kadan claude refresh --yes --role`만 `restartRole`에 `accountRefresh`를 넘길 수 있다(`kadan restart` 명령줄·대시보드 버튼으로는 못 넘긴다). 이 경로는 `--force` 없이 같은 안전 지점 확인(건너뛰지 않음, 상태 바뀜 코드·"건너뜀" 문구)을 하고 `forced` 대신 `accountRefresh`·`pendingTasks`를 남긴다. 비서는 대상이 아니다.
- `--model-from-settings`(선택, 명령줄 전용, 2026-11-10 [kyle]): 옵션이 없으면 restart는 마지막 `start` 명령의 모델·강도를 그대로 쓴다. 실행 모델 설정을 바꿔도 살아 있는 역할은 옛 모델로 다시 뜬다. 이 옵션을 주면 **같은 대화를 그대로 이어 열되** 모델·강도만 지금 설정값으로 바꾼다.
  - **모델·강도만 바꾸고 다른 옵션은 그대로 둔다.** 새 명령은 평소 restart가 만드는 명령(옛 명령 + 지금 대화의 resume 꼬리)에서 모델·강도 자리의 **값만** 바꾼 것이다. 실행 파일(래퍼 포함)·다른 옵션과 그 값·낱말 순서가 옛 그대로다. 권한 옵션이 없던 역할에 권한 옵션이 붙지 않고, 손으로 준 옵션(`--add-dir /x` 등)도 그대로 남는다.
  - 설정에서 쓰는 것은 값뿐이다: 마지막 `start`의 `roleProfile`과 지금 활성 프리셋의 모델·강도. 설정의 `spawn` 틀은 옛 명령에서 모델·강도 자리를 찾는 데만 쓴다(옵션 이름 `--model` 등은 코드에 없다).
  - **명령에 카단이 아는 옵션만 있을 때 바꾼다. 모르는 옵션이 있으면 거절한다.** 옛 명령(대화 꼬리를 뗀 것)을 실행기별 옵션 표(`src/conversation-ref.mjs`, 첫 안내의 '새 대화로 확실함' 판정과 같은 표)로 처음부터 끝까지 걸어 옵션과 값을 가른다. 표에 없는 옵션·옵션 자리가 아닌 맨 낱말(첫 프롬프트 등)·`--`·표가 없는 실행기를 만나면 그 낱말을 보여 주고 "모델 자리를 확실히 가릴 수 없어 바꾸지 않는다"로 끝낸다. 모델·강도 자리는 이렇게 가른 **옵션 자리**에서만 찾으므로, 다른 옵션의 값이 `--effort` 같은 글자여도 자리로 읽지 않는다. 바꾼 뒤에는 새 명령을 같은 방법으로 다시 걸어 모델·강도 값 말고 달라진 낱말이 없는지 확인한다.
  - 자리 규칙: 모델 자리는 옛 명령에 정확히 1번 있어야 하고, 거기서 읽은 값이 시작 기록의 모델과 같아야 한다. 강도 자리는 0번 또는 1번이다. 설정에 강도 값이 있는데 옛 명령에 강도 자리가 없으면 틀의 강도 낱말을 모델 자리 바로 뒤에 넣는다(틀에 강도 자리가 없는 실행기는 넣지 않는다). 설정에 강도 값이 없으면 옛 강도를 그대로 둔다.
  - 살아 있는 프로세스와 대화를 찾는 3번은 **옛 모델** 기준이다(프로세스 인자는 옛 명령 그대로다. `/model`로 바꾼 세션도 같다). 다시 만든 명령의 확인은 **새 모델** 기준이다: 실행기가 같고, 모델이 설정값이고, 같은 대화 resume으로 읽혀야 한다.
  - 끄기 전에 거절하는 경우: 시작 기록에 프로필이 없다 · 설정에 그 역할 값이 없다 · 설정의 실행기가 이 역할의 실행기와 다르다(대화를 이어 열 수 없다) · 비교 모드로 띄운 역할(`compareMode`, 비교 보고서 귀속이 바뀐다) · 비서 · 계정 전환 재시작과 함께 · 옛 명령을 옵션 표로 끝까지 해석하지 못한다(모르는 옵션·맨 낱말·`--`) · 모델 자리를 정할 수 없다(0번·2번 이상·읽은 값이 시작 기록과 다름. 예: 틀과 다른 꼴의 `--model=<모델>`) · 강도 자리가 2번 이상이다.
  - 설정의 모델·강도가 옛 명령과 같으면 평소 restart와 같은 명령으로 다시 띄우고 "설정과 같음: 바뀐 것 없음" 한 줄을 낸다.
  - 앞 시작 기록에 `difficulty`가 있으면 새 `start`에 그대로 이어 적고, `difficulty: "hard"`면 모델·강도는 활성 프리셋의 `worker-hard` 값(비어 있으면 작업자 값)에서 가져온다.
  - 새 `start`에 `modelFromSettings: true`·`settingsRevision`·`settingsPreset`·`runnerChoice`를 남긴다(`kadan start --profile`의 칸과 같은 이름이라 발령 기록과 [옛 세션 발령 막기](runner-settings.md#옛-세션-발령-막기)가 그대로 읽는다). 바뀐 값만 `previousModel`·`previousEffort`로 남긴다. `launchSource`는 적지 않는다(명령이 설정 틀 그대로가 아니라 옛 명령에서 값만 바꾼 것이다). `stop`에는 평소 restart 칸만 남는다.
  - 안전 지점 확인·`pendingTasks`·`--force`·`--reason`·`--expect-pid`는 옵션이 없을 때와 같다. 대시보드 '다시 띄우기' 버튼은 이 옵션을 보내지 않는다.
- 위치 인자는 역할 하나만 받는다. 낱말이 더 있으면(`kadan restart a b`, 값 없는 옵션 뒤에 붙인 값 포함) 어느 것이 역할인지 추측하지 않고 사용법 오류로 끝낸다(세션 조회 전).
- `--expect-pid <pane PID>`(선택): 원장의 최신 `start`의 pane PID와 다르면 끄기 전에 거절한다. 화면이 본 세대와 지금 세대를 대조해 두 번 재시작을 막는 장치다.
- 역할 이름은 정규화 전후가 같아야 한다. 앞뒤 하이픈 등 별칭(`-역할`·`역할-`)은 같은 세션을 가리켜도 거절한다 — 미해결 카드와 원장 기록이 항상 같은 이름을 쓰게 하려는 것이다(2026-10-15 2라운드).
- 화면 진입점(2026-10-15, 2026-10-25 옮김): 대시보드 전략 맵(`#strategy-map`)에서 살아 있는 역할의 유닛을 누르면 열리는 옆 칸과, 지도 유닛이 아닌 감시기·대시보드는 지도 아래 '기반 세션' 묶음의 '다시 띄우기' 버튼(세대는 `/api/dashboard/status`의 `live[].recordedPid`). 이유 칸은 필수이고, 서버는 POST `/roles/restart`로 받아 `kadan restart <역할>`을 자식 프로세스로 부른다(사람 명의). 이유·세대 표시는 CLI 옵션으로 재해석되지 않게 환경변수(`KADAN_RESTART_REASON`·`KADAN_RESTART_EXPECT_PID`)로만 넘긴다. CLI는 읽은 즉시 자기 환경에서 지워 새 역할·tmux 서버에 남지 않게 하고(자식 프로세스를 만들기 전), 명시 옵션과 환경값이 둘 다 있고 다르면 어느 쪽인지 사람이 확인하도록 거절한다. 화면 응답 상한은 28초이고, 넘기면 '진행 중' 안내를 답한 뒤 자식은 끊지 않고 최종 상한 120초까지 돌게 한다(끊으면 stop만 남는 반쯤 끝난 상태가 되므로). `--force`는 화면에서 보내지 않는다 — 끝나지 않은 카드 거절은 CLI 메시지가 그대로 보인다.
- 최종 상한·도중 실패로 남은 회복 잠금(`<홈>/recovery/role-*.lock`)은 자동으로 지우지 않는다. 다음 restart·start가 '역할 복원이 진행 중입니다'로 거절되면 잠금 경로를 확인하고 사람이 지운다(기존 dir-lock 규칙).
- 아직 안 한 것: 실행 모델 화면에 표 보이기.
