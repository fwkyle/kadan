# 검수 자리와 무거운 명령 제한

## Why

병렬 에이전트가 검수할 때마다 새 worktree와 새 `node_modules`(약 0.9GB, 파일 수만 개)를 만들고 지웠다. 전후 비교면 두 벌이었다. 2026-10-02 한 Mac에서 한 제품 저장소 3곳의 worktree가 105개, 파일 감시 프로세스(fseventsd)가 CPU 82%·메모리 11GB, 스왑 25/25.6GB, 부하 평균 75였다. 다른 프로젝트의 러스트 빌드도 여러 개가 동시에 돌았다.

검수자는 저장소마다 정해진 몇 개의 **검수 자리**를 빌려 쓰고 돌려준다. 설치는 잠금 파일이 바뀔 때만 한다. 설치·빌드·러스트 빌드는 **무거운 명령 제한**을 거쳐 종류와 상관없이 기계 전체에서 한 번에 하나만 돌고(기본), 맥 전체의 압축 메모리 공간이 높으면 시작하지 않으며 도는 중에 위험해지면 끊는다. 데몬이나 서비스는 없고 카단 폴더(`$KADAN_HOME`, 기본 `~/.kadan`)의 파일만 쓴다.

## 검수 자리 (`kadan slot`)

| 명령 | 하는 일 |
|---|---|
| `kadan slot acquire <저장소 경로|저장소 이름> --for <카드\|역할> [--ref <SHA\|브랜치>]` | 빈 자리를 빌린다. 처음 쓰는 자리는 이때 worktree를 만든다(분리된 HEAD). 요청한 커밋으로 옮기고 결과 JSON의 `path`가 자리 경로다. `--ref`가 없으면 원본 저장소의 HEAD |
| `kadan slot deps <자리경로> [--cmd "<설치 명령>"]` | 잠금 파일이 그 자리의 마지막 설치 때와 다르거나 `node_modules`가 없을 때만 설치한다. 설치는 `kadan limit run install`과 같은 제한을 거친다 |
| `kadan slot release <자리경로>` / `kadan slot release --for <카드\|역할>` | 자리를 돌려준다. `node_modules`는 남긴다(다시 쓰려고 만든 기능이다). 경로로 찾을 때 경로가 아직 없는(자리를 준비하는 중인) 임차는 후보에서 뺀다 — 다른 판의 임차가 함께 풀리지 않게 |
| `kadan slot status [<저장소 경로|저장소 이름>]` | 자리별 빌린 쪽·커밋·경과 분·회수 가능 여부 |

- **저장소 인자**: `/`를 포함하거나 `.`·`~`로 시작하면 경로, 그 밖의 순수 이름은 항상 카드 원장(`card.repo` → `repoPath`)의 저장소 이름이다(cwd의 같은 이름 폴더를 경로로 쓰려면 `./이름`). 경로든 이름이든 저장소(또는 worktree) 꼭대기만 받는다. 하위 폴더나 상위 저장소로 올라가 찾은 것은 거절하고, 꼭대기가 아니면 이름 후보에서도 뺀다. 이름은 고유한 원본 저장소 하나로 정해져야 하고, 못 찾거나 둘 이상이면 실패하며 경로를 달라고 안내한다. 원장은 읽기만 한다.
- **자리 위치**: 원본 저장소 옆 `<저장소이름>-review-slots/slot-1…4`. worktree 경로를 줘도 원본 저장소의 자리 묶음을 쓴다.
- **자리 수**: 저장소마다 기본 4. 임차 기록은 `$KADAN_HOME/review-slots/<저장소>/slot-N.lease.json`, 설치 기록은 같은 폴더의 `slot-N.meta.json`이다.
- **모두 사용 중**: 기본은 기다린다(5초 간격, 최대 `--wait-timeout` 초, 기본 1800). 기다리는 동안 누가 쥐었는지 표준 오류에 알린다. `--no-wait`이면 빌린 쪽 정보와 함께 종료 코드 3으로 바로 실패한다.
- **임시 자리**: 자리가 모두 찼을 때만 쓰고 `--temporary --reason "<이유>"`가 있어야 한다. 이유는 임차 기록에 남고 `release` 때 worktree를 지운다(`--force` 없이. 변경이 남아 거부되면 임차를 남기고 알린다).
- **더러운 자리**: 커밋 안 된 변경·새 파일이 있는 자리는 다시 빌려주지 않는다. 검수자는 코드를 고치지 않으므로 변경이 생겼다면 확인해 치운 뒤 쓴다. 대상 저장소의 `.gitignore`에 `node_modules`가 없으면 설치 뒤 항상 더럽게 보인다.
- **버려진 임차 회수**: 카단 역할(`KADAN_ROLE` 또는 `--role`)이 빌렸으면 그 역할 세션이 사라지거나 세션 PID가 바뀐 임차를, 역할 밖에서 빌렸으면 12시간이 지난 임차를 다음 사람이 회수한다. 회수했으면 결과의 `reclaimed`에 이유가 나온다.
- **참조 가져오기**: `--ref`가 로컬에 없을 때만 `git fetch origin <ref>` 하나를 한다. 검수는 작업자 결과의 SHA를 `--ref`로 주는 것이 가장 정확하다.
- 결과 JSON은 표준 출력, 대기·설치 출력은 표준 오류로 나온다: `kadan slot acquire <저장소 경로|저장소 이름> --for <카드> --ref <SHA> | jq -r .path`.
- 위치 인자(저장소·자리 경로)를 옵션보다 앞에 둔다.

### 검수 흐름

```bash
kadan slot acquire <저장소 경로|저장소 이름> --for <카드id> --ref <검수할 SHA>   # path 확인
kadan slot deps <자리경로>                                      # 필요할 때만 설치
# … 검수 (코드 수정 금지) …
kadan slot release <자리경로>
```

전후 비교가 필요하면 새 worktree 대신 **두 번째 자리**를 빌린다(`--for <카드id>-before --ref <기준 SHA>`). `kadan slot release --for <카드id>`는 그 이름으로 빌린 자리를 모두 돌려준다. 작업자(구현)는 지금처럼 자기 브랜치의 worktree를 쓴다.

## 무거운 명령 제한 (`kadan limit`)

| 명령 | 하는 일 |
|---|---|
| `kadan limit run <rust\|install\|build> -- <명령...>` | 맥 전체 한 줄의 자리가 비어 있을 때만(종류와 상관없이) 명령을 돌린다. 차 있으면 쥔 쪽을 알리며 기다린다. 자리를 잡은 뒤 명령을 띄우기 직전에 맥 전체 압축 메모리 공간을 재고 높으면 자리를 쥔 채 기다리며, 도는 동안에도 재서 위험하면 끊는다([메모리 보호](#메모리-보호)). 종료 코드는 명령의 것을 그대로 돌려준다. 최대 90초 기다려도 풀리지 않으면 명령을 돌리지 않고 종료 코드 75, 도는 중에 끊었으면 종료 코드 76. 명령은 표준 입력을 받지 않는다 |
| `kadan limit status` | 동시 개수(`heavy`)와 지금 쥔 쪽(잠금마다 이름·종류·`pid`·시작 시각 `since`·역할 `role`·`state`: `alive`·`dead`·`pid-reused`), 감독 업무 기준 개수(`conductorOpenWorks`), 메모리 확인 켜짐·꺼짐(`memoryCheck`). 설정 파일에 옛 `limits`가 있으면 "더 이상 쓰지 않음" 한 줄(`notice`)이 붙는다. 명령 인자·작업 폴더는 나오지 않는다 |
| `kadan limit set conductor-works <0 이상의 정수>` | 일반감독 한 명에게 맡길 진행 중 업무의 기준 개수를 바꾼다(기본 3, 0이면 안내 문장 끔). 그 밖의 값은 종료 코드 2 |

| 종류 | 대상 |
|---|---|
| `rust` | `cargo build/test/check/clippy` 등 러스트 빌드. `CARGO_BUILD_JOBS=2`가 붙는다 |
| `install` | node 패키지 설치(`pnpm install`, `yarn install`, `npm ci`) |
| `build` | 그 밖의 모든 무거운 작업: node 빌드·전체 시험·격리 DB 시험·내장 Postgres·`vite build`·`build:gui`·playwright·브라우저 |

세 종류는 **같은 자리 묶음 하나**를 나눠 쓴다(기본 동시 1개). 종류 이름은 대기 줄·`status` 표시와 rust의 `CARGO_BUILD_JOBS`에만 쓰고, 새 종류를 늘리지 않는다. 앞에서 끝까지 돌리고 `&`·nohup·백그라운드로 띄워 놓지 않는다.

- `rust`는 `CARGO_BUILD_JOBS=2`를 환경 변수로 붙인다. 이미 그 변수가 있거나 명령에 `-j`·`--jobs`가 있으면 그대로 둔다. 인자에 `-j 2`를 끼우지 않는 이유는 `cargo test -- …`처럼 인자 위치가 중요한 명령을 깨뜨릴 수 있어서다.
- 잠금은 `$KADAN_HOME/limits/heavy-N.lock`이다(N은 1부터 동시 개수까지, 종류는 잠금 안에 적는다). 명령이 실패하거나 중단돼도(SIGINT·SIGTERM·SIGHUP은 명령의 프로세스 그룹에 전달) 잠금을 푼다. 강제 종료로 남은 잠금은 PID가 죽었으면 다음 사람이 회수한다.
- 잠금에는 잡을 때 읽은 주인 프로세스의 시작 표지(`startToken`)를 함께 적는다. Linux는 부팅 식별값과 부팅 뒤 틱으로 센 시작 시각(`/proc/<pid>/stat`), macOS는 커널이 저장해 둔 시작 시각(`ps -o lstart=`, UTC)이다. 둘 다 벽시계를 고쳐도 변하지 않는다. 그 밖의 OS에서는 표지를 적지 않는다. 잠금의 PID가 살아 있어도 지금 그 PID의 표지가 적힌 것과 다르면, 재부팅이나 PID 재사용으로 번호만 같은 다른 프로세스다. 이 잠금도 회수한다. `kadan limit status`의 `state`와 대기 줄은 `(죽음)`과 `(PID 재사용: 시작 표지 다름)`을 구분해 보인다.
- 표지가 없는 옛 잠금, 모양이 다른 표지, 지금 표지를 읽지 못한 경우는 살아 있는 것으로 보고 회수하지 않는다. 그런 잠금이 재부팅 뒤 남으면 잠금 파일을 직접 치운다.
- 내용이 없거나 JSON이 아니거나 `pid`가 없는 잠금은 주인을 알 수 없다. 막 만든 것은 쓰는 중일 수 있어 두고, 파일 수정 시각이 60초를 넘으면 죽은 잠금처럼 회수한다(영원히 막지 않는다). 새 잠금은 내용을 임시 파일에 먼저 쓰고 hard link로 한 번에 만들어 내용 없는 잠금이 생기지 않는다.
- 회수는 자리마다 회수 표지(`heavy-N.lock.reclaim`)를 잡은 쪽만 하고, 표지 안에서 잠금을 다시 읽어 아직 죽은 것일 때만 치운다. 두 회수자가 같은 죽은 잠금을 보아도 늦은 쪽은 새 주인의 살아 있는 잠금을 치우지 않고 기다린다. 다만 죽은 표지를 정리하는 두 프로세스가 겹치는 경로는 막지 못한다(아래 "수용한 위험").
- `--` 뒤의 인자는 카단 옵션으로 해석하지 않고 명령에 그대로 넘긴다.
- 잠금 파일에는 주인의 명령 인자와 작업 폴더를 적지 않는다(PID·종류·시작 시각·시작 표지·`KADAN_ROLE`이 있으면 역할만). 명령줄에 토큰이 실리면 대기 안내 줄을 통해 남의 세션 기록에 비밀이 남기 때문이다(2026-11-18). 대기 안내 줄과 `kadan limit status`는 읽는 쪽에서도 같은 허용 목록(잠금 이름·종류·PID·시작 시각·역할·상태)만 내보내므로, 옛 버전이 `command`·`cwd`를 적은 잠금 파일이 남아 있어도 새지 않는다.

### 메모리 보호

패닉 3번(2026-11-13, 11-21 두 번)은 모두 맥의 압축 메모리 공간이 100% 찬 것이었다. 그래서 맥 전체의 **압축 공간**을 본다: 압축 세그먼트 비율과 보관 페이지 비율 중 큰 값이고, 감시기의 기기 메모리 경보와 같은 정의다(`sysctl` 한 번, `src/machine-memory.mjs`). 스왑 잔량과 메모리 여유 비율은 보지 않는다. 스왑은 평소에도 0으로 내려오지 않아(2026-11-13~17 정상 3.4일 중앙값 6.9GiB) 옛 조건 "스왑 used 0"이 계속 대기를 만들었다. 스왑은 대기 줄에 참고로만 보인다. 압박 단계를 못 읽으면 위급이 아닌 것으로 본다.

| 때 | 조건 | 결과 |
|---|---|---|
| 시작 전 | 맥이 아님 | `메모리 확인 건너뜀: 맥이 아님(<OS>)` 한 줄만 남기고 시작한다. 실행 중 보호도 없다(우분투 CI는 항상 이 길이다) |
| 시작 전 | 압축 공간 75% 미만이고 압박 단계가 위급이 아님 | 바로 시작 |
| 시작 전 | 압축 공간 75% 이상, 또는 압박 위급, 또는 맥에서 값을 못 읽음 | 자리를 쥔 채 5초마다 다시 잰다. 최대 **90초** 안에 풀리면 시작하고, 아니면 명령을 돌리지 않고 자리를 풀고 **종료 코드 75** |
| 실행 중 | 5초마다 읽은 값으로 압축 공간 85% 이상이 2번 연속 | 그 명령의 프로세스 그룹을 끊고 **종료 코드 76** |
| 실행 중 | 압박 위급이면서 압축 공간 75% 이상이 2번 연속 | 위와 같음 |
| 실행 중 | 1번 걸리고 다음에 내려옴, 또는 값을 못 읽음 | 끊지 않는다. 연속 셈은 0으로 돌아간다(못 읽은 값은 끊는 근거로 쓰지 않는다) |

- **시작 전 대기**: 기다리는 동안 자리는 쥔 채라서 다른 무거운 작업도 시작하지 못한다. 잰 값(못 읽었으면 "못 읽음")을 한 줄로 알리고, 값이 바뀔 때만 다시 알린다. 기다림은 단조 시계로 재고, 90초를 넘은 뒤의 측정은 통과여도 시작하지 않는다.
- **끊는 순서**: 그 `limit run`이 띄운 프로세스 그룹에 SIGTERM을 보내고, **10초** 뒤에도 그룹에 남은 프로세스가 있으면 SIGKILL을 보낸다(이미 없으면 보내지 않는다). 그룹이 사라진 것을 본 뒤에 자리를 풀고, 잰 값을 적은 사유 한 줄과 종료 코드 76으로 끝난다. 끊기를 시작한 뒤에는 명령이 어떤 코드로 끝났든 76이다.
- **76을 받으면** 같은 명령을 바로 다시 돌리지 않는다. 끊긴 뒤에는 압축 공간이 내려가 시작 관문이 다시 열리므로, 그대로 다시 돌리면 같은 끊김이 반복될 수 있다. 감독에게 알리고 감독이 원인과 범위 축소를 정한다. 코드로 재실행을 막지는 않는다.
- **75·76과 명령 자신의 종료 코드**: 75·76은 명령의 실패(1 등)와 구별하려는 값이다. 명령이 스스로 75·76으로 끝나면 보통 종료이고 코드도 그대로다. 구별이 필요한 호출자는 종료 코드가 아니라 `runLimitedResult`의 결과(`started`: 명령을 띄웠는지, `memoryStop`: 메모리 보호가 끊었는지)를 본다.
- **`kadan slot deps`**: 설치를 맡기기 전에 그 자리의 설치 기록을 지우고 성공한 뒤에만 다시 쓴다. 시작하지 못하면 "메모리 보호로 설치를 시작하지 않음(종료 75)", 도는 중에 끊기면 "메모리 보호로 설치를 중단(종료 76): 다음 deps가 다시 설치한다"로 끝난다. 끊겨서 `node_modules`가 반쯤 깔린 채 남아도 기록이 없으므로 다음 `deps`가 건너뛰지 않고 다시 설치한다. 설치 명령이 스스로 75·76으로 끝나면 보통의 설치 실패다.
- **프로세스 그룹과 표준 입력**: 명령은 자기 프로세스 그룹(새 세션)에서 돈다. 끊을 때 명령이 띄운 프로세스까지 함께 끊으려는 것이다. 그래서 터미널의 Ctrl-C는 명령에 직접 가지 않고, `limit run`이 받은 SIGINT·SIGTERM·SIGHUP을 그 그룹에 전달한다. 명령의 표준 입력은 닫혀 있다(바로 끝을 읽는다). 무거운 명령은 입력을 받지 않는다. 출력과 오류 출력은 그대로 이어진다.
- **끄는 스위치**: `$KADAN_HOME/memory-check.off` 파일이 있거나 환경 변수 `KADAN_MEMORY_CHECK=off`면 시작 전 확인도 실행 중 보호도 하지 않는다. 스위치는 자리를 잡은 뒤 한 번 읽고, 도는 중에 바꾼 값은 다음 실행부터 적용된다. 환경 변수는 tmux·herdr로 역할 세션에 넘기지 않는다(시험 실행기의 끄기가 새지 않게). 운영 tmux 서버의 전역 환경에 이 값을 넣지 않는다(이미 들어 있으면 역할 세션에 남는다). 시험 실행기(`tests/run.mjs`)가 환경 변수를 깔아 시험이 실제 맥 측정값에 걸리지 않게 하고, 운영 기본은 켜짐이다. 문턱이 실측 전 값이라 잘못 막거나 끊을 때 사람이 바로 끌 수 있게 파일 스위치를 둔다.
- `limit run` 안에서 `kadan limit run`·`kadan slot deps`를 다시 부르지 않는다. 같은 한 줄을 안쪽이 기다려 부모와 서로 멈춘다(코드·문서·스크립트에는 그런 경로가 없음을 확인했다, 2026-11-21).

## 설정

`$KADAN_HOME/resource-limits.json`은 선택이다. 없으면 아래 기본값을 쓴다.

```json
{"reviewSlots": 4, "leaseMaxHours": 12, "heavy": 1, "conductorOpenWorks": 3}
```

`heavy`는 무거운 명령의 동시 개수(종류와 상관없이 전체, 기본 1)다. 옛 종류별 `limits`는 더 쓰지 않는다(파일에 남아 있어도 무시하고 `kadan limit status`가 알린다).

`conductorOpenWorks`는 슈퍼감독이 일반감독에게 일을 맡길 때 나오는 안내의 기준 개수다([업무 맥락 전달](flows.md)). 이 키만 `kadan limit set conductor-works <N>`으로 쓴다: 다른 키는 그대로 두고, 파일이 없으면 이 키만 든 파일을 만들며, 파일이 깨져 있으면 덮어쓰지 않고 거절한다. 읽을 때 파일이 깨졌거나 값이 0 이상의 정수가 아니면 기본 3으로 본다(우편 전송을 막지 않는다).

## 수용한 위험

- 새 코드는 `heavy-N.lock`만 본다. 옛 코드가 남긴 `<종류>-N.lock` 주인이 아직 돌고 있으면 새 한 줄과 잠깐 겹칠 수 있다(막는 장치는 만들지 않는다, 2026-11-21). 옛 잠금 파일은 세지도 회수하지도 않으니 필요하면 직접 치운다.

- 검수 자리 임차: 두 사람이 같은 버려진 임차를 같은 순간 회수하면 아주 짧은 틈에 둘 다 잡을 수 있다. 드문 경합이라 두 단계 잠금을 만들지 않는다(2026-10-02 [kyle]: 단순하게). 무거운 명령의 잠금(`heavy-N.lock`)은 한 줄이 모든 작업을 막으므로 회수 표지로 막는다(위 잠금 설명, 2026-11-21 검수). 회수 표지는 잠금과 같은 주인 판정(살아 있으면 오래 걸려도 치우지 않고, 죽었거나 PID가 재사용됐으면 치운다)이다. 다만 다음 세 조건이 겹치면 두 무거운 작업이 한 번 겹쳐 돌 수 있다(같은 자리 획득 둘, 일시적인 대기로 끝나지 않는다): (1) 이전 주인이 비정상 종료로 잠금을 남기고, (2) 그 잠금을 회수하던 프로세스도 회수 도중 죽어 표지까지 남고, (3) 기다리던 두 프로세스가 같은 순간 그 죽은 표지를 정리한다. 이름 바꾸기(rename) 방식의 회수는 "확인하고 치우기"를 한 번에 할 수 없어 이 틈을 코드로 완전히 막지 못한다. 드문 경합은 수용한다(2026-10-02 [kyle] 결정, 검수 exec-73630795 `evidence/guard-interleaving.md`의 순서). 후속: 프로세스가 죽으면 운영체제가 풀어 주는 잠금으로 교체하는 안을 검토한다.
- 로컬에 없는 커밋 SHA를 `--ref`로 주면 `FETCH_HEAD`로 읽는다. 같은 저장소에서 두 검수자가 같은 순간 서로 다른 SHA를 가져오면 섞일 수 있다(브랜치 이름은 원격 추적 참조를 먼저 봐서 해당 없음). 결과의 `sha`를 확인한다.
- `kadan limit run`을 강제 종료(SIGKILL)하면 신호를 전달하지 못해, 자기 프로세스 그룹으로 분리된 명령과 그 자식이 남아 돌 수 있다(실행 중 메모리 보호도 함께 사라진다). 그 잠금은 회수 대상이 된다.
- 메모리 보호가 끊는 범위는 그 명령의 프로세스 그룹이다. `setsid`로 따로 떨어진 데몬(내장 Postgres 등)은 그룹 종료에서 살아남을 수 있다. 76 뒤에는 남은 프로세스를 확인한다.
- 실행 중 보호는 맥 전체 기준이다. `limit run` 밖의 원인(브라우저 등)으로 압축 공간이 차도 그때 돌던 무거운 작업이 대신 끊긴다(의도된 것).
- 메모리 보호의 문턱(75%·85%·2번 연속·90초·10초)은 실측으로 정한 값이 아니라 시작값이다. 압박 위급 단계와 85% 구간은 정상 운영 기록(2026-11-13~17, 압축 공간 최대 61.5%)에 한 번도 없었다.
- 기존 설치 명령은 잠금 파일 기준이다(`pnpm install --frozen-lockfile`, `yarn install --frozen-lockfile`, `npm ci`). 저장소 사정이 다르면 `--cmd`로 바꾼다. 하위 폴더의 잠금 파일은 보지 않는다.
