# 카드 작업 시간과 모델별 요약

## Why

[kyle]이 작업자 기본 모델을 바꾼 뒤 실제로 얼마나 빨라졌는지 본다. 세션 시간은 대기와 추가 지시가 섞여 비교할 수 없으므로, 카드 기록만으로 '작업 시간'을 계산해 모델별로 보여 준다(2026-09-29). 읽기 전용 계산이며 원장·SQLite·카드 저장소에는 아무것도 쓰지 않는다.

## 화면

- 카드 목록에 두 칸이 있다: **모델(강도)**(그 카드를 실제로 돌린 모델, 끝난 카드도 말한다)와 **작업 시간**(칸에 마우스를 올리면 대기·마감 대기·재작업). 작업 시간 열로 정렬할 수 있다. 값이 하나도 없는 열은 숨긴다. 워크 목록에는 작업 시간 열이 없다.
- 카드 목록 위 **모델별 작업 시간**을 펼치면 요약 표가 나온다. 펼칠 때만 읽고 접혀 있으면 요청도 갱신도 없다. 기간은 오늘·7일·전체이고 기준은 결과 등록 시각이다('오늘'은 한국 시간 0시부터).
- 요약 표는 역할 프로필(작업자·검수자) × 모델(강도) × 종류(구현·수정·검수·조사)로 건수·중간값·평균을 묶는다. 모델을 알 수 없는 카드는 '모름'으로 따로 묶고 이유별 건수를 아래에 밝힌다. 배정 기준으로 계산한 건수와 2라운드 이상 건수는 비고에 적는다.
- API: `GET /api/dashboard/worktime?period=today|7d|all`(다른 값은 400). 카드 행(`workspace`)에는 `workMs`·`waitMs`·`closeMs`·`workBasis`·`reworks`·`profile`·`modelState`가 실린다.

## 계산 규칙

| 값 | 기준 |
| --- | --- |
| 시작 | 카드 이력에서 **처음 `activity=running`이 된 사건**의 `activityAt`(`kadan card progress --activity running`). 메모의 "시작:" 문자열은 읽지 않는다 |
| 작업 시간 | 시작 → 결과 등록(`result.at`). 시작 기록이 없으면 처음 배정(assigned) → 결과이고 `workBasis: assigned`로 구분해 '배정 기준'이라 표시한다 |
| 대기 시간 | 배정 → 시작 |
| 마감 대기 | 결과 등록 → **원장 완료 확정(`done`)** 시각. 확정이 없거나 결과보다 앞서면 빈칸. 카드 상태 done의 시각은 쓰지 않는다(옛 카드 일괄 상태 변경이 가짜 대기를 만든다) |
| 재작업 | 결과 재등록이 아니라 티키타카 라운드로 센다: 같은 묶음(`rallyId`)의 앞선 라운드 수 = `rallyRound − 1`. 묶음이 없거나 조사 카드는 세지 않는다 |
| 종류 | `rallyStep`이 기준이다. 구현 카드가 2라운드 이상이면 '수정'으로 나눈다(`review-flow`의 수정 횟수와 같은 규칙) |
| 대상 | 조율(coordination) 카드는 계산하지 않는다 |

결과 등록은 카드당 한 번뿐이다. `CardStore.report`는 같은 결과를 다시 등록하면 그대로 돌려주고, 다른 결과면 거부한다(`src/card-store.mjs`). 그래서 "결과가 여러 번이면 마지막 기준"이라는 경우는 생기지 않으며, 재작업은 새 카드로 이어진다(2026-09-29 실측: 결과 있는 카드 635장 중 결과가 바뀐 카드 0).

## 모델 판정

원장 `start` 기록으로 판정한다. 세션이 이미 끝났어도(stop) 원장에 남으므로 화면이 사라진 뒤에도 답할 수 있다.

1. **실행 세대**는 실행 명령(`cmd`)이 있는 start부터 그 역할의 다음 stop 전까지다. `cmd`가 없는 start(살아 있는 세션을 다시 부른 재사용)는 새 세대도 모델 근거도 아니다.
2. 카드의 **첫 시작**(없으면 첫 배정) 시각을 품는 세대의 실행 명령에서 실행기·모델·강도를 읽는다. 강도는 명령 안에 있다(`--effort`, `model_reasoning_effort`, `--thinking`; `card-center.mjs`의 `effortOfCmd`). 세대 안에 실행 명령이 여럿이면 같은 모델·강도인지만 비교하고, 화면에 보이는 실행기·프로필은 **카드 첫 시작 직전**(같은 시각 포함)에 띄운 실행 명령 기록의 것이다(직전 기록이 없으면 첫 기록).
3. 작업 역할은 running을 보고한 역할(`activityRole`)이다. 담당이 나중에 바뀌어도 그 세션의 모델을 쓴다.
4. 판정할 수 없으면 이유와 함께 **모름**이다.

| 이유 | 뜻 |
| --- | --- |
| `no-anchor` | 카드에 시작·배정 기록이 없다 |
| `no-launch` | 그 시각을 품는 세대가 없다(실행 명령 기록이 없는 옛 세션 포함) |
| `restarted` | 같은 세대 안에서 다른 모델·강도로 다시 시작됐다. 시각만으로 어느 쪽인지 단정하지 않는다. **모델·강도가 같으면 실행 도구(omo·codex 등) 이름만 달라도 재시작으로 보지 않고 알려진 모델로 판정한다** |
| `no-model` | 실행 명령에서 모델을 읽을 수 없다 |

- 아직 살아 있는 세대(stop 없음)는 옛 세션 발령 막기와 같이 "지금 pane PID와 같은 start만" 본다. 읽기 전용 계산에서 바닥(tmux·rottie)을 조회하지 않으므로, 세대의 마지막 실행 명령 기록의 PID를 지금 PID로 본다.
- **한계**: 원장이 아는 것은 세션을 띄울 때의 명령뿐이다. 세션 안에서 나중에 바꾼 모델(`/model` 등)은 알 수 없다.
- 역할 프로필(작업자·검수자)은 start 기록의 `roleProfile`이 기준이고, 없으면 카드 단계로 추론한다(review는 검수자, 그 밖은 작업자).

## 계산 위치

`src/card-worktime.mjs`가 순수 함수로 계산하고, `src/dashboard-api.mjs`가 **수집(snapshot)당 한 번** 원장 색인을 만들어 캐시한다(계산 반복을 줄인 `dashboard-compute` 경로 안). 카드마다 원장을 다시 훑지 않는다. 시험은 `tests/card-worktime.test.mjs`, 화면 표시 규칙은 `gui/src/worktime.ts`(`gui/tests/worktime.test.ts`)다.
