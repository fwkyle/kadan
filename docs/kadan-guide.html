카단(kadan) 안내서 — 그림으로 이해하기

Why — 새로 온 사람이 5분 안에 "카단이 뭘 하는 도구인지" 알게 하려고. 아래로 갈수록 자세해진다. 지금 이해한 만큼만 보고 멈춰도 된다.

장면 1 · 문제

AI 일꾼이 많으면 뭐가 힘들까요?

코덱스·클로드 같은 AI 일꾼을 여러 명 띄우면 누가 뭘 하는지, 멈췄는지 알 수 없어요. 카단은 AI마다 이름표(역할)를 붙이고 창(tmux 세션)을 열어 줘서, 사람이 한눈에 보고 직접 말을 걸 수 있어요.

장면 2 · 원리

무슨 일이 있었는지 어떻게 기억할까요?

카단은 모든 사건을 공책(원장, ledger) 맨 끝에 한 줄씩만 적어요. 쓴 줄은 절대 지우지 않고, 중간에 끼우지도, 순서를 바꾸지도 않아요 — 그래서 나중에 다시 읽어도 그날 그대로예요.

장면 3 · 원리

편지를 넣기 전에 뭘 확인할까요?

죽은 창이나 엉뚱한 프로세스에 편지를 넣으면 큰일이에요. 그래서 send는 검문소(guardedSend) 네 칸을 순서대로 통과해야만 상대 창에 닿아요. 하나라도 걸리면 보내지 않고 이유를 알려요.

장면 4 · 비교

"다 했어요"를 어떻게 믿을까요?

완료 신호는 AI가 화면에 출력하는 마커 한 줄(KADAN:DONE)이에요. 완성된 마커를 지문에 쓰면 입력 에코까지 마커로 보여 완료를 오판해요. 그래서 지문에는 형식과 카드 id만 알려 주고, 조립은 AI가 해요.

장면 5 · 비교

바닥이 바뀌면 카단도 바뀔까요?

AI가 사는 곳(바닥)은 tmux에서 로티(rottie) 같은 다른 곳으로 바뀔 수 있어요. 하지만 원장·검문소·DONE 마커·명령(코어)은 그대로 두고 바닥 조각만 갈아끼워요.

장면 6 · 경계

남의 창을 만지면 안 되는 이유가 뭘까요?

카단은 전용 울타리(tmux -L kadan 구획) 안에서만 놀아요. 사람의 개인 창과 절대 섞지 않고, 카단이 만든 창만 닫을 수 있어요. 창 주소는 번호(%3)가 아니라 이름(kadan-<역할>)이에요.

장면 7 · 관계

누가 누구에게 묻나요?

모르는 게 생기면 바로 위 한 칸에게 물어요. 작업자는 일반감독에게, 일반감독은 슈퍼감독에게요. 사용자에게 "결정해 주세요"(사용자 결정, decision request)를 올릴 수 있는 건 슈퍼감독뿐이에요. 감독이 답을 기다리는 동안 그 카드는 묻는 쪽의 할 일에서 잠깐 빠지지만, 답할 쪽에게는 할 일로 남아요.

시니어 (kadan senior)

작업 결과에 결정할 부분이 있을 때, 감독이 고급 모델에게 의견을 한 번 묻는 카단 기능. 답은 기록이지 결정이 아니고, 카드 상태도 우편도 건드리지 않는다.

docs/senior.md, docs/flows.md 1절

Claude Code 어드바이저

카단 기능이 아니다. Claude Code로 띄운 감독이 카드를 완수하려고 쓰는 Claude Code 안의 도구로, 판단이 무거운 카드를 쓰기 전에 묻는다. 시니어와 서로 대신하지 않는다.

docs/senior.md, docs/flows.md 1·3절

장면 8 · 경계

조용해진 일꾼을 카단이 혼자 판단할까요?

아니요, 카단은 알리기만 해요. 작업자 화면이 5분 동안 그대로면 감시 AI가 살펴보고 그 감독에게 알려요. 감독이 할 일을 두고 15분 동안 그대로면 먼저 본인에게, 그래도 그대로면(두 배 시간) 윗사람에게 알려요. 답을 기다리는 일은 할 일로 세지 않아요. 풀리면 따로 편지하지 않고 기록만 남겨요.

장면 9 · 규칙을 직접 만져 볼까요?

보통 탭에서는 방금 본 발령 검문소를 직접 눌러 볼 수 있어요. 세션을 죽여 보거나, PID를 바꿔 보거나, 초안 카드에 발령해 볼까요?

    규칙표 1 — 카드 상태 세 묶음
    
  
    화면 이름은 한 곳(src/status-labels.mjs)에서 정하고, 저장 값(draft·ready…)은 그대로 둔다. 저장 값은 여덟 가지이고, 작업중은 작업대기(assigned) 카드에 착수 보고가 붙은 모습이다. 목표 상태마다 필요 조건이 붙는다. (src/card-store.mjs:138-145)
    
  
    
    
    묶음화면 이름 (저장 값)뜻이 상태로 가려면
    
    
    진행 전초안 (draft)중앙 등록 직후. 아직 판·담당이 없다— (등록하면 draft)
    
    
    설계완료 (ready)범위 승인까지 끝나 맡길 수 있음. 옛 이름 발령 가능발령 가능한 범위(scope)를 먼저 적어야 한다 · 판·담당은 비워 둔다
    
    
    보류 (archived)시작 전, 지금은 안 하지만 나중에 할 수도 있음. 끝이 아니다. 옛 이름 보관—
    
    
    진행 중작업대기 (assigned)역할에게 맡겼고 시작 보고 전. 감시는 여기서부터판+담당 역할 필요 · 실행 카드 수동 발령은 티키타카 묶음(rally) 정보와 '읽고 시작할 것' 문서 필요
    
    
    작업중 (running, waiting도 작업중으로 셈)맡은 역할이 착수를 보고함. 결과 대기(waiting)는 상세에서만 '기다림'을 붙인다저장 값은 assigned 그대로 · 진행 보고(activity)는 배정된 역할만 올린다
    
    
    일시정지 (hold)시작 뒤 잠시 멈춤. 옛 이름 보류. 워크(업무)도 같은 이름—
    
    
    끝완료 (done)이 카드로 해냄. 감독이 근거를 확인하고 확정결과 등록과 별개로 감독의 kadan done
    
    
    취소 (cancelled)하지 않기로 함—
    
    
    대체 (superseded)다른 카드나 업무가 이어받아 끝냄. 완료 실적으로 세지 않는다replacedBy(후속 카드) 또는 replacedByText(업무 키·짧은 설명) 중 하나 이상
    
  
    
  
    실행 기록으로 계산한 신호(발령됨·실패·확인 필요)는 세 묶음과 따로 본다. 옛 이름 '보류'는 이제 일시정지(hold)이고, 지금의 보류는 시작 전 미뤄 둔 archived다 — 헷갈리기 쉬운 자리. (src/status-labels.mjs, docs/glossary.md 카드 상태 세 묶음)

    명령하는 일
    
    
    kadan start <역할> --cmd codex역할 이름의 창을 열고 start 사건을 원장에 적는다
    
    
    kadan send <역할> [--task <카드>] 메시지검문소를 통과하면 창에 붙여넣고 send 사건을 적는다
    
    
    kadan done <역할> <카드> ok|failed확인한 사람·감독이 완료를 원장에 확정한다
    
    
    kadan wait <역할>화면에서 DONE 마커를 찾아 보고한다. 대신 판정하지 않는다
    
    
    kadan read <역할>창 화면을 읽는다
    
    
    kadan status창·카드·원장을 읽어 지금 상태를 보여 준다
    
    
    kadan log원장 사건을 보여 준다
    
    
    kadan attach <역할>살아 있는 창에 사람이 들어간다
    
    
    kadan stop <역할>카단이 만든 창만 닫는다
