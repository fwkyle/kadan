# 하던 대화를 카단 감독으로 이어가기

## Why

사용자가 하던 대화를 다시 설명하거나 권한을 다시 맞추지 않고 카단에 맡기고,
새 감독이 이어받았을 때 원래 Rottie 탭까지 정리되게 한다.

## 세 가지 길 비교

대화나 담당을 옮기는 방법은 세 가지다. 이 문서는 첫 번째 길을 설명한다.

| 길 | 언제 쓰나 | 무엇이 넘어가나 | 원래 대화는 어떻게 되나 | 주의할 점 |
| --- | --- | --- | --- | --- |
| `kadan adopt <감독> --model <모델>` | 카단 밖(앱·터미널)에서 하던 대화를 처음 카단 감독으로 들일 때 | 대화 전체의 복제본(Claude Code는 `--resume <대화ID> --fork-session`, Codex는 `fork`)과 현재 권한 | 그대로 남는다. 새 감독이 인수를 확인한 뒤, 정확히 찾은 원본 Rottie 탭만 닫는다 | 대화를 시작한 폴더에서 실행한다. 인수 확인이 끝나기 전에 원래 탭에 입력하면 확인이 거절된다 |
| `kadan handover <선임> --to <후임> …` | 이미 카단에 등록된 역할의 담당을 다른 역할로 바꿀 때 | 카드 책임, 확정 당시 있던 우편, 상위·하위 관계. 후임은 기준 문서(`--context`)와 카드·원장·결과를 직접 읽고 인수한다 | 후임이 인수를 확인하고 관계가 반영된 뒤 선임을 종료한다 | 문서와 기록으로 넘기므로, 선임의 대화에만 있고 어디에도 적지 않은 맥락은 빠질 수 있다. 인수 확인은 근거 파일이 있는지를 볼 뿐 후임의 이해를 증명하지 않는다 |
| `kadan start <역할> --cmd "<실행기의 resume 명령>"` | 복제하지 않고 같은 대화를 그대로 카단 역할로 열 때 | 같은 대화 그 자체. 카단이 원본 대화의 권한을 자동으로 복사하지 않으므로, 필요한 권한 옵션은 명령에 직접 지정한다 | 복제본이 없다. 같은 대화를 카단 세션에서 이어 쓴다 | 같은 대화를 이어 연 세션에는 첫 안내를 보내지 않으므로 역할과 할 일을 직접 알려야 한다. 인수 확인과 원본 탭 정리 절차가 없다. 원래 창을 먼저 닫아야 하는지는 실행기에 달려 있어 여기서는 다루지 않는다 |

세 번째 길의 예: `kadan start 프로젝트-감독 --profile conductor --cmd "claude --resume <대화ID> --model <모델>" --reason "<이유>"`.
실행 모델 설정이 있을 때 그 역할의 기본 명령과 다른 명령으로 띄우면 `--reason`으로 이유를 함께 적어야 한다. 빠지면 시작이 거절된다.
자세한 옵션은 [명령어 사전](commands.md), 두 번째 길은 [인계 안내](handover.md)에 있다.

## 무엇이 넘어가고 무엇이 안 넘어가나

- **대화 전체가 넘어간다.** `adopt`는 요약본이나 인수인계서를 만들어 넘기지 않는다. 지금까지의 대화를 복제해 새 감독 창으로 연다.
  그래서 새 감독은 대화에서 정한 목표·승인 범위를 다시 설명받지 않고 읽는다. 권한이 이어지는 범위는 [아래](#권한을-이어받는-범위)에 있다.
- **`accept --summary`는 맥락을 전달하는 수단이 아니다.** 새 감독이 이어받은 대화를 읽고 무엇을 맡았는지 스스로 적는 이해 확인이다.
  여기에 적은 한 문장이 새 감독의 기억이 되는 것이 아니며, 사용자가 대신 써 줄 필요도 없다.
- **복제한 뒤 원래 탭에 친 입력은 넘어가지 않는다.** 복제본은 `adopt`를 실행한 시점까지의 대화다.
  그 뒤 원래 탭에서 한 말은 새 감독이 모른다. 이어서 할 말은 감독 창(`kadan attach <감독>`)에서 한다.
- **옮긴 뒤 원래 탭에 입력하지 않는다.** 지금은 새 감독의 인수 확인이 끝나기 전에 원래 탭에 한마디라도 입력하면
  `adopt accept`가 "원본 대화의 지시 또는 권한이 바뀌었습니다"로 거절되고, 다시 실행해도 같은 이유로 거절되어 인수가 끝나지 않는다.
  이때 원본 탭은 닫히지 않고 남는다. 인수가 끝난 뒤에도 원래 탭에서 지시하면 같은 일을 두 번 맡기게 된다.

## 정상 흐름

대화를 시작한 폴더에서 평소처럼 실행한다.

```sh
kadan adopt 프로젝트-감독 --model opus
# 대화 밖에서 비서가 실행할 때는 원본 대화 주소도 지정한다.
kadan adopt 프로젝트-감독 --model opus --resume <대화ID> --harness claude
```

1. 원본 대화의 현재 권한을 읽고 같은 모델·지정한 생각 강도로 복제본을 연다.
2. 새 감독이 목표·승인 범위·다음 행동을 읽고 첫 안내의 인수 명령을 한 번 실행한다.
3. 새 감독의 실제 권한과 프로세스, 원본 탭이 그대로인지 확인한 뒤 원본 탭을 닫고 목록에서 제거한다.
4. 새 감독은 맡은 작업을 이어간다. 원본 대화에는 더 입력하지 않는다([이유](#무엇이-넘어가고-무엇이-안-넘어가나)).

```sh
# 이 명령은 새 감독이 실행한다. 사용자가 복사해 전달할 필요는 없다.
kadan adopt accept <인수ID> --summary "이어받은 목표·승인 범위와 다음 행동"
kadan adopt status <인수ID>
```

`accept`의 설명은 실제 이어받은 내용으로 바꾼다. 이는 감독이 대화를 읽고 실행할 수 있다는 확인이며,
업무 완료나 이후의 push·병합·배포 승인이 아니다. 화면 출력·입력 에코·정지된 안내창은 인수로 인정하지 않는다.

원본 탭 정리 결과(`result.json`, 원장 `adopt` `finished`의 `result`)는 `source`가 `removed`·`retained`·`close-failed`·`remove-failed` 중 하나다.
닫기나 제거가 실패하면 `code`(로티 오류 코드) 옆에 로티가 준 원인 문구를 `message`에 남긴다. 줄바꿈·제어 문자는 공백 하나로 줄이고
글자 200개(넘으면 앞 200개 + `…`)로 자르며(`stop`의 `rottieWindowMessage`와 같은 정리), 문구가 없거나 성공이면 `message` 칸이 없다.

## 권한을 이어받는 범위

- Claude: 정확한 대화 기록의 마지막 권한 모드. `bypassPermissions`, `plan`, `acceptEdits` 등 현재 값을 사용한다.
  예전 `default` 이름은 현재 CLI의 `manual`로 옮긴다. 같은 시작 폴더의 사용자·프로젝트 설정은 그대로 읽는다.
- Codex: 정확한 대화의 승인 정책과 샌드박스. 쓰기 허용 경로·네트워크·임시 폴더 제한도 함께 옮긴다.
- Claude 실행 명령에 별도 도구 목록이나 설정 파일을 지정한 경우처럼 자동으로 보존을 확인할 수 없는 옵션은
  조용히 버리지 않고 비서에게 확인을 넘긴다. 모르는 권한을 카단 기본 바이패스로 바꾸지 않는다.

## 비서가 이어받는 경우

첫 안내가 안내창에 막히거나, 인수 확인이 3분 안에 오지 않거나, 원본 탭을 특정하지 못하면
기존 비서 우편함에 인수 ID·새 감독·확인할 점을 남긴다. 3분은 확인 요청 시점이며 이후 정상 인수를 막는 마감이 아니다.
비서는 기록과 두 창을 보고 필요한 맥락·안내를 연결한다. 사용자의 기존 승인으로 처리할 수 있는 일을 다시 묻지 않는다.
인자 빠짐·잘못된 옵션 같은 사용법 오류는 인수 준비 전이라 우편을 남기지 않고 오류 문구와 종료 코드 2만 낸다.
우편 저장은 비서 화면을 즉시 깨웠다는 뜻은 아니다. 별도 AI 반복 호출이나 자동 재시작은 하지 않는다.

원본 Rottie 탭은 제목 대신 원본 AI의 상위 프로세스와 탭 ID로 찾는다. 비서가 대신 실행하면
원본 대화 파일을 열고 있는 정확한 AI 프로세스로 찾는다. 확인할 수 없으면 새 감독은 인수할 수 있지만
원본 탭은 보존하며, 비서가 남은 탭 확인을 돕는다. 비서 자신의 탭을 닫지 않는다.

인수 확인 전에 원본에 새 사용자 입력이 들어오거나 권한이 바뀌면 `adopt accept`가 거절되고 원본 탭을 보존한다.
새 감독의 프로세스나 원본 탭이 달라진 경우도 같다. 확인이 3분 안에 끝나지 않으면 위와 같이 비서 우편함에 알린다.
종료 결과가 불확실하면 같은 종료를 자동 반복하지 않는다. `status`와 두 창을 확인해 남은 작업만 처리한다.
`--no-prompt`는 첫 안내와 자동 대기 확인을 생략하므로 원본 탭이 저절로 닫히지 않는다.

인수 요청·확인·결과는 데이터 폴더의 `adoptions/<인수ID>/`에, 인수·종료 결과 사건은 기존 원장에 남는다.
이는 카단 밖 대화를 처음 편입하는 절차다. 이미 등록된 역할 간 책임 교대는 [handover](handover.md)를 쓴다.
