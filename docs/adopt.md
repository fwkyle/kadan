# 하던 대화를 카단 감독으로 이어가기

## Why

사용자가 하던 대화를 다시 설명하거나 권한을 다시 맞추지 않고 카단에 맡기고,
새 감독이 이어받았을 때 원래 Rottie 탭까지 정리되게 한다.

## 정상 흐름

대화를 시작한 폴더에서 평소처럼 실행한다.

```sh
kadan adopt 프로젝트-감독 --model opus
# 대화 밖에서 비서가 실행할 때는 원본 대화 주소도 지정한다.
kadan adopt 프로젝트-감독 --model opus --resume <대화ID> --harness claude
```

1. 원본 대화의 현재 권한을 읽고 같은 모델·지정한 생각 강도로 복제본을 연다.
2. 새 감독이 목표·승인 범위·다음 행동을 읽고 첫 안내의 인수 명령을 한 번 실행한다.
3. 새 감독의 실제 권한과 프로세스, 원본 탭이 그대로인지 확인한 뒤 원본 탭을 닫고 목록에서 제거한다.
4. 새 감독은 맡은 작업을 이어간다. 원본 대화에서는 추가 지시를 보내지 않는다.

```sh
# 이 명령은 새 감독이 실행한다. 사용자가 복사해 전달할 필요는 없다.
kadan adopt accept <인수ID> --summary "이어받은 목표·승인 범위와 다음 행동"
kadan adopt status <인수ID>
```

`accept`의 설명은 실제 이어받은 내용으로 바꾼다. 이는 감독이 대화를 읽고 실행할 수 있다는 확인이며,
업무 완료나 이후의 push·병합·배포 승인이 아니다. 화면 출력·입력 에코·정지된 안내창은 인수로 인정하지 않는다.

## 권한을 이어받는 범위

- Claude: 정확한 대화 기록의 마지막 권한 모드. `bypassPermissions`, `plan`, `acceptEdits` 등 현재 값을 사용한다.
  예전 `default` 이름은 현재 CLI의 `manual`로 옮긴다. 같은 시작 폴더의 사용자·프로젝트 설정은 그대로 읽는다.
- Codex: 정확한 대화의 승인 정책과 샌드박스. 쓰기 허용 경로·네트워크·임시 폴더 제한도 함께 옮긴다.
- Claude 실행 명령에 별도 도구 목록이나 설정 파일을 지정한 경우처럼 자동으로 보존을 확인할 수 없는 옵션은
  조용히 버리지 않고 비서에게 확인을 넘긴다. 모르는 권한을 카단 기본 바이패스로 바꾸지 않는다.

## 비서가 이어받는 경우

첫 안내가 안내창에 막히거나, 인수 확인이 3분 안에 오지 않거나, 원본 탭을 특정하지 못하면
기존 비서 우편함에 인수 ID·새 감독·확인할 점을 남긴다. 3분은 확인 요청 시점이며 이후 정상 인수를 막는 마감이 아니다.
비서는 기록과 두 창을 보고 필요한 맥락·안내를 연결한다. 사용자의 기존 승인으로 처리할 수 있는 일을 다시 묻지 않는다.
우편 저장은 비서 화면을 즉시 깨웠다는 뜻은 아니다. 별도 AI 반복 호출이나 자동 재시작은 하지 않는다.

원본 Rottie 탭은 제목 대신 원본 AI의 상위 프로세스와 탭 ID로 찾는다. 비서가 대신 실행하면
원본 대화 파일을 열고 있는 정확한 AI 프로세스로 찾는다. 확인할 수 없으면 새 감독은 인수할 수 있지만
원본 탭은 보존하며, 비서가 남은 탭 확인을 돕는다. 비서 자신의 탭을 닫지 않는다.

원본에 새 사용자 지시가 들어오거나 권한·프로세스·탭이 바뀌면 자동 종료를 멈추고 비서에게 알린다.
종료 결과가 불확실하면 같은 종료를 자동 반복하지 않는다. `status`와 두 창을 확인해 남은 작업만 처리한다.
`--no-prompt`는 첫 안내와 자동 대기 확인을 생략하므로 원본 탭이 저절로 닫히지 않는다.

인수 요청·확인·결과는 데이터 폴더의 `adoptions/<인수ID>/`에, 인수·종료 결과 사건은 기존 원장에 남는다.
이는 카단 밖 대화를 처음 편입하는 절차다. 이미 등록된 역할 간 책임 교대는 [handover](handover.md)를 쓴다.
