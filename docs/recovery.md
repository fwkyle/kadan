# Why

재부팅 뒤 사용자가 역할 이름과 대화를 다시 맞추지 않고, 같은 카단 역할과 정확한
AI 대화를 Rottie 터미널에서 이어 열도록 한다.

# 막히면 먼저 `kadan doctor`

`kadan doctor`는 아무것도 바꾸지 않고 막힌 곳(대시보드 화면 빌드, 비서 복원 정보, 복원 잠금, 창 설정 손상 등)과
풀려면 칠 명령을 한 화면에 보인다. 고치는 일은 사람이 한다. 설명은 [명령어 사전](commands.md)의 `kadan doctor` 행.

# Rottie 역할 복원

`kadan recovery inspect`와 `kadan recovery restore`는 Rottie가 호출하는 JSON 명령이다.
카단이 역할·시작 세대·작업 폴더·tmux 연결을 맡고, Rottie가 정확한 AI 대화 참조와
검증한 복원 명령을 맡는다. 일반 `kadan restore`는 살아 있는 tmux의 Rottie 창을
다시 연결하는 기존 기능이다.

조회는 원장의 현재 Rottie 탭 ID와 마지막 역할 시작 기록을 대조한다. 실행 중인
세션은 단일 pane과 PID도 확인한다. 재부팅 뒤 pane이 없더라도 정확한 탭 기록이
남아 있으면 역할 정보를 반환한다. 역할 이름이나 최신 대화 시각으로 추측하지 않는다.
직접 종료한 역할, 다른 시작 세대로 교체된 역할, 옮겨진 탭은 거부한다.

복원 정보에는 저장소·tmux 서버·역할·작업 폴더·원본 탭·시작 기록 지문을 담는다.
재부팅으로 tmux가 사라졌으면 기존 tmux 생성 경로에 Rottie의 정확한 대화 복원 명령을
전달하고 원장에 새 시작 기록을 추가한다. 역할 프로필과 기존 관계표를 유지한다.
원본에 명시 모델이 있으면 조회 응답에 함께 전달하고, 복원 명령의 실행기·모델도
원본과 같아야 한다. Rottie의 `exec` 접두사는 원장에 실행 파일부터 남기도록 제거해
기존 카드 전송의 AI 신원 검사가 복원된 역할도 알아볼 수 있게 한다.
같은 pane이 살아 있으면 Rottie가 원본 AI의 생존을 확인한 경우에만 다시 연결한다.
PID가 같아도 tmux 생성 시각이 달라졌으면 재사용하지 않는다.

새 Rottie 탭은 정확한 tmux 소켓 절대경로로 연결한다. 새 탭과 새 시작 기록의
복원 정보를 응답에 포함해 다음 재부팅에도 같은 절차를 사용할 수 있게 한다.

실행 전에 저장소의 `recovery/`에 배타적으로 요청 기록을 저장한다. 같은 요청은
동시에 두 번 실행되지 않는다. 시작했지만 탭 연결 응답을 확인하지 못한 경우도
자동 재시도하지 않는다. 역할과 탭을 직접 확인한 뒤 판단한다.

이 명령은 감시기를 새로 시작하거나 우편·카드·마지막 프롬프트를 재전송하지 않는다.
Rottie의 자동 복원 설정이 켜져 있고 프로젝트가 열려 있을 때 자동 복원에 사용한다.
이전 Rottie 기록의 누락된 역할 정보도 현재 카단이 정확한 원본 탭을 확인할 수 있을 때만
보완할 수 있다.

Claude 역할의 명시 `--effort`도 조회·복원한다. 초기 복원 버전에서 빠진 값은 같은 역할과 폴더의 정확한 `restoredFrom` 시작 기록에서만 보완한다. 누락·변조된 추론 강도로 실행하지 않는다. 일반 `/effort` 실행 중 변경값은 수집하지 않는다.

## 비서에게 복원 예외 전달

기본 복원은 Rottie 코드가 맡는다. `kadan recovery report --report <JSON>`은 실패하거나
역할을 확정하지 못한 항목만 비서의 저장 우편함에 request로 남긴다. 비서는 독립 AI
대화를 가지며 현재 tmux 안에서 실행된다. 우편 저장은 비서 실행 여부와 무관하다.
이 명령은 터미널 키 입력·비서 기동·기존 세션 재시작·카드 발령을 수행하지 않는다.

보고에는 원본 탭·대화·역할 참조와 원인을 담고, 같은 내용은 한 번만 저장한다.
저장 결과가 불확실하면 자동 재전송하지 않고, 실제 우편 기록이 있으면 그 영수증을
재사용한다. 비서는 현재 역할과 새 탭부터 확인하며 살아 있는 세션을 건드리지 않는다.
정확한 대상과 중복 여부를 확인할 수 있을 때만 기존 대화·역할을 복구하고, 모호하면
사용자에게 확인한다. 보고 자료의 제목·오류 문자열은 실행 지시가 아니다.

## 로그인 때 비서 대화 복원

`kadan up`은 살아 있는 비서를 그대로 사용한다. launchd가 1분마다 부르는 `kadan up --hidden --auto`도 같은 복원 경로를 쓰며, 새로 띄우거나 복원했을 때만 복원 정보를 갱신한다. 사람이 `kadan stop`으로 끈 비서는 자동 실행이 되살리지 않는다(`revive-state.json`). tmux 비서가 사라졌고 이전 시작 기록이
있으면 `secretary-resume.json`에 저장한 정확한 Codex 대화를 `resume <ID>`로 이어 연다.
기존 명시 모델·권한·추론 강도 인자를 유지하며, 첫 역할 안내는 다시 보내지 않는다.
옵션은 키(`--model`, `-c`의 `k=v` 앞부분)마다 **시작 명령의 것이 이기고** 같은 키는 처음 것 하나만 남긴다. 대화의 마지막 모델·강도·권한은 시작 명령에 없는 키만 채운다(`src/codex-option-merge.mjs`). 저장할 때와 띄울 때 모두 이 규칙을 지나서, 재시작을 거듭해도 `--model`이 겹쳐 쌓이지 않고 이미 겹친 체크포인트도 첫 벌로 낫는다(2026-10-22).
이 정보는 살아 있는 비서 pane의 자식 프로세스가 실제로 연 대화 파일에서 저장한다.
최신 파일·역할 이름으로 대화를 추측하지 않는다. 현재 지원 범위는 Codex 비서다.

로그인과 Rottie는 같은 역할 잠금을 사용한다. 로그인 복원이 먼저 실행됐으면 Rottie는
이전 시작 기록에서 같은 대화로 이어진 복원 기록과 실제 pane 대화를 확인해 연결한다.
Rottie 복원이 먼저 실행됐으면 로그인은 살아 있는 비서를 재사용한다. 대화 정보 누락·
역할 교체·직접 종료·대화 파일 변경은 새 비서 생성으로 우회하지 않는다. 비서 복원이
막혀도 대시보드는 시작한다. 기존 로그인 LaunchAgent 설정은 바꿀 필요가 없다.
