# 카단 흐름 지도

## Why

사람이든 AI(Claude·codex 등)든 카단에 처음 와서 **누가, 무엇을, 어떻게 주고받고, 감시가 무엇을 잡는지**를 이 한 장에서 잡는다. 이 흐름이 여러 문서에 흩어져 있어 AI가 일부만 읽고 틀린 결론을 내린 일이 있었다(2026-10-05, 감독→슈퍼감독 질문 경로를 빠뜨림). 여기에는 **지금 규칙만** 적는다. 바뀐 경위와 날짜는 각 상세 문서와 작업장 기록에 있다. 표의 각 줄은 상세 문서로 이어진다.

## 1. 누가 — 역할

관계는 관계표(`kadan watch --hierarchy`가 읽는 JSON, 값 = 직속 상위)가 정한다. 새 역할은 시작할 때 자동 등록되고, 담당이 바뀌면 `kadan handover`로 넘긴다. 이름이 비슷하다고 상하관계를 추측하지 않는다. → [책임 관계](hierarchy.md), [인계](handover.md)

| 역할 | 하는 일 | 직속 상위 | 실체 |
|---|---|---|---|
| 사용자 (`@user`) | 승인·결정. 대시보드로 본다 | — | 사람. 감시 경보는 OS 알림으로 받는다 |
| 비서 | 사용자 요청을 전하고 확인 결과를 돌려준다 | 사용자 | 대화형 AI 세션(`--profile secretary`) |
| 슈퍼감독 | 판 사이 충돌·우선순위 조정, 일반감독이 못 푼 판단, **사용자 결정 요청**(이것만 할 수 있다) | 사용자 | 대화형 AI 세션(`--profile super`) |
| 일반감독 | 카드 발령, 결과 검수, 승인 범위 안의 방법 선택·진단·복구 | 슈퍼감독 | 대화형 AI 세션(`--profile conductor`) |
| 작업자 | 구현 | 일반감독 | 대화형 AI 세션(`--profile worker`) |
| 검수자 | 독립 검증 | 일반감독 | 대화형 AI 세션(`--profile reviewer`) |
| 감시기 | 화면·원장을 읽고 이상을 알린다(감시sh + 작업 감시AI + 감독 관찰AI) | — | `kadan watch` 프로세스 하나 |
| 시니어 | 작업 결과에 결정할 부분이 있을 때 감독이 의견을 한 번 묻는 고급 모델. 결정하지 않는다 | — | 세션 아님. `kadan senior`가 부르는 일회성 호출 → [시니어](senior.md) |
| Claude Code 어드바이저 | 카드를 완수하려고 Claude Code 기능을 쓰는 것. 판단이 무거운 카드를 쓰기 전에 묻는다 | — | 카단 기능이 아니라 Claude Code로 띄운 세션 안의 도구. 시니어와 다른 기능이다 |

## 2. 무엇을 — 일의 단위

| 단위 | 뜻 | 누가 관리 | 상세 |
|---|---|---|---|
| 워크(업무 카드) | 약속한 결과 하나. 목표·범위·완료 조건·책임 감독(owner) | 책임 감독. 최종 완료는 `work complete` | [업무 카드](business-work.md) |
| 실행 카드 | 그 결과를 위해 지금 누구에게 무엇을 맡겼나. 구현·검수·수정·조사 | 일반감독이 만들고 발령 | [카드 안내](card-center.md) |
| 실행(발령 한 번) | 실행 카드를 역할에게 보낸 한 번. 실행 ID로 부른다 | 원장의 plan·dispatch·done | [카드 주소](task-identity.md) |
| 라운드(티키타카) | 구현 턴 + 독립검수 턴. 검수 불합격이면 다음 라운드 | 감독 | [티키타카](rallies.md) |

카드 상태는 세 묶음으로 읽는다: **진행 전**(초안·설계완료·보류) · **진행 중**(작업대기·작업중·일시정지) · **끝**(완료·취소·대체). 실행 기록으로 계산한 신호(발령됨·실패·확인 필요)는 묶음과 따로 본다. 모든 사건은 뒤에만 붙는 원장에 남는다 → [구조와 원장](architecture.md)

## 3. 어떻게 주고받나 — 소통 경로

| 흐름 | 누가 → 누구 | 명령 | 닫히는 조건 | 감시는 |
|---|---|---|---|---|
| 발령 | 일반감독 → 작업자·검수자 | `kadan send <역할> --task <실행>` 또는 `kadan work execute … --assign <역할> --dispatch "<지시>"` | 완료 보고 | 착수 보고가 없으면 `시작보고누락`. 발령 우편은 읽음 확인 대상이 아니다 |
| 착수 보고 | 작업자·검수자 → (카드) | `kadan card progress <카드> --activity running` | — | 읽음 확인을 대신한다 |
| 완료 보고 | 작업자·검수자 → 일반감독 | 결과 파일 등록 → 화면에 `KADAN:DONE <실행ID> <ok\|failed>` | 감독이 근거를 보고 `kadan done …`(필요하면 `--from-screen`, `--close-card`) | 화면에 표시만 있고 확정이 없으면 `완료후보` |
| 일반 우편 | 누구나 → 누구나 | `kadan send <역할> "<내용>"` (일에 관한 말이면 `--work`·`--execution`) | 받은 쪽이 `kadan inbox ack <우편ID>` | 5분 넘게 미확인이면 받은 쪽에 묶음 재알림 |
| 질문(답 대기) | 하위 → 상위 (예: 일반감독 → 슈퍼감독) | `kadan send <상위> --expect-reply "<질문>"` | 답하는 쪽이 `kadan send <묻는 쪽> --reply-to <우편ID> --reply-final "<답>"` | 그 카드는 **묻는 쪽의 할 일에서 빠지고, 답할 쪽의 할 일로 남는다** |
| 사용자 결정 | 슈퍼감독 → 사용자 | `kadan decision request …` | 사용자가 대시보드 '내 결정' 또는 `kadan decision answer`로 답 → 요청자에게 통지 | 그 카드(와 소속 워크)는 **모두의 할 일에서 빠진다** |
| 시니어 의견 | 일반감독·슈퍼감독 → 시니어 | `kadan senior <카드> --question "<질문>"` | 한 번 호출로 끝. 답은 기록이지 결정이 아니다 | 대상 아님 |
| 어드바이저 자문 | Claude Code 감독 → 어드바이저 도구 | Claude Code 안의 도구. 요지를 카드의 `advisor 자문 요지` 칸에 | 카드 작성 전 한 번 | 대상 아님 |
| 인계 | 선임 → 후임 | `kadan handover <선임> --to <후임>` | `finish` | 카드·워크·우편의 책임을 후임으로 따라간다 |
| 감시 경보 | 감시기 → 직속 상위(최상위면 사용자 OS 알림) | 자동 | 해소 우편은 없다. 원장 기록과 감시 출력만 | 경보를 받으면 행동 전에 `GET /api/dashboard/status?super=<슈퍼감독>`으로 지금 상태를 읽는다 |

질문이 올라가는 순서(작업자 → 일반감독 → 슈퍼감독 → 사용자)와 사용자만 답할 수 있는 질문은 [질문 사다리](../skills/kadan-conductor/references/tiki-taka.md)를 따른다. 감독은 사용자에게 묻기 전에 슈퍼감독에게 먼저 묻는다. 예외(기존 승인 밖의 삭제·초기화·마이그레이션·push·병합·배포, 범위 변경, 18라운드 상한, 슈퍼감독이 없거나 답이 없을 때)에만 사용자에게 직접 간다. `decision request` 명령 자체는 슈퍼감독만 쓸 수 있다. 명령 전체는 [명령어 사전](commands.md).

## 4. 감시가 잡는 것 — 경보

경보는 관계표의 직속 상위에게 가고, 상위가 죽었으면 같은 사슬의 다음 상위, 끝까지 없으면 사용자(OS 알림)에게 간다. 해소 우편은 보내지 않는다. 시간 기준은 기본값이며 감시 프로필(`~/.kadan/watch-profile.json`)이 바꿀 수 있다. → [감시 안내](watch-overview.md)

| 경보 (원장 이름) | 대상 | 울리는 조건 | 누구에게 |
|---|---|---|---|
| 작업자 멈춤 (`정체`) | 작업자·검수자 | 실행을 맡고 화면이 `--stall-after`(기본 5분) 안 바뀜 → 작업 감시AI가 판정 | 직속 감독 |
| 진행 조정 (`진행조정`) | 작업 중인 작업자 | 30분 간격 화면 비교에서 반복 실패·범위 확장 판정 | 직속 감독(연속이면 상위로 조정 요청) |
| 감독 멈춤 (`놀고 있음`) | 일반감독·슈퍼감독 | 할 일(안 끝난 카드, 진행 중 실행이 없는 열린 워크)이 있는데 그 감독과 아래 화면이 `--idle`(기본 15분) 안 바뀜. **답을 기다리는 일은 할 일에서 뺀다**(3절 질문·사용자 결정) | 1단: 본인. 2단(두 배 시간): 상위, 최상위면 사용자. 2단이 뜨면 1단은 해소가 아니라 흡수로 닫힌다 |
| 시작 보고 누락 (`시작보고누락`) | 발령받은 역할 | 발령 뒤 `--start-report-after`(기본 5분) 안에 착수(`running`)·기다림(`waiting`)·완료 보고가 없음 | 직속 감독 |
| 완료 후보 (`완료후보`) | 작업자·검수자 | 화면에 완료 표시가 떴는데 `--completion-grace`(기본 15분) 안에 done 확정이 없음 | 직속 감독 |
| 세션 종료 (`죽음`) | 모든 등록 역할 | 세션이 없거나 PID가 바뀜 | 직속 상위. 최상위 슈퍼감독이면 사용자(RED) |
| 연결 끊김 (`끊김`) | 등록 역할 | 화면에 접속·네트워크 오류 | 직속 상위 |
| 한도 (`한도`) | 작업자 | 화면에 한도(429) 표시. 일시 한도는 1·2·3분 뒤 최대 3번 자동 재개, 일일 한도·잔액 부족은 재개하지 않음 → [429 재개](rate-limit-retry.md) | 직속 감독 |
| 설정 오류 (`설정`) | 등록 역할 | 화면에 인증·설정 오류 | 직속 상위 |
| 입력 큐 (`입력큐`) | 실행 중 작업자 | 큐 배너(`Press Enter to send queued messages now`)가 뜸. 안전하면 Enter를 한 번 보내고, 배너가 남으면 경보 하나 | 직속 감독 |
| 큐 대기 (`큐대기`) | 발령 없는 세션 등 | 그 밖의 큐 배너·큐 블록이 5분 넘게 남음 | 직속 상위 |
| 상태 확인 필요 (`모름`) | 등록 역할·감시기 | 화면을 읽지 못함(역할), 원장을 읽지 못함(감시기) | 역할은 직속 상위, 원장 오류는 공통 수신자 |
| 감시AI 오류 (`감시AI오류`) | 감시 AI 호출 | 판정 호출이 실패·시간 초과·보고 누락(대체 후보까지 실패). 인터넷 없음은 깨어 있는 동안 3번 연속일 때만, 맥북 잠자기로 끊긴 호출은 알리지 않음 | 사용자(OS 알림·감시 출력). 판정 프로그램·모델 장애는 운영자 몫이라 감독에게 보내지 않는다 |
| 전달 실패 (`전달실패`) | 경보 자체 | 경보 우편을 받는 쪽 창에 넣지 못함 | 받지 못한 쪽의 상위(관계표에 없으면 `--super`) |
| 감시 제외 (`감시제외`) | 경보 자체 | 대상이 감시 범위를 벗어나 경보를 닫음(회복 편지 없음) | 기록만 |
| 자원 (`자원`) | 이 컴퓨터 | 메모리·스왑·부하 | 우편 없음. 대시보드에서 본다 |

감독 관찰AI는 활성 책임이 있는 감독의 응답 상태를 1시간마다 따로 점검한다(정당한 결과 대기는 정상).

## 5. 사람이 보는 곳

대시보드(`kadan dashboard`, 기본 8790): 전체 현황(내 결정 대기·지금 막힌 것·슈퍼감독별 현황), 전략 맵(기지·유닛 지도), 워크·카드, 내 결정, 실행 모델(시니어·감시 AI 모델 포함), 우편함, 기록. → [화면 지도](dashboard-status-guide.md#화면-지도)

## 이 문서를 고칠 때

- 역할·소통 경로·경보 종류·명령을 바꾸는 PR은 같은 PR에서 이 표도 고친다. 상세 규칙은 각 상세 문서에 두고, 여기에는 한 줄 요약과 링크만 둔다.
- `tests/flows-map.test.mjs`가 감시 코드의 경보 종류와 핵심 명령이 이 문서에 빠지지 않았는지 확인한다.
