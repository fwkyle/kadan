# 대시보드에서 구현·검수 왕복 읽기

## Why

사용자가 여러 실행 카드를 읽지 않고도 한 작업을 몇 번 고쳤고 어떤 검수 결과로 끝났는지 확인한다.

카드 상세 위에는 같은 티키타카 묶음의 검수 횟수, 수정 횟수, 최신 검수 판정과 라운드별 구현·검수 표가 나온다. 이전 구현 카드나 마지막 검수 카드 어느 쪽을 열어도 같은 흐름을 읽는다. 업무 상세의 **작업별 티키타카**에서는 여러 작업을 각각 펼친다. 옛 대시보드의 구현·검수 비교 표를 현재 화면에 복구한 것이다.

- **검수 횟수:** 검수 단계에서 등록한 `pass` 또는 `changes` 결과 수. 결과 하나를 진행 보고에 반복해서 언급해도 한 번만 센다.
- **수정 횟수:** `fix` 또는 2라운드 이후 구현 단계의 `implemented` 결과 수. 진행 중인 수정은 횟수에 아직 포함하지 않는다.
- **최신 판정:** 가장 뒤 라운드의 검수 결과. 실행 `ok`·DONE만으로 통과를 만들지 않는다. 이후 발령·범위 변경으로 낡은 결과는 과거 횟수에는 남기고 최신 판정에서 제외한다.
- **결과 읽기:** 각 칸의 결과 원문을 필요할 때 읽는다. 등록한 SHA-256과 현재 파일이 다르면 바뀐 파일을 당시 검수 근거로 보여주지 않는다.
- **연결 확인 필요:** 라운드가 빠졌거나 같은 단계가 중복됐거나 검수에 대응하는 구현이 없으면 최종 통과로 표시하지 않는다. 이름·PR 번호·우편 횟수로 연결을 추측하지 않는다.

## 같은 작업의 다음 카드 연결

구현과 검수는 같은 묶음 ID·같은 라운드다. 수정과 재검수는 그 묶음의 다음 라운드다. 단계마다 새 묶음 ID를 만들지 않는다.

```sh
kadan card update 저장소/검수카드 --revision 2 \
  --rally-from 저장소/구현카드 --rally-round 1 --rally-step review \
  --note '같은 구현의 첫 검수'
kadan card update 저장소/수정카드 --revision 2 \
  --rally-from 저장소/구현카드 --rally-round 2 --rally-step fix \
  --note '첫 검수 지적을 수정하는 다음 라운드'
```

`--rally-from`은 앞 카드의 묶음 ID·제목·판을 이어받는다. 저장소·판이 다르면 거부한다. 이번 라운드와 단계는 명시해야 하며 메시지를 보내거나 실행을 다시 시작하지 않는다. 업무 연결의 `--round`도 같은 번호로 적는다. 병렬 작업의 일련번호를 라운드로 쓰지 않는다.

한 업무 카드 안에서 여러 번 왕복해도 기존 업무와 묶음을 이어간다. 실행 결과는 한 실행 카드에 한 번 등록하는 기존 규약을 유지하며, 수정·독립 재검수는 같은 묶음의 후속 실행으로 연결한다. 같은 카드 안의 대화·시험 재실행 횟수는 검수 횟수로 추측하지 않는다. 과거 연결을 고칠 때도 원래 결과·상태는 보존하고 변경 이유가 있는 새 카드 이력을 추가한다.
