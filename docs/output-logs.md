# 터미널 출력 기록

## Why

사용자가 오래 쌓인 터미널 출력을 실행 시작 단위와 제한된 파일 크기로 보관하고,
필요할 때 원문 바이트를 다시 확인할 수 있도록 한다.

## 새 세션의 형식

tmux 세션을 새로 만들 때 `out/<세션>/<UTC 시작시각-고유값>/` 폴더를 만든다.
`start.outputLog`에는 이 폴더의 `manifest.json` 경로가 기록된다.

- `format`: `kadan-output-v1`
- `session`, `createdAt`: 세션 이름과 기록 시작 시각
- `encoding`: `gzip` 또는 `raw`
- `partPrefix`, `suffixLength`: `part-` 뒤에 영문 소문자 6개
- `partBytes`: 파일당 최대 8MiB. 분할 도구가 없으면 `null`로 상한 없음을 표시

gzip으로 압축한 바이트 스트림을 `part-aaaaaa`, `part-aaaaab` 순서로 나눈다.
출력이 10배이면 디스크의 조각 수가 늘지만 로거의 버퍼·프로세스 수는 늘지 않는다.
같은 역할을 다시 시작해도 다른 폴더를 쓰므로 이전 실행에 이어 쓰지 않는다.
형식 파일과 조각은 소유자만 읽고 쓸 수 있게 만든다.

## 복원과 종료

먼저 형식 파일의 `encoding`을 확인한다. `gzip`이면 아래처럼 **그 세대의 모든 조각을
이름 순서대로 이어 붙인 다음** 압축을 해제한다. 조각 하나씩 해제하면 안 된다.

```sh
log_dir='/absolute/path/to/out/session/generation'
cat "$log_dir"/part-?????? | gzip -dc
```

`raw`이면 같은 순서로 `cat "$log_dir"/part-??????`만 실행한다.
출력이 없는 raw 세션은 조각이 없을 수도 있다.
실행 중에는 gzip 종료부가 아직 없어 복원 명령이 오류로 끝날 수 있다.
완전한 압축 검증은 세션을 끝내 로거의 입력까지 닫힌 뒤 한다.
형식 파일이 존재한다는 사실만으로 기록이 끝났거나 모든 쓰기가 성공했다고 판단하지 않는다.
파이프의 압축·분할 실패는 로거가 성공 종료로 숨기지 않지만, 세션 자체를 종료하지는 않는다.

## 보존과 자원 비용

이미 실행 중인 로거는 교체하지 않는다. 기존 `.log`·`.log.gz`와 원장 사건도 그대로 둔다.
옛 `.log.gz`는 기존처럼 `gzip -dc`로 복원하며 여러 gzip 멤버도 순서대로 읽는다.
gzip이 없으면 경고 후 원문 조각으로 보존한다. split 또는 `/bin/bash`가 없으면
경고 후 해당 세대의 한 파일로 보존하며 기본 `/bin/sh`만 쓴다. 도구를 자동 설치하지 않는다.
원문·근거의 자동 삭제나 보존 기한은 추가하지 않는다.

기존 gzip에 bash·split 프로세스가 더해진다. macOS의 작은 2.5MB 입력 비교에서는
프로세스 RSS 합이 세션당 약 3.3MiB 증가했다. 파일 관리 개선이며 메모리 감소 기능은 아니다.
Node 로거를 세션마다 추가하지 않으며, 화면 읽기·DONE 판정·원장 저장 경로는 유지한다.
herdr의 출력 기록 방식은 이 변경의 대상이 아니다.

검증 근거에는 필요한 로그·결과·원본 경로·커밋이나 파일 지문을 남긴다.
저장소 복제본·패키지·빌드 캐시는 작업 공간에 두고 기존 근거 파일은 자동으로 옮기거나 지우지 않는다.
