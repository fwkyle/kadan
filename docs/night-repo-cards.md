# 나이트런 중 자동 머지 정책: 카단 설정과 카드 폴더 연결

## Why

저장소마다 "배포 브랜치가 무엇이고, 나이트런 중 자동 머지를 해도 되는가"를 카단이 알아야 자동 단계의 머지 관문이 판정할 수 있다. 이 값의 원본은 카단 자체 설정이다. 그래서 카단을 내려받아 쓰는 누구나 같은 방식으로 쓴다. 자기 노트의 마크다운 카드 폴더가 있는 사람은 그 폴더를 연결해 빈 칸을 채울 수도 있다(선택).

## 카단 설정(원본)

저장소(GitHub `소유자/이름`, 소문자, 끝 `.git`·`/` 제거)마다 칸 두 개를 `$KADAN_HOME/night-repo-policy.json`에 둔다. 칸은 따로 둘 수 있다.

| 칸 | 값 | 뜻 |
|---|---|---|
| `deployBranch` | 브랜치 이름 또는 `없음` | 이 브랜치로 가는 PR은 나이트런 중 자동 머지 안 함. `없음`은 어떤 브랜치도 아니다 |
| `nightMerge` | `허용` · `금지` | `금지`면 이 저장소는 나이트런 중 자동 머지 안 함. 비어 있으면 허용으로 본다 |

```
kadan night repo <소유자/이름> --deploy-branch <브랜치|없음> --night-merge 허용|금지   # 둘 중 하나만 줘도 된다
kadan night repo <소유자/이름> --clear deployBranch|nightMerge                       # 칸 하나 지우기
kadan night repo list | show <소유자/이름>                                            # 읽기
```

## 카드 폴더 연결(선택, 기본은 연결 없음)

```
kadan night source                      # 보기
kadan night source --cards <폴더> [<폴더>…]   # 등록(이미 있던 목록을 바꾼다)
kadan night source --clear              # 해제
```

연결한 폴더의 `.md` 파일 앞머리(`---` 사이)만 읽는다. 하위 폴더는 훑지 않고 링크는 따라가지 않는다. 폴더 자체가 링크면 등록을 거절하니 실제 폴더 경로를 등록한다. 읽는 칸은 셋이고 정확히 `키: 값` 형식이어야 한다. 형식이 틀리거나 같은 칸이 두 번 나오면 그 카드는 못 읽은 것이다.

```
---
remote: github.com/소유자/이름 (또는 git@github.com:소유자/이름.git, 맨 소유자/이름. 첫 낱말만 읽는다)
deploy_branch: main (낱말 하나, 뒤에는 괄호 설명만. 또는 {소유자/이름: 브랜치, …} 짝 목록)
night_merge: 금지 (허용 | 금지. 칸이 없으면 허용)
---
```

설명은 괄호로 적는다. `#` 주석은 지원하지 않는다(`main # 설명`은 읽지 못한 것으로 본다).

카드 찾기: 먼저 `deploy_branch` 짝 목록에 그 저장소 키가 있는 카드, 없으면 `remote`가 그 키인 카드. 하나만 맞아야 한다(둘 이상이면 못 읽은 것).

## 합치기와 판정

칸마다 카단 설정 값이 있으면 그 값, 없으면 연결된 카드의 값, 둘 다 없으면 비어 있다. 판정(위에서부터 처음 맞는 것):

0. 연결된 카드 중 하나라도 못 읽으면, 두 칸을 카단 설정으로 다 정하지 않은 저장소는 설정 필요(`setup-needed`)
1. 카드 쪽이 못 읽히는데 그 칸을 카단 설정이 채우지 않았으면 → 보류(`setup-needed`)
2. `nightMerge`가 `금지` → 보류(`night-merge-forbidden`)
3. `deployBranch`가 비어 있음 → 보류(`setup-needed`)
4. 대상 브랜치 == `deployBranch` → 보류(`deploy-branch`)
5. 그 밖 → 나이트런 중 자동 머지(`allowed`)
