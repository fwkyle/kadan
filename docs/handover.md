# 역할 인계 CLI

## Why

[kyle]이 문맥이 찬 감독을 교대할 때 후임의 인수 확인부터 담당 이전까지 한 번에 이어가고, 상위 AI가 그동안 상태를 반복 조회하며 기다리지 않도록 한다. 후임이 준비되기 전에는 선임을 종료하지 않는다.

## 순서

외부 지휘자가 시작 명령을 한 번 실행한다. 기본값은 백그라운드 처리다. 후임은 직접 자료를 읽고 인수를 확인하며, 일회성 프로그램이 그 뒤의 전환을 이어간다.

승인 범위 안에서 실제 응답 장애가 확인된 작업자·검수자의 단일 교대는 소유 일반감독이 결정한다. 감독 자신의 교대는 직속 상위가 맡는다. 정상 입력 대기·문맥 사용률만으로 교대하지 않으며, 기존 업무·실행·결과와 모델·작업공간을 보존한다. 권한·중지 조건은 [공통 운영 기준](../skills/kadan-conductor/references/operating-contract.md#일반감독의-결정-범위)을 따른다.

```sh
KADAN_ROLE=프로젝트-슈퍼감독 kadan handover 프로젝트-감독 --to 프로젝트-감독-2 --at-boundary \
  --hierarchy /절대경로/역할관계.json --context /절대경로/현재승인과카드.md \
  --cwd /절대경로/작업폴더

# 시작 결과를 받은 지휘자는 여기서 응답을 끝낸다.
# 후임의 독해가 끝날 때까지 read/status/finish를 반복하지 않는다.

# 후임이 카드·원장·결과를 읽고 작성한 인수 근거
KADAN_ROLE=프로젝트-감독-2 kadan handover accept <인계ID> --receipt /절대경로/인수근거.json

# 완료 통지나 문제를 확인할 때만 조회한다.
kadan handover status <인계ID>
```

- 시작 명령이 돌아왔다는 것은 인계가 완료됐다는 뜻이 아니다. 대기 프로그램이 맡았다는 뜻이다. 후임의 인수 확인과 watch의 관계 반영을 기다린 뒤 완료 또는 문제를 한 번 알린다. 정상 진행·도착 확인 편지를 별도로 요구하지 않는다.
- 후임이 자료를 읽는 동안 상위 AI는 다른 작업을 하거나 응답을 끝낸다. 후임의 첫 업무 결과까지 기다리는 절차를 추가하지 않는다.
- 최종 통지는 호출자의 `KADAN_ROLE`로 보낸다. 역할 없이 사람이 실행하면 기존 비서 우편함에 저장한다. `--notify <역할>`로 수신자를 지정하거나 `--notify @user`로 사용자 알림을 선택할 수 있다. 비서 우편의 `stored`는 저장을 뜻하며 대화창 도착 확인은 아니다.
- `--wait-timeout <초>`는 인수·watch 반영을 합친 프로그램의 대기 한계다. 기본은 1800초다. 시간 초과는 인계 문제로 기록하며 선임을 강제로 종료하지 않는다. 제품 작업의 마감 시각이나 새 승인 조건을 만드는 옵션이 아니다.
- `--at-boundary`는 선임이 새 발령을 멈추고 안전한 카드 경계에 있다는 호출자의 확인이다. 프로그램이 진행 중인 AI를 강제로 정지시키지는 않는다.
- `--context`는 현재 승인 범위·카드·보류 사항의 기준 문서다. 인계 자체가 새 구현이나 배포 승인은 아니다.
- 명령과 폴더는 선임 start 원장의 값이 있으면 생략 가능하다. 과거 기록에 없으면 명시해야 한다. 실행 도구와 모델을 임의로 바꾸지 않는다.
- 후임 이름은 과거에도 쓰지 않은 이름을 쓴다. 창은 `KADAN_WINDOW`를 따른다. 미설정 시 `KADAN_ROTTIE_BIN`이 있으면 로티, 없으면 백그라운드다. 로티 생성 실패는 선임을 보존하고 오류로 끝낸다.
- 인수 근거 형식: `{"taskIds":["card-a"],"evidencePaths":["/절대경로/결과.md"],"nextAction":"이어서 할 행동"}`. 카드 목록은 준비 시점의 선임 미완료 카드와 일치해야 한다.
- 인수 확인은 후임 역할의 선언과 근거 파일 존재를 검사한다. AI의 이해나 실제 구현 성공까지 자동 증명하는 기능은 아니다.

## 전환과 보존

`finish`는 후임 인수 확인 → 직속 상위·하위 수신자 관계 변경 → 살아 있는 watch의 새 관계표 반영 기록 확인 → 카드 책임 이전 기록 → 정확한 선임 PID 종료와 연결 창 닫기 시도 → 후임 활성화 편지·하위 역할 수신자 변경 편지 순서다.

기본 백그라운드 처리는 이 `finish` 절차를 재사용한다. 인수 대기 중 공용 인계 잠금을 잡지 않으므로 후임의 `accept`를 막지 않는다. 새 감시기나 AI 반복 호출을 만들지 않는다.

원장의 옛 줄은 수정하지 않는다. 시스템 원장에 `handover/transferred`를 한 번 추가하면 카드와 우편의 현재 책임 계산에 함께 반영한다. 인수 수락만으로는 우편 책임을 옮기지 않는다. 확정 이전 당시 존재한 우편만 승계하고, 이후 재사용한 역할 이름의 새 독립 우편은 소급 이전하지 않는다. 늦게 도착한 `replyTo` 답장은 원본 발신자의 현재 책임을 따른다. 과거 우편의 보낸이(`by`)·받는이(`role`)와 본문, 카드 파일은 보존한다. 실행 중 하위 역할에는 새 보고 대상을 알리지만 과거 카드 문장을 자동 고치지 않는다.

후임은 자기 역할로 `inbox received`·`to-reply`·`sent`·`waiting`을 조회한다. 현재 수신 책임자는 명시적 ack와 답장을, 현재 발신 책임자는 답변 대기 취소를 맡는다. 답장의 수신 주소도 현재 발신 책임자를 사용한다. 이전에 기록된 읽음·답변은 당시의 인계 상태로 판정하며, 현재 화면에서는 원래 참가자와 현재 책임자를 함께 보여준다. 여러 차례 인계와 감시 알림의 책임 기준은 [구조 기준](architecture.md#인계-뒤의-우편-책임)을 따른다.

인계 스냅샷·안내문은 `$KADAN_HOME/handovers/`(기본 `~/.kadan/handovers/`)에 보관한다. 일회성 프로그램 기록은 `<인계ID>.runner/`에 남는다. 시작 결과와 `status`에서 `runner.pid`, `runner.resultPath`, `runner.status`, `runner.notification`을 확인할 수 있다. 전체 명령·관계표 원문은 보존 파일에 두며 기본 출력에서 반복하지 않는다.

자동 시작 결과의 `nextAction`은 지정 수신자에게 종결 통지를 맡기고 호출한 AI가 응답을 끝내도록 안내한다. 일반 상태 조회나 실패 결과에는 이 안내를 넣지 않는다.

`status`의 `childNotices`와 종료 원장의 창 닫기 결과도 보존한다. `complete`는 전환 절차가 끝났다는 뜻이며 하위 편지 실패나 사용자의 실제 열람까지 보장하지 않는다.

## 수동 처리와 복구

직접 전환 시점을 정할 때만 시작 명령에 `--manual`을 붙인다. 이 경우 대기 프로그램을 띄우지 않는다. 후임의 `accept` 뒤 외부 지휘자가 아래 명령으로 전환한다.

```sh
kadan handover finish <인계ID> --timeout 90
```

자동 인계가 문제로 멈춘 경우에도 원래 인계 ID와 `status`의 현재 상태를 기준으로 복구한다. 새 후임을 만들거나 동일 프로그램을 다시 띄워 수를 늘리지 않는다. 알 수 없는 송신 실패는 자동 재전송하지 않는다.

## 실패 시

- `prepared`: 후임이 아직 인수 확인 전이다. 선임 보존.
- `routes-pending`: 새 관계표를 watch가 읽었다는 기록이 없다. 선임 보존. 감시기 버전·생존·설정 경로를 확인한 뒤 같은 `finish`로 이어간다. 인계 대상 관계표를 실제 감시하는 watch가 필요하다.
- 준비 이후 카드·승인·관계가 달라지면 선임 종료를 막는다. `abort`로 준비를 취소하고 새 근거로 다시 준비한다.
- `transferred`: 카드 책임은 후임에 있으나 선임 종료가 실패했을 수 있다. 상태/PID를 확인하고 같은 `finish`로 이어간다.
- `activation-pending`: 활성화 편지의 성공 여부가 불확실하다. 중복 발령을 막기 위해 자동 재전송하지 않는다. 후임 화면과 원장을 확인하고 외부 지휘자가 수동으로 처리한다.
- `kadan handover abort <인계ID>`는 책임 이전 전에만 가능하다. 다른 사람이 관계표를 바꾸지 않았다면 원본을 복원한다. 후임은 자동 종료하지 않는다. 감시기의 원복 반영을 확인한 뒤 선임을 재개한다.
- 중단된 프로세스가 `.lock`을 남기면 자동 제거하지 않는다. 진행 중 인계가 없는지 확인하고 보존 이동한 뒤 재개한다.
- 대기 프로그램이 끝났는데 인계가 완료되지 않았다면 `runner.status`와 `runner.error`를 먼저 읽는다. 비정상 종료는 `interrupted`, 통지 중단으로 전달 여부를 모르면 `notification.status=unknown`으로 구분한다. 결과·단일 실행 소유 기록을 지워 자동으로 재시도하지 않는다.
- 프로그램 초기화나 모듈 불러오기가 실패하면 결과 파일에 실패 단계를 남긴다. 통지 기능까지 실행하지 못한 경우는 `notification.status=not-attempted`이며, 통지가 전달된 것으로 보지 않는다.

현재 버전은 자동 문맥 임계치 감지, 주기적인 교대 예약, 미배정 카드 자동 발령을 포함하지 않는다. 사용자 직접 승인 또는 위임 범위에서 담당 감독이 결정한 인계 한 건의 남은 절차만 이어간다.

## 이미 종료된 선임 복구

사용자 실수 등으로 선임 세션이 이미 사라졌으면 명시적으로 `--source-ended`를 붙인다. 마지막 start 원장의 PID와 세션 부재를 확인하고 같은 인수·관계 이전 절차를 사용한다. 살아 있는 선임에는 사용할 수 없으며, 도중 선임이 다시 나타나면 전환을 중단한다. 죽은 선임을 임시 재기동하거나 종료 명령을 보내지 않는다.
