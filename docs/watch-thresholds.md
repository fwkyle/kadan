# 이름과 시간 기준 한 곳 표

## Why

같은 말이 곳마다 다른 기준을 가리켜 사람이 숫자를 맞춰 보다 오해한다(예: 우편 '미확인'이 inbox·대시보드는 2,053통, 감시 후보는 476통). 이 문서는 **값이 일부러 다른 것**을 이름으로 나누고, 시간 기준을 한 표에 모은다. 근거: 같은 개념 감사(최종안 7번, 2026-10-21). 판정 코드·상수 값은 바꾸지 않았다.

**원칙: 값이 같다고 합치지 않는다.** 5분이 네 군데, 15분이 세 군데, 24시간이 다섯 군데 있어도 각각 다른 개념의 독립 상수다. 한 곳을 고쳐도 다른 곳은 따라오지 않으며, 그것이 의도다.

## 1. 이름 나누기

### 우편

| 화면·CLI에 쓰는 이름 | 뜻 | 센 곳 |
|---|---|---|
| 읽음 기록 없음 | 수신자가 직접 `ack`한 기록도, 창 전달 읽음(`delivered-read`)도 없는 우편(기록용 알림 제외, 이전 세대 제외). 읽음 판정 `mailbox-state.mjs:68-69`, 집계 `:17` | `kadan inbox`, 대시보드 우편함·홈 `mailbox-state.mjs` `isUnreadLetter` |
| 알림 대상 | 감시기가 수신자에게 다시 알릴 우편. '읽음 기록 없음'에서 발령 우편·시스템 우편·사용자 수신을 더 빼고 유예·업무 상태까지 맞은 것 | `watch-mail.mjs` |

- 두 숫자는 **일부러 다르다.** 같은 사본에서 읽음 기록 없음 2,053통, 알림 대상 후보 상한 476통이었다(발령 우편 1,577통은 감시가 일부러 뺀다. 감사 때 계산한 근사값).
- 숫자를 맞추지 않는다. 화면에서 제외 사유를 다시 계산하지 않는다. 필요해지면 `watch-mail.mjs` 판정이 사유를 돌려주게 한다(후속).
- 감시기가 수신자 창에 보내는 알림 첫 줄 `미확인 우편 N건`은 [kyle]이 글자 단위로 정한 형식(`tests/watch-notice-mail-format.test.mjs`)이라 바꾸지 않았다. 이 N은 '알림 대상' 수다.
- '창 전달 읽음'은 수신자가 확인했다는 뜻이 아니라 창에 전달됐다는 뜻이다. 그래도 `read=true`로 투영되어(`mailbox-state.mjs:68-69`) 직접 `ack`가 없어도 '읽음 기록 없음'에서 빠진다(`tests/mail-delivered-read.test.mjs:23`).
- '이전 세대 미확인'은 같은 이름을 새 세션이 다시 쓰기 전 우편이며 위 두 숫자에 들어가지 않는다.

### 막힘 세 가지

| 이름 | 기준 시간 | 어디에 보이나 |
|---|---|---|
| 지금 막힘 | 담당 세션이 살아 있거나 마지막 신호가 24시간 안인 미완료 실행 | 대시보드 칩 '지금 막힌 것', 전략 맵 '막힘' |
| 오래된 미확정 | 담당 세션이 없고 신호가 24시간(`STALE_MS`) 넘게 없거나 다음 일로 넘어간 실행 | 대시보드 접힌 '오래된 미확정' |
| 완료 미확인 | 발령 뒤 완료 확인이 없는 실행. 실행 이력 표시는 시간 유예 없이 바로 붙는다(`decision-wall.mjs:21`, `card-center.mjs:37`) | 실행 이력 상태 '완료 미확인' |
| 설명 AI 막힘 사건 | `unconfirmed` 실행이 발령 뒤 10분(`UNCONFIRMED_GRACE_MS`)을 넘기면 `blocked` 사건을 만든다. `orphaned`는 유예 없이 바로 만든다(`explain-events.mjs:9,29-31`) | 설명 AI 사건 `blocked` |

위 세 이름은 이미 화면에서 서로 다른 글자라 라벨은 바꾸지 않고 기준 시간만 여기 적는다. 설명 AI 막힘 사건은 이름이 아니라 사건 종류이며 '완료 미확인' 표시와 시간 기준이 다르다.

## 2. 멈춤·정체 시간 계단

같은 '안 움직임'을 **근거가 다른** 여러 기준으로 가른다. 한 함수로 합치면 의미가 바뀐다.

| 시간 | 이름 | 근거 | 위치 |
|---|---|---|---|
| 4분 | 멈춤 | 화면 모양: 상태 줄 idle + 빈 입력창 | `watch-status-line.mjs:10` |
| 5분 | 정체 | 화면 지문이 `--stall`(기본 2)주기 같고 변화 없는 시간도 `--stall-after`(기본 5분) 이상(`watch-judge.mjs:82-84`) | `commands/watch.mjs:141` |
| 15분 | 놀고 있음 | 감독 화면 지문 무변화(`--idle`) | `commands/watch.mjs:152` |
| 1시간 | 감독 정기 확인 | 시간(AI 점검 한 번) | `watch-supervisor-health.mjs:8` |
| 4시간 | 같은 화면 재사용 상한 | 원장의 마지막 요청 뒤 이 시간이 지나면 지난 정상 화면과 같아도 다시 확인 | `watch-supervisor-health.mjs:11` |

대시보드의 '작업중'·'막힘'은 화면이 아니라 카드 진행 보고와 세션 생존을 근거로 하므로 이 계단과 축이 다르다.

## 4. 세대 규칙 두 개

- 우편: `mail-generation.mjs`. 편지·인계 시각이 기준이고, 못 넣은 새 우편은 이전 세대가 아니라는 예외(`isGenerationExempt`)가 있다.
- 책임: `owner-generation.mjs`. 책임이 마지막으로 붙은 시각(`ownedAt`)이 기준이다. `owner-generation.mjs:4`가 이미 우편의 세대 경계를 가져다 쓴다.
- 남은 차이(못 넣은 새 우편 예외가 책임엔 없음)는 **의도**다. 합치면 기존 예외가 바뀐다. 합치지 않는다. 새 사고가 나면 그때 다룬다.

## 5. 'idle'의 두 뜻

- 작업자 상태 줄의 idle은 '진행 증거(시계 증가)가 없다'는 뜻이다. **정상 대기의 증거가 아니다.** 일을 기다리는 중과 멈춘 것을 이 글자만으로 가르지 못한다.
- 감독 관찰AI(#219)는 정상 대기를 화면 모양으로 해석하지 않고, 지난 관찰AI가 정상(`입력대기`·`실행완료`)으로 본 화면과 지문(`changeDigest`)이 같을 때만 정기 확인을 건너뛴다. 화면 모양 판정을 없앤 커밋이 `9f71670`이고, 건너뛰는 조건은 [watch-overview](watch-overview.md)의 감독 관찰AI 절에 있다. 4시간(`SUPERVISOR_REUSE_MS`)은 같은 화면 재사용의 상한이다.

## 6. 감독 오류 판정은 현행 유지

감독 화면의 오류는 아래 20줄 어디든 목록 문구가 있으면 후보로 보는 **넓은 판정**(`watch-supervisor-health.mjs:69`)을 유지한다. 오류 덩어리 구조만 보는 좁은 판정과 비교한 표본(운영 원장 사본, 감독 점검 요청 1,691건)의 결과다.

| 판정 | 후보가 된 건 | 실제 오류 | 헛 후보 | 놓침 |
|---|---|---|---|---|
| 넓은 판정(현행, 아래 20줄) | 9 | 9 | 0 | 0 |
| 좁은 판정(오류 덩어리) | 6 | 6 | 0 | 3 |

- 놓친 3건은 줄바꿈으로 머리줄을 못 찾음, 알림 줄이 오류와 입력창 사이에 낌, 위 응답 문단 때문에 소개문단으로 제외됨이었다.
- 한계: 표본이 모두 codex 화면이라 claude 감독의 화면은 없다. 인용·설명 글이 오류로 오판된 정상 화면은 이 사본에 0건이다(운영 사례 확인 못 함).
