# 작업별 티키타카

## Why

같은 작업의 구현·수정·검수 카드와 현재 담당을 한 묶음으로 보여주어 역할 이름을 해석하지 않아도 진행을 이해하게 한다.

새 업무의 전체 결과·병렬 실행·최종 완료는 [업무 카드와 실행](business-work.md)의 `work`를 쓴다. 아래 랠리는 기존 카드의 연결 방식이며, 랠리 완료를 업무의 최종 완료로 바꾸어 읽지 않는다. 기존 랠리 이력은 보존한다.

## 원본

기존 카드 사건에 rallyId(저장소·판 안의 묶음 ID), rallyTitle(사람용 제목), rallyRound(1부터 시작하는 왕복 번호), rallyStep(implementation/fix/review/research)을 함께 기록한다. 조사는 round=0으로 연결하며 왕복에 세지 않는다. 연결 변경은 revision과 이유를 요구하고 과거 이력을 보존한다. 이름 유사도만으로 자동 연결하지 않는다. 검수 카드 결과 ok는 해당 검수 완료이지 판 전체 배포 완료가 아니다.

```sh
kadan card update 저장소/카드 --revision 4 --rally-id product-tags --rally-title '제품 태그 편집' --rally-round 2 --rally-step review --note '기존 구현의 2라운드 독립검수 연결'
```

같은 묶음의 제목은 같게 기록한다. 제목 충돌·라운드 누락·동일 라운드 중복 역할은 확인 필요로 표시한다. 최신 라운드의 구현/수정과 검수가 모두 완료되고 관련 조사도 마감돼야 묶음 완료로 센다. 후속 검수가 아직 연결되지 않으면 검수 연결 필요다. 이전 라운드 실패는 이력이며 이후 라운드 합격을 무효화하지 않는다. 이름으로 추정하는 옛 라운드 표시는 원본이 아니다.

대시보드 진행 막대는 묶음 수 기준이며 미연결 실행 카드는 별도로 센다. 상세 카드는 보존하고 연결된 카드를 남은 작업으로 중복 합산하지 않는다. 18회는 상한 안내이지 채워야 할 진행률이 아니다. 단계 경과 시간은 발령 기록부터의 경과이며 실제 집중 작업시간이나 pause 제외 시간은 아니다.

구현·수정 또는 독립검수 한쪽 작업은 **턴**, 구현 또는 수정 + 독립검수 왕복은 **라운드**다. `rallyRound`와 업무 실행의 `round`는 라운드 번호, `rallyStep`과 `phase`는 해당 턴의 단계다. 저장 필드와 명령 옵션은 바꾸지 않는다. 화면은 `2라운드 · 검수 중`처럼 표시한다.
