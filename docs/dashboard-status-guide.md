# 대시보드 상태·색상 안내

## Why

[kyle]이 카단 라이트의 그래프와 카드 라벨을 같은 의미로 읽고, 진행 상태·보고 시각·사용자 결정 요청을 구분하게 한다.

## 잘 진행되는지 확인하는 순서

요약 화면은 **현황** 하나다(2026-09-12). 옛 관제 요약·판 현황은 현황 안의 접힘 구역이 됐고 옛 주소(`#overview`, `#boards`)는 현황으로 온다. 모든 수치는 실행 카드 한 장을 한 번씩 센 값이며 관리·조율 카드는 제외한다. 화면마다 다른 집계 규칙을 두지 않는다.

1. 맨 위 **감시기 한 줄 판정**을 본다. 정상·설정 빠짐·없음·지연과 최근 24시간 공백을 한 줄로 보여주며 뜻은 [감시 안내](watch-overview.md#한-줄-판정-2026-09-12)에 있다.
2. **최근 24시간에 일어난 일**에서 실제로 끝나고 실패하고 발령된 실행을 본다. 실행 원장의 시각만 쓰고 카드 편집은 세지 않는다.
3. **지금 막힌 것**을 본다. 담당 세션이 살아 있거나 신호가 24시간 안인데 시작 보고·실패·PID 근거를 확인할 실행이다. 작업 중·결과 대기·열린 업무가 그 아래에 온다.
4. **오래된 미정리**는 접혀 있다. 담당 세션이 없고 24시간 이상 신호가 없는 실행이며, 감독이 대체·취소·보류로 정리해야 목록에서 빠진다. ‘정리 요청 복사’ 버튼이 카드별 `kadan card update ... --status superseded` 뼈대를 담은 요청문을 복사한다. 같은 일을 새 카드로 다시 발령할 때는 `kadan card create ... --supersedes <옛카드>`로 옛 카드를 함께 정리한다.
5. 판별 진행 막대·다음으로 시작할 일·비서에게 확인할 일·끝난 판은 접힘 구역이다. 각 실행의 **최근 실행 신호**는 현재 담당의 지시 전달·진행 보고·실행 결과에서 가져오며 카드 메모 수정은 신호를 갱신하지 않는다.

| 표시 | 근거와 의미 |
| --- | --- |
| 작업 중 | 현재 발령 이후 담당자의 유효한 진행 보고와 같은 담당 세션이 확인됨 |
| 결과 대기 | 현재 담당이 대기를 보고했고 같은 세션이 확인됨. 시간이 지났다는 이유로 정지 판정하지 않음 |
| 지금 막힌 것 | 시작 보고 없음, PID 변경·조회 실패, 보고 근거 불명확, 실패 결과 등을 구체적인 이유로 표시. 담당 세션이 살아 있거나 신호가 24시간 안 |
| 오래된 미정리 | 담당 세션이 없고 24시간 이상 신호가 없는 미완료 실행. 지금 막힌 것과 구분해 접어 두며 감독의 정리 대상 |
| 활동 보고 확인 | 진행 메모는 있지만 `kadan card progress`의 작업 중·결과 대기 활동 보고가 없어 상태를 확정하지 않음 |
| 실행 준비 / 발령 가능 | 아직 실행 전. 열린 업무라는 이유로 작업 중으로 세지 않음 |
| 감독 확인 차례 | 업무 안의 실행은 종료됐지만 업무의 최종 결과 확인이 남음 |
| 보류 / 종료 | 실행 중과 별도로 표시. 종료된 카드의 세션이 없어도 실행 장애로 보지 않음 |

**최근 실행 신호**는 실제 명령 실행·코드 저장·화면 변화 전체를 수집한 시각이 아니다. 현재 대시보드가 가진 발령·보고·결과 기록의 최신 시각이다. 오래된 보고를 최신 카드 메모로 덮거나, 세션이 열려 있다는 사실만으로 정상 진행을 확정하지 않는다. 감시 프로세스와 감시 주기 정상 여부도 구분한다.

기존 ‘최근 변경’ 열은 실행 표에서 **카드 수정**, 업무 표에서는 **관련 기록 갱신**으로 표시한다. ‘마지막 보고’는 현재 담당자의 유효한 진행 보고이고, 업무 표의 ‘업무 기록’은 업무 자체 기록 시각이다. 업무와 실행은 같은 단위가 아니므로 수를 합산하지 않는다.

실행 표에는 **카드 상태** 열을 따로 두지 않는다. **실행 흐름**이 같은 값을 근거와 함께 보여주므로 두 열이 같은 글자를 반복하기 때문이다(2026-09-18). 업무 표에서만 **업무 상태**(업무 수준)와 **실행 흐름**(실행 수준)을 나란히 둔다. 끝난 카드와 발령 전 초안의 **실행 흐름** 칸은 라벨과 색만 보여주고, ‘실행을 마친 카드입니다’ 같은 상수 설명을 줄마다 반복하지 않는다. **최근 실행 신호**가 없으면 ‘신호 없음’ 한 줄만 남기고, **현재 차례**는 종료·미기록 카드에서 빈 칸이며 근거는 칸에 마우스를 올려 확인한다. 값이 하나도 없는 **실행 모델** 열은 표에서 빠진다.
작업 표는 기본으로 여섯 열만 그린다. 실행 표는 카드·목적, 실행 흐름, 최근 실행 신호, 티키타카, 현재 차례, 실행 모델(합계 990px)이고, 업무 표는 최근 실행 신호 자리에 업무 상태를 둔다(합계 960px). 다음 행동·판·마지막 보고·카드 수정은 상세와 필터에서 확인한다. **상태 필터 요약은 개수가 아니라 뜻으로 읽는다.** 완료만 빼고 보면 ‘완료 제외’, 완료와 취소를 빼면 ‘완료·취소 제외’, 전부 고르면 ‘전체’다. 필터의 상태는 카드에 기록된 상태이고, **실행 흐름** 열은 그 기록을 세션·보고 근거로 다시 판단한 값이라 서로 다를 수 있다.
작업 표 위에는 **상태 빠른 선택 칩**이 있다(미완료·진행 중·대기·발령 전·확인 필요·완료·전체). 칩은 지금 좁혀진 판·저장소·검색 조건에서 몇 장인지 함께 보여주고, 주소에는 상태 필터와 같은 값을 쓴다. **실행 흐름**과 **묶음**은 표에서 바로 좁히는 빠른 필터다. 실행 흐름 필터는 카드에 기록된 상태가 아니라 세션·보고 근거로 다시 판단한 값이라 상태 필터와 다르며, 둘을 함께 걸면 더 좁혀진다. 업무 표의 **티키타카** 줄은 ‘남은 실행 N건’으로 말한다. 끝나지 않은 실행 수이며 초안·보류도 포함한다(2026-09-18).

## 색상과 라벨

| 색상 | 그래프 구간 | 포함하는 카드 라벨 | 의미 |
| --- | --- | --- | --- |
| 초록 | 완료 | 완료 | 해당 카드의 완료가 확인됨 |
| 주황 | 작업 중 | 작업 중 | 담당자의 유효한 시작 보고가 있음 |
| 파랑 | 결과 대기 | 결과 대기 | 담당자가 결과 대기를 보고함 |
| 회색 | 발령 전 | 초안·발령 가능·배정됨 | 준비 또는 배정 단계. 다음 실행 순서 확정은 아님 |
| 보라 | 보류 | 보류 | 작업 보류. 이유와 재개 조건은 카드에서 확인 |
| 황토색 | 지금 막힌 것 | 발령됨·실패 기록 있음·PID 변경 등 | 시작 보고 또는 실행 상태 확인이 필요하며 세션이 살아 있거나 신호가 최근 |
| 갈색 | 오래된 미정리 | 세션 확인 필요 | 세션이 없고 24시간 이상 신호 없음. 감독이 정리해야 함 |
| 연회색 | 취소·보관 | 취소·보관 | 완료와 구분하는 종료·보관 상태 |

라벨의 점과 그래프 구간은 같은 색상 정의를 쓴다. 라벨 배경은 가독성을 위해 같은 계열의 옅은 색이다. 그래프는 일부 세부 라벨을 묶으므로 라벨과 구간이 항상 일대일인 것은 아니다.

## 작업 상태와 마지막 보고

- ‘작업 중 · 마지막 보고 32분 전’은 시작 보고가 있었고 마지막 보고 후 32분이 지났다는 뜻이다. 보고가 오래됐다는 이유만으로 작업 중이나 결과 대기를 해제하지 않는다.
- 완료·실패·보류, 재발령·담당 변경, 세션 소실·PID 불일치·조회 실패가 확인되면 상태를 다시 판단한다. 세션 생존만으로 작업 중이라고 판정하지 않는다.
- ‘발령됨 · 진행 보고 없음’은 지시 전달 기록은 있지만 유효한 시작 보고가 없다는 뜻이다. 이미 전달된 작업을 다음 실행 큐로 추측하지 않는다.
- ‘발령 가능’은 맡길 준비가 된 후보이며 순서가 정해졌다는 뜻은 아니다. 순서 대기는 별도 기록이 있을 때만 확정할 수 있다.

## 숫자와 사용자 결정

- 막대와 첫 화면의 남은 일은 실행 카드 한 장을 한 번씩 센다. 관리·조율 카드는 집계에서 제외하고 관리 기록에 보존한다. 구현·검수 등 서로 다른 실행 단계의 카드 수이며 제품 완성률이나 배포 완료율은 아니다.
- 취소·보관은 완료와 별도다. 중앙 카드에 연결되지 않은 실행은 막대에서 제외하고 별도로 안내한다.
- ‘확인 필요’는 사용자에게 답변을 요구한다는 뜻이 아니다. 정식 사용자 질문은 ‘내 결정 필요’에만 표시한다.
- 진행 중인 카드는 ‘지금 하는 일’, 다른 미완료 카드는 작업 묶음, 완료 판은 접힌 이전 기록에서 확인한다.

## 상태 필터

작업 목록의 ‘상태’를 펼치면 체크박스로 여러 상태를 함께 선택할 수 있다. 예를 들어 ‘작업 중’과 ‘결과 대기’를 선택하면 두 상태의 카드를 모아 보여준다. 검색·판·저장소 조건은 함께 적용한다.

- ‘모두 선택’: 모든 상태를 표시한다.
- ‘모두 제외’: 선택을 모두 해제하며 목록은 0장이 된다.
- ‘미완료만’: 완료·취소·대체됨·보관을 제외한 기본 선택으로 돌아간다.

선택은 즉시 반영되고 주소에 저장되어 새로고침·뒤로 가기에도 유지된다. 필터 밖을 누르거나 Esc를 누르면 선택창이 닫힌다.

## 화면에서 확인하기

그래프 범례에 마우스를 올리면 짧은 설명이 나온다. ‘상태·색상 안내’를 클릭하거나 키보드로 펼치면 모바일에서도 전체 설명을 볼 수 있다. 안내를 펼쳐 읽는 동안 자동 새로고침은 멈춘다.

## 메뉴 선택과 원본 위치

| 메뉴 | 의미 | 볼 때 | 원본 |
|---|---|---|---|
| 현황 | 감시 판정·최근 24시간·막힌 것·업무·판 진행을 한 화면에 | 지금 무엇이 중요한가 | 카드 이벤트 + 실행 원장 + 감시기 원장 |
| 담당자 세션 | 담당자 자리의 현재 생존·실행 도구 | 누가 켜져 있나 | 실행 환경 실시간 조회 + ledger.jsonl 시작 기록 |
| 우편함 | 역할 간 메시지 전달 | 무엇을 주고받았나 | ledger.jsonl send + mail/<지문>.txt |
| 시스템 기록 · 작업별 보기 | 카드·역할별 최신 발령/결과 | 누가 맡았고 끝났나 | ledger.jsonl send/done을 묶은 보기 |
| 시스템 기록 · 사건순 보기 | 시스템 사건 원문 | 왜 이런 상태가 됐나 | ledger.jsonl |

기본 저장 폴더는 ~/.kadan이며 KADAN_HOME으로 지정할 수 있다. 카드 변경 이유·진행 보고는 cards/<저장소>/<카드>/events.jsonl이다. 세션 시작·카단 종료 사건은 원장에 남지만, 모든 터미널 대화나 외부 종료 순간이 자동으로 같은 기록에 저장되는 것은 아니다.
