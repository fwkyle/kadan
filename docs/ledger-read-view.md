# 원장 조회 상태와 활동 기록

## Why

지난 기록이 늘어도 활동 기록 한 쪽을 읽는 데 모든 사건을 메모리에 보관하지 않도록 한다.
원본은 `kadan.sqlite`의 `events`이며, 조회 상태는 언제든 원본에서 다시 만들 수 있다.

## 저장과 검증

조회 DB는 `KADAN_HOME/.cache/ledger-view-v1.sqlite`다. 사건 원본을 수정하거나 옮기지 않는다.
영역별 목록 위치·검색 색인·총수, 검증에 필요한 우편·실행·인계 연결과 적용 위치를 저장한다.
화면에 보여 줄 원문은 선택된 사건의 `(stream, seq)`로 원본에서 읽는다.
큰 감시 관계표를 제외하는 기존 조회 규칙도 유지한다.

- 조회 상태와 네 원장 스트림의 순번·끝 지문·누적 지문은 같은 조회 DB 트랜잭션으로 확정한다.
  원본 DB는 읽기만 한다. 두 DB의 쓰기가 동시에 확정된다고 가정하지 않는다.
- 새 사건은 최대 256행을 기준으로 나누되, 같은 순번의 지시/발령과 완료/바로 뒤 결과 우편은
  한 묶음에서 기존 검증기로 확인한다. 오류나 강제 종료는 상태와 적용 위치를 함께 되돌린다.
- 프로세스의 첫 조회는 원본의 적용 구간 전체 지문과 조회 행 수를 대조한다.
  정상 반복에서는 파일 식별값·끝 순번·끝 지문을 확인하고 새 사건만 처리한다.
  옛 원장 스트림 변경, 파일 교체, 끝 순번 감소, 지문·메타 불일치는 새 조회 세대로 재생한다.
- 최초 완료, 발령/우편 연결, 완료 우편, 인계 검증을 그대로 쓴다.
  재생 중 전송·AI 호출·프로세스 재시작은 일어나지 않는다.
- 원본의 암묵적 `rowid`는 적용 위치로 저장하지 않는다. 화면 커서는 조회 세대와 명시적 위치를 쓴다.
  최초 재생과 프로세스 시작 대조는 전체 이력에 비례한다. 재생 중의 객체는 묶음 단위로 해제한다.

SQLite가 읽을 수 없는 물리적 조회 DB 손상이나 다른 종류의 파일은 오류로 표시한다.
이 경우 조회 프로세스를 종료하고 해당 **조회 DB와 그 `-wal`·`-shm`만** 보존 폴더로 옮긴 뒤
다시 조회하면 원본에서 재생한다. `kadan.sqlite`나 원본 WAL을 이 절차로 옮기면 안 된다.
읽을 수 있는 메타·행 수 불일치는 자동으로 재생한다. 일반 반복 조회에서 과거 모든 행의 손상을
매번 다시 검사하는 것은 아니며, 전체 대조는 프로세스 시작·재생 시 수행한다.

## 화면과 API

`GET /api/dashboard/ledger`는 카드·업무·tmux·자원 수집을 거치지 않고 이 조회 상태를 쓴다.
종류·사고·카드 주소·역할·서울 날짜·반복 감시 필터와 기존 표시 내용을 유지한다.
DB에서 필요한 원문만 확보하고 읽기를 닫은 뒤 표시 문구를 만든다.

응답의 `nextCursor`·`previousCursor`를 `logCursor`로 보내면 다음·이전 50건을 읽는다.
화면은 이 커서를 사용하며, 첫 쪽으로 돌아오거나 검색 조건을 바꾸면 최신 범위에서 시작한다.
첫 조회 이후 새로 추가된 사건 때문에 다음 쪽의 기록이 중복되거나 빠지지 않도록 조회 끝을 고정한다.
조회 세대 또는 조건이 달라진 커서는 첫 쪽으로 돌아간다(`cursorReset: true`).
잘못된 커서는 400이며, 저장소를 읽지 못하면 빈 목록 대신 오류다.
인증·출처 제한과 조건부 응답(ETag/304), 강제 갱신을 적용한다.

옛 `logPage` 숫자 링크는 그대로 열린다. 이 호환 경로는 본문 대신 위치 정수만 앞에서 찾아간다.
새 이전/다음 이동은 이 순회와 깊은 `OFFSET`을 사용하지 않는다.
일반 첫 쪽의 총수는 저장된 집계를 사용한다. 특정 조건의 총수와 오래된 커서 뒤 추가분의 총수에는
SQL 집계가 남으므로 모든 검색을 항상 일정한 비용이라고 보장하지 않는다.

현재 적용 범위는 활동 기록이다. 감시기·우편함·카드/업무의 다른 읽기가 모두 이 상태를 사용하거나
전체 이력을 메모리에서 제거한 것은 아니다. 원본을 대신하는 업무 상태표로 취급하지 않는다.

## 참고

WAL은 각각의 DB 안에서 트랜잭션을 보장하며 여러 DB에 걸친 동시 확정을 보장하지 않는다.
조회용 상태와 cursor를 한 DB에 두는 이유다. [SQLite WAL](https://www.sqlite.org/wal.html)

작은 문자·복합 기본키 색인에는 중복 저장을 줄일 수 있는 `WITHOUT ROWID`를 사용한다.
원본 스키마는 바꾸지 않는다. [SQLite WITHOUT ROWID](https://www.sqlite.org/withoutrowid.html)
