# 카단 역할과 알림 경로

## Why

역할 이름이나 작업폴더가 달라도 누가 누구를 책임지는지 명시하여 완료·이상 알림을 올바른 상위에 전달한다.

## 현재 카단과 역할의 자리

- 실행 코어는 이 저장소다. 이전 카단 구현(2026-08-30 동결)은 설명서 참고 원본일 뿐이다.
- 비서·슈퍼감독은 공통 지휘 공간, 일반감독은 담당 프로젝트, 작업자·검수자는 해당 기능 worktree를 기본으로 한다. cwd 자체는 권한이나 상하관계를 증명하지 않는다.
- 비서는 사용자 요청과 확인 결과를 전달한다. 일반감독은 카드 발령·결과 검수와 승인 범위 안의 방법 선택·진단·장애 복구·재개를 결정한다. 슈퍼감독은 판 간 충돌·우선순위·일반감독이 풀지 못한 판단을 조정하고, 작업자는 구현, 검수자는 독립 검증을 소유한다. 구체적인 위임과 기존 방법 제한 정정은 [공통 운영 기준](../skills/kadan-conductor/references/operating-contract.md#일반감독의-결정-범위)을 따른다.
- 기존 세션의 cwd를 이 규칙 때문에 강제 재시작하지 않는다. 다음 정상 인계에서 맞춘다.

## 명시적인 직속 상위

`kadan watch --hierarchy /절대경로/역할관계.json`은 시작 시와 매 감시 주기에 아래 JSON을 읽는다.

```json
{
  "제품-슈퍼감독": "@user",
  "제품-감독": "제품-슈퍼감독",
  "제품-wave2-작업자": "제품-감독",
  "데이터-감독": "제품-슈퍼감독",
  "품질-감독": "제품-슈퍼감독"
}
```

- 값은 직속 상위다. `@user`는 OS 알림과 watch 출력이다. 새 역할은 아래 자동 등록으로 들어가며, 자동 등록이 건너뛴 경우(사람이 직접 시작 등)에는 `kadan hierarchy add`로 더한다. 다음 감시 주기에 변경을 검증하고 `hierarchy-loaded` 원장에 경로·파일 지문·감시 PID를 남긴다. 실행 중 파일 오류는 마지막 정상 관계를 유지하고 사용자에게 오류를 알린다. 이전 버전 감시기는 재시작해야 이 동작이 적용된다.
- 빈/잘못된 이름, 자기 참조, 순환, 상위 미등록, 파일 읽기/JSON 오류는 시작 실패다. 잘못된 관계를 이름 추정으로 덮지 않는다.
- 등록된 역할의 모든 역할 알림(완료후보·정체·죽음·끊김·읽기불가)은 명시된 상위로 간다. 감독유휴(`--idle`, 놀고 있음)는 작업 감시 범위와 감독 점검 범위의 세션에 적용되고, 먼저 그 감독 본인에게, 그 두 배 시간이 지나면 상위에게 간다([멈춤 규칙](watch-overview.md#멈춤-규칙-2026-10-05); `--wake` 자가점검은 2026-10-05에 없앴다). 관계표에서 하위를 가진 감독과 최상위 슈퍼감독도 아래에 활성 실행이 있으면 받는다(2026-10-05, 그 전에는 작업 감시 범위로만 걸러 등록된 감독에게 닿지 않았다). 등록된 감독의 응답은 [감독 관찰AI](watch-overview.md#감독-관찰ai의-응답-점검-2026-09-09)가 맡는다(`--judge-cmd`가 있을 때). 직속 상위가 죽었으면 같은 책임 사슬에서 살아 있는 다음 상위로, 모두 없으면 사용자에게 간다.
- 미등록 역할은 기존 `--route`/판이름/`--super` 규칙을 유지한다. 자원·원장 읽기 오류처럼 특정 역할이 없는 경보도 기존 공통 수신자를 유지한다. 한 프로젝트를 고치려고 타 판의 전역 수신자를 바꾸지 않는다.
- 감독 유휴는 자기/하위의 미완료 카드와 실제 출력 변화를 본다. 미완료가 없거나 하위 작업이 진행하면 조용한 상위를 유휴로 알리지 않는다. 역할별 done을 구분하며 동일 카드ID의 다른 역할 완료로 지우지 않는다.
- 계획만 있는 카드는 같은 판의 직속 감독을 찾는다. 비표준 별도 판 이름의 미발령 계획은 정확한 판 등록/담당 확인이 필요하며 이름만으로 직속 관계를 만들지 않는다.

## 시작할 때 자동 등록 (2026-09-11 [kyle] 지시)

`kadan start`는 세션을 만든 뒤 **만든 사람을 그 역할의 직속 상위로 관계 파일에 적는다.** 사람이 한 줄을 기억해서 넣지 않아도 알림이 갈 곳이 정해진다. 대상 파일은 원장의 마지막 `hierarchy-loaded`가 가리키는 경로, 즉 현재 감시기가 실제로 읽는 관계 파일이다.

추가만 하고 기존 줄은 고치거나 지우지 않는다. 아래에 해당하면 적지 않고 시작은 그대로 진행한다.

| 건너뛰는 경우 | 이유 |
|---|---|
| `KADAN_ROLE` 없이 사람이 직접 시작 | 상위로 적을 역할이 없다 |
| 실행 명령이 카단 자신의 `watch`·`dashboard`·`wall` | 보고 관계의 역할이 아니다. 넣으면 트리에 부하처럼 보이고 만든 감독의 인계 때 "보고 대상 변경" 편지가 그 프로그램 창에 붙는다(2026-09-23 [kyle]) |
| 감시기가 읽는 관계 파일을 모름 | 감시기 없는 환경은 정상이다 |
| 이미 등록된 역할 | 기존 상위를 덮지 않는다 |
| 만든 사람이 관계 파일에 없음 | 위로 올라가는 길이 끊긴 줄을 만들지 않는다 |
| 파일 읽기·검증·쓰기 실패, 동시 등록 잠금이 2초 이상 지속 | 깨진 표를 남기지 않는다 |

성공하면 `감시 등록: <역할> → <상위>`를 출력한다. 관계 파일을 찾고도 못 적었을 때만 표준 오류로 알린다. 쓰기는 임시 파일과 이름 바꾸기로 한 번에 반영하며, 같은 순간 두 곳이 고치지 않게 `hierarchy-register.lock`을 쓰고 남의 잠금은 지우지 않는다. 작업자를 여러 개 동시에 시작하면 잠금이 짧게 겹칠 수 있으므로 등록은 최대 2초 기다렸다가 다시 얻는다(2026-09-28). 그래도 못 얻으면 시작은 그대로 진행하고 등록만 건너뛴다. 이 기능은 등록만 하며 역할 생성·모델 선택·발령 권한을 넓히지 않는다.

## 빠진 역할을 수동으로 더하기

사람이 `KADAN_ROLE` 없이 직접 시작한 역할처럼 자동 등록이 빠진 줄은 사람이 더한다.

```sh
kadan hierarchy add <역할> <상위|@user>
```

자동 등록과 같은 검증·잠금을 거치며 추가만 한다. 이미 있는 역할의 상위는 덮어쓰지 않고,
표에 없는 상위·공백 있는 이름·`@user`를 역할로 쓰는 것은 거부한다. 결과를 JSON으로 출력한다.

## 끝난 역할 정리

끝난 역할이 관계표에 계속 쌓일 때 수동으로 정리한다. 원장·카드의 이력은 그대로 남는다.
관계표 크기를 줄이는 기능이며 `tree` 전체 조회의 속도 개선을 보장하지 않는다.

```sh
kadan hierarchy prune
kadan hierarchy prune --file /절대경로/관계표-복사본.json
kadan hierarchy prune --apply
```

- 기본은 미리 보기다. 파일을 바꾸거나 잠금·백업을 만들지 않고, 전체·제거·보존 개수와 역할별 보존 이유를 JSON으로 출력한다.
- 기본 대상은 마지막 `hierarchy-loaded`의 파일이다. `--file`은 복사본 검증 등 대상 파일만 바꾼다. 생존 정보와 카드·업무·원장은 현재 바닥과 `KADAN_HOME`에서 읽는다.
- 세션이 살아 있으면 남긴다. PID 불일치·시작 기록 없음도 남긴다. 생존 목록·카드·업무·원장 조회 실패는 정리 실패이며, `0개`로 취급하지 않는다. tmux 서버가 없어 목록을 확인할 수 없는 경우도 적용하지 않는다.
- 카드 상태 또는 현재 실행 상태가 미완료이거나, 완료 기록 없는 발령이 있으면 남긴다. 보류·미발령·입력 대기도 종료로 취급하지 않는다. 카드 주소와 확정 인계는 기존 계산을 사용하며, 연결이 불명확한 역할은 남긴다.
- 열린·보류 업무의 현재 책임 감독과 다음 담당도 남긴다. 실행이 끝났어도 업무 최종 확인이 남아 있을 수 있다. 감시 대상에서 제외됐다는 사실은 정리 가능 근거가 아니다.
- 마지막 `start` 이후 `stop` 또는 해소되지 않은 `죽음` 경보가 있어야 한다. 그 관측부터 **24시간**이 지나야 후보가 된다. 재시작·경보 해소·후속 전달/완료 기록이 있으면 새 종료 관측을 기다린다. 시작 시각을 종료 시각 대신 쓰지 않는다. 24시간은 보수적인 기본값이며 알림 처리 시간으로 검증된 수치는 아니다.
- 현재 표에 자식이 있는 역할은 이번 회차에 남긴다. 하위부터 빠지고 다음 실행 때 다시 판단하므로, 살아 있거나 책임이 남은 역할의 상위 사슬이 보존된다.

`--apply` 때만 쓴다. 인계의 `handovers/.lock`과 등록의 `hierarchy-register.lock`을 함께 잡고
자료를 다시 읽는다. 같은 파일에 열린 인계가 있으면 거부한다. 기존 인계 취소는 파일 지문이
달라지면 원복을 거부하며, 두 잠금을 함께 잡는 것은 확인과 쓰기 사이의 동시 변경도 막기 위해서다.

쓰기 전 원문을 `$KADAN_HOME/.trash/<파일명>.before-prune-<시각>-<고유값>`에 권한 `600`으로
보존한다(기본 홈 `~/.kadan`). 자료 변경·역할 생존 복귀·파일 변경을 다시 확인하고,
`parseHierarchy`를 통과한 결과를 임시 파일 후 이름 바꾸기로 반영한다. 중간에 실패하면
적용하지 않으며 이미 만든 백업·임시 파일은 보존한다. 파일 밖에서 직접 실행한 세션 생성이나
수동 편집까지 잠그지는 못하므로 적용 중에는 같은 역할 재시작·관계표 수동 편집을 겹치지 않는다.
자동 감시 주기에는 정리를 넣지 않는다.

## 완료·전달·사용자 확인은 별개

- 작업자 완료 편지는 카드에 적힌 직속 감독에게 `kadan send`로 보낸다. 이 옵션은 감시 경로를 바꾸며 작업 카드의 수신자 문장을 자동 수정하지 않는다.
- AI는 발령 뒤 응답 종료·입력 대기한다. 외부 배포는 일회성 대기 프로그램이 결과를 저장하고 CLI로 통지한다. 반복 AI 조회를 하지 않는다.
- 명시된 최상위 경보는 `--user-notify` 유무와 무관하게 사용자 알림을 시도한다. 그 옵션은 기존 공통 RED/죽음 알림의 선택 기능으로 남는다. OS 알림 권한·집중모드로 실제 표시가 안 될 수 있으므로 osascript 성공을 사용자가 읽었다는 증거로 취급하지 않는다.
- 알림 실패는 원장 delivered:false와 watch 출력에 남긴다. 감시가 죽거나 OS 알림 자체가 실패한 뒤 자동 복구/재시도를 보장하지 않는다.
- 대시보드의 기존 판 묶음/진행 막대는 카드 원장과 이름에 의한 요약이다. 새 관계표가 대시보드의 모든 분류와 진행률을 고친다고 주장하지 않는다.

## 판별 감시 확인

대시보드와 `kadan tree`가 공유하는 감시 조회 기준은 [판별 감시 조회 기준](watch-overview.md)을 따른다. 직속 관계 설정 반영, 감시기 생존, 감시 주기 정상 여부, 경보 전송 결과를 서로 구분한다.
