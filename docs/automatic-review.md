# 구현·검수 자동 전달

## Why

감독이 정상 왕복마다 같은 지시를 다시 쓰지 않아도 구현·검수·수정이 이어지고,
감독은 합격·예외·3라운드 경계에서 판단한다.

## 적용 범위

감독이 명시적으로 설정한 열린 업무에만 켠다. 기존 수동 발령·완료 편지, 미설정 업무,
공용 watch는 그대로다. SQLite events/heads의 `automatic-review/<업무키>/events.jsonl`
스트림에 설정·보고·예약·결과를 추가한다. 새 DB나 상시 서비스는 만들지 않는다.

기존 구현·검수 중앙 카드를 각각 원본으로 지정한다. 두 카드는 승인 범위가 있어야 하며
ready/assigned/done 상태만 가능하다. 원본 본문을 복제하지 않고 경로와 지문으로 참조한다.
새 실행은 기존 `work execute`로 만들고 업무 실행 목록·중앙 카드의 라운드를 함께 기록한다.

## 경로 선택

작은 직접 수정은 이 자동화도 설정하지 않는다. 반복 구현·독립검수가 필요한 업무만 승인된 두 담당과 기존 원본을 한 번 설정한다. 정상 중간 결과는 `auto-report`로 충분하며 감독의 별도 수신 확인·요약·수동 검수 발령을 덧붙이지 않는다. 기존 수동 업무나 지원되지 않는 실행 환경을 임의 전환하지 않는다. 실제 AI/Rottie 왕복의 확인 범위는 해당 실행 근거로 판단한다.

## 시작

감독이 승인된 실행기·모델로 작업자와 독립검수자 두 세션을 준비하고 입력창·실제 명령을
확인한다. 프로그램은 역할 생성, 모델 변경, 권한 확대, 시한 연장을 하지 않는다.
같은 업무의 다른 실행이나 다른 담당이 두 역할을 점유하고 있으면 설정·전달을 막는다.

```sh
kadan work show repo/work-id
kadan work auto-configure repo/work-id --revision 1 \
  --implementation repo/implementation-source --review repo/review-source \
  --worker board-worker --reviewer board-reviewer --notify board-supervisor \
  --deadline 2026-09-10T12:00:00+09:00
kadan work auto-run repo/work-id
```

`--revision`은 최신 업무 버전이다. `--notify` 기본값은 업무 책임 감독이다.
원본에 시한이 있으면 **그 시한 그대로** `--deadline`에 적는다. 원본에 시한이 없을 때만
생략한다. 본문의 자연어 시한을 프로그램이 추측해서 읽지는 않는다.

`auto-run`은 설정한 한 업무만 2초 간격으로 확인하는 명시 실행 프로그램이다.
`--interval 0.1~60`으로 확인 간격을 정할 수 있다. 별도 AI 조회 루프는 만들지 않는다.
감독이 응답을 끝내도 유지되는 기존 실행 환경에서 실행하고 PID·대상·종료 시 확인 담당을
기록한다. 이 명령 자체가 백그라운드 서비스 설치나 공용 watch 재시작을 하지는 않는다.
일회성 동작 확인은 `auto-step`, 상태 조회는 `auto-show`다.

## 작업자·검수자의 보고

새 실행은 `card show <현재실행키>`의 `resultPath`에 보고서를, `evidenceDir`에 검증 자료를 쓴다. `auto-report`에서 결과 경로를 생략하면 그 경로를 사용한다. 프로그램이 파일·완료 근거를 확인하면서 카드에 경로·지문·판정을 등록하므로 별도 `card report`는 필요 없다. 이전 실행은 기존 `--result-file <절대경로>`를 유지한다. [결과 저장 계약](card-center.md#카드-결과와-검증-자료).

자동 생성된 실행 카드는 원본 카드 경로, 현재 실행 ID, 직전 결과 경로·지문을 전달한다.
원본의 범위·검수 기준·필수 근거는 유지하고, 이 경로의 **중간 통지만** 아래로 바꾼다.
원본에 옛 카드 ID가 있더라도 보고·완료 마커에는 새로 발령받은 현재 실행 ID를 쓴다.

```sh
kadan work auto-report repo/work-id --execution repo/exec-현재UUID \
  --outcome implemented
```

| 담당 | outcome | 의미 |
|---|---|---|
| 구현·수정 | `implemented` | 이번 실행을 마침. 품질 합격을 뜻하지 않음 |
| 검수 | `pass` | 명시 기준에 따른 품질 PASS 보고. 감독의 최종 판단 필요 |
| 검수 | `changes` | 승인 범위 안의 품질 수정 필요. 근거 파일을 같은 작업자에게 전달 |
| 양쪽 | `exception` | 실행 장애·판정 불명확·범위 밖 수정 요구. 감독 판단 필요 |

결과 파일을 완성하고 보고 명령을 실행한 뒤 자기 화면 마지막 줄에
`KADAN:DONE <현재카드id> <ok 또는 failed>` 형식을 조립해 출력한다.
정상 중간 편지를 감독에게 따로 보내지 않는다. `ok/failed`는 실행 종료,
`pass/changes`는 품질 판정이며 서로 바꿔 쓰지 않는다. 검수자는 소스를 수정하지 않는다.
형식 밖의 자유본문에서 PASS를 추정하지 않는다. 같은 실행의 충돌 보고는 예외로 넘긴다.

프로그램은 발령 전 화면과 다른 현재 ID의 완료 마커 또는 발령 뒤 공식 `done` 기록을
확인한다. 보고·마커·파일 저장의 순서가 바뀌어도 결과 파일과 완료 근거가 모두 있기 전에는
다음 실행을 만들지 않는다. `failed` 실행은 품질 수정으로 돌리지 않고 예외로 넘긴다.
마커가 화면에서 사라져 확인할 수 없으면 자동 완료하지 않는다. 감독이 실제 결과·출력을
대조한 뒤 기존 `kadan done`으로 확정할 수 있다.

## 블록과 최종 판단

- 1라운드는 구현 또는 수정 + 독립검수 1회다. 저장 필드 `round`는 이 라운드 번호다. 같은 블록에서는 같은 두 세션을 유지한다.
- PASS가 오면 즉시 감독에게 1회 통지한다. 3회를 채우지 않는다.
- 3번째 검수도 수정 필요면 `boundary`로 멈추고 감독에게 1회 통지한다.
- 다음 블록은 감독이 두 역할을 모두 새 세션으로 준비한 뒤 같은 원본·시한으로
  `auto-configure ... --next-block`을 실행한다. 과거 블록 세션도 재사용하지 않는다.
- 기존 업무의 구현·수정·검수 라운드를 이어 센다. 전체 18라운드에서 `limit`으로 멈춘다.
- 프로그램은 업무 최종 완료, 체크포인트 커밋, 배포를 수행하지 않는다.

## 중단·재시작·전달 불명확

전송 예약은 SQLite 트랜잭션을 먼저 커밋한다. 전송 직전 다시 업무 HOLD/종료·범위·실행 연결,
원본 변경·다른 실행 점유·카드 배정·담당 차례·시한·시작 기록·PID를 확인한다.
실제 바닥 send를 수행하는 짧은 구간에는 SQLite 쓰기 잠금을 유지하여 카드/업무의
동시 변경과 전송 순서를 정한다. PID는 기존 `guardedSend`와 마지막 전달 검사에서 대조한다.
원본 본문·결과 파일의 외부 편집까지 SQLite 잠금으로 막는 것은 아니며 전송 직전 지문을 대조한다.

`auto-show`의 `sending/notifying`는 전송 예약 상태다. 예약 프로세스가 살아 있으면
다른 실행 프로그램은 발령을 반복하지 않고 상태만 반환한다. 프로세스가 죽은 뒤에는
`sending`을 예외로 통지하고, `notifying`는 통지 여부 `unknown`으로 남긴다.
전달 성공 뒤 영수증을 못 쓰거나 응답이 유실된 경우에도 자동 재전송하지 않는다.
통지 실패는 notification에 보존하며 반복 전송하지 않는다. 감독이 결과·원장·수신 화면을
대조하고 기존 수동 경로로 판단한다. 예외 설정을 `auto-configure`로 덮어 재발령할 수 없다.

운영 사용은 독립검수와 감독 판단 뒤 필요한 업무만 설정한다. 코드·격리 CLI 시험 통과는
운영 업무 자동화 시작이나 공용 watch 반영을 뜻하지 않는다.

## 첫 운영 시범과 종료 뒤 처리

새로운 실제 업무 하나를 첫 3라운드 블록으로 설정한다. 기존 수동 실행을 중간에 전환하지 않는다. 작업자·검수자·책임 감독, 원본·시한, 프로그램 PID와 종료 후 확인 담당은 기존 설정 기록을 이용한다. PASS가 나오면 즉시 끝내고, 경계에 도달했다고 다음 블록을 자동 설정하지 않는다.

종료 뒤 `work show`와 업무 화면의 후속 표시를 확인한다. 책임 감독은 기존 업무에 다음 행동·담당을 기록하거나 전체 결과 확인 후 마감한다. 화면 표시나 수신 ack가 그 판단을 대신하지 않는다. 전달 불명확 상태는 재전송하지 않는다.

검증은 정상 중계 횟수·최종 통지·추가 발령 여부와 종료 후 감독 판단을 확인한다. 격리 시험의 PASS·경계·상한·예외 증거와 실제 운영에서 발생한 경로의 증거를 구분한다. 기존 18라운드보다 작은 임의 숫자 상한을 자동으로 읽는 기능은 없으므로, 첫 블록보다 작은 제한이 필요하면 기존 수동 경로를 사용한다.
