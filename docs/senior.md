# 시니어

## Why

슈퍼감독을 항상 비싼 모델로 돌리기는 부담스럽다(2026-10-05 [kyle]). 그런데 작업 결과를 받고 결정해야 할 부분(검수 판정이 갈림, 결과대로 갈지 되돌릴지 등)은 값싼 모델의 판단만으로 넘기기 불안하다. 시니어는 그 간극을 메운다: 감독이 그 결과를 두고 kyle이 등록한 고급 모델(최대 2명) 전원에게 **한 번** 의견을 묻고, 모델별 답을 읽고 스스로 판단하거나 사용자에게 올린다. 감독은 모델을 고르지 않는다(2026-10-22 [kyle]).

- **Claude Code 어드바이저와는 다른 기능이다**(2026-10-05 [kyle] 정리). 어드바이저는 카드를 완수하려고 Claude Code 기능을 최대한 쓰는 것으로, 판단이 무거운 카드를 쓰기 전에 묻고, 물어서 받은 답의 요지만 카드의 `advisor 자문 요지` 칸에 적는다(2026-09-27부터, 지침의 기존 규칙 그대로). 시니어는 작업 결과에 결정할 부분이 있을 때 의견을 구하는 것이다. 서로를 대신하지 않는다.
- 자문은 **기록이지 결정이 아니다.** 카드 상태·범위를 바꾸지 않고 우편을 보내지 않는다. 감독이 판단 근거로 쓰고, 필요하면 카드 기록(`card note --kind decision`)에 요지를 남긴다. 사용자 결정이 필요하면 그대로 `decision request`로 올린다.
- 등록된 시니어에게 동시에 한 번씩 묻는다. 기본은 호출마다 새로 띄우는 대화형 세션(codex·agy 대화창)이며 로티 탭에서 진행을 볼 수 있다. 끝난 세션과 탭은 끄지 않고 남겨 두었다가 `kadan senior cleanup`으로 한꺼번에 정리한다(2026-11-19 [kyle]). 모델별 입력과 답은 `KADAN_HOME/advice/<askId>/<n>-<실행기>-<모델>/`에 남는다.
- 대화형 준비 단계는 작업 폴더가 git 밖인지와 빈 입력칸만 확인한다(agy는 첫 호출에 그 홈의 고정 작업 폴더 신뢰 창을 한 번 지난다). 연결된 MCP 도구는 확인하지 않는다(2026-11-18 [kyle]). 기존 헤드리스 호출은 `$KADAN_HOME/senior-mode`에 `headless`를 한 줄로 적어 선택한다 — **codex만**이고, agy가 등록돼 있으면 헤드리스 호출은 전원 거절한다. [대화형 방식](#대화형-방식-senior-mode) · [agy 대화창](#agy-대화창)
- **저장소 문맥은 시니어가 직접 읽는다.** 카드의 저장소 폴더(`repoPath`)에서 읽기 전용 샌드박스로 돌리므로 그 저장소의 파일·이력을 스스로 본다. 슈퍼감독이 여러 저장소의 문맥을 들고 있을 필요가 없다. codex가 자동으로 읽는 안내 파일은 `AGENTS.md`이고, 없으면 `CLAUDE.md`·`.agents.md`를 대신 읽는다(`senior.sh`가 `project_doc_fallback_filenames`를 명시, 2026-10-05). 그 밖의 이름이거나 하위 폴더의 문서라면 `--file <절대경로>`로 함께 넘긴다.

- **이름**: 처음 이름은 자문위원(`advisor`, 명령 `kadan advise`)이었다. Claude Code의 advisor 도구와 헷갈려 2026-10-05 [kyle] 결정으로 시니어(`senior`)로 바꿨다. 옛 명령 `kadan advise`와 실행 모델 설정의 옛 키 `roles.advisor`는 그대로 읽힌다(설정은 다음 저장 때 `senior`로 남는다). 시니어가 남기는 기록은 계속 자문(`advice` 사건, `KADAN_HOME/advice/` 폴더)이라 부른다.

## 명령

```
KADAN_ROLE=<감독> kadan senior <카드키> --question "<질문>" [--file <절대경로>]... [--timeout <초>] [--effort <강도>] [--runner <실행기> --model <모델>(등록된 시니어 한 명만 고를 때)]
KADAN_ROLE=<감독> kadan senior cleanup [--dry-run]   # 끝난 호출의 남긴 세션·탭 정리(아래 '남겨 두기와 정리')
```

- 부를 수 있는 명의: 감독(이름이 `감독`·`슈퍼감독`으로 끝나는 역할)과 사람. 작업자·검수자는 거절된다 — 자기 카드의 판단은 감독에게 묻는다.
- 입력: 질문, 카드 본문(`card.md`), 첨부 파일(절대경로, 5개·각 64KB까지). 더 큰 자료는 필요한 부분만 잘라 넣는다.
- 모델: 실행 모델 설정의 `senior` 칸이다([실행 모델 설정](runner-settings.md#시니어)). 비어 있으면 거절한다. 폴백은 없다.
- **등록된 전원에게 동시에 묻는다(2026-10-22 [kyle] 승인)**: `roles.senior`는 최대 2명 목록이다(옛 단일 객체 설정은 1명 목록으로 읽는다). 감독은 시니어 모델을 고르지 않는다 — `kadan senior`는 등록된 전원을 `Promise.allSettled`로 한꺼번에 부르고, 모델별로 나눠 돌려준다. 둘은 폴백이 아니라 동등하다. 첫 값이 실패해도 둘째로 넘어가지 않고, 둘 다 각자의 칸에 결과를 낸다.
  - 이유: 감독이 '시니어 둘'에게 물으려고 두 번째 모델을 스스로 골랐다(10/22 가벼운 flash 계열, 10/21 다른 모델). 시니어 구성은 kyle이 정하는 일이다.
  - 등록: `kadan runners set senior --set "codex:gpt-6-astra:high,agy:gemini-4-argon-medium" --revision N --reason …`(최대 2명, 같은 실행기+모델 중복·3명 이상은 거절). 한 명만 등록하려면 기존 `--runner/--model [--effort]`(목록이 그 한 명이 된다).
  - **덮어쓰기는 등록된 시니어 중 고르기만 한다.** `--runner X --model Y`는 등록된 항목과 같아야 하고, `--model Y`만 주면 등록 항목을 모델로 찾는다(같은 모델이 두 실행기에 있으면 `--runner`도 필요). 고르면 그 한 명만 부른다. 등록에 없는 값은 호출 전에 거절하고 오류 글에 등록된 시니어 목록을 보여 준다. 새 모델을 부르려면 kyle이 설정을 바꾼다. `--runner`만 주면 오류다.
  - `--effort`는 이번 호출만 강도를 바꾸며 **부르는 모델마다** 검사한다(지원하지 않는 모델이 하나라도 있으면 아무도 부르지 않는다). agy에는 강도를 넘기지 않는다(강도는 모델 이름이 정한다) — `--effort`를 줘도 무시하고 그 칸에 `note`를 단다. 그 칸의 강도는 아래 **강도 표시**대로 값 없이 보인다.
  - **호출 직전 검사는 저장 검사와 같은 함수다**(`assertSeniorCallable`, 저장은 `setSeniors`가 같은 `assertSeniorShape`를 쓴다). 설정 파일에 든 목록 전체가 3명 이상·같은 실행기+모델 중복·안전 실행기 밖·정책 차단(`block` 전역 또는 `--roles senior`)에 걸리면 **하나라도 걸리면 전원 거절(fail closed)**한다. 차단 안 된 시니어만 부르지 않는다 — kyle이 정한 목록과 다른 조합으로 몰래 도는 것을 막으려는 판단이다(2026-10-22). 덮어쓰기로 한 명만 골라도 같다. 외부 호출·증거 폴더 전에 거절하고, 오류 글에 걸린 항목과 고치는 명령(`kadan runners set senior --set …`)이 있다.
  - 준비(헤드리스의 agy 등록 검사·프롬프트 크기·증거 폴더·대화형의 자리와 agy 고정 작업 폴더)는 호출 전에 모두 끝낸다. 한 명이라도 거절되면 아무도 부르지 않는다(실행 0회).
  - **동시 호출 충돌 확인(2026-10-22)**: 감시 AI·설명 AI와 같은 `runJudgeProcess`(`src/watch-ai-process.mjs`)를 쓰지만 호출 하나가 자기 자식 프로세스·자기 `settings` 객체를 가진다. 직렬화(전역 잠금·큐)가 없고 공유하는 임시 파일·환경도 없다(환경은 호출마다 새로 합친다). 시니어마다 따로 갖는 것: 증거 폴더, `input.txt`·`diagnostic.log`·`stderr.txt`·`exit-code.txt`·`result.txt`·`model.txt`, 로티 탭. agy 대화창은 그 홈의 고정 작업 폴더 하나(`$KADAN_HOME/senior-agy`, 에이전트 파일 포함)를 여러 호출·여러 자리가 함께 쓰고 질문 파일만 자리별이다([agy 대화창](#agy-대화창)). 코드에서 확인한 것이며 실제 codex·agy를 동시에 돌린 실측은 하지 않았다(모델 호출 금지). 두 도구가 사용자 홈의 자기 상태(`~/.codex`·`~/.gemini`)를 동시에 쓰는 문제는 이 쪽에서 막지 못한다.
  - **시니어 하나의 방식**
  - 실행기는 **안전 허용 목록**(`SENIOR_SAFE_RUNNERS`, 지금 `codex`·`agy`)에 있어야 한다. 목록 밖은 저장(`kadan runners set senior`)에서 거절하고, 설정 파일을 직접 고친 값도 실행 직전 같은 검사로 거절한다(실행 0회).
  - **codex**는 기본으로 대화형 세션에서 카드 저장소의 절대경로를 읽는다. 헤드리스 모드는 `scripts/senior.sh`를 쓴다.
  - **agy는 대화창으로만 부른다(2026-11-18 [kyle])**: 헤드리스(`--print`) 자동 호출은 하지 않는다. 실행기 표의 `exec` 틀(설명 AI용)은 시니어가 쓰지 않으며, 시니어 코드에는 그 틀로 가는 갈래가 없다. `senior-mode`가 `headless`인데 등록 목록에 agy가 하나라도 있으면 — 등록 순서와 무관하게, `--model`로 codex만 골라도 — **아무도 부르지 않고 거절한다**(호출 0회, 이유 낱말 `headless-agy`). 대화형이 실패해도 헤드리스로 넘어가지 않는다. 방식은 [agy 대화창](#agy-대화창).
    - **저장소 읽기(2026-10-21 [kyle])**: 카드의 `repoPath` 자체가 `git rev-parse --show-toplevel`과 같을 때만(하위 폴더·홈·`/`는 제외하고, git 메타데이터로 부모를 계산하지 않는다) 그 실경로를 `--add-dir <절대경로>`로 넘겨 읽기 전용 폴더로 연다. 프롬프트에는 그 절대경로가 읽기 전용 폴더로 열려 있다고 적는다.
    - 경로가 없거나 git이 아니거나 공백·메타문자·`{}`·한글처럼 허용 글자 밖이면 `--add-dir`를 붙이지 않고 카드 본문과 `--file` 첨부만 근거로 쓴다. 프롬프트에 '저장소를 직접 읽을 수 없다'고 적는다.
    - **가림 범위**: `scrubForAI`(웹훅 주소·토큰 모양 가림)는 **프롬프트에만** 적용된다. agy가 직접 읽는 저장소 파일에는 적용되지 않는다. codex 시니어가 저장소를 읽어 외부로 보내는 것과 같은 수준이다(kyle 판단). 비밀이 든 파일이 있는 저장소는 이 점을 알고 부른다.
    - 프롬프트 200KB 상한과 `scrubForAI` 가림은 그대로다. 상한을 넘으면 부르지 않는다.
    - `--effort`는 agy에 넘기지 않는다. 영수증에 `note`로 알린다. 모델 이름의 강도가 우선 적용되는 것은 조사에서 쓴 조합(`gemini-4-argon-medium` + `--effort low` → 경고 뒤 medium)에서만 확인했다. 그래서 카단은 agy 칸의 강도를 **적지 않는다**(아래 강도 표시).
  - 기록: 덮어쓰기로 한 명만 골라 부르면 원장 `advice` 사건과 영수증 칸에 `source: "flag"`와 쓴 `runner`·`model`이 남는다.
- 상한: 기본 1800초(30분), `--timeout`으로 1..3600초. 고급 모델이 저장소를 읽고 시험까지 돌려 보며 오래 고민할 수 있게 넉넉히 둔다(2026-10-05 [kyle]).
- **결과(모델별)**: 영수증(JSON)에는 `askId`·`card`와 `answers[]`가 있고, 그 뒤에 시니어마다 답변 본문을 `--- 시니어 <실행기>/<모델>/<강도> · <상태> ---` 머리로 나눠 출력한다. 각 칸에는 실행기·모델·강도(`effort`, 카단이 강도를 넘기지 않는 칸은 `effortSource`)·`status`(`ok`·`한도`·`실패(<이유>)`)·`reason`·`adviceId`·`durationMs`·`evidencePath`·따라 보기 정보가 있고, 답은 `ok`인 칸에만 `answer`로 있다. **옛 단일 `answer`·`model` 칸은 없앴다**(2026-10-22): 예전 명령 출력을 읽던 코드는 `answers[0]`을 본다. 답변은 네 칸이다 — **결론** 한 줄, **근거**, **위험**, **확인할 것**.
  ```
  {"askId": "…", "card": "repo/card", "answers": [
    {"runner": "codex", "model": "gpt-6-astra", "effort": "high", "status": "ok", "reason": "ok", "adviceId": "…", "evidencePath": "…/advice/<askId>/1-codex-gpt-6-astra", …},
    {"runner": "agy", "model": "gemini-4-argon-medium", "effortSource": "model-name", "status": "한도", "reason": "limit", "adviceId": "…", "evidencePath": "…/2-agy-gemini-4-argon-medium", …}]}
  --- 시니어 codex/gpt-6-astra/high · ok ---
  결론: …
  --- 시니어 agy/gemini-4-argon-medium/강도 모델 이름 따름 · 한도 ---
  (답 없음 — 증거 폴더 참고)
  ```
- **강도 표시(2026-11-19 [kyle])**: 강도 칸은 카단이 그 모델에 **실제로 넘긴 값**만 적는다.
  - codex 칸: `effort`는 codex 실행 인자(`model_reasoning_effort`)에 넘긴 값이다. 설정에 강도가 없으면 `max`, `--effort`를 주면 그 값이다.
  - agy 칸(카단이 강도를 넘기지 않는 칸): `effort` 칸이 **없고** `effortSource: "model-name"`만 있다. 화면 머리의 강도 자리는 고정 문구 `강도 모델 이름 따름`이다. `--effort low`를 줘도 같다(무시한 사실은 `note`). 설정에 강도가 적힌 agy 항목도 같다.
  - 카단은 모델 이름에서 강도 낱말(`medium` 등)을 뽑아 적지 않는다. 실제 강도는 agy 화면 아래의 모델 줄에서 본다.
  - 이유: 2026-11-19 agy 칸(`gemini-4-neon-medium`)이 `effort: max`로 찍혔다. 넘기지 않은 값을 빈 칸 기본값 `max`로 채운 것이었다. 그 전의 원장 줄(agy 칸의 `effort: "max"`)은 고치지 않는다 — agy 칸의 옛 `effort` 값은 믿지 않는다.
  - JSON 모양을 `effort: null`이 아니라 '칸 없음 + `effortSource`'로 한 이유: 왜 없는지가 줄에 남고, `effort`를 그대로 문자열로 다루는 코드가 `null`을 글자로 찍거나 비교하다 멈추지 않는다.
- **종료 코드**: 하나라도 `ok`면 0이고 나머지 칸은 상태로 보인다. 전원이 `ok`가 아니면 1이고 오류 글에 시니어마다 이유와 증거 경로가 있다.
- **한도 판정(헤드리스)**: 실패한 호출의 stderr·stdout에 `429`·`quota`·`usage limit`·`rate limit` 중 하나가 있으면(대소문자 무시) `reason: limit`, 화면 '한도'다. 그 밖의 실패는 시간 초과(`timeout`)·호출 실패(`call-failed`)·빈 답(`empty`)이다. **어떤 실패도 자동 재시도하지 않는다.** `ocx refresh` 같은 한도 복구 동작도 하지 않는다. 다시 부르는 것은 감독이 명령을 다시 내는 것이다.
- 실패 기준: `ok`는 종료 코드 0이고 답이 비어 있지 않을 때뿐이다(fail closed). 답을 쓰지 않는다.

## 대화형 방식 (senior-mode)

codex는 헤드리스로도 문제없이 호출할 수 있다. 그래도 대화창으로 띄우는 이유는 다른 카단 역할(작업자·감독)과 같은 방식으로 통일하고 로티에서 실제 진행을 보기 위해서다(2026-11-18 [kyle]: "그냥 카단처럼 띄우면 되잖아. 코덱스는 문제없긴 해"). agy는 헤드리스(`--print`) 자동 호출이 계정 차단으로 이어진 사례가 있다고 들어서(원문은 확인하지 못했다) 헤드리스로 부르지 않고 대화창으로만 부르기로 했다. 대화형 길은 codex와 agy를 모두 부른다(2026-11-18). 헤드리스 길은 codex만 부른다.

- **모드 선택**. 설정 파일이 없으면 `interactive`다. `$KADAN_HOME/senior-mode`에는 `interactive`와 `headless` 중 하나만 쓴다. 잘못된 값은 호출 전에 거절하고 실패 시 자동 전환은 없다.
- **헤드리스는 codex만**: `headless`에서 등록 목록에 agy가 하나라도 있으면 아무도 부르지 않고 거절한다(위 '시니어 하나의 방식'). 대화형에서는 codex와 agy를 함께 등록해도 전원이 자리 확보·질문 전 준비를 함께 통과해야 질문이 나간다.
- **무엇이 도나(codex)**: 시니어마다 codex 대화형 화면을 카단 전용 tmux 소켓 `-L kadan-senior`의 세션(`senior-<askId 앞 8자>-<순번>`)으로 띄운다. 프롬프트 전체는 호출 폴더의 `input.txt`(200KB 상한·`scrubForAI`)에 쓰고 화면에는 "`../input.txt`를 끝까지 읽고 적힌 대로 수행하라" 한 줄만 넣는다. 모델은 작업 폴더 `out/`의 `result.txt`에 답을 쓰고 마지막 줄에 끝 표지를 붙인다. 카단은 표지를 뗀 답을 호출 폴더의 `result.txt`에 둔다(원장 `bytes`·`digest`와 영수증 `answer`가 같은 글이다). 세션은 끄지 않고 남겨 둔다 — 끄는 것은 `kadan senior cleanup`과 남긴 세션 내보내기다(아래 '남겨 두기와 정리').
- **창 크기는 고정한다**: 세션은 150x50으로 만들고 `window-size manual`을 건다. 로티 읽기 전용 탭(`attach -r`)이 입력은 막아도 크기는 못 막아서, 고정하지 않으면 작은 탭이 붙는 순간 창이 탭 크기로 줄어 codex가 다시 그린다(2026-11-18 검수 실측: 150x50 → 60x20). 붙여넣기 직전 검사는 화면을 한 번만 읽고 아니면 거절하는 그대로다 — 크기가 안 바뀌면 다시 그릴 일이 없어 기다림을 더하지 않았다.
- **역할이 아니다**: 원장에 `start`·`stop`을 쓰지 않고 지침 우편·관계표·감시 대상에 들지 않는다. 기록은 지금처럼 호출마다 `advice` 한 줄(`mode: "interactive"`가 붙는다)과 증거 폴더다. 시니어 소켓은 자원 감시(`process-watch`)에 잡히지 않는다.
- **agy는 [agy 대화창](#agy-대화창)** 절이 다른 점을 적는다. 같은 것: 전용 소켓·세션 이름·창 크기 고정·역할 아님·남겨 두기와 정리·동시 수(진행 중은 codex와 agy를 합쳐 4, 남긴 세션은 6)·키 두 단계·제출 뒤 로티 탭.
- **유지하는 것**: 등록된 전원에게 동시에 묻기, 칸별 상태(`ok`·`한도`·`실패(<이유>)`), 감독이 모델을 고르지 않음, 종료 코드(하나라도 답하면 0), 시간 상한(기본 1800초), 준비가 한 명이라도 거절되면 아무도 부르지 않음.

### 격리 수준 (codex)

"읽기 전용 보장"이 아니다. **지금 헤드리스 시니어와 같은 수준**이다(2026-11-17 [kyle] 결정: codex 설정은 사용자 것 그대로 쓴다).

- 확인됨(실측): 셸로 저장소·홈·`/tmp`·호출 폴더 위쪽 쓰기 실패, 네트워크(`curl`) 실패, 편집 도구로 저장소 쓰기 실패, 모델이 MCP 도구를 부르면 승인 정책 never로 거절(시험용 도구 1개에서만).
- 지금 헤드리스와 같은 것: 같은 호출 꼴의 **표식 홈**에서 헤드리스도 MCP 서버 프로세스를 띄우고(샌드박스 밖에서 돈다) 훅·notify가 발화했다. 사용자 실제 설정으로는 직접 호출하지 않았으며 같은 경로가 적용될 것으로 본다(추정).
- 지금 헤드리스와 다른 것(측정): 샌드박스가 `read-only`가 아니라 `workspace-write`다(모델 작업 폴더 `out/` 쓰기). 대화형에만 내장 `codex_worktrees`(worktree 만들기 도구, 승인 없이 실행됨)가 붙는다 — 작업 폴더가 git 밖이면 쓰기 실패.
- 미확인: 플러그인 커넥터의 쓰기 도구가 never에서 막히는지, 주석 있는 MCP 도구, 웹 도구 `web__run`, 샌드박스 안에서 유닉스 소켓 접속(운영 tmux 등)이 막히는지.

실행 꼴은 코드에 고정돼 있다(`codexArgv`, `src/senior-session.mjs`): `codex --no-alt-screen -C <out/> -s workspace-write -a never --model <모델>`에 강도·업데이트 확인 끄기·`sandbox_workspace_write`의 `/tmp`·`TMPDIR` 제외·네트워크 끔·쓰기 폴더 추가 없음을 `-c`로 준다. `-s`·`-a`는 반드시 준다(사용자 기본값이 더 넓을 수 있다). 세션 안의 명령에서는 `KADAN_ROLE`·`TMUX`·`TMUX_PANE`을 지운다 — 부른 감독의 역할이 새면 사용자 설정의 카단 Stop 훅이 그 감독의 역할로 돈다.

### 질문을 넣기 전 관문

세션을 띄운 뒤 질문을 넣기 전에 아래를 모두 확인한다. 하나라도 아니면 질문을 넣지 않는다(모델 호출 0회). 그 칸은 `실패(call-failed)`이고 상세 이유는 영수증·원장의 `detail`(`isolation:<이유>`)과 증거 폴더 `gate.json`에 있다. 두 명을 부를 때 한 명이라도 걸리면 **누구에게도 질문을 넣지 않는다**(통과한 쪽의 `detail`은 `isolation:peer-gate-failed`).

1. 모델 작업 폴더 `out/`이 git 저장소 밖이다(안이면 codex를 띄우지도 않는다). agy는 고정 작업 폴더가 git 밖인지를 자리 준비에서 먼저 보고, 안이면 **세션도 에이전트 파일도 만들지 않고 호출 전체를 거절한다**(codex 칸 포함, 원장 줄 없음).
2. 빈 입력칸까지 떴다. 업데이트 선택 창·번호 선택 창·모르는 선택 화면이 떠 있으면 끝내 거절한다. codex는 이 단계에서 키를 하나도 보내지 않는다. agy는 첫 화면이 **그 고정 작업 폴더의 신뢰 창**일 때만 Enter를 한 번 보낸다([agy 대화창](#agy-대화창)의 조건).

**연결된 MCP 서버는 확인하지 않는다.** 예전에는 세션에서 `/mcp`를 넣어 허용 목록(`$KADAN_HOME/senior-mcp-allow`)과 견줬지만, 2026-11-18 kyle이 "MCP 확인 빼고 단순하게"로 정해 걷어냈다. 격리 수준은 위 "지금 헤드리스 시니어와 같은 수준"이고, 사용자 설정의 MCP 서버는 헤드리스처럼 그대로 뜬다. 허용 목록 파일은 더 읽지 않으며 있어도 쓰이지 않는다. 이 관문은 도구의 행동을 안전하다고 인증하지 않는다. "git 밖 작업 폴더 + 키 조건"일 뿐이다.

### 키를 보내는 조건

2026-11-17 시험 중 codex 업데이트 선택 창에 Enter가 들어가 전역 업데이트가 시작된 적이 있다(기본 선택이 `npm install -g`). 그래서 키는 아래 두 단계로만 나간다(보내는 키는 질문 한 줄뿐이다). 전송은 바닥의 `sendTmux`를 그대로 쓰고, 전용 소켓 실행 함수가 키 명령 직전에 화면을 새로 읽는다.

1. **붙여넣기 직전**: 화면의 마지막 입력 기호(`›`) 줄이 빈 입력칸이고, 그 아래는 상태 줄 몇 줄뿐이며(번호 선택지·키 안내·다른 기호 줄이 없다), 일하는 표시가 없다. 업데이트 선택 창에는 옛 빈 입력칸이 위에 남아 있어 "빈 입력칸이 보인다"만으로는 통과하지 못한다.
2. **Enter 직전**: 화면을 다시 읽어 입력칸의 글이 방금 붙인 자기 한 줄과 같을 때만(공백은 걷고 비교) 보낸다. 붙인 뒤 다른 창으로 바뀌었으면 Enter를 보내지 않는다.

**로티 읽기 전용 탭은 질문을 제출한 뒤에 연다.** tmux 3.8은 읽기 전용 클라이언트가 붙은 세션에 `send-keys`를 보내면 `client is read-only`로 거절한다(3.6은 통과, 2026-11-18 CI macOS 실패로 확인). 이 거절을 우회하려고 Enter를 `paste-buffer`로 대신 보내는 길을 한때 만들었지만 없앴다 — 복사(기록보기) 모드에서 일반 `send-keys Enter`는 프로그램에 키를 넘기지 않는데 `paste-buffer`는 닿는 것처럼, 같은 확인을 붙여도 일반 Enter와 같아질 수 없었고 검수마다 더 약한 곳이 나왔다. 그래서 키를 보내는 동안에는 읽기 전용 클라이언트가 아예 없게 한다: 질문 붙여넣기와 Enter를 모두 보낸 뒤(tmux가 Enter를 받아들인 뒤)에야 탭을 연다. 이 뒤로 이 세션에 보내는 키는 없다 — 끝 판정 대기는 화면 읽기·생존 조회뿐이고 끄기는 `kill-session`뿐이다.

조건이 안 되면 키를 보내지 않고 그 칸은 실패다. 다시 넣거나 창을 스스로 닫지 않는다. **Esc는 보내지 않는다** — 알아본 안전한 닫기 대상이 따로 없다. 업데이트 확인 끄기(`-c check_for_update_on_startup=false`)는 실행 꼴에 넣었고, 로그인 안 된 시험용 codex 홈에서 이 옵션이 선택 창을 막는 것을 관찰했다(codex 0.166, 옵션 없이 2회 모두 창이 뜨고 옵션을 주면 2회 모두 안 뜸. 로그인된 사용자 설정에서는 확인하지 못했다). 그래도 실제 방어는 이 키 조건이다.

### 끝과 실패를 아는 법

- **`ok`**: 답 파일이 일반 파일(링크 아님)이고 256KB 안이며, 마지막 줄이 이번 호출의 끝 표지이고, 표지가 정확히 한 번이며, 표지를 뗀 답이 비어 있지 않다. 그리고 질문을 넣은 뒤 화면이 **일하는 표시를 거쳐** 다시 빈 입력칸으로 쉴 때만 확정한다(쓰는 중인 파일을 받지 않는다). 끝 표지는 `input.txt`에 조각으로만 적고 모델이 조립한다 — 완성된 표지는 `input.txt`에도 화면 입력에도 없다.
- **`empty`**: 화면이 쉬는데 위 조건을 못 채웠다(답 파일 없음·표지 없음·표지 둘·표지만 등, `detail`에 이유). 한계: 모델이 너무 빨리 끝나 폴링이 일하는 표시를 한 번도 못 보면 정상 답도 `ok`로 받지 않는다(`detail: no-work-seen`). 잘못된 `ok`를 막으려고 고른 한계다.
- **`limit`**(화면 '한도'): 입력칸 바로 위 오류 덩어리(`■` 줄)에 한도 낱말(`429`·`quota`·`usage limit`·`rate limit`·`at capacity`)이 있을 때. 같은 낱말이 답 본문에만 있으면 한도가 아니다.
- **`timeout`**: 시간 상한(`--timeout`, 호출 시작부터 잰다 — 자리·관문 시간 포함). 관문 준비, 질문 프로세스 시작, 질문 붙여넣기, Enter 직전마다 남은 시간을 다시 보고(화면을 읽고 판정한 뒤, 키 명령 바로 앞에서 본다), 끝났으면 **새 입력 없이** `timeout`으로 끝낸다(`detail: deadline:<어디서>`). 이미 제출한 질문은 같은 폴링에서 완성된 답이 `timeout`보다 먼저다. 답 파일에 표지가 있어도 화면이 아직 일하는 중이면 `ok`가 아니라 `timeout`이다.
- **`call-failed`**: 세션이 죽었거나, 관문·키 조건에 걸렸다.
- **자동 재시도·`ocx refresh`·헤드리스 전환을 하지 않는다.** 호출이 끝난 때의 화면은 증거 폴더 `screen-final.txt`에 남는다(세션은 끄지 않는다 — 아래 '남겨 두기와 정리').
- agy 칸은 답 파일이 아니라 화면에서 회수하므로 `ok`·`empty`·`call-failed`의 조건이 다르다([agy 대화창](#agy-대화창)의 '답 회수'). 판정 낱말과 영수증·원장 모양은 같다.

### agy 대화창

Why: kyle이 gemini 모델(아르곤 등)을 시니어로 다시 쓰고 싶다(2026-11-18: "agy를 사용하는 건 괜찮아"). 걱정은 agy 헤드리스(`--print`) 자동 호출뿐이라(차단 사례를 들었다, 원문 미확인), agy를 codex처럼 대화창으로 띄워 묻는다. 근거는 agy 1.5.10 대화창 한 세션의 조사다(모델 호출 4회).

- **실행 꼴**(코드에 고정, `agyArgv` — `src/senior-agy.mjs`): `agy --model <모델> --agent kadan-noexec [--add-dir <카드 저장소>]`. `--print`·`-p`·`--effort`는 넣지 않는다. 세션 안에서는 codex와 같이 `KADAN_ROLE`·`TMUX`·`TMUX_PANE`을 지운다. 모델 값은 `--model` 뒤의 인자로 그대로 놓이므로 **옵션 모양이면 안 된다**: 영문·숫자·`./-[]`만 쓰고 `-`로 시작할 수 없다(`--print` 같은 값이 옵션으로 읽히면 헤드리스로 돈다). 저장(`runners set senior`)이 받지 않고, 설정 파일을 직접 고친 값도 호출 전에 등록 목록 전체를 보고 전원 거절한다(호출 0회, 이유 낱말 `senior-model-shape`).
- **작업 폴더는 홈마다 고정 하나**: `$KADAN_HOME/senior-agy/`. 호출마다 새 폴더를 쓰면 호출마다 신뢰 창이 뜨고 사용자 agy 신뢰 목록이 호출 수만큼 늘어난다. 고정 폴더면 **처음 한 번만** 늘어난다. 준비 순서는 자리 준비 잠금(`senior-seats.lock`) 안에서 (1) 고정 폴더가 git 저장소 밖인지 확인 → (2) 도구 없는 에이전트 파일(`.agents/agents/kadan-noexec/agent.md`, `tools: view_file`, `commandExecutionPolicy: off`) → (3) 자리별 질문 파일 → (4) 세션이다. git 안이거나 폴더가 링크거나 에이전트 파일을 못 쓰면 아무도 부르지 않는다.
- **질문 파일은 자리별**: 프롬프트 전체는 고정 폴더의 `asks/<askId>-<자리 번호>.txt`에 쓰고(같은 글이 증거 폴더 `input.txt`에도 남는다) 화면에는 "다음 파일을 끝까지 읽고 거기 적힌 대로 수행하라: <절대경로>" 한 줄만 넣는다(`/`로 시작하는 글은 agy가 명령 완성 목록을 띄워서 글로 시작한다). 질문 파일은 세션과 함께 남고, 그 세션을 끌 때(정리 명령·남긴 세션 내보내기) 카단이 만든 그 파일만 지운다. 세션이 스스로 사라진 호출(agy가 죽음)은 호출 끝에 지운다. 세션을 끄지 못했으면 파일도 그대로 둔다.
  - **받아들인 노출**: 같은 고정 폴더를 쓰는 다른 agy 호출이 `view_file`로 남의 질문 파일을 읽을 가능성이 있으며 확인하지 못했다. 이름은 추측하기 어려운 askId이고 호출 끝에 지운다. 같은 사람의 시니어 질문끼리라 위험이 낮다고 보고 받아들였다.
- **신뢰 창(운영에서의 자동 승인 범위)**: 자동으로 지나는 것은 **그 홈의 고정 작업 폴더 실경로 하나뿐**이다. 처음 한 번 사용자 agy 신뢰 목록에 그 경로가 하나 더해진다(카단은 사용자 agy 설정 파일을 직접 고치지 않는다). 조건을 모두 채울 때만 Enter를 **한 번** 보낸다:
  1. 화면이 agy 신뢰 창의 구조다(`src/senior-agy-screen.mjs`의 `readAgyTrust` — 첫 줄 `Accessing workspace:`, 경로, 질문, `> Yes, I trust this folder`·`No, exit`, `enter Confirm`, 그 아래 상태 줄 한 줄까지. claude 신뢰 창 판정기를 그대로 쓰지 않는다).
  2. 경로 줄이 정확히 한 줄이고 그 실경로(realpath)가 이 세션의 고정 작업 폴더와 같다.
  3. 선택 표시(`>`)가 정확히 하나이고 Yes 줄에 있다.
  4. Enter 직전에 codex 질문 키와 같은 순서로 다시 확인한다: 그 pane이 기록보기(복사) 모드가 아니다 → 붙은 사람이 최근에 입력하지 않았다(바닥의 키 전송과 같은 확인 함수 `checkPaneMode`·`checkHumanIdle`) → 같은 pane이 기록한 PID로 살아 있다 → 화면을 다시 읽어 같은 경로·같은 선택이다 → 시간 상한이 남아 있다. PID·생존을 사람 입력 조회 뒤에 보는 이유는 그 조회 도중 창의 프로세스가 바뀌면 새 프로세스로 Enter가 가지 않게 하려는 것이다. 기록보기 중이거나 사람 입력이 감지되면 다시 시도하지 않고 그 칸은 실패다(`trust-pane-in-mode`·`trust-human-active`).
  5. 끄기 스위치 `$KADAN_HOME/auto-trust.off`가 없다(claude 폴더 신뢰 자동 통과 #418과 같은 스위치).

  하나라도 아니면 키 0회로 그 칸은 `실패(call-failed)`(`detail: isolation:startup:trust-…`)이고, 함께 부른 칸도 질문을 받지 않는다. Enter 뒤에는 같은 pane에 정상 빈 입력칸이 뜰 때까지 기다리고, 신뢰 창이 그대로면 더 보내지 않고 실패한다. 지난 사실은 증거 폴더 `gate.json`의 `trust`와 영수증 `note`에 남는다(역할이 아니라 원장 `trust` 사건은 쓰지 않는다).
- **화면 판정**(`src/senior-agy-screen.mjs`): 입력칸은 가로줄 두 개 사이의 `>` 줄이고 그 아래는 바닥글 **한 줄**이어야 한다(우리가 띄운 에이전트 이름 `kadan-noexec`가 그 줄에 있다). 바닥글 왼쪽 글이 상태다 — 빈 입력칸은 `? for shortcuts`, 일하는 중은 `esc to cancel`, 글이 든 입력칸은 비어 있다. 그래서 첫 기동의 안내 글(`Auto mode: …`)이 든 입력칸과 배너(`esc to dismiss`)는 빈 입력칸으로 통과하고, 생성 중에 보이는 빈 `>`·명령 완성 목록·모르는 선택 화면은 통과하지 못한다. 키는 codex와 같은 두 단계다: 붙여넣기 직전 빈 입력칸, Enter 직전 '입력칸의 글 = 방금 붙인 자기 한 줄'(긴 줄은 화면에서 감기므로 공백을 걷고 견준다)이고 바닥글 왼쪽이 비어 있을 것. 신뢰 창을 지난 자리도 이 두 조건을 각각 지난다. 업데이트·로그인·약관 창의 모양은 조사에서 못 봤다 — 이 조건이 막는다(키 0회).
- **답 회수(스크롤 기록)**: 도구 없는 에이전트는 답 파일을 쓸 수 없어, 답을 화면에 쓰고 마지막 줄에 끝 표지만 단독으로 쓰게 한다(표지는 codex와 같이 조각으로만 건넨다). 한 화면에는 긴 답이 다 안 보이므로(조사: 60줄 답 중 마지막 화면에는 32줄) tmux 전체 스크롤 기록(`capture-pane -J -S -`)에서 읽는다. `ok`는 아래를 모두 채울 때만이다.
  1. 질문을 넣은 뒤 화면이 일하는 표시를 거쳐 다시 빈 입력칸으로 쉰다(생성 중에는 지금 화면만 읽고, 끝 판정 때만 전체 스크롤을 한 번 읽는다). **답을 읽는 그 스크롤 캡처도 쉬는 화면이어야 한다**: 지금 화면을 본 뒤 캡처하는 사이에 일하는 표시·선택 창·글이 든 입력칸으로 바뀌어 있으면 `call-failed`(`final-capture-not-idle:<이유>`)다.
  2. **이번 질문의 시작 경계**(제출해 화면에 되찍힌 자기 한 줄 — askId가 든 질문 파일 경로라 호출마다 다르다)가 스크롤에 정확히 한 번 남아 있다. 넣기 전에는 그 줄이 스크롤 어디에도 없음을 먼저 확인한다. 경계가 사라졌거나(밀려남·지워짐) 둘 이상이면 `call-failed`(`boundary-lost`·`boundary-repeated`)다 — 표지와 빈 입력칸이 남아 있어도 잘린 답을 받지 않는다.
  3. 경계 뒤부터 입력칸 위 가로줄까지에서 이번 표지가 **단독 줄로 정확히 한 번**이고 본문 속 인용을 포함해 다른 곳에는 없다. 표지 뒤에는 agy의 꼬리(빈 줄, `Sources:` 묶음, `(ctrl+o to expand)`)만 있다 — 다른 글이 있으면 `ok`가 아니다(`text-after-marker`).
  4. 표지 앞 답이 비어 있지 않고 256KiB 안이다.
  5. 스크롤이 한도까지 차지 않았고(`scrollback-limit`), 캡처가 성공했으며 출력 상한(32MiB) 안이다(`capture-failed`·`capture-too-big`). 이 셋은 `ok`가 아니라 `call-failed`다.

  표지 조건을 못 채운 화면은 `empty`(`no-marker`·`marker-repeated`·`marker-not-alone`·`text-after-marker`·`marker-only`·`answer-too-big`·`no-work-seen`)다.
  - **받는 답은 화면에 그려진 글이다**: agy가 두 칸 들여 그린 줄만 모아 들여쓰기를 걷는다. 첫 칸에서 시작하는 줄(생각·도구 표시 `▸ Thought…`·`● Explored…`)은 뺀다. tmux가 감은 줄은 `-J`로 잇지만 **앱이 화면 폭에 맞춰 스스로 넣은 줄바꿈은 그대로 남는다**(긴 문장이 중간에서 끊겨 보일 수 있다). 앱이 끊어 놓은 표지를 추측해 이어 붙이지 않는다. 글머리표 같은 꾸밈도 그려진 모양(`•`)으로 온다. 사용자 agy 세션 DB는 읽지 않는다.
  - **한도**: agy의 한도·오류 화면 모양은 관찰한 적이 없어 `limit`으로 가르지 않는다. 표지가 없으면 `empty`, 세션이 죽으면 `call-failed`다.
- **격리 수준**: 기존 헤드리스와 같은 수준을 **목표로** `kadan-noexec` 정의를 재사용한다. agy 1.5.10의 한 세션에서 시험 저장소 읽기 성공, 시험 저장소와 호출 폴더의 요청한 파일 생성 0건, 지정한 로컬 요청 0건을 관측했다. **미확인**: 모델이 있다고 답한 `manage_task` 도구의 효과, 실제 홈·`/tmp` 쓰기 차단, 저장소 밖 읽기 경계, 외부 네트워크, MCP 연결·훅 실행·확장·전역 규칙의 전달, 고정 폴더 안 다른 질문 파일 접근. 남는 관문은 작업 폴더 git 밖과 키 조건이며 MCP는 확인하지 않는다(codex와 같다).
- **설명 AI는 따로다**: 설명 AI는 시니어 등록과 무관하게 자기 설정의 `exec` 틀로 부른다([실행 모델 설정](runner-settings.md#설명-ai)). 이 절의 '헤드리스로 부르지 않는다'는 시니어에 한한다.

### 남겨 두기와 정리

**호출이 끝난 세션은 끄지 않고 남겨 둔다**(2026-11-19 [kyle]: "시니어들도 나중에 일괄정리하는 방향으로 가자. 이런 거 확인 좀 할 수 있게"). 답을 받자마자 세션과 로티 탭을 닫으면 사람이 화면(모델·강도 줄, 한도 화면, 관문에서 뜬 창)을 직접 볼 수 없었다.

- **남기는 경우**: 대화형 호출에서 세션을 만든 뒤 끝나는 모든 경우다 — `ok`·`empty`·`limit`·`timeout`·`call-failed`·관문 거절·함께 부른 쪽의 관문 실패·TERM/INT 중단. 로티 탭도 함께 남는다.
  - 끝난 때의 화면은 지금처럼 `screen-final.txt`에 남긴다. 호출 폴더의 `session.json`에는 `endedAt`·`endReason`(끝난 이유)·`keptAt`(남긴 시각)을 적는다. 먼저 적은 쪽의 값이 남는다(감싼 프로세스가 적은 이유를 부른 쪽이 덮어쓰지 않는다).
  - 영수증에는 `keptSessions`(남긴 수)가 있고, 영수증 아래에 `세션 N개를 남겼다 — 정리: kadan senior cleanup` 한 줄이 붙는다. 전원이 실패한 호출의 오류 글에도 같은 줄이 있다. 남긴 수는 만든 자리 수가 아니라 **전원이 끝난 시점에 다시 조회해** 살아 있고 기록 대조가 맞는 수다(한 칸이 먼저 끝난 뒤 다른 정리가 그 세션을 껐으면 세지 않는다). 그때 확인하지 못한 세션(조회 실패·기록과 다름)은 세지 않지만 끄거나 탭을 닫지도 않는다 — 살아 있으면 정리 명령이 나중에 다시 본다.
  - **남기지 않는 경우**: (1) 자리 만들기 도중 실패(만든 자기 세션을 끄고 아무도 부르지 않는다), (2) 헤드리스 모드(세션이 없고 탭은 지금처럼 호출 끝에 닫는다), (3) 세션이 스스로 사라진 호출(pane이 죽어 세션이 없다는 것이 확정된 경우 — 볼 것이 없어 열린 탭을 닫고 그 자리의 질문 파일을 치운다), (4) 문을 열지 않은 자리(codex 작업 폴더가 git 안이라 관문이 띄우기 전에 거절 — 모델이 뜨지 않은 대기 셸이라 그 자리에서 끈다).
- **키 0회**: 답을 회수한 뒤, 또는 호출이 끝난 뒤에는 남긴 세션에 `send-keys`·`paste-buffer`를 하나도 보내지 않는다. 남기는 길(정상·실패·시간 초과)은 끝 화면을 읽기만 하고, 신호 처리기는 tmux를 아예 부르지 않고 기록만 적는다. 정리 명령과 내보내기도 키를 보내지 않는다. 빈 입력칸 확인은 새로 만든 자기 세션에서만 한다(남긴 세션의 화면은 보지 않는다).
  - 그래서 **시간 초과·중단으로 남긴 세션은 모델이 계속 일하고 있을 수 있다**(멈추는 키를 보내지 않는다). 멈추려면 정리 명령으로 끈다.
- **끄는 길은 셋뿐이고 모두 같은 확인을 쓴다**(`killOwn`): 정리 명령, 남긴 세션 상한을 넘겼을 때의 내보내기, 만들다 만 자리의 정리. 소켓·세션 이름·생성 식별값(askId)·호출 폴더·pane PID가 호출 폴더의 `session.json`과 같을 때만 `kill-session -t =<세션>`. 다르면 끄지 않고 이유를 `session.json`의 `killSkipped`에 남긴다. 끈 시각과 까닭은 `closedAt`·`closeReason`(`cleanup`·`evicted`·`partial-create`·`not-kept`)으로 끝난 이유와 따로 남는다. 운영 코드에 `kill-server`는 없다(마지막 세션이 꺼지면 그 소켓의 tmux 서버도 스스로 끝난다).
  - 서버는 살아 있는데 그 이름의 세션이 없으면 tmux는 실패하지 않고 네 칸이 모두 빈 답을 준다(tmux 3.6a, 2026-11-19 격리 소켓에서 관찰: 종료 코드 0). 전에는 답을 받자마자 세션을 꺼서 서버도 함께 끝났기 때문에 드러나지 않았다. 그래서 칸이 다 온 답의 세션 이름이 기록과 다르면 '없음'으로 읽는다('기록과 다름'이 아니다). 칸이 다 오지 않은 답(신호를 받은 tmux 호출은 종료 코드 0·출력 없이 끝난다)은 '조회 실패'다 — 끝난 것으로 적지 않는다.
- **만드는 순서**: 대기 셸로 세션을 만든다 → 세션 옵션(호출 폴더·askId)을 쓴다 → `session.json`을 쓴다 → 관문 직전에 문 파일을 만들면 대기 셸이 그 자리에서 codex가 된다(pane PID가 바뀌지 않는다). 문이 60초 안에 안 열리면 대기 셸이 스스로 끝난다.
  - **예약 종료는 걸지 않는다**(전에는 `run-shell -b -d <상한+2분>`으로 tmux 서버가 세션을 껐다). 끝난 세션을 남겨 두므로 끌 일이 없고, 부른 쪽이 기록 없이 죽은 호출은 기록의 만료 시각(`expiresAt`, 상한+2분)·부른 프로세스 생존으로 끝난 것을 안다. '끝남만 적는 예약'으로 바꾸지 않고 아예 없앤 이유: 그 정보가 이미 기록에 있어 tmux 서버가 따로 프로세스를 띄울 일이 없다.
  - 이미 떠 있는 tmux 서버에 걸린 **옛 예약**은 새 코드의 `reap`을 부른다. 새 `reap`은 세션을 끄지 않고(tmux 호출 0회) 끝남 기록만 남기며 늘 0으로 끝난다.
- **감싼 프로세스**: 질문 넣기 → 폴링 → 남김 표시는 호출 하나당 프로세스 하나(`src/senior-session-run.mjs`)로 감싸 기존 호출 프로세스(`runJudgeProcess`)로 돌린다. 그 프로세스가 TERM을 받으면 세션을 끄지 않고 판정(`interrupted`)과 남김 표시만 적고 나간다. 판정은 `outcome.json`의 낱말로 넘긴다. TERM은 프로세스 묶음 전체에 가므로 그때 돌던 tmux 호출도 같이 죽는데, 이것을 죽은 세션(`call-failed`)으로 읽지 않는다: 세션이 살아 있다는 답이 아니면 한 번 더 묻고 그래도 아닐 때만 죽은 것으로 본다(TERM을 받은 tmux 호출은 종료 코드 0·빈 출력으로 끝나 답만 보면 죽은 세션과 같다). 상한에 걸린 것이면 그 칸은 `timeout`이다.
- **세션 분류**(`seniorSessionStates`): 소켓의 세션 목록에서 출발해 세션 옵션이 가리키는 `session.json`을 찾는다. 이름으로 추측하지 않고 `advice/` 전체를 훑지 않는다.
  - **남긴 세션**: 그 호출이 끝났고(끝남 기록이 있음 · 만료 시각이 지남 · 부른 프로세스가 없음) 기록 대조가 맞는 것. 꺼도 되는 것은 이것뿐이다.
  - **진행 중으로 세는 세션**: 그 밖의 모두 — 도는 호출, 기록이 없거나 못 읽는 세션, 이 홈의 기록이 아닌 세션, 대조가 안 되는 세션. 보수적으로 진행 중 자리를 차지한다.
- **동시 수**: 진행 중 자리는 4개까지다(남긴 세션은 세지 않는다). 남긴 세션은 따로 6개까지다(3번 부른 분량). 짧은 생성 잠금(`$KADAN_HOME/senior-seats.lock`) 안에서 분류 → 남긴 세션 내보내기 → `진행 중 + 이번 전원 ≤ 4` → 이번 전원의 세션 만들기를 한 묶음으로 한다.
  - 진행 중 자리가 모자라면 아무도 부르지 않는다(줄 세우기 없음). 이때는 남긴 세션도 끄지 않는다.
  - `남긴 수 + 이번 인원 > 6`이면 가장 오래 남긴 것부터 끄고 그 탭을 닫는다. **남긴 세션 때문에 새 호출을 거절하지 않는다.** 끄지 못한 세션은 그대로 두고 진행 중 쪽에 센다.
  - 다음 호출은 남긴 세션을 끄지 않는다(전에는 다음 호출이 끝난 세션을 청소했다). 두 호출이 거의 동시에 끝나면 남긴 수가 잠깐 6을 넘을 수 있고, 다음 호출의 자리 확보에서 다시 맞춘다.
  - 세션 이름은 호출마다 다르다(`senior-<askId 앞 8자>-<순번>`). 같은 이름이 이미 있으면 새 세션 만들기가 실패해 아무도 부르지 않는다.
  - 한 세션을 만든 뒤 다음이 실패하면 만든 자기 세션을 끄고 거절한다. 만들다 만 세션의 정리도 같은 확인을 쓴다: 기록을 쓴 앞자리는 `killOwn`만, 기록을 쓰기 전이면 방금 읽은 pane PID·세션 옵션과 다시 견줘 같을 때만 끈다. 확인이 틀리거나 조회가 실패하면(접속 권한 오류 등 — tmux가 세션·서버가 없다고 확정한 문구만 "없음"으로 읽는다) **이름만으로 끄지 않고** 이유를 남긴다(`session.json`의 `killSkipped` 또는 호출 폴더 `create-cleanup.json`).
- **정리 명령**: `KADAN_ROLE=<감독> kadan senior cleanup [--dry-run]`. 감독과 사람만 부른다.
  - 시니어 소켓의 세션을 한 줄씩 보인다: `끔|끌 것|둠  <세션 이름>  <실행기>/<모델>  만든 <시각>  끝 <끝난 이유>  남긴 <시각>  <호출 폴더>`.
  - 남긴 세션(끝난 호출 + 대조 맞음)만 끈다. 끄면서 그 호출 폴더 `tab.json`에 열린 탭(`rottieTerminalId`)이 있으면 기존 탭 닫기로 닫는다. 로티 실행 파일이 없거나 운영 로티 보호에 걸리면 세션만 끄고 줄 끝에 `탭 close-skipped(<이유>) · 다음 cleanup이 다시 닫는다`를 보인다.
  - **세션 없이 남은 탭도 닫는다**: 세션 줄 뒤에 `탭 닫음|탭 닫을 것  (세션 없음)  탭 <id>  <호출 폴더>` 줄로 보인다. 내보낼 때 닫지 못했거나 세션이 먼저 사라진(재부팅 등) 호출의 탭이다. 세션이 없다고 확정하지 못한 탭은 닫지 않고 `탭 둠  (세션 줄 밖의 탭) … — 닫지 않음: <이유>`로 보인다(아래 '닫을 탭 표지').
  - 진행 중 호출·기록 없는 세션·대조가 안 되는 세션은 끄지 않고 줄 끝에 이유를 보인다(`끄지 않음: 진행 중인 호출` 등).
  - `--dry-run`은 무엇을 끌지만 보이고 **아무것도 바꾸지 않는다**(세션·기록·탭·표지·잠금 모두 그대로). 빈 홈에서도 파일을 하나도 만들지 않는다(tmux 설정 파일 포함).
  - **받는 인자는 `--dry-run` 하나뿐이다.** `--dry-run=true`처럼 이 명령이 모르는 표기나 다른 인자가 오면 아무것도 끄지 않고 종료 코드 1로 거절한다. 모르는 인자를 흘려보내면 미리보기로 친 명령이 실제 정리가 되기 때문이다(2026-11-19 검수에서 `--dry-run=true`가 세션을 껐다).
  - 쓰는 tmux 명령은 `list-sessions`·`display-message`·`kill-session`뿐이다. 본 실행은 자리 잠금을 잡아 다른 호출의 자리 확보와 겹치지 않는다(잠금을 못 얻으면 아무것도 끄지 않고 거절한다).
  - 이름이 `cleanup`인 카드에 묻으려면 `<저장소>/cleanup`처럼 저장소를 붙인 키를 쓴다.
- **감시는 붙지 않는다**: 시니어는 역할이 아니라서 남긴 세션은 감시기·대시보드·원장 start/stop에 보이지 않는다. 무엇이 남았는지는 `kadan senior cleanup --dry-run`으로 본다.
- **닫을 탭 표지**(`$KADAN_HOME/senior-open-tabs/`): 남긴 탭을 세션 없이도 다시 찾기 위한 작은 폴더다. 탭 하나에 파일 하나(`<askId>--<자리 폴더 이름>.json`, 호출 폴더 경로와 탭 id)이고, 원장·`advice/` 전체를 훑지 않는다.
  - 만든다: 대화형 호출이 탭을 열었을 때, 그리고 닫으려다 닫지 못했을 때(건너뜀·실패).
  - 지운다: **확실할 때만** — 닫기가 확인됐거나(닫힘, 또는 로티가 `ROTTIE_TERMINAL_NOT_FOUND`로 답함), `tab.json`을 정상으로 읽었더니 상태가 이미 닫힘일 때. `tab.json`을 읽지 못했거나 깨졌거나 모양이 다르면 '모름'이다: 표지를 그대로 두고 줄 끝에 이유를 보인다(다른 프로세스가 쓰는 순간에 읽었을 수 있다).
  - 표지는 찾는 실마리일 뿐이다. 닫는 탭 id는 그 호출 폴더의 `tab.json`에서 읽고(상태가 `opened` 또는 `close-failed`), 표지의 id와 같으며 호출 폴더가 이 홈의 `advice/` 아래일 때만 닫는다. 믿을 수 없는 표지는 닫지 않고 이유를 보인다.
  - 닫을 때 필요한 것은 로티 실행 파일과 운영 로티 보호(기본이 아닌 홈은 거절) 통과뿐이다. 탭 스위치와 창 설정은 '새 탭을 열지'를 정하는 값이라 닫기에는 보지 않는다(카단 pane 안의 감독은 `KADAN_WINDOW=none`을 물려받는다).
  - 정리 명령은 세션 줄을 다룬 뒤 표지를 훑는다. 세션 줄에서 이미 다룬 호출 폴더의 탭은 건너뛴다(껐으면 그때 닫아 봤고, 뒀으면 그 세션의 탭이다).
  - 나머지 탭은 **세션이 없다는 것이 확정됐을 때만** 닫는다. 근거는 그 호출의 `session.json`에 적힌 세션 이름으로 같은 소켓에 직접 조회한 결과다(세션을 끌 때의 소유 확인과 같은 기준). 세션 목록에 그 호출 폴더가 보이지 않는다는 것은 근거가 아니다 — 목록의 호출 폴더 칸은 비어 있을 수 있다.
    - 그 이름의 세션이 있으면 탭을 두고 진행 중으로 본다(호출 폴더 칸이 비었거나 PID·식별값이 기록과 달라도 같다).
    - 조회에 실패했거나, 다른 소켓의 호출이거나(표지는 홈마다, 세션은 소켓마다 있다), 세션 기록을 읽지 못하면 모르는 것이다: 탭을 두고 이유를 보인다.
    - 닫지 않은 탭은 `탭 둠  (세션 줄 밖의 탭)  탭 <id>  <호출 폴더>  — 닫지 않음: <이유>` 줄로 보이고 표지가 남는다.
  - **파일 안전**: 표지와 `tab.json`은 정규 파일일 때만 읽고 쓴다(링크·폴더는 따라가지 않고 거절). 표지 폴더가 링크면 읽지도 쓰지도 않는다. 호출 폴더가 이 홈의 `advice/` 아래인지는 실제 경로(링크를 푼 경로)로 본다. 쓰기는 임시 파일에 쓴 뒤 옮겨, 다른 프로세스가 읽는 순간에 반쯤 쓴 파일이 보이지 않는다.
  - 닫으려는 탭이 로티에 이미 없으면(사람이 남겨 둔 탭을 보고 직접 닫음 등) 닫힌 것으로 치고 표지를 지운다(`tabReason: already-gone`).
- **내보내기 결과**: 남긴 세션 상한을 넘겨 오래된 세션을 껐으면 영수증에 `evicted[]`(세션 이름과 탭 닫기 결과·이유)가 있고, 영수증 아래에 `남긴 세션 상한(6개)을 넘겨 오래된 세션 N개를 껐다: <세션>(탭 닫음 | 탭 close-failed: <이유> — 다음 kadan senior cleanup이 다시 닫는다 | 탭 없음)` 한 줄이 붙는다. 전원 실패 오류 글과, 내보낸 뒤 자리를 못 잡고 거절하는 오류 글에도 같은 줄이 있다.
- **알려진 한계**: 재부팅·tmux 서버 종료로 남긴 세션이 한꺼번에 사라지면 정리 명령이 찾을 세션이 없다. 그 호출들의 열린 탭은 표지로 찾아 닫지만, agy 질문 파일(`senior-agy/asks/`)은 남는다. 생성 응답이 유실된 탭(`tab: unknown`, 탭 id 없음)은 표지가 없어 로티에서 직접 닫는다(아래 '남은 탭 찾는 법').
- **로티에서 보기**. 질문을 제출한 뒤(붙여넣기와 Enter가 끝난 뒤) 로티 탭을 연다. 그래서 탭은 답을 쓰는 과정부터 보여 준다(질문 줄도 화면·스크롤에 남는다). 탭과 영수증의 `follow`는 같은 읽기 전용 명령(`tmux -L kadan-senior attach -r -t '=<세션>'`)을 쓴다. 탭 생성이 실패해도 자문은 계속하며 탭 결과는 `advice`에 남는다.

## 실측 시험

시니어는 비싼 모델이라 실제로 부르는 시험은 강도를 낮춰 돌린다(2026-10-05 [kyle]).

- `kadan senior … --effort low`: 이번 호출만 강도를 바꾼다. 실행 모델 설정은 그대로이고, 원장에는 `effort`(쓴 값)·`effortOverride: true`·`settingsEffort`(설정 값)가 남는다(agy 칸에는 셋 다 없고 `effortSource: "model-name"`만 있다). 모델이 지원하지 않는 강도는 호출 전에 거절한다.
- `npm run smoke:senior [-- --effort low --timeout 600]`: 임시 `KADAN_HOME`에 실행 모델 설정만 복사하고 가상 카드 하나로 실제 모델을 한 번 부른다. 답에 결론·근거·위험·확인할 것 네 칸이 있으면 통과. 비용이 들어 `npm test`에는 넣지 않는다. 운영 원장은 건드리지 않는다.

## 원장 기록

질문 하나에 시니어마다 `advice` 사건 한 줄을 남긴다(성공·실패 모두). 줄마다 같은 `askId`(질문 하나의 공통 ID), 자기 `adviceId`, `seniorIndex`·`seniorCount`(몇 번째/몇 명)가 있다. 그 밖에 `by`(부른 감독), `card`, 질문 앞 200자와 지문, `model`·`effort`(agy 칸은 `effort` 없이 `effortSource: "model-name"`, 덮어쓰기로 골랐으면 `runner`·`source: "flag"`)·`settingsRevision`·`settingsPreset`, `reason`(`ok`·`limit`·`timeout`·`call-failed`·`empty`·`interrupted`), `exitCode`, `durationMs`, 답변 `bytes`·`digest`, 첨부 `files`, `evidencePath`, 따라 보기 탭의 `tab`·`tabReason`·`rottieTerminalId`가 있다. 대화형 방식으로 부른 줄에는 `mode: "interactive"`와(실패했으면) 상세 이유 `detail`이 붙는다. 증거 폴더는 `KADAN_HOME/advice/<askId>/<n>-<실행기>-<모델>/`다(옛 `advice/<adviceId>/` 폴더 기록은 그대로 남는다). 신호(TERM/INT)로 끊기면 아직 끝나지 않은 시니어마다 `reason: interrupted` 줄을 남긴다. 새 사건 종류는 만들지 않았다. 답변 본문은 원장에 넣지 않고 증거 폴더의 `result.txt`에만 둔다. 기록 화면에서는 **자문**으로 보이고, 질문 하나에 줄이 여러 개일 수 있다(`askId`로 묶인다). 사건은 호출이 끝난 뒤 쓰므로 SIGKILL이면 증거 폴더만 남을 수 있다.

횟수 제한은 일부러 두지 않는다(2026-10-05 [kyle] 결정): 감독이 필요할 때만 부르는 것이 전제이고, 같은 카드로 다시 부르면 다시 돈다(비용이 든다). "카드당 1회"는 템플릿의 기본 습관이지 명령이 막는 규칙이 아니다.

## 언제 묻는가

[슈퍼감독](../skills/kadan-conductor/references/role-templates/super.md)·[일반감독](../skills/kadan-conductor/references/role-templates/conductor.md) 템플릿의 규칙 그대로다: 작업 결과를 받고 결정할 부분이 있을 때(검수 판정이 갈림, 결과대로 갈지 되돌릴지 등) 한 번 묻는다. 카드를 쓰기 전의 자문은 시니어가 아니라 Claude Code 어드바이저의 몫이다. 보통 결정 하나에 1회로 끝낸다(필요하면 더 불러도 막지 않는다). 취향·제품 방향처럼 사용자만 답할 수 있는 질문은 자문으로 대신하지 않는다 — [질문 사다리](../skills/kadan-conductor/references/tiki-taka.md)대로 우편과 결정 요청으로 올린다.

## 따라 보기 탭

Why: kyle이 시니어가 무엇을 읽고 어떻게 고민하는지 화면에서 보고 싶다(2026-10-16 [kyle]). 시니어는 여전히 일회성 호출이고 역할 세션이 아니다.

- **언제 뜨나**: 창 설정이 `rottie`이고(`kadan window`), 로티 실행 파일 경로가 있고, 기본이 아닌 홈이 운영 로티에 닿는 것을 막는 보호(`live-floor-guard`)를 통과하고, 카드의 저장소 폴더(`repoPath`)가 로티에 이미 열려 있을 때. `KADAN_SENIOR_TAB=off`로 끄고 `on`으로 켠다(없으면 켬).
- **무엇이 뜨나**: 방식에 따라 다르다.
  - **대화형(기본)**: `tmux -L <시니어 소켓> attach -r -t '=<세션>'`이 도는 탭. 시니어 대화창(codex·agy) 화면을 읽기 전용으로 붙여 보며 입력은 세션에 닿지 않는다(창 크기는 위에서 고정). 관문을 통과한 칸에만, 질문이 제출된 뒤에 연다. 질문을 제출한 감싼 프로세스가 호출 폴더에 `submitted.json`(이번 호출의 askId·세션 이름·pane PID·호출 폴더 경로)을 쓰면, `kadan senior`가 그 파일을 **읽어 확인하고**(일반 파일이어야 하고 — 링크·폴더는 거절 —, JSON으로 읽혀야 하고, 값이 이번 호출·이번 자리와 모두 같아야 한다) 열기 직전에 세션이 살아 있는지(자식이 끝났다는 판정 `outcome.json`이 아직 없고 pane이 기록한 그 PID로 살아 있음) 본 뒤에만 연다. 표지가 있기만 해서는 열지 않는다. 이 탭은 호출이 끝난 뒤에도 세션과 함께 남는다(닫는 때는 아래 '닫기').질문이 제출되지 않고 끝난 칸, 표지가 믿을 수 없는 칸, 열기 전에 호출이 끝난 칸에는 열지 않는다(탭은 답 판정과 무관한 꾸밈이다). 열기 직전에 본 뒤 세션이 끝나는 틈은 막지 못한다 — 그때 열린 탭은 호출이 끝날 때 기존 닫기·지우기로 정리된다. 세션이 끝나면 탭 명령도 끝난다.
  - **헤드리스**(`senior-mode`에 `headless`): `scripts/senior-follow.sh <호출 폴더> <kadan senior의 PID>`가 도는 탭. `diagnostic.log`를 `tail -F`로 보여 주는 읽기 전용이고 입력을 받지 않는다. `exit-code.txt`가 생기거나 부모 PID가 사라지면 스스로 끝난다(TERM으로 죽은 `kadan senior`는 `exit-code.txt`를 남기지 않아서).
- **역할이 아니다**: `KADAN_ROLE`·`kadan-*` 이름을 쓰지 않고 제목은 `시니어 · <카드키>`(시니어가 둘 이상이면 ` · <모델>`을 덧붙여 탭을 가른다), 멱등 키는 `kadan-senior-<호출ID>`다. `start` 원장 사건을 쓰지 않으므로 `kadan status`·바닥 `list()`·감시기가 잡지 않는다.
- **탭은 꾸밈이다**: 앱 꺼짐(`ROTTIE_APP_NOT_RUNNING`)·workspace 없음(`ROTTIE_WORKSPACE_NOT_OPEN`)·닫기 실패가 시니어 호출을 실패시키지 않는다. 앱을 띄우거나 workspace를 새로 추가하지 않는다.
- **닫기**: 헤드리스 호출의 탭은 성공·실패·시간 초과·TERM/INT 모두 `terminal close`를 부른다(신호 처리기는 create 전에 설치하고, create가 동기라 신호는 id를 받은 뒤 처리된다). **대화형 호출의 탭은 세션과 함께 남긴다**(영수증·원장에 `tab: opened`). 닫는 것은 그 세션을 끄는 정리 명령과 남긴 세션 내보내기이고, 세션이 스스로 사라진 호출만 호출 끝에 닫는다. 남긴 탭을 닫을 때는 탭 스위치(`KADAN_SENIOR_TAB`)·창 설정과 무관하게 `tab.json`의 자기 탭 id로 닫는다(아래 '닫을 탭 표지'). 닫는 방법은 같다: 닫은 뒤 `show`가 NOT_FOUND면 사라진 것이고, 그 밖의 오류거나 남아 있으면 자기 탭 id만 `terminal remove`한다.
- **탭 없이 보려면**: 영수증의 `follow` 줄을 직접 실행한다. 대화형은 `tmux -L <시니어 소켓> attach -r -t '=<세션>'`(읽기 전용 붙이기, 세션이 살아 있는 동안만), 헤드리스는 `tail -F <호출 폴더>/diagnostic.log`다.

### 알려진 한계

- **로티 실행 파일 첫 인자 가드**: 로티 실행 파일을 첫 인자가 `status|workspace|terminal|recovery`가 아닌 꼴(인자 없음·`--version`·오타)로 부르면 CLI가 아니라 앱 전체가 다시 떠서 약 3초 뒤 기존 창을 앞으로 가져온다(2026-10-16 로티 쪽 실측). `terminal create`·`workspace add` 자체는 맨 앞 앱·활성 탭을 바꾸지 않아 포커스 없는 생성 옵션은 필요 없다. 그래서 `runRottie`(`src/rottie-cli.mjs`)는 주입 spawn이어도 첫 인자를 먼저 검사해 `ROTTIE_ARGV_REJECTED`(effect none)로 실행하지 않는다.

- **어떤 종료에서 탭이 남을 수 있나**: 탭을 만드는 순간에 터미널 Ctrl-C처럼 프로세스 그룹 전체가 SIGINT를 받아 로티 CLI도 함께 죽은 경우, SIGKILL, 전원·강제 종료. 이때는 탭 주소(id)를 받지 못해 닫을 수 없고, 보기 탭 1개가 남을 수 있다. 주소를 모르면 정리하지 않는다(제목·키로 목록을 뒤져 지우면 남의 탭을 지울 수 있다).
- **남은 탭 찾는 법**: 호출 폴더 `KADAN_HOME/advice/<askId>/<n>-<실행기>-<모델>/tab.json`의 `key`(`kadan-senior-<호출ID>`, create 전에 먼저 쓴다) 또는 원장 `advice` 사건의 `tabKey`를 보고, 로티에서 `시니어 · <카드키>` 제목의 탭을 직접 닫는다. 신호 처리기가 돌 수 있고 저장이 성공했을 때만 `reason: interrupted`로 원장에 남는다. 저장 거절·SIGKILL·전원 종료 때는 증거 폴더 `tab.json`만 남는다.
- **영향 없는 것**: 시니어 답·원장 기록·운영 카단. 탭은 꾸밈이라 남아도 읽기 전용 로그 화면 하나일 뿐이고, 따라 보기 스크립트는 부모가 사라지면 스스로 끝난다.

### 포커스 실측 (2026-10-16, 1회, kyle 허락)

로티 `terminal create`에는 포커스를 끄는 옵션이 없어 실제 로티로 한 번 쟀다. 조건: 격리 `KADAN_HOME`, `KADAN_ALLOW_LIVE_FLOOR=1`, 실제 로티, 가짜 `codex`(약 8초, 비용 0).

- 맨 앞 앱은 `osascript`로 읽기만 했다(포커스를 옮기는 명령 없음). 1초 간격으로 표본 10개(실행 전·실행 중 8·실행 후, 약 9초)를 읽었고 관측한 표본에서는 로티가 맨 앞에 없었다(맨 앞 앱이 Notion·Aside로 바뀐 것은 사용자 조작으로 추정되며 확정하지 않는다. 로티 없는 리허설에도 같은 변화가 있었다).
- 열린 동안 `terminal list`에 `시니어 · smoke/senior-probe` 하나가 `running`으로 보였고(839 → 840), 끝난 뒤 사라졌다(839). `terminal close` 뒤에도 목록에 남아 `terminal remove`가 필요했다 — 그래서 close 뒤 remove를 넣었다.
- **확인하지 못한 것**: 로티 안에서 새 탭이 선택(전환)되는지는 CLI 출력에 선택 필드가 없어 관찰하지 못했다. 1초 간격이라 순간적인 앞으로 오기도 못 잡았을 수 있다.
- 결정: 로티가 맨 앞으로 오지 않았으므로 기본은 켬이다(`src/senior-tab.mjs`의 `SENIOR_TAB_DEFAULT_ON`). 맨 앞으로 오는 것이 확인되면 `false`로 바꿔 자동 열기를 끈다(영수증 `follow` 명령만 남는다).
- 로티에 포커스 없는 `terminal create` 옵션이 생기면 `buildSeniorTabCreateArgv`(`src/senior-tab.mjs`)에 그 옵션을 붙이도록 바꾼다.

### 다른 일회성 호출에 쓸 수 있나 (메모, 코드는 바꾸지 않음)

감시 AI(`scripts/watch-judge.sh`)와 설명 AI도 같은 모양의 일회성 호출이라 진행 출력 파일이 있으면 `senior-follow.sh`로 따라 볼 수 있다. 다만 감시 AI는 주기마다 자주 돌아 탭이 계속 열고 닫히므로 꾸밈 이상의 소음이 된다. 쓰려면 호출 폴더·`exit-code.txt`·진행 로그 규약을 시니어와 맞추고, 켜는 스위치를 따로 두는 것이 먼저다.
