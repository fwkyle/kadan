# 감시 AI 관계표의 중복 저장 줄이기

## Why

같은 역할 관계와 전달 경로를 요청마다 다시 저장해 원장이 커지는 일을 줄인다.

새 `watch-ai-request`의 `parents`와 `routes`는 내용 지문(SHA-256)으로 가리킨다.
배열 순서를 포함한 같은 내용은 `watch-context/<지문>.jsonl` 스트림 한 줄에만 저장한다.
이 이름은 SQLite 안의 스트림 이름이며 새 JSONL 파일을 만들지 않는다.
관계표와 요청은 같은 트랜잭션에서 함께 커밋한다. 사건 수정·삭제 금지와 FULL 내구성은 유지한다.

10배 요청에서도 관계표 본문은 내용이 바뀐 횟수만큼 저장하고, 각 요청에는 64자 참조만 추가한다.
과거 요청은 그대로 보존하며 `readWatchRequest`가 과거 본문과 새 참조를 모두 읽는다.
일반 감시 조회에는 관계표를 올리지 않는다. 실제 보고·전달 경로를 계산할 때 단건으로 복원한다.
누락·다중 행·지문 불일치는 빈 관계표나 기본 경로로 바꾸지 않고 오류로 멈춘다.
`storage verify`는 관계표 지문과 요청 참조도 확인한다. SQLite 백업에 함께 포함된다.

참조 형식을 모르는 이전 실행 파일로 새 요청을 처리하는 것은 지원하지 않는다.
운영 감시기를 새 버전으로 재시작한 뒤 쓰며, 과거 사건의 일괄 변환이나 삭제는 하지 않는다.
