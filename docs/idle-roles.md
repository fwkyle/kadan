# 쉬는 역할 정리 후보 알림

## Why

일이 끝난 역할 세션이 꺼지지 않고 쌓이면 메모리와 화면이 계속 붙들린다. 감독이 일일이 찾아보지 않아도 되도록, 카단이 "오래 쉬고 있고 맡은 일이 없는 역할"을 골라 그 역할의 직속 상위 감독에게 알려 준다.

**카단은 아무것도 끄지 않는다.** 끌지는 우편을 받은 감독이 정한다(2026-11-13 [kyle] 결정). 사용자에게는 알리지 않고, 대시보드에 후보 수만 보인다.

## 무엇이 정리 후보인가

아래를 모두 충족하는 살아 있는 역할 세션이다(tmux 바닥만).

- 프로필이 작업자·검수자·일반감독이다.
- 화면 글자가 **기준 시간**(기본 12시간) 넘게 그대로다.
- 끝나지 않은 카드가 없다. 일반감독은 책임진 끝나지 않은 업무(보류 포함)도 없다.

하나라도 걸리거나 **확인하지 못하면 후보가 아니다**(모르면 고르지 않는다).

| 후보에서 빼는 조건 | 이유 |
|---|---|
| 슈퍼감독·비서·기반 프로세스(비서·대시보드·디코 다리·감시기)·프로필 기록 없음 | 대상이 아니다 |
| 열린 사용자 결정을 낸 역할 | 답을 받아 이어 갈 역할이다 |
| 답 대기 — `--expect-reply` 질문을 보냈거나 답할 차례 | 대화가 끝나지 않았다 |
| 안 읽은 보관 우편이 있음 | 받을 일이 남았다 |
| 인계 진행 중 | 책임이 옮겨 가는 중이다 |
| 열린 업무의 차례(`turnOwner`) | 그 역할이 움직일 차례다 |
| 살아 있는 하위 역할이 있는 감독 | 하위가 보고할 곳이 사라진다 |
| 응답 생성 중·최근 사람 입력·입력 대기가 아닌 화면 | `kadan restart`의 끄기 직전 확인과 같은 기준 |
| 백그라운드 셸·터미널이 도는 화면(`… 2 shells still running`, `2 background terminals running …`) | 일하는 화면이다. 감시가 정당한 대기로 보는 것과 같은 판독을 쓴다([감시 안내](watch-overview.md)). 표시가 있는 동안은 쉼 시계를 세지 않는다 |
| 마지막 확인에서 화면 본문이 표본 때와 달라짐 | 방금 움직였다. 쉼 시각을 그 실행 시각으로 다시 센다 |
| 관계표에 없거나 살아 있는 상위 감독이 없음 | 알릴 곳이 없다(사용자에게는 알리지 않는다) |
| 원장·카드·업무·결정·관계표·화면을 읽지 못함 | 확인 불가 |

다시 띄운 세대(`restart`·`reopen`·복원)인지는 보지 않는다. 업무 마감 때 함께 끄는 정리(`kadan work complete`)의 "다시 띄운 세대 제외" 제한은 "이 세션이 그 업무를 한 세션인가"를 지키는 것이고, 여기서는 세션 자신의 쉼만 본다. 그 정리는 그대로다.

다시 열 수 없는 세션(대화 번호를 찾지 못함, 이어 열기 명령이 설정에 없음, 작업 폴더 없음)은 빼지 않고 우편 줄에 `reopen 불가(이유)`로 적는다. 이 표시는 "지금 끄면 그럴 것"이라는 예상이다.

## 우편

받는 사람은 그 역할의 직속 상위다(작업자·검수자 → 일반감독, 일반감독 → 슈퍼감독, 관계표 기준). 직속 상위가 꺼져 있으면 살아 있는 가장 가까운 상위에게 간다. 받는 감독마다 한 통으로 묶는다.

```text
[정리 후보] 화면이 12시간 넘게 그대로이고 맡은 일이 없는 하위 역할 2개입니다. 카단은 아무것도 끄지 않습니다.
더 쓰지 않을 역할은 아래 명령으로 끄고, 계속 쓸 역할은 그대로 두세요. 끈 역할은 kadan reopen <역할>로 같은 대화를 다시 엽니다(reopen 불가 표시는 다시 열 수 없음).
같은 역할은 12시간 뒤에도 그대로면 다시 알립니다. 이 우편에 답장할 필요는 없습니다.
- demo-작업자 · worker · 마지막 화면 변화 11/13 03:20 무렵(약 13시간 전) · reopen 가능(대화 0197aaaa) · 끄기: kadan stop demo-작업자
- demo-검수자 · reviewer · 마지막 화면 변화 11/13 02:10 무렵(약 14시간 전) · reopen 불가(대화 번호를 찾지 못함: undetermined) · 끄기: kadan stop demo-검수자
```

- 같은 역할은 기준 시간에 한 번만 알린다. 근거는 **보낸 우편**이다: 원장의 `send`(보낸 쪽 `idle-roles`)와 그 본문의 `끄기: kadan stop <역할>` 줄을 다시 읽는다. 새 원장 종류는 없고, 감시기·기계를 다시 띄워도 이어진다.
- 우편은 일반 우편과 같은 길(`kadan mail`)로 간다. 받는 감독이 입력 중이면 보관되고 감시기가 나중에 알린다.
- 확실히 못 보낸 우편은 다음 시간에 다시 보낸다. 갔는지 불명확한 우편은 기준 시간 동안 다시 보내지 않는다(같은 우편이 매시간 쌓이지 않게).
- 한 번 실행에 우편은 5통까지다. 넘는 묶음은 다음 실행으로 미룬다. 한 통에는 역할 20개까지 적는다.

## "화면이 그대로"를 재는 방법

한 시간에 한 번 살아 있는 역할 세션의 화면을 읽어 글자의 지문을 뜨고, 지난번과 같으면 "그 지문이 처음 된 시각"을 유지한다. 그 시각이 기준 시간보다 오래됐으면 쉬는 것이다. 값은 `$KADAN_HOME/idle-roles-state.json`에 있다(원장이 아니고, 살아 있는 세션 수만큼의 줄).

- 저절로 바뀌는 줄은 지문에서 뺀다: 입력칸 아래 바닥글(모델·ctx %·권한 줄·알림), codex 상태 줄(주간 한도 % 등), claude의 "쉬는 동안 자동 압축" 안내 줄. 입력칸 모양을 확인하지 못한 화면은 아무것도 빼지 않는다.
- 모르면 "방금 바뀜"이다: 처음 본 세션, 프로세스가 바뀐 세션, 상태 파일이 없거나 깨진 경우. 화면을 읽지 못한 세션은 후보에서 빠진다.
- 백그라운드 셸·터미널 표시가 있는 화면은 글자가 그대로여도 시계를 세지 않는다. 표시가 사라진 때부터 기준 시간을 센다(셸이 방금 끝난 역할이 바로 후보가 되지 않는다). `--dry-run`은 이런 역할을 "쉼 시계를 세지 않는 역할"로 따로 보인다.
- 다른 조건을 모두 통과한 역할은 우편을 만들기 전에 화면을 한 번 더 읽는다. 표본 때와 본문이 다르면 후보에서 빼고 쉼 시각을 다시 센다.
- tmux의 창 활동 시각은 쓰지 않는다. 쉬는 claude 화면이 글자는 그대로인 채 30분마다 다시 그려져 그 시각이 계속 움직였다(2026-11-13 운영 실측). 출력 기록 파일의 수정 시각도 64KB 버퍼가 찰 때만 바뀌어 쓰지 않는다.

알아 둘 한계:

- 정밀도는 한 시간이다. 우편의 "마지막 화면 변화" 시각은 "그 무렵"이다.
- 처음 켠 뒤와 tmux 서버가 내려갔다 올라온 뒤(재부팅 포함)에는 기준 시간이 지나야 첫 후보가 나온다.
- 로티 탭을 다른 크기로 열면 화면이 다시 그려져 시계가 다시 시작한다(사람이 들여다본 것으로 본다).
- claude가 쉬는 동안 대화를 자동 압축하면 화면 본문이 바뀌어 시계가 한 번 다시 시작한다.
- herdr 바닥은 재지 않는다.

## 언제 도나

`kadan up --auto`(launchd가 1분마다 부른다)가 **한 시간에 한 번** 돈다. 되살리기 잠금 안에서는 차례만 잡고, 잠금을 푼 뒤에 고른다. 감시 주기 안에서는 돌지 않는다.

비용: 살아 있는 세션마다 화면 읽기 1번과 상태 파일 1번(다른 조건을 모두 통과한 역할은 화면 읽기가 1번 더 든다). 기준 시간을 넘긴 세션이 하나도 없으면 여기서 끝나고 원장을 읽지 않는다. 넘긴 세션이 있으면 원장·카드 요약·업무 목록·결정 목록을 한 번씩 읽고, 보낼 우편마다 우편 명령을 한 번 부른다. 원장이 10배면 이 읽기들도 약 10배다.

## 명령과 설정

```bash
kadan idle-roles show                                # 기준 시간, 마지막 실행, 후보 수
kadan idle-roles set 24 --revision N --reason '이유'  # 기준 시간 바꾸기(1~168시간)
kadan idle-roles run --dry-run                       # 보낼 묶음과 빠진 이유만 출력(우편·상태 파일 없음)
kadan idle-roles run                                 # 지금 한 번 고르고 보낸다
```

- 기준 시간은 값 하나이고, 후보가 되는 쉼 시간이자 같은 후보를 다시 알리는 간격이다. 기본 12시간.
- 값은 실행 모델 설정 파일(`runner-settings.json`)의 `idleRoleHours` 칸에 있다. 바꿀 때 그 파일의 revision을 대조하고, 바꾼 사람·이유가 원장의 `runner-settings` 사건(`action: idle-hours`)으로 남는다. 설정 파일이 없으면 `kadan runners init`을 먼저 한다. 파일이 없거나 값이 범위 밖이면 기본값으로 읽는다.
- 대시보드 **실행 모델 설정**의 접힌 칸 "쉬는 역할 알림 기준"에서도 바꾼다. 후보 수는 그 칸과 전체 현황의 "쉬는 역할 정리 후보"에 보인다(마지막 실행 기준, 모르면 "모름").
- 자동 실행의 우편을 끄려면 `$KADAN_HOME/idle-roles.off` 파일을 둔다. 화면 표본은 계속 쌓이므로, 끈 채로 기준 시간이 지난 뒤 `--dry-run`으로 목록을 먼저 볼 수 있다. `--dry-run`은 끄기 파일이 있어도 목록을 보인다.

## 받은 감독이 할 일

우편의 역할을 보고 더 쓰지 않을 역할만 `kadan stop <역할>`로 끈다. 끈 역할은 원장 `stop`에 대화 번호가 남아 `kadan reopen <역할>`로 같은 대화를 다시 연다([명령](commands.md)). 계속 쓸 역할은 그대로 둔다. 답장은 필요 없다.
